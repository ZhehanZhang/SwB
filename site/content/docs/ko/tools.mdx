`tools/list`는 내 로그인으로 쓸 수 있는 도구를 보여 줍니다. 전체 권한을 가진 소유자 로그인에서는 켜진 모든 블록의 도구가 나옵니다.

## 페어링 키

페어링 키는 소유자가 허용한 접근 범위 안에서 다음 도구를 사용할 수 있습니다.

| 용도 | 도구와 제한 |
| - | - |
| 메시지 | `send`와 `targets`를 사용합니다. 이전 이름이 켜져 있으면 `agent_send`를 사용합니다. 키의 대화 접근 범위 안에서 `inbox`, `wait`, `reply`, `status`, `result`, `cancel`, `get_message`를 사용합니다 |
| 메모리와 프로젝트 | 키가 허용하는 범위 안에서 `context_pack`과 `project_list`를 사용합니다. 메모리 도구는 권한을 받은 범위에서 사용합니다 |
| 라우트 | `routes_list`와 `routes_resolve`를 사용합니다. `routes_set`과 `routes_remove`에서는 `agent`에 자기 에이전트 이름을 지정합니다. 프로젝트는 키의 범위 안에 있는 것을 사용합니다 |
| 설정 | 상태를 확인하려면 `switchboard_status`와 `modes_status`를 사용합니다. 클라이언트 안내를 받으려면 `connect`를 사용합니다. 블록 설정과 페어링 코드 발급에는 소유자 로그인을 사용합니다 |
| 블록 | 받은 권한과 채널 모드가 허용하는 동작 안에서 블록 도구를 사용합니다 |

`login_link`, `connect_code`, `connect_list`, `connect_revoke`, `visibility_list`, `visibility_set`에는 전체 권한을 가진 소유자 로그인이 필요합니다. `project_create`, `project_update`, `project_sync`, `space_mode`에도 소유자 로그인을 사용하세요. 소유자 로그인으로는 `memory_promote`, `routine_register`, `routine_add`, `routine_remove`, `discord_provision`, `telegram_provision`도 쓸 수 있습니다.

소유자는 `auth.key_tools`로 도구를, `auth.key_targets`로 전송 대상을 제한할 수 있습니다. `auth.key_scopes` 설정은 라우팅, 메시지, 대화를 제한합니다. 메모리 도구는 SwB이 페어링 키마다 저장한 권한을 따릅니다.

## 메시지

| 도구 | 용도 |
| - | - |
| `send` | 작업이나 메시지를 `task`에 넣습니다. 대상을 고르려면 `to`를 설정합니다. 키가 허용하면 `to`를 비워 라우트를 사용합니다 |
| `agent_send` | 지원이 중단된 도구입니다. `to="codex"`처럼 `to`에 에이전트 이름을 넘깁니다. `blocks.mcp.legacy_aliases`가 기본으로 이 도구를 켭니다. 새 호출에는 `to="agent:codex"`와 함께 `send`를 사용합니다 |
| `wait` | 새 메시지나 답장을 기다립니다 |
| `inbox` | 받은편지함을 읽고 바로 돌아옵니다 |
| `reply` | 전송이나 받은편지함 항목의 `handle`을 `conversation`에 넘깁니다. 답장은 `text`에 넣습니다 |
| `status` | 대화 하나의 상태를 보여 줍니다. Capy에서는 `messages`로 최근 메시지 수를 정합니다. 도구 활동까지 보려면 `include_tools=true`를 설정합니다 |
| `switchboard_status` | 로그인한 신원, 대기 한도, 블록, 인스턴스 상태를 보여 줍니다 |
| `result` | 대화의 최종 답장을 가져옵니다. 지원되는 곳에서는 `tail`로 최근 답장이나 메시지 수를 정합니다 |
| `cancel` | 대화 추적을 멈춥니다 |
| `targets` | 사용할 수 있는 대상 주소를 나열합니다. 보낼 수 있는 곳은 내 키와 대상의 규칙이 정합니다 |
| `get_message` | 받은편지함이나 MCP 이벤트의 `message_id`로 저장된 메시지를 읽습니다 |

### 받은편지함 커서

커서는 받은편지함에서의 위치를 표시합니다. `inbox`와 `wait` 도구는 항목을 돌려줄 때 새 위치를 저장합니다. 필터를 쓰면 별도의 위치가 앞으로 이동할 수 있습니다. 나중에 호출한 `wait`는 저장된 위치부터 읽습니다. 처음부터 읽으려면 `inbox`에 `since_cursor=0`을 넘기세요. 특정 위치부터 이어 읽으려면 돌려받은 `cursor`를 `since_cursor`로 넘기세요.

스크립트는 bearer 키로 `GET /inbox/poll`을 호출해 자기 받은편지함의 항목을 기다릴 수 있습니다. 이어서 받으려면 돌려받은 `cursor`를 `after`로 넘기세요. 기본적으로 받은편지함의 현재 끝에서 시작합니다. 항목이 도착하거나 대기 시간이 끝나면 호출이 돌아옵니다. 이때 MCP 커서는 그대로 유지됩니다. 메시지가 도착하는 대로 받으려면 [받은편지함 이벤트 스트림](/ko/docs/connect#받은편지함-이벤트-스트림)을 사용하세요. 내 로그인으로 볼 수 있는 맥락 항목과 Watch 요약본은 `inbox`로 읽으세요.

페어링 키로 접근 범위 밖의 메시지나 대화를 요청하면 존재하지 않는 ID를 요청했을 때와 같은 오류가 납니다. [제한이 있는 키](/ko/docs/security#제한이-있는-키)를 참고하세요.

### 전송 옵션

| 옵션 | 용도 |
| - | - |
| `wait_s` | 블록의 첫 답장을 기다릴 시간(초)을 정합니다. SwB은 에이전트의 대기 한도를 적용합니다. 에이전트 우편함에는 `wait`를 사용합니다 |
| `forward` | `owner` 신뢰 수준으로 받은 대화 가운데 조건에 맞는 대화의 ID를 넘깁니다. SwB은 최종 답장을 원래 발신자에게 보냅니다 |
| `new_conversation` | `true`로 설정하면 Capy Captain의 프로젝트에서 새 스레드를 시작합니다. `false`로 설정하면 Capy Captain의 스레드로 보냅니다 |
| `files` | Capy 작업에 파일을 첨부합니다. 각 파일에 `name`과 `text` 또는 `base64` 내용을 지정합니다. 파일 유형은 `media_type`으로 정합니다 |
| `repos` | Capy 작업에 쓸 저장소를 `owner/repo` 이름으로 넘깁니다. SwB 프로젝트에 연결된 저장소를 사용합니다 |
| `in_reply_to` | 메시지에 답하려면 이 옵션 대신 `conversation`과 함께 `reply`를 사용합니다 |

## 메모리와 프로젝트

소유자 로그인이나 해당 메모리 범위의 권한을 가진 자격 증명을 사용하세요. 에이전트로서 항목을 업데이트하거나 옮기거나 삭제하려면 그 항목을 마지막으로 쓴 자격 증명을 사용하세요. 소유자는 모든 항목을 관리할 수 있습니다. `general`에 있는 기존 항목을 바꾸려면 소유자 권한이 필요합니다.

| 도구 | 용도 |
| - | - |
| `context_pack` | 프로젝트 브리핑을 읽습니다. `general`은 자격 증명에 접근 권한이 있을 때만 포함됩니다. 페어링 키의 Capy 섹션에는 대화 범위 안에서 그 에이전트가 한 작업이 나옵니다 |
| `memory_write` | 권한을 받은 범위에 저장합니다. `scope`, `namespace`, `title`, `body`를 넘깁니다. 네임스페이스는 범위 안에서 항목을 묶습니다. `notes/meetings`처럼 소문자로 세 단계까지 씁니다. 프로젝트 메모리는 `project`와 `scope`에 같은 프로젝트를 넘깁니다. `general`에 쓰려면 먼저 소유자에게 확인을 요청한 뒤 `confirm_general=true`를 설정합니다 |
| `memory_search` | `query`로 검색합니다. `project`를 넘기면 그 프로젝트와 권한을 받은 `general` 메모리를 검색합니다. 그 프로젝트만 검색하려면 `include_general=false`를 설정합니다. `agent:<name>` 같은 특정 권한에는 `scopes`를 사용합니다 |
| `memory_list` | `memory_search`와 같은 범위 입력으로 항목을 나열합니다 |
| `memory_read` | 권한을 받은 범위에서 항목 하나를 기록과 함께 읽습니다 |
| `memory_delete` | 권한을 받은 범위에서 항목을 제거합니다 |
| `memory_move` | 항목을 프로젝트 범위나 에이전트 범위로 옮깁니다. 두 범위 모두의 권한이 필요합니다 |
| `memory_promote` | 항목을 `general`로 옮깁니다. 소유자 로그인을 사용합니다 |
| `project_list` | 프로젝트와 그 링크를 나열합니다 |
| `project_create` | 프로젝트를 만듭니다 |
| `project_update` | 프로젝트 이름을 바꾸거나, 연결하거나, 보관하거나, 비공개로 만듭니다 |
| `project_sync` | 프로젝트를 대응하는 프로젝트에 다시 연결합니다 |

이 값들을 설정하려면 `project_update`의 `links`를 사용하세요. SwB은 설정된 에이전트와 블록에 맞는 프로젝트 링크 키를 제공합니다.

| 키 | 값 |
| - | - |
| `repos` | `owner/repo` 형식의 저장소 이름 목록 |
| `claude_project` | Claude 프로젝트 이름 또는 ID |
| `chatgpt_project` | ChatGPT 프로젝트 이름 또는 ID |
| `capy_project` | Capy 프로젝트 이름 또는 ID |

비공개 프로젝트에 접근하려면 그 프로젝트를 지정한 권한이나 소유자 권한이 필요합니다. `memory_search`와 `memory_list`에서는 비공개 프로젝트를 `project`에 지정하세요. 접근할 수 있는 다른 공개 프로젝트는 `scopes`로 지정하세요.

## 설정

| 도구 | 용도 |
| - | - |
| `connect` | 플랫폼의 다음 설정 단계를 받습니다 |
| `connect_code` | 새 에이전트용 페어링 코드를 만듭니다 |
| `connect_list` | 에이전트 키를 나열합니다 |
| `connect_revoke` | 에이전트 키를 제거합니다 |
| `login_link` | 소유자용 일회용 로그인 링크를 만듭니다 |
| `modes_status` | 접근할 수 있는 채널과 저장소의 모드, 대상, 설정 문제를 보여 줍니다 |
| `space_mode` | 소유자로서 모드, 프로젝트, 허용할 동작을 설정합니다. 설정을 지우려면 `inherit`을 사용합니다 |
| `visibility_list` | 기본 접근 규칙과 개별 리소스 규칙을 보여 줍니다. 소유자 로그인을 사용합니다 |
| `visibility_set` | 소유자로서 리소스를 비공개나 공유로 설정합니다. 도구는 항상 비공개입니다 |

### 컴패니언 도구

이 도구는 소유자로서 사용하세요.

| 도구 | 제목 | 용도 |
| - | - | - |
| `companion_code` | Pair a companion | 기기용 페어링 코드를 만듭니다 |
| `companion_list` | List companions | 페어링된 기기와 그 상태, 동작을 봅니다 |
| `companion_invoke` | Run a companion action | 연결된 기기에서 동작을 실행합니다. 기기 ID와 동작 정보는 `companion_list`에서 확인합니다 |
| `companion_revoke` | Disconnect a companion | 기기 키를 폐기하고 연결을 닫습니다 |

## 라우트

라우트는 `send`의 대상을 고릅니다. `capy`, `claude-routine`, `grok-routine`처럼 라우트를 받는 블록을 사용하세요. 에이전트 우편함으로 바로 보내려면 `to="agent:<name>"`을 사용하세요. Muse 우편함으로 보내려면 `to="agent:muse"`를 사용하세요. [Muse를 깨우려면](/ko/docs/setup/muse#muse-실시간으로-깨우기) `to="muse:gadget:muse"`를 사용하세요.

| 도구 | 용도 |
| - | - |
| `routes_list` | 우편함 라우트를 포함한 모든 라우트를 나열합니다 |
| `routes_set` | 라우트를 저장합니다. `target`에는 `agent:<name>` 같은 에이전트 우편함이나 `capy:captain:<name>` 같은 블록 주소를 지정합니다. 라우트 적용 범위를 좁히려면 `agent`나 `project`를 사용합니다 |
| `routes_resolve` | 수신처 하나에 맞는 라우트를 보여 줍니다. `grok-routine`이나 `agent` 같은 `block`을 넘깁니다 |
| `routes_remove` | 고른 `block`에서 `agent`와 `project`가 정확히 일치하는 라우트를 제거합니다 |

수신처 하나의 라우트를 확인하거나 제거하려면 `block`을 사용하세요. 기본적으로 `routes_resolve`는 에이전트와 프로젝트를 함께 확인한 뒤 프로젝트, 에이전트, 전역 라우트 순서로 확인합니다. 단계마다 블록을 순서대로 확인한 다음 `agent`를 확인합니다. `routes_remove`도 기본적으로 정확한 에이전트와 프로젝트에 대해 같은 수신처 순서로 확인합니다.

## 블록 도구

### Capy

이전 Capy 도구 이름은 `blocks.mcp.legacy_aliases`가 켜져 있을 때 나타납니다.
| 도구 | 용도 |
| - | - |
| `capy_captains` | 내 Capy 연결로 접근할 수 있는 Capy Captain을 나열합니다 |
| `capy_captain_digest` | Capy Captain의 요약을 읽고 작업 중이거나 소유자 확인이 필요한 크루 스레드를 봅니다. 소유자 로그인을 사용합니다 |
| `capy_list` | SwB으로 보낸 작업이나 Capy Captain 크루, 연결된 Capy 프로젝트의 스레드를 나열합니다. 페어링 키는 범위 안에서 자기 에이전트의 작업만 봅니다 |
| `capy_delegate` | Capy에 작업을 보냅니다. 새 호출에는 `to="capy"`와 함께 `send`를 사용합니다 |
| `capy_inbox` | Capy 받은편지함을 읽고 바로 돌아옵니다. 새 호출에는 `block="capy"`와 함께 `inbox`를 사용합니다 |
| `capy_wait` | 받은편지함의 다음 항목을 기다립니다. 새 호출에는 `wait`를 사용합니다 |
| `capy_status` | Capy 스레드의 상태와 최근 메시지를 보여 줍니다. 새 호출에는 `status`를 사용합니다 |
| `capy_reply` | Capy 스레드에 후속 메시지를 보냅니다. 새 호출에는 `reply`를 사용합니다 |
| `capy_result` | Capy 스레드의 최신 답장을 파일과 풀 리퀘스트 링크와 함께 가져옵니다. 새 호출에는 `result`를 사용합니다 |
| `capy_cancel` | Capy에 보낸 작업의 추적을 멈춥니다. Capy 스레드는 계속 진행될 수 있습니다. 새 호출에는 `cancel`을 사용합니다 |

### Claude Code 루틴

이 도구는 `claude-routine` 블록이 켜져 있을 때 나타납니다. 루틴은 SwB이 시작할 수 있는 Claude Code 작업입니다.

| 도구 | 용도 |
| - | - |
| `routine_register` | 루틴을 등록하고 소유자가 토큰을 입력할 등록 링크를 받습니다 |
| `routine_list` | SwB이 시작할 수 있는 루틴을 나열합니다 |
| `routine_pickup` | 루틴이 빈 프롬프트로 시작하면 메시지를 가져옵니다 |
| `routine_add` | 소유자로서 루틴을 토큰과 함께 추가합니다 |
| `routine_remove` | 소유자로서 SwB으로 저장한 루틴을 제거합니다 |

### Slack

| 도구 | 용도 |
| - | - |
| `slack_workspaces` | 쓸 수 있는 Slack 워크스페이스, 워크스페이스별 계정, 게시 규칙을 나열합니다 |
| `slack_channels` | 선택한 Slack 계정에 보이는 채널을 나열합니다. SwB이 지켜보는 채널은 목록에 표시됩니다 |
| `slack_search` | 소유자의 Slack 계정으로 워크스페이스의 메시지를 검색합니다 |
| `slack_history` | 채널의 최근 메시지를 최신순으로 읽습니다 |
| `slack_thread` | 스레드의 첫 메시지와 답장을 오래된 순으로 읽습니다 |
| `slack_watched` | 새 메시지가 SwB 받은편지함으로 들어오는 채널을 나열합니다 |
| `slack_events` | 지켜보는 채널의 최근 메시지, 봇 멘션, 다이렉트 메시지를 읽습니다. 최신 항목이 먼저 나옵니다 |
| `slack_wait` | 받은편지함의 다음 Slack 항목을 기다립니다 |
| `slack_personas` | 봇 게시물에 쓸 수 있는 이름과 이미지, 기본 선택을 보여 줍니다 |
| `slack_targets` | Slack에서 봇 멘션 뒤에 쓸 대상 이름을 나열합니다 |
| `slack_post` | 봇이나 소유자의 Slack 계정으로 게시합니다. 스레드에 답장하려면 `thread_ts`를 사용합니다. 게시 규칙에 따라 소유자 승인이 필요할 수 있습니다 |
| `slack_react` | 메시지에 이모지 반응을 남깁니다. `slack_post`와 같은 규칙이 적용됩니다 |
| `slack_request_write` | 게시하려는 Slack 메시지를 소유자에게 보내 승인을 요청합니다 |
| `slack_write_requests` | Slack 승인 요청의 상태를 확인합니다. 요청 하나를 읽으려면 `request_id`를 사용합니다 |

### GitHub

GitHub 대화 동작에서는 SwB 대화 ID를 `conversation`이나 `handle`에 넘기세요. `github_reply`와 `github_notify_owner`에는 `text`를 사용하세요.

| 도구 | 용도 |
| - | - |
| `github_status` | 웹훅, 저장소 모드, GitHub App 권한을 확인합니다 |
| `github_label` | 이슈나 풀 리퀘스트에 기존 라벨을 붙입니다 |
| `github_comment` | 이슈나 풀 리퀘스트에 댓글을 답니다 |
| `github_open_issue` | 저장소에 이슈를 엽니다 |
| `github_link_duplicate` | 이슈를 같은 저장소의 원래 이슈에 연결합니다. SwB은 `duplicate` 라벨을 붙이고 중복 이슈를 `not_planned`로 닫습니다 |
| `github_notify_owner` | 대화를 시작한 이슈나 풀 리퀘스트 링크를 담아 소유자 받은편지함에 알림을 보냅니다 |
| `github_reply` | SwB 대화를 시작한 GitHub 스레드에 답장합니다 |
