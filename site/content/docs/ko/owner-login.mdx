소유자는 SwB을 관리하려고 로그인합니다. 소유자는 이 권한으로 에이전트 로그인을 승인하고 토큰을 저장합니다.

| 페이지 | 용도 |
| - | - |
| `/login` | 소유자로 로그인합니다. |
| `/authorize` | 에이전트의 연결 요청을 검토합니다. |

## 일회용 링크

```bash
swb login-link
```

이 명령은 `https://swb.example.com/login#t=...` 같은 링크를 출력합니다. 5분 안에 브라우저에서 여세요. 링크는 한 번만 쓸 수 있습니다. 소유자로 로그인한 에이전트도 `login_link` 도구로 링크를 만들 수 있습니다. 토큰은 링크에서 `#` 뒤에 있습니다.

처음 로컬에서 시작하면 `swb up`이 일회용 링크를 출력합니다. 로컬 주소의 기본값은 `http://localhost:8870`입니다. `SWB_PORT`를 설정하면 주소에 그 포트를 사용합니다. `swb login-link`에서 다른 서버를 고르려면 `--url`을 사용하세요. 다른 인스턴스 폴더의 소유자 키를 읽으려면 `--dir`를 사용하세요.

링크로 로그인하다가 실패하면 `swb login-link`를 다시 실행하세요. 새 링크를 브라우저에서 여세요.

## 설정 코드

설정 코드는 첫 소유자 로그인에 한 번만 쓸 수 있습니다. SwB이 로그인을 직접 처리할 때 사용하세요. 호스팅 서버에서 코드를 받는 곳은 [배포 가이드](/ko/docs/deploy)에 나와 있습니다.

코드를 직접 정하려면 임의의 32바이트를 만드세요. 이를 소문자 16진수 64자나 표준 Base64로 인코딩하세요. 이 명령은 비공개 `.env` 파일에 16진수 코드를 추가합니다. `swb init` 다음에 인스턴스 폴더에서 실행하세요.

```bash
(umask 077; printf 'SWB_SETUP_CODE=%s\n' "$(openssl rand -hex 32)" >> .env)
```

`SWB_SETUP_CODE`를 설정한 상태로 SwB을 시작하세요. 브라우저에서 `/login`을 여세요. **Setup code**에 코드를 붙여 넣으세요. **Sign in**을 선택하세요.

## 패스키

**패스키**는 내 기기로 로그인을 확인하는 방식입니다. 처음 로그인한 뒤 **Passkey name**에 기기 이름을 입력하세요. **Add a passkey**를 선택하세요.

다른 기기를 추가하려면 **Settings**를 여세요. **Sign-in**에서 **Add a passkey**를 선택하세요. 이름을 입력하세요. **Add passkey**를 선택해 저장하세요. 다음 로그인부터 패스키를 사용하세요.

## OIDC

OIDC(OpenID Connect)는 Google 같은 로그인 서비스가 내 신원을 확인하게 해 주는 규약입니다. 설정 파일에 사용하는 서비스를 추가하세요. `SWB_OIDC_CLIENT_SECRET`에 그 서비스의 시크릿을 설정하세요.

```yaml
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
  oidc:
    name: Google
    issuer: https://accounts.google.com
    client_id: 1234.apps.googleusercontent.com
    client_secret_env: SWB_OIDC_CLIENT_SECRET
```

공급자 설정에서 리디렉션 주소를 `https://swb.example.com/auth/oidc/callback`으로 지정하세요. 로그인 페이지에 그 서비스의 버튼이 나타납니다. SwB은 `auth.owner_emails`에 있는 검증된 이메일을 받아들입니다. 서비스의 계정 ID를 `auth.oidc.owner_subjects`에 나열할 수도 있습니다.

## Cloudflare Access

Cloudflare Access로 콘솔을 보호하려면 [Cloudflare 설정](/ko/docs/setup/cloudflare)을 따르세요. SwB은 Access 토큰을 확인하고 이메일을 `auth.owner_emails`나 `SWB_OWNER_EMAILS`와 대조합니다.

## 에이전트 로그인

OAuth는 내 승인을 받아 앱이 SwB에 연결하게 해 주는 규약입니다. `/authorize`에서 연결을 승인하세요. 앱은 OAuth 범위 `switchboard`를 받습니다. 이 값은 앱이 요청하는 접근 권한의 이름입니다. 앱은 `/token`으로 토큰을 받거나 갱신합니다.

앱에 OAuth 오류가 나면 `error_description`에서 자세한 내용을 확인하세요.

| 오류 | 의미 |
| - | - |
| `access_denied` | 소유자가 연결을 거절했습니다. |
| `invalid_client` | SwB이 앱 신원이나 자격 증명을 거부했습니다. |
| `invalid_client_metadata` | SwB이 앱 등록 설정을 거부했습니다. |
| `invalid_redirect_uri` | 등록할 때 허용된 콜백 주소가 필요합니다. |
| `invalid_request` | 요청 형식이나 필수 값이 잘못되었습니다. |
| `invalid_grant` | SwB이 인증 코드나 갱신 토큰을 거부했습니다. |
| `invalid_target` | 요청에 잘못된 MCP 주소가 들어 있습니다. |
| `unsupported_response_type` | `response_type=code`를 사용하세요. |
| `unsupported_grant_type` | `grant_type=authorization_code`나 `grant_type=refresh_token`을 사용하세요. |
| `temporarily_unavailable` | `public_url`을 설정하거나 클라이언트 등록 한도를 확인하세요. |

SwB이 [페어링 코드](/ko/docs/connect#페어링-코드로-연결)를 거부할 때도 `/connect`는 `invalid_grant`를 돌려줍니다.

## 세션

**쿠키**는 로그인 상태를 유지하려고 브라우저가 저장하는 값입니다. SwB은 이 쿠키에 `Secure` 플래그를 설정합니다. 공개 주소에는 HTTPS를 사용하세요.

설정을 바꾸면 브라우저가 토큰을 함께 보냅니다. SwB은 이 토큰으로 요청을 확인합니다. 로그아웃은 **Settings**에서 하세요.

브라우저는 `/auth/session`에서 현재 로그인 상태를 읽습니다.

## 로그인 오류

SwB은 브라우저 로그인 실패를 **Audit**에 기록합니다. 각 행에는 이유가 나오고 코드와 토큰은 비공개로 유지됩니다. 일부 실패는 반복 기록 수를 제한합니다.

| 오류 | 의미 |
| - | - |
| `link_used` | 링크가 만료되기 전에 누군가 그 링크로 로그인했습니다. |
| `link_expired` | 링크가 만료되었습니다. |
| `link_invalid` | SwB이 링크를 거부했습니다. |
| `setup_failed` | 설정 코드의 형식이 틀렸거나 `SWB_SETUP_CODE`와 다릅니다. |
| `setup_closed` | 설정 코드 로그인이 닫혔습니다. 다른 로그인 방법을 사용하세요. |
| `passkey_failed` | 패스키 설정이나 확인에 실패했습니다. |
| `last_method` | OIDC와 Cloudflare Access가 모두 꺼져 있으면 SwB은 마지막 패스키를 유지합니다. |
| `not_found` | 패스키 ID가 틀렸거나 패스키가 제거되었습니다. |
| `oidc_failed` | ID 공급자를 통한 로그인에 실패했습니다. |
| `signed_out` | 이 요청에는 소유자 세션이 필요합니다. |
| `csrf` | SwB이 페이지 주소나 보안 토큰을 거부했습니다. |
| `slow_down` | 로그인 시도가 한도에 이르렀습니다. `Retry-After`에 나온 시간만큼 기다리세요. |
