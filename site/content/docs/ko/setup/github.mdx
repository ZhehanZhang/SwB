SwB은 GitHub App에서 저장소 이벤트를 받습니다. 이벤트는 GitHub에서 일어난 동작을 알리는 알림입니다. 앱의 개인 키가 있으면 에이전트가 이슈에 라벨을 붙이고, 댓글을 달고, 이슈를 열 수도 있습니다.

## 시작하기 전에

연결할 저장소에 앱을 만들고 설치할 수 있는 GitHub 계정을 사용하세요. 소유자로 SwB에 로그인하세요.

GitHub가 내 서버의 `https://swb.example.com/github/webhook`에 접속할 수 있어야 합니다.

## GitHub App 설정

### GitHub App 설정 열기

프로필 사진 → **Settings** → **Developer settings** → **GitHub Apps**를 클릭하세요. **New GitHub App**을 클릭하세요.
### 앱 이름 정하기

**GitHub App name**과 **Homepage URL**을 입력하세요. 홈페이지로는 저장소 주소를 쓰면 좋습니다.
### 웹훅 설정

**Webhook**에서 **Active**를 선택된 상태로 두세요. 웹훅은 GitHub가 이벤트를 보내는 웹 주소입니다. **Webhook URL**에 `/github/webhook`을 붙인 SwB 주소를 입력하세요.
### 웹훅 시크릿 설정

비공개 파일에 시크릿을 만드세요.

```bash
(umask 077; set -C; openssl rand -hex 32 > "$HOME/.swb-github-secret")
```

시크릿을 비밀번호 관리자에 저장하세요. **Webhook secret**에 시크릿을 입력하세요. SwB은 16자 이상의 시크릿을 받아들입니다.
### 권한 설정

**Repository permissions**에서 표에 나온 접근 수준을 사용하세요.
### 이벤트 구독

**Subscribe to events**에서 아래 표의 이벤트를 선택하세요.

### 앱 만들기

**Where can this GitHub App be installed?**에서 **Only on this account**를 선택하세요. **Create GitHub App**을 클릭하세요.
### 개인 키 만들기

**Private keys**에서 **Generate a private key**를 선택하세요. 내려받은 `.pem` 파일은 비공개로 보관하세요.

### 자격 증명 저장

웹훅 시크릿을 SwB 등록 링크로 저장하세요. 시크릿을 저장한 뒤 임시 시크릿 파일을 삭제하세요. SwB이 요청하면 **App ID**와 `.pem` 파일도 각각의 등록 링크로 저장하세요.
### 앱 설치

내 계정 옆의 **Install App** → **Install**을 클릭하세요. **Only select repositories**를 선택하세요.
### 저장소 선택

저장소를 선택하세요. **Install**을 클릭하세요.

| 저장소 리소스 | 접근 | 이벤트 |
| --- | --- | --- |
| **Issues** | **Read & write** | `issues`, `issue_comment` |
| **Pull requests** | **Read & write** | `pull_request`, `pull_request_review`, `pull_request_review_comment`, `pull_request_review_thread` |
| **Contents** | **Read-only** | `push` |
| **Checks** | **Read-only** | `check_run`, `check_suite` |
| **Actions** | **Read-only** | `workflow_run` |
| **Metadata** | 자동으로 **Read-only** | |

조직에서는 GitHub가 **Install** 대신 **Request**를 보여 줄 수 있습니다. 이때는 조직 소유자가 요청을 승인합니다.

## 에이전트가 하는 일

에이전트가 `connect(what="github")`를 호출합니다. SwB은 웹훅 주소, 시크릿 상태, 저장소 라우트 수를 보여 줍니다. 라우트는 이벤트를 대상으로 보냅니다.

에이전트는 `config/switchboard.yaml`의 `blocks.github.spaces` 아래에 저장소를 하나씩 추가합니다. 공간은 저장소의 모드, 프로젝트, 대상을 정합니다. 이 예제는 `acme/app`의 Watch 요약본을 프로젝트 `demo`의 `agent:beta`로 보냅니다.

```yaml
blocks:
  github:
    use: github
    spaces:
      acme/app:
        mode:
          mode: watch
          target: agent:beta
        project: demo
```

Work 모드에서는 에이전트가 `mode.mode`를 `work`로 설정합니다. 그리고 내 GitHub 숫자 사용자 ID를 공간의 `owner_ids`에 추가합니다. ID를 찾는 방법과 예제는 [소유자 계정](/ko/docs/blocks/github#소유자-계정)을 참고하세요.

SwB은 이벤트 텍스트의 작성자를 확인합니다. `owner_ids`에 있는 사람이 쓴 텍스트는 `owner` 신뢰 수준을 가질 수 있습니다. SwB은 브랜치 이름, ref, 워크플로 제목, 검사 이름을 `external`로 취급합니다.

검사 이름은 소유자가 검사를 시작했더라도 `external`입니다. 포크에서 온 풀 리퀘스트가 그 이름을 바꿀 수 있기 때문입니다.

웹훅 시크릿을 저장하고 라우트를 업데이트한 뒤 SwB을 다시 시작하세요.

남은 App ID나 개인 키 링크가 있으면 에이전트가 `connect(what="github")`를 다시 호출합니다. 기존 개인 액세스 토큰에서 App으로 바꾸려면 `choose={"credential":"app"}`를 선택합니다.

다시 시작한 뒤 에이전트는 `github_status`를 호출해 설치 상태와 권한을 확인합니다.

triage 모드에서는 `space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")`를 호출하세요. 주소는 `targets`에서 고르세요. assist 모드에는 `mode="assist"`를 사용하세요. triage 모드에서 기본 GitHub 쓰기 동작은 `github_reply`입니다.

외부 발신자에게는 `channel:github/acme/app`과 `target:beta` 모두에 접근 권한을 주세요. 접근 규칙은 [채널 공개 범위](/ko/docs/channel-modes#외부-github-발신자-허용)를 참고하세요.

Watch는 `modes.digest_minutes`가 지나거나 이벤트가 50개 모이면 대상 우편함으로 요약본을 보냅니다. 요약본은 소유자로서 콘솔의 **Inbox**에서 읽거나 `inbox` 또는 `wait`로 읽으세요.

## 자격 증명

| 토큰 | GitHub에서 표시되는 곳 | 형식 | 입력할 곳 |
| --- | --- | --- | --- |
| 웹훅 시크릿 | `openssl rand -hex 32`로 직접 만듭니다 | 16자 이상 | SwB 등록 링크 |
| App ID | 앱 설정의 **App ID** | 숫자 | SwB 등록 링크 |
| 개인 키 | **Generate a private key** 후 한 번 내려받습니다 | `.pem` 파일 | SwB 등록 링크 |

SwB은 개인 키로 GitHub에서 설치 토큰을 받습니다. 설치 토큰은 각각 1시간 동안 유효합니다.

웹훅 시크릿을 바꾸려면 에이전트에게 `connect(what="github", choose={"replace":"secret"})` 호출을 요청하세요. `webhook_secret`을 써도 결과는 같습니다. App 자격 증명이나 개인 액세스 토큰까지 바꾸려면 `all`을 사용하세요. 값마다 돌려받은 안내를 따르세요. [자격 증명](/ko/docs/credentials#자격-증명-교체)을 참고하세요.

## 연결 확인

에이전트에게 `connect`를 다시 호출하도록 요청하세요. 설정이 끝나면 `connected`가 나옵니다. `github_status`에는 `secret_present`와 설치 권한이 나옵니다.

GitHub에서 앱 설정 → **Advanced** → **Recent deliveries**를 여세요. 가장 최근 전달을 열고 SwB이 성공 코드로 응답했는지 확인하세요.

## 문제 해결

서명 오류가 나면 [웹훅 시크릿 설정](#웹훅-시크릿-설정)을 따라 새 시크릿을 만드세요. GitHub App 설정에 새 시크릿을 입력하세요. 에이전트에게 `connect(what="github", choose={"replace":"secret"})` 호출을 요청하세요. 같은 시크릿을 등록 링크로 저장하세요. SwB을 다시 시작하세요. **Recent deliveries**에서 이벤트를 다시 보내세요.

`connect`가 **Issues** 쓰기 권한을 요청하면 앱 설정 → **Permissions & events**를 여세요. **Issues**를 **Read & write**로 설정하고 설치 화면에서 변경을 수락하세요.
