## 에이전트에 SwB 추가

SwB 컴퓨터에 있는 앱이면 [소유자 권한이나 페어링](/ko/docs/setup/mcp-client)을 고르세요. 서버에서 실행되는 앱이면 SwB을 원격 MCP 서버로 추가하세요. `https://swb.example.com/mcp` 같은 공개 MCP 주소를 사용하세요. SwB 페이지에서 그 앱의 [OAuth 로그인](/ko/docs/owner-login#에이전트-로그인)을 승인하세요.

| 앱 | SwB을 추가하는 곳 |
| - | - |
| [로컬 MCP 클라이언트](/ko/docs/setup/mcp-client) | 소유자 키를 쓰거나 코드로 페어링하세요. SwB 컴퓨터에서는 `http://localhost:8870/mcp`를 사용하세요. |
| Claude와 Claude Projects | Customize → Connectors → Add → Add custom connector |
| ChatGPT | [chatgpt.com/plugins](https://chatgpt.com/plugins) → Add a custom MCP server |
| Grok | [grok.com](https://grok.com) → Connectors → New Connector → Custom |
| Capy | Settings → MCP & plugins → Add a custom MCP server |
| Claude Code | `claude mcp add --transport http --scope user swb https://swb.example.com/mcp` |
| Codex, Gemini CLI와 그 밖의 코딩 에이전트 | `swb connect coding-agent --choose agent=codex` |

코딩 에이전트는 `swb connect coding-agent`를 실행해 지원하는 이름 목록을 확인하세요. `codex`를 그 목록의 이름으로 바꾸세요.

## 에이전트에게 요청하기

소유자 권한이 있는 에이전트는 나머지 연결을 설정할 수 있습니다. 페어링 키를 쓰는 에이전트는 소유자 전용 단계마다 터미널 명령을 알려 줍니다.

소유자 권한에는 소유자가 승인한 OAuth 로그인이나 `SWB_KEY_<NAME>`의 키가 필요합니다. 범위, 도구, 대상에 모두 접근할 수 있는 자격 증명을 사용하세요. `auth.key_scopes`, `auth.key_tools`, `auth.key_targets` 설정은 이 접근 범위를 좁힙니다.

| 요청 | 에이전트가 하는 일 |
| - | - |
| Claude Projects를 어떻게 연결하나요? | 프로젝트용 Claude 루틴을 등록하고 토큰용 링크 하나를 줍니다 |
| Slack을 SwB에 연결해 줘. | [Slack 설정](/ko/docs/setup/slack#앱-매니페스트)의 YAML 매니페스트를 알려 주고 필요하면 등록 링크를 받아 옵니다 |
| 내 Discord 봇을 연결해 줘. | 토큰 링크와 봇 초대 링크를 줍니다 |
| 이걸 내 Capy Captain에게 보내 줘. | 작업을 보내고 답을 기다립니다 |
| 어디로 보낼 수 있어? | 에이전트가 닿을 수 있는 대상을 나열합니다 |

에이전트는 `connect` 도구를 호출합니다. SwB은 그 플랫폼의 다음 단계로 답합니다. 단계에 토큰이 필요하면 SwB이 일회용 등록 링크를 줍니다. 링크를 열고 그곳에 토큰을 붙여 넣으세요. 등록 링크는 [자격 증명](/ko/docs/credentials)에서 설명합니다.

## 터미널에서 연결

SwB 인스턴스 폴더에서 `swb connect PLATFORM`을 실행하세요. `PLATFORM`을 `slack` 같은 플랫폼 이름으로 바꾸세요. 이 명령은 `.env`의 소유자 키를 사용합니다. 기본적으로 로컬 SwB 주소를 사용합니다. 인스턴스 폴더를 고르려면 `--dir`를 사용하세요. SwB 주소를 지정하려면 `--url`을 사용하세요. 일회용 소유자 로그인 링크는 `swb login-link`로 받으세요.

```bash
swb connect mcp-client
swb connect capy-captain
swb connect grok
```

## 페어링 코드로 연결

페어링은 새 에이전트에게 전용 키를 줍니다. 소유자로 로그인한 에이전트에게 `connect_code`를 호출하도록 요청하세요. 새 에이전트의 이름을 알려 주세요. 코드는 10분 동안 한 번만 쓸 수 있습니다. 새 에이전트는 `POST /connect`로 코드를 전용 키와 교환합니다. 전체 페어링 절차는 [MCP 클라이언트](/ko/docs/setup/mcp-client)를 참고하세요.

콘솔에서 코드를 만들려면 **Tokens**를 여세요. **Pairing code**를 여세요. 에이전트 이름을 입력하세요. **Create code**를 선택하세요. SwB은 이 양식을 `POST /pairing/code`로 보냅니다.

페어링하면 `agent:<name>`과 `auth.key_scopes`에서 그 에이전트에 지정한 범위의 메모리 접근 권한이 생깁니다. 프로젝트를 지정한 페어링 코드는 그 프로젝트의 메모리 범위 권한도 줍니다.

`POST /connect`는 지정한 프로젝트를 `project`에 담아 돌려줍니다. 이 값을 클라이언트의 기본 프로젝트로 사용하세요. 도구에 프로젝트가 필요하면 `project`에 넘기세요.

이 키로 에이전트가 보내거나 받는 메시지를 읽을 수 있습니다. 읽을 수 있는 범위는 키의 [대화 범위](/ko/docs/security#제한이-있는-키) 안입니다.

페어링 키로 호출하면 `tools/list`에 페어링된 에이전트 역할의 도구가 나옵니다. `auth.key_tools` 설정으로 목록을 좁힐 수 있습니다. 소유자 도구에는 소유자 로그인을 사용하세요. [페어링 키](/ko/docs/tools#페어링-키)를 참고하세요.

## 받은편지함 이벤트 스트림

`POST /connect`는 `inbox_events_url`을 돌려줍니다. 이 값은 `GET /inbox/events`의 URL입니다. 페어링된 에이전트의 키로 `Authorization: Bearer <key>`를 붙여 그 URL을 여세요. SwB은 키의 접근 범위 안에서 그 에이전트의 받은편지함 메시지를 보냅니다. 이 SSE(서버 전송 이벤트)는 연결이 열려 있는 동안 도착합니다. Watch 요약과 컨텍스트 항목은 `inbox`로 읽으세요.

스트림은 `ready` 이벤트로 시작합니다. 각 `item` 이벤트에는 `cursor`, 대화 `handle`, 메시지 데이터가 담긴 JSON 데이터가 있습니다. 이벤트 ID가 곧 커서입니다. 커서는 스트림에서의 위치를 표시합니다.

스트림은 기본적으로 가장 최근 위치에서 시작합니다. 이어서 받으려면 마지막 이벤트 ID를 `Last-Event-ID` 헤더나 `after` 쿼리 매개변수로 보내세요. `reply`와 `get_message`의 입력은 [메시지](/ko/docs/tools#메시지)를 참고하세요.
