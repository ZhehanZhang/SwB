Un **compagnon** est un appareil connecté à votre serveur SwB. Vos agents peuvent alors utiliser les fonctions de cet appareil.

## Appairer un appareil

Demandez à un agent connecté en tant que propriétaire d'appeler `companion_code`. Demandez à l'agent d'enregistrer le code dans un fichier avec les permissions `0600`. Avec ces permissions, seul le propriétaire du fichier y a accès.

Pour obtenir un code dans la console, [connectez-vous avec une clé d'accès](/fr/docs/owner-login#clé-daccès). Ouvrez **Settings**. Dans **Connections**, sélectionnez **Pair a device**. Si vous utilisez Cloudflare Access, utilisez l'outil `companion_code`.

Exécutez cette commande sur l'appareil. Remplacez l'adresse d'exemple par l'adresse HTTPS de votre SwB. Pour un SwB installé sur cet appareil, vous pouvez utiliser `http://127.0.0.1:8870`.

```sh
uvx swb-one companion connect https://swb.example.com --cap notify
```

Saisissez le code d'appairage à l'invite masquée. Le code fonctionne une seule fois et expire après 10 minutes. Le journal d'audit enregistre son auteur.

L'appareil enregistre sa propre clé dans un fichier privé.

## Choisir les fonctions

Ajoutez une option `--cap` pour chaque fonction à activer.

| Option | Fonction |
| --- | --- |
| `--cap notify` | Affiche des notifications de bureau sur l'appareil |
| `--cap drop` | Partage des fichiers d'au plus 10 Mio chacun via le dossier `~/SwB Drop` |
| `--cap mcp --mcp NAME=COMMAND` | Donne à vos agents l'accès aux outils d'un serveur MCP de l'appareil |
| `--cap herdr` | [Herdr](/fr/docs/blocks/local-sessions#herdr) |
| `--cap codex` | [Serveur d'application Codex](/fr/docs/blocks/local-sessions#codex) |
| `--cap opencode` | [Serveur OpenCode](/fr/docs/blocks/local-sessions#opencode) |
| `--cap dsh` | [DeepSeek Harness](/fr/docs/blocks/local-sessions#deepseek-harness) |
| `--cap hooks` | [Hooks d'état](/fr/docs/blocks/local-sessions#hooks-détat) |
| `--cap muse` | Appaire Muse en Bluetooth sur un Mac ou un ordinateur Linux |

Sous Linux, les notifications utilisent `notify-send`. Sous Debian et Ubuntu, installez-le avec le paquet `libnotify-bin`.

Utilisez Python 3.13 pour la fonction Muse. Suivez le [guide d'appairage de Muse](/fr/docs/setup/muse).

```sh
uvx --python 3.13 --from 'swb-one[companion]' swb companion connect https://swb.example.com --cap muse
```

Ajoutez une option `--mcp` par serveur MCP. Pour un programme, utilisez `--mcp 'NAME=COMMAND'`. Remplacez `NAME` par un nom pour votre serveur. Remplacez `COMMAND` par la commande de démarrage du programme. Pour un serveur HTTP sur l'appareil, utilisez son adresse locale, par exemple `--mcp notes=http://127.0.0.1:8000/mcp`.

Vos agents utilisent `companion_list` pour voir chaque appareil appairé et ses actions. Ils utilisent `companion_invoke` pour exécuter une action.

Les résultats texte du compagnon sont limités à 1 Mio. Lisez les données des fichiers Drop dans `structuredContent.result.content_b64`.

## Sessions locales

Une **session locale** est la conversation ouverte d'un agent de code sur l'appareil. SwB affiche son état avec son adresse `local:session:<companion>:<harness>:<session>`.

Suivez le lien de votre agent de code dans le tableau des fonctions. Configurez l'agent avant l'appairage. Après l'appairage, laissez le compagnon actif. Demandez à un agent connecté en tant que propriétaire d'appeler `targets(block="local")`. Vérifiez que l'adresse de votre session apparaît.

SwB essaie de livrer chaque message à la session ouverte. Il dépose le message dans la boîte aux lettres de l'agent quand l'expéditeur peut utiliser cette boîte. La réponse revient dans la même conversation.

Utilisez l'adresse de session indiquée par `targets`. Trouvez la ressource de cette adresse dans `visibility_list`. Partagez la ressource avec `visibility_set`.

Pour les commandes et les agents pris en charge, consultez [Sessions locales](/fr/docs/blocks/local-sessions).

## Garder le compagnon actif

L'appairage démarre le compagnon. Utilisez `swb companion run` pour le redémarrer. Utilisez `swb companion status` pour voir l'ID local de l'appareil et ses fonctions.

Pour exécuter ces commandes avec `uvx`, remplacez `swb` par `uvx swb-one`. Pour Muse, gardez les options de paquet et de Python du [guide de Muse](/fr/docs/setup/muse).

L'appareil ouvre lui-même chaque connexion vers SwB.

## Déconnecter

Exécutez `swb companion disconnect` sur l'appareil pour supprimer sa clé. Pour révoquer la clé dans la console, ouvrez **Connections** dans **Settings**. Sélectionnez **Disconnect** pour l'appareil.

Un compagnon actif supprime sa clé locale quand il détecte la révocation. Si une clé reste sur l'appareil, exécutez `swb companion disconnect` avant un nouvel appairage.
