## Docker Compose

Installez Docker Compose 2.24 ou une version plus récente. Exécutez ces commandes avec un utilisateur ordinaire, propriétaire du dossier de données.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Ouvrez le lien de connexion à usage unique affiché dans le terminal dans les cinq minutes. Gardez ce lien privé.

Le navigateur utilise `http://localhost:8870` pour la connexion du propriétaire. La commande dans le conteneur utilise le port `8000`. Compose garde les données dans `./data`. Après une modification de `.env`, exécutez de nouveau `docker compose up -d`.

Pour un serveur distant, redirigez son port `8870` vers le port local `8870` avant d'ouvrir le lien.

Une requête hors connexion vers `/healthz` renvoie `status` et `version`. Utilisez une session propriétaire ou la clé propriétaire pour obtenir le détail complet.

## Cloudflare Tunnel

Suivez les [instructions de Cloudflare Tunnel](/fr/docs/setup/cloudflare) pour créer un tunnel vers votre domaine. Pour Compose, indiquez `http://switchboard:8000` comme adresse de service. Enregistrez le jeton du tunnel dans `.env`, sous le nom indiqué dans le [fichier Compose de la version](https://github.com/ZhehanZhang/SwB/blob/release/1.0/compose.yaml#L32-L37). Dans `.env`, remplacez `SWB_PUBLIC_URL` par l'adresse du tunnel. Démarrez Compose avec le profil tunnel.

```bash
docker compose --profile tunnel up -d
```

## Proxys de confiance

Un proxy inverse transmet les requêtes à SwB. Ajoutez l'adresse du proxy ou son réseau dédié à `trusted_proxies` dans `config/switchboard.yaml`. Écrivez les plages réseau au format CIDR, par exemple `192.0.2.0/24`.

Vous pouvez aussi définir `SWB_TRUSTED_PROXIES` dans `.env`. Séparez les entrées par des virgules. Le réglage YAML a la priorité.

Pour un Cloudflare Tunnel sur l'hôte SwB ou sur le réseau Docker, ajoutez l'adresse du connecteur du tunnel ou son réseau dédié. Le connecteur se relie directement à SwB. Utilisez l'entrée `cloudflare` pour les connexions directes depuis les serveurs périphériques de Cloudflare.

## Plateformes d'hébergement

Utilisez une seule instance SwB avec un disque persistant monté sur `/data`. Consultez le [guide de déploiement](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy) pour les modèles Railway, Render et Fly.io et pour le script Koyeb.

## Railway [#railway]

La [définition du modèle Railway](https://github.com/ZhehanZhang/SwB/blob/release/1.0/.railway/railway.ts) lance un service SwB et monte un volume de 1 Go sur `/data`.
Déployez depuis la marketplace Railway après la publication du modèle.

## Fly.io [#fly]

Utilisez la copie de la version SwB de l'[exemple Docker Compose](#docker-compose). Installez l'[outil en ligne de commande Fly.io](https://docs.fly.io/flyctl/). Connectez-vous à Fly.io.

Exécutez `sh deploy/fly.sh my-swb` depuis le dossier SwB. Remplacez `my-swb` par un nom d'application unique. Le script utilise `fly deploy --ha=false` pour démarrer une seule Machine.

Ouvrez la page de connexion de votre application. Copiez `SWB_SETUP_CODE` depuis le fichier `.env.swb-setup-fly-my-swb` de votre copie. Saisissez-le dans **Setup code**. Supprimez le fichier après la connexion.

Consultez le [forfait gratuit de Fly.io](https://docs.fly.io/about/free-plan) et les [tarifs actuels](https://fly.io/docs/about/pricing/) pour la facturation.

## Sauvegardes et mises à jour

Arrêtez SwB avant de copier son dossier de données. Gardez le dossier entier, avec la base de données et ses clés, dont `mcp-events.key` et `claim-key`. Sauvegardez aussi vos fichiers de configuration et `.env`. Gardez la sauvegarde privée. Installez ou compilez la nouvelle version. Démarrez SwB avec le même dossier de données.

## Exporter la mémoire

Exécutez l'export dans le conteneur Compose.

```bash
docker compose exec -T switchboard swb export /data/export
```

L'export enregistre des fichiers Markdown classés par portée dans `./data/export` sur l'hôte. Il comprend un fichier `INDEX.md`. Définissez `memory.mirror_dir` pour garder une copie Markdown à jour.
