## Docker Compose

Docker Compose 2.24 以降をインストールしてください。これらのコマンドは、データフォルダーを所有する一般ユーザーとして実行してください。

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

ターミナルに表示されるワンタイムのサインインリンクを 5 分以内に開いてください。リンクは自分だけで使ってください。

オーナーのサインインには、ブラウザーで `http://localhost:8870` を使います。コンテナー内のコマンドはポート `8000` を使います。Compose はデータを `./data` に保存します。`.env` を変更したら、もう一度 `docker compose up -d` を実行してください。

リモートのサーバーでは、リンクを開く前に、サーバーのポート `8870` をローカルのポート `8870` に転送してください。

`/healthz` へのリクエストは、サインイン前でも `status` と `version` を返します。ヘルスチェックの詳細をすべて見るときは、オーナーのセッションかオーナーキーを使ってください。

## Cloudflare Tunnel

[Cloudflare Tunnel の手順](/ja/docs/setup/cloudflare)に従って、自分のドメイン用のトンネルを作成してください。Compose では、サービスのアドレスに `http://switchboard:8000` を使います。トンネルのトークンは、[リリースの Compose ファイル](https://github.com/ZhehanZhang/SwB/blob/release/1.0/compose.yaml#L32-L37)にある名前で `.env` に保存してください。`.env` の `SWB_PUBLIC_URL` を、トンネルのアドレスに置き換えてください。tunnel プロファイルを付けて Compose を起動してください。

```bash
docker compose --profile tunnel up -d
```

## 信頼済みプロキシ

リバースプロキシは、リクエストを SwB に渡すサーバーです。`config/switchboard.yaml` の `trusted_proxies` に、プロキシのアドレスか専用のネットワークを追加してください。ネットワークの範囲は、`192.0.2.0/24` のような CIDR 形式で書いてください。

`.env` で `SWB_TRUSTED_PROXIES` を設定することもできます。複数の項目はカンマで区切ってください。YAML の設定が優先されます。

SwB のホストか Docker ネットワーク上で Cloudflare Tunnel を使うときは、トンネルのコネクターのアドレスか専用のネットワークを追加してください。コネクターは SwB に直接接続します。Cloudflare のエッジサーバーから直接接続するときは、`cloudflare` の項目を使ってください。

## Cloudflare Access

[Cloudflare のセットアップガイド](/ja/docs/setup/cloudflare)に従って SwB を設定し、オーナーとクライアントのリクエストに対するアクセスルールを設定してください。

## ホスティングプラットフォーム

`/data` に永続ディスクをマウントした SwB のインスタンスを 1 つ使ってください。Railway、Render、Fly.io のテンプレートと Koyeb のスクリプトについては、[デプロイガイド](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy)をご覧ください。

## Railway [#railway]

[Railway のテンプレート定義](https://github.com/ZhehanZhang/SwB/blob/release/1.0/.railway/railway.ts)は、SwB のサービスを 1 つ実行し、1 GB のボリュームを `/data` にマウントします。
テンプレートの公開後は、Railway のマーケットプレイスからデプロイしてください。

## Fly.io [#fly]

[Docker Compose の例](#docker-compose)で取得した SwB のリリースのチェックアウトを使ってください。[Fly.io のコマンドラインツール](https://docs.fly.io/flyctl/)をインストールしてください。Fly.io にサインインしてください。

SwB のフォルダーで `sh deploy/fly.sh my-swb` を実行してください。`my-swb` を、固有のアプリ名に置き換えてください。スクリプトは `fly deploy --ha=false` を使って、Machine を 1 つ起動します。

アプリのサインインページを開いてください。チェックアウトにある `.env.swb-setup-fly-my-swb` から `SWB_SETUP_CODE` をコピーしてください。その値を **Setup code** に入力してください。サインインしたら、このファイルを削除してください。

料金の詳細は、[Fly.io の Free プラン](https://docs.fly.io/about/free-plan)と[現在の料金](https://fly.io/docs/about/pricing/)をご覧ください。

## バックアップとアップグレード

データフォルダーをコピーする前に、SwB を停止してください。データベースとキーを含むフォルダー全体をまとめて保管してください。キーには `mcp-events.key` と `claim-key` も含まれます。設定ファイルと `.env` もバックアップしてください。バックアップは安全な場所に保管してください。新しいバージョンをインストールまたはビルドしてください。同じデータフォルダーを使って SwB を起動してください。

## メモリを書き出す

Compose のコンテナー内で書き出しを実行してください。

```bash
docker compose exec -T switchboard swb export /data/export
```

書き出すと、ホストの `./data/export` に、スコープごとの Markdown ファイルが保存されます。`INDEX.md` も作成されます。常に最新の Markdown コピーを保つときは、`memory.mirror_dir` を設定してください。
