Agents set up connections, but tokens stay with you. SwB gives you a **claim link** for each token. A claim link is a one-time page on your SwB host. You open it, paste the token and click Save. The token goes from your browser to SwB only. Chat, MCP calls and config files stay free of tokens.

## How a claim link works

An agent asks for a connection, for example Discord. SwB returns a link such as `https://swb.example.com/claim/...`. The agent gives you the link. The link works one time, for 30 minutes. You must be signed in as the owner to use it.

![A claim page for one token](/shots/token-handoff-light.webp)

SwB checks each value before it saves it. It seals the value with a key in its data folder. The value then appears to SwB as the environment variable the block needs. An environment variable on the server wins over a saved value.

| Page | Use |
| - | - |
| `/claim/{code}` | Save the credentials for a connection. |
| `/routines/claim/{code}` | Use a one-time claim link to save a Claude routine token. |
| `/routines/claim/owner/{registration}` | Save a pending Claude routine token from the Agents page. |

## Grouped credentials

Some platforms need several values. A GitHub App needs an App ID, a private key and a webhook secret. A Slack workspace needs a bot token, a user token and an app token. SwB puts all the values of one platform on one page. Each field has a link to the place where you get the value. Fields for keys also take a file, for example a `.pem` file.

## Claim from the terminal

```bash
swb claim 'https://swb.example.com/claim/...'
```

The command asks for the token at a hidden prompt. It sends the token to your local SwB server, or to the server you name with `--url`.

## Rotate a token

Ask the agent to connect the platform again. SwB gives you a new claim link. The new value replaces the old one.
