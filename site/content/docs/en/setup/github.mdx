SwB gets repository events from a GitHub App that you register. With the private key of the app, agents can also label, comment on and open issues.

## Before you start

You need a GitHub account and the repositories to connect. For an organization, you need the owner role or the GitHub App manager role. You also need the owner sign-in to your SwB server, for example https://swb.example.com.

GitHub must reach `https://swb.example.com/github/webhook` on your server.

<Steps>
<Step>
### Open the GitHub App settings

Click your profile picture → **Settings** → **Developer settings** → **GitHub Apps**. Click **New GitHub App**.
</Step>
<Step>
### Name the app

Type a **GitHub App name** and a **Homepage URL**. Your repository address is a good homepage.
</Step>
<Step>
### Set the webhook

Under **Webhook**, keep **Active** selected. Type `https://swb.example.com/github/webhook` in **Webhook URL**.
</Step>
<Step>
### Set the webhook secret

Generate a secret in a private file.

```bash
(umask 077; set -C; openssl rand -hex 32 > "$HOME/.swb-github-secret")
```

Save the result in your password manager. Enter it in **Webhook secret**. SwB accepts secrets of at least 16 characters.
</Step>
<Step>
### Set the permissions

Under **Repository permissions**, set **Read-only** for each resource in the table below. Set **Issues** and **Pull requests** to **Read & write** for agent replies.
</Step>
<Step>
### Subscribe to events

Under **Subscribe to events**, select the events in the table below.
</Step>

In an organization, GitHub can show **Request** in place of **Install**. Then an organization owner approves the request.

## What the agent does

The agent calls `connect` with `what="github"`. SwB shows the webhook address, the webhook secret state and the number of repository routes. A route sends the events of one repository to a target.

The agent adds the repositories under `blocks.github.spaces` or `blocks.github.routes` in `config/switchboard.yaml`. Save the same webhook secret through its claim link. The agent restarts SwB to load the secret and apply the route changes.

The agent calls `connect(what="github")` again for any remaining App ID or private key links. To switch from an existing personal access token to an App, it selects `choose={"credential":"app"}`.

After a restart, the agent calls `github_status` to check the installation and its permissions. See [Channel modes](/docs/channel-modes) to bind the project route and enable triage actions. Triage allows `github_reply` by default.

## Credentials

| Token | Where GitHub shows it | Format | Where it goes |
| --- | --- | --- | --- |
| Webhook secret | You generate it with `openssl rand -hex 32` | At least 16 characters | SwB claim link |
| App ID | App settings, **App ID** | A number | SwB claim link |
| Private key | Downloaded once after **Generate a private key** | A `.pem` file | SwB claim link |

SwB makes installation tokens from the private key by itself. Each installation token works for one hour.

## Check the connection

Ask the agent to call `connect` again. It reports `connected` when the setup is complete. `github_status` shows `secret_present` and the permissions of the installation.

On GitHub, open the app settings → **Advanced** → **Recent deliveries**. Open the newest delivery and check that SwB answered with a success code.

## Fix problems

If deliveries fail with a signature error, the two secrets differ. Make a new secret, enter it at GitHub and save it through a new claim link.

If `connect` asks for **Issues** write access, open the app settings → **Permissions & events**. Set **Issues** to **Read & write** and accept the change on the installation.
