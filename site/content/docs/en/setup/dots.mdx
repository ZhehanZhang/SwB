A dot is a personal ChatGPT agent that keeps working between chats. This connection gives your dot a SwB mailbox and wakes the dot when a message arrives.

## Before you start

Dots are available to Pro users and to some Plus users who are 18 or older. Dots are available outside the EEA, the UK and Switzerland. Business, Enterprise and Edu members in supported regions can make one personal dot.

Dot access and custom MCP access are two separate rights, and you need both. Full custom MCP access comes with Business, Enterprise and Edu. An MCP server is a tool server that an AI app calls.

On Enterprise and Edu, an admin turns on dots in **Workspace settings** → **Permissions & roles** → **Permissions** → **Workspace default** → **Workspace capabilities** → **Use dots**.

Your SwB server needs a public HTTPS address, owner sign-in and the `dots` block. A block is one SwB connection that you turn on in the config file.

## Your steps

<Steps>

<Step>

### Turn on the dots block

Add this block to `config/switchboard.yaml`. Then restart SwB.

```yaml
blocks:
  dots:
    delivery: mailbox
    dots:
      dot:
        mailbox: chatgpt
```

</Step>

<Step>

### Open Plugins

Open [chatgpt.com/plugins](https://chatgpt.com/plugins) in a desktop web browser. Use the web app for this step, also when you talk to your dot in the desktop app.

</Step>

<Step>

### Add the server

Select **+**. Then select **Add custom MCP server**.

</Step>

<Step>

### Enter the address

Enter `SwB` as the name. Under **Connection**, enter `https://swb.example.com/mcp` in **Server URL**.

</Step>

<Step>

### Create the plugin

Select **OAuth**. Select **I understand and want to continue**. Then select **Create as a plugin**.

</Step>

<Step>

### Install and sign in

Install the plugin. Sign in to SwB as the owner. Approve the access.

</Step>

<Step>

### Open your dot

Open your dot at chatgpt.com. Add the SwB plugin to the dot.

</Step>

### Ask the dot

## What the agent does

The dot calls `connect(what="chatgpt")` to confirm the OAuth sign-in. OAuth is the sign-in method where you approve access on a SwB page. Then the dot calls `connect(what="dots")` to check the `dots` block. It sends a test message with `send` and reads it with `inbox`.

Last, the dot subscribes to the MCP event `switchboard.message.created` for its mailbox, `chatgpt` by default. A mailbox is the SwB inbox of one agent. An MCP event is a call from SwB to the dot when a message arrives. SwB checks the callback address of the dot first. On each event, the dot reads the message with `get_message` and answers with `reply`. If events are unavailable, the dot calls `wait` or `inbox`.

## Credentials

| Token | Where it is shown | Format | Where it goes |
| - | - | - | - |
| SwB sign-in token | ChatGPT gets it when you sign in | Random text | ChatGPT keeps it for you |
| Event signing secret | The dot sends it when it subscribes | `whsec_` and random text | SwB keeps it encrypted |

Give any other token to SwB only through the SwB claim link. A claim link is a private one-time SwB page for one token.

## Check the connection

Ask another SwB agent to run `send(to="dot", task="SwB setup test: reply pong")`. The dot wakes by itself and answers pong on that conversation. A good `inbox` read proves the sign-in only.

## Fix problems

If `connect(what="dots")` returns the kind `unknown`, the `dots` block is off. Add the block and restart SwB.

If `connect` asks for a Slack workspace, the block uses Slack delivery. Set `delivery: mailbox` and restart SwB.

Add the server in a browser at chatgpt.com. The desktop apps only open plugins that you already added. If the dot stops waking after some days, sign in to the plugin again.
