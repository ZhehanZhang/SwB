SwB reads and posts in Slack through a Slack app that you make from a manifest. A manifest is a file that holds all the settings of the app.

The app uses Socket Mode. Socket Mode is a connection that SwB opens to Slack, so your SwB server can stay on a private address.

## Before you start

You need a Slack account in the workspace and the right to create and install apps there. In an Enterprise Grid organization, an Org Owner or Org Admin must approve the app. You also need the owner sign-in to your SwB server, for example `https://swb.example.com`.

## App manifests

### Bot and your account

```yaml
# Example Slack app for an agent-to-agent workspace: a bot user and the owner's user token.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
# The bot's @handle and member-list profile come from features.bot_user.display_name and the
# app icon; they do not change per message. Per-message name/avatar = personas (chat:write.customize).
display_information:
  name: Switchboard
  description: Agent switchboard for the owner's assistants
  background_color: "#1d2733"
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: switchboard
    always_online: true
oauth_config:
  scopes:
    bot:
      - app_mentions:read      # @mentions -> push kind "mention"
      - channels:history       # watched public channels the bot is in
      - channels:read
      - groups:history         # watched private channels the bot is in
      - groups:read
      - im:history             # DMs to the bot -> push kind "dm"
      - im:read
      - im:write               # approval DMs to the owner
      - chat:write
      - chat:write.customize   # personas: per-message username + icon
      - reactions:write        # ack reaction on mentions/DMs
      - users:read             # names in pushed events
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # posts as the owner (policy-gated)
      - reactions:write
      - search:read            # search_messages
      - users:read
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.channels
      - message.groups
      - message.im
  interactivity:
    is_enabled: true           # Approve/Reject buttons, delivered over Socket Mode
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

### Your account only

```yaml
# Example Slack app for a user-only workspace. No bot user, bot scopes, bot events, or interactivity.
# It never joins or invites; every post appears as the owner.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
display_information:
  name: Switchboard (personal)
  description: Lets the owner's agents read on their behalf; writes need approval
  background_color: "#333333"
oauth_config:
  scopes:
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # only ever used after the owner approves a request
      - reactions:write        # same
      - search:read
      - users:read
settings:
  event_subscriptions:
    user_events:
      - message.channels
      - message.groups
      - message.im
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

## What the agent does

The agent calls `connect` with `what="slack"`. SwB shows which tokens each workspace still needs and returns one claim link for them.

The agent adds the workspace under `blocks.slack.workspaces` in `config/switchboard.yaml`. It uses the workspace ID and token names. It adds an owner grant under `blocks.slack.agents` so the owner can call `slack_workspaces`. If the agent needs you to edit the file, it gives you the YAML.

This example connects one workspace with a bot and your account. Replace `T0DEMO0001` with your workspace ID.

```yaml
blocks:
  slack:
    use: slack
    enabled: true
    workspaces:
      example:
        team_id: T0DEMO0001
        app_token_env: SLACK_EXAMPLE_APP_TOKEN
        identities:
          bot:
            token_env: SLACK_EXAMPLE_BOT_TOKEN
          user:
            token_env: SLACK_EXAMPLE_USER_TOKEN
    agents:
      owner:
        workspaces:
          example: [bot, user]
```

Use the same workspace label in the workspace entry and the grant. For the account-only manifest, add `user_only: true` next to `team_id`. Remove the `bot` entry under `identities`. Set the grant to `[user]`.

When SwB asks for a restart, the agent tells you. After the restart, it uses `slack_workspaces` to check each identity. An identity is the bot or your own account. Last, it sends a test message with `slack_post`.

## Credentials

| Token | Where Slack shows it | Format | Where it goes |
| --- | --- | --- | --- |
| App-level token | **Basic Information** → **App-Level Tokens** | Starts with `xapp-` | SwB claim link |
| Bot token | **OAuth & Permissions** → **OAuth Tokens** → **Bot User OAuth Token** | Starts with `xoxb-` | SwB claim link |
| User token | **OAuth & Permissions** → **OAuth Tokens** → **User OAuth Token** | Starts with `xoxp-` | SwB claim link |

The workspace ID and channel IDs are names for places in Slack. They are safe to put in the config file.

## Check the connection

Ask the agent to call `connect` again. It reports `connected` when the setup is complete. `slack_workspaces` shows `ready` for each identity and `connected` for Socket Mode.

Mention the bot in a channel and add a target name. The agent sees the message with `slack_events` or `slack_wait`.

## Fix problems

If SwB reports a Socket Mode problem, open **Socket Mode** in the app settings. Turn on **Enable Socket Mode**.

If you change the scopes of the app, install the app again. Then save the new tokens through a new claim link.

Search with `slack_search` uses your own account. It needs the user token with the scope `search:read`.
