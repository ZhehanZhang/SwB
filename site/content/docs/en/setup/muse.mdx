SwB pairs with Muse as a text gadget named **SwB**. A gadget is a device that the Muse app talks to over Bluetooth. A Linux device runs the SwB bridge, which carries messages between Muse and SwB.

## Before you start

You need a Muse account and the Muse app on iOS or Android. Use a Linux device with Bluetooth Low Energy. Make sure it can reach your SwB server. On Ubuntu 24.04, install `bluez`, `git`, `python3-dbus`, `python3-gi` and `python3-venv`.

The Muse block must be on in `config/switchboard.yaml` with `muse: {use: muse}` under `blocks`. You also need the owner sign-in to SwB.

```sh
/usr/bin/python3 -m venv --system-site-packages .venv-muse
.venv-muse/bin/pip install swb-one 'musegadget @ git+https://github.com/facebookincubator/muse-gadget-sdk.git@a5f809f621c4cbdbd37336fe17e7cdb74cebf3fe#subdirectory=linux'
.venv-muse/bin/swb muse-bridge --url https://swb.example.com --setup
```

Keep the bridge running. The terminal shows **SwB is ready for Muse messages.** when the bridge is ready.

## What the agent does

The agent calls `connect` with `what="muse"`. SwB returns the claim link for the bridge token and your steps. It tracks the token, the bridge state and the first reply from Muse.

When the bridge is online, the agent calls `connect` again. It sends a test message to `muse:gadget:muse` with `send`. It reads the answer with `result`. For later messages, use `send` with `to="muse"`. You can also set a route to `muse:gadget:muse`.

To change the bridge token, the agent calls `connect` with `what="muse"` and `choose={"replace":true}`.

## Credentials

| Token | Where it is shown | Format | Where it goes |
| --- | --- | --- | --- |
| Bridge token | You make it in your password manager | 64 letters and digits | SwB claim link, then the hidden prompt on the Linux device |
| Meta Gadget SDK token | https://gadgets.muse.ai/settings/sdk-tokens, shown once | Starts with `mgst_` | Hidden prompt on the Linux device only |

The Meta token stays on the Linux device. SwB keeps only the bridge token.

## Check the connection

Check that **SwB** is under **Devices** in the Muse app. Ask the agent to call `connect` again and send the test. A real reply in `result` shows that the connection works.

## Fix problems

After a restart, run `.venv-muse/bin/swb muse-bridge --url https://swb.example.com` from the same directory. Add `--setup --pair-again` to pair again.

Meta keeps the pairing window open for ten minutes. Pair on a network that you trust.

SwB keeps messages while the device is offline and sends them when it comes back. Check Muse before you send a message again.
