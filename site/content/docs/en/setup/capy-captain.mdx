A Capy Captain is a Capy agent that directs a group of threads. SwB sends tasks to the Captain and returns each reply to the sender.

## Before you start

You need a Capy account, a project and a Captain in the same organization. A service user is a Capy account for software.

Enable the `capy` block. In Capy, add SwB under **Settings** → **MCP & plugins**. Use a SwB client with full owner access.

## Set up the Captain route

### Open API settings

In Capy, open **Settings** → **API**. Check that the right organization is open.

### Create the read key

Create a personal API key with access to your Captain. Copy the key while Capy shows it.

### Save the read key

Open the claim link from your agent. Paste the key in **Token**. Select **Save token**.

### Restart SwB

Restart SwB when your agent asks. SwB then loads the key.

### Make a Capy Captain

Create a Capy Captain if you need one. Choose the project and the machine on which the Captain runs.

### Choose the Capy Captain

Tell your agent which Capy Captain gets the work.

### Create the send key

In **Settings** → **API**, create a service user with the role `read_write`. Grant it access to the project. Create a key for the service user.

### Share the Capy Captain

Open the Capy Captain menu. Select **Share**. Grant access to the service user. For a Captain on a paired device, grant the service user access to the device too.

### Save the send key

Open the second claim link. Paste the key in **Token**. Select **Save token**.

### Restart SwB again

Restart SwB. Then tell your agent that you are done.

## What the agent does

From a client with full owner access, call `connect(what="capy-captain")`. If SwB needs the read key, it returns a claim link. A claim link is a private page for entering a credential.

After the restart, `connect` lists the available Captains. Confirm which Captain should receive the work. Call `connect(what="capy-captain", choose={"captain":"<Capy Captain ID>"})`. For a project route, add `"project":"<project>"` to `choose`. A route tells SwB where to send work.

SwB asks for a service key if the agent needs one to send. Use `capy_captains`, `routes_list` and `routes_resolve` to check the route.

## Credentials

| Token | Where it is shown | Format | Where it goes |
| - | - | - | - |
| Read key | **Settings** → **API**, one time | `capy_` and 43 random characters | **Token** on its SwB claim link |
| Send key | **Settings** → **API**, one time | `capy_` and 43 random characters | **Token** on its SwB claim link |

## Check the connection

Ask your agent to call `connect(what="capy-captain")` again. Check for `connected`. Send a short test task to the route. Check for the task in the Captain thread. Read the reply with `result` or `inbox`. Use `/healthz` as the owner to check the name and status of the configured send key.

## Fix problems

A Capy key uses the permissions of its account. If `connect` asks for a new read key, create one with access to the Captain.

If a send fails with an access error, check the service user’s access to the project, Captain and paired device.

A value in the server environment wins over a claimed value. Change it in the server environment and restart SwB.

To replace a lost key, revoke it in **Settings** → **API**. Create a new key. Each claim link works once and expires after 30 minutes.
