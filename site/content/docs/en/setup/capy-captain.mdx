A Capy Captain is a long-lived Capy agent that directs a crew of threads. This connection sends SwB work to the agent and brings each reply back to the sender.

## Before you start

You need a Capy account in the right organization, a project and a Capy Captain. Any member can create a `read_write` service user. A service user is a Capy account for software, with its own key.

Your SwB server needs the `capy` block. Paste the prompt into an agent that has SwB with owner sign-in. In Capy, you add SwB under **Settings** → **MCP & plugins**.

## What the agent does

The agent calls `connect(what="capy-captain")` from the owner sign-in. SwB asks for the read key, `CAPY_API_KEY`, through a claim link. A claim link is a private one-time SwB page for one token.

After the restart, `connect` lists each available Capy Captain. The agent confirms the Capy Captain with you and calls `connect(what="capy-captain", choose={"captain":"<Capy Captain ID>"})`. It adds `"project":"<project>"` for a project route. A route is the SwB rule that names where work goes. A new route sends each message to the Capy Captain thread.

Then SwB asks for the send key, `CAPY_API_KEY_SERVICE`. The agent checks the route with `capy_captains`, `routes_list` and `routes_resolve`. It sends a test task with `send` and reads the answer with `result` or `inbox`. Last, the agent subscribes to `switchboard.message.created` if its app supports MCP events. Otherwise it calls `wait`.

## Credentials

| Token | Where it is shown | Format | Where it goes |
| - | - | - | - |
| Read key `CAPY_API_KEY` | **Settings** → **API**, one time | `capy_` and 43 random characters | **Token** on its SwB claim link |
| Send key `CAPY_API_KEY_SERVICE` | **Settings** → **API**, one time | `capy_` and 43 random characters | **Token** on its SwB claim link |

## Check the connection

Ask your agent to call `connect(what="capy-captain")` again. The answer shows the state `connected`. Run `routes_list` to see the route. Send a short test task. The task appears in the Capy Captain, and the answer comes back through `result` or `inbox`. Sign in as the owner to see the send key for each agent in `/healthz`.

## Fix problems

A Capy key acts with the access of its owner. If `connect` asks for a new read key, give that owner access to the Capy Captain.

If a send fails with an access error, share the project and the paired device with the service user.

A value in the server environment wins over a claimed value. Change it in the server environment and restart SwB.

Capy shows a key one time. For a lost key, create a new key and revoke the old key in **Settings** → **API**. Claim links work one time and expire after 30 minutes.
