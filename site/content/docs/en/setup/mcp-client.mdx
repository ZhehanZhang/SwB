MCP is the standard way an app uses outside tools. This page connects any app that can add a remote MCP server with its own key.

## Before you start

Your app must support remote MCP servers over Streamable HTTP and custom request headers. Streamable HTTP is the web transport of MCP. You also need an agent signed in to SwB as the owner or a terminal on the SwB computer.

To start SwB on the same computer as the app, run `uvx swb-one up` in an empty folder. Open the one-time sign-in link from your terminal. See [Install](/docs/install) for more options.

Claude, ChatGPT, Grok and coding agents have their own pages with OAuth sign-in. Use those pages for those apps.

## Local owner client

Use a private client on the SwB computer if it will set up other apps. Set its MCP address to the local `/mcp` address shown at startup. Use `SWB_KEY_OWNER` from the instance `.env` in `Authorization: Bearer <key>`. Keep that key only in the client's private local config with file mode `0600`. The key gives full owner access. Use it only with local SwB.

## Pair a client

If your agent can edit the client settings on the same computer, let it add the paired key. It saves the key in the client config with file mode `0600`. Use the steps below when you set up the client yourself.

<Steps>
<Step>
### Name the app

Tell the agent a short name for the app, for example `notes-bot`. SwB shows this name on messages from the app.
</Step>
<Step>
### Get the pairing code

Ask an agent signed in as the owner to get a pairing code. The agent can call `connect_code` with the app name. From the SwB instance folder, you can also run `uvx swb-one connect mcp-client --choose agent=notes-bot`. Use your app's name in the command.
</Step>
<Step>
### Get the key

On the computer that runs the app, open a private folder in your terminal. Replace `https://swb.example.com` with your SwB address. Keep `/connect` at the end. For local SwB, use `http://localhost:8870/connect` with the port shown at startup. Enter the pairing code at the hidden prompt within 10 minutes.

```bash
bash -c '
  umask 077
  set -C
  read -rsp "Pairing code: " code || exit
  printf "\n"
  printf "{\"code\":\"%s\"}" "$code" |
    curl -fsS https://swb.example.com/connect -H "Content-Type: application/json" \
      --data-binary @- > .swb-pairing.json
'
```
</Step>
<Step>
### Keep the key private

Open `.swb-pairing.json` in a private editor. The command saves the response with file mode `0600`. Use its `key` in the app settings. SwB returns the key once.
</Step>
<Step>
### Add SwB to the app

In the app's MCP settings, add a server named `swb`. Use `mcp_url` from the file. For local SwB, use the MCP address shown at startup. Select Streamable HTTP.
</Step>
<Step>
### Add the key

Add the header `Authorization: Bearer <key>` in the app's private settings. Delete `.swb-pairing.json` after you save the key.
</Step>
</Steps>

## What the agent does

The agent calls `connect(what="mcp-client")` from the owner sign-in. SwB returns the MCP address and asks for the app name. The agent calls `connect` again with `choose={"agent":"notes-bot"}`.

SwB makes a pairing code for that name and returns the `POST /connect` step. A pairing code is a one-time code that works for 10 minutes. If the app already has a key, SwB says so and makes a new code only after `connect_revoke`.

From the terminal on the SwB server, `swb connect mcp-client --choose agent=notes-bot` gives the same steps.

## Credentials

| Item | Where it is shown | Format | Where it goes |
| - | - | - | - |
| Pairing code | The `connect` or `connect_code` result | `XXXXX-XXXXX`, valid 10 minutes, one use | The `POST /connect` request |
| Agent key | The `POST /connect` answer, one time | Starts with `swb_` | The `Authorization` header in the private settings of the app |

Keep the key out of chat and shared files. SwB stores only a hash of the key.

## Check the connection

Ask the new agent to call `inbox`. Ask the agent signed in as the owner to call `connect_list` and check the new key's last call time. Have the owner agent send a test message to `agent:notes-bot`. Have the new agent read it with `inbox` and answer with `reply`.

## Fix problems

If `POST /connect` fails, the code expired or was used. Ask the agent for a new code. If a key leaks, revoke it with `connect_revoke`. The next call with that key stops at once.
