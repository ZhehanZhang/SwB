## Docker Compose

Run these commands as the user who owns the data folder.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Open the one-time sign-in link from the terminal within five minutes.

The browser uses `http://localhost:8870` for owner sign-in. The command inside the container uses port `8000`. Compose keeps the data in `./data`. After you change `.env`, run `docker compose up -d` again.

Run `docker compose exec switchboard swb login-link` to get a sign-in link for `http://localhost:8870`.

Signed-out requests to `/healthz` return two fields, `status` and `version`. Use an owner session or the owner key for full health details.

## Cloudflare Tunnel

A tunnel gives SwB a public address on your domain and keeps your ports closed. Make a tunnel in Cloudflare Zero Trust. Point its public hostname to `http://switchboard:8000`. Put the tunnel token in `.env` as `TUNNEL_TOKEN`. Start Compose with the tunnel profile.

```bash
docker compose --profile tunnel up -d
```

Set `SWB_PUBLIC_URL` to the tunnel hostname, for example `https://swb.example.com`.

## Trusted proxies

A reverse proxy passes requests to SwB. Add the proxy's address or dedicated network to `trusted_proxies` in `config/switchboard.yaml`. Specify a range in CIDR format, which combines an IP address and a prefix length.

You can also set `SWB_TRUSTED_PROXIES` in `.env`. Separate entries with commas. The YAML setting takes precedence.

For a Cloudflare Tunnel on the SwB host or Docker network, add the tunnel connector's address or dedicated network. The connector connects directly to SwB. Use the `cloudflare` entry for direct connections from Cloudflare edge servers.

## Cloudflare Access

Open the [Cloudflare setup guide](/docs/setup/cloudflare) to set up the owner and bypass policies.

| Path | Policy |
| --- | --- |
| `/mcp`, `/register`, `/token`, `/revoke`, `/.well-known/*` | Bypass |
| `/healthz`, `/connect`, `/avatars/*` | Bypass |
| `/inbox/poll`, `/inbox/events` | Bypass |
| `/github/webhook` | Bypass for GitHub |
| All other paths, including `/`, `/authorize`, `/inbox` and its conversation pages | Owner |

Set `CLOUDFLARE_ACCESS_TEAM_DOMAIN` and `CLOUDFLARE_ACCESS_AUD` from the owner application. SwB applies its own checks to requests on the bypass paths.

## Hosted platforms

Use one SwB instance with a persistent disk mounted at `/data`. See the [deployment guide](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy) for the Railway, Render and Fly.io templates and the Koyeb script.

## Fly.io [#fly]

Use the [SwB release checkout](#docker-compose). Install the [Fly.io command line tool](https://docs.fly.io/flyctl/) and sign in.

Run `sh deploy/fly.sh my-swb` from the SwB folder. Replace `my-swb` with a unique app name. The script uses `fly deploy --ha=false` to start one Machine.

Open `.env.swb-setup-fly-my-swb` in your checkout. Use `SWB_SETUP_CODE` to sign in.

Add a card to get $5 of usage each month on the [Fly.io Free plan](https://docs.fly.io/about/free-plan). Your account starts with $1 of credit for 7 days before you add a card.

A `shared-cpu-1x` Machine with 512 MB of memory costs $3.69 per month in Ashburn (`iad`). A 1 GB volume costs $0.15 per month.

When usage passes $5, Fly.io moves your organization to Pay As You Go. Fly.io bills the whole month at [standard rates](https://fly.io/docs/about/pricing/).

## Backups and upgrades

All state is in the data folder. Back it up before an upgrade. Keep `mcp-events.key` and `claim-key` with the database, because they seal stored secrets. To upgrade, install the new version and start SwB. Database changes only add tables and columns.

## Export memory

```bash
swb export /data/export
```

The export writes one Markdown folder per scope and an `INDEX.md`. Set `memory.mirror_dir` to keep a live copy in a folder.
