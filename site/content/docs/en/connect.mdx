## Add SwB to an agent

For an MCP client on the SwB computer, use local pairing. For a hosted app, add SwB as a remote MCP server. Use your public MCP address, for example `https://swb.example.com/mcp`. Approve the app's OAuth sign-in on the SwB page.

| App | Where to add SwB |
| - | - |
| [Local MCP client](/docs/setup/mcp-client) | Pair with a code. Use `http://localhost:8870/mcp` on the SwB computer. |
| Claude and Claude Projects | Customize → Connectors → Add → Add custom connector |
| ChatGPT | [chatgpt.com/plugins](https://chatgpt.com/plugins) → Add a custom MCP server |
| Grok | grok.com → Connectors → New Connector → Custom |
| Capy | Add an MCP server with the Automatic OAuth client |
| Claude Code | `claude mcp add --transport http --scope user switchboard https://swb.example.com/mcp` |
| Codex, Gemini CLI and other coding agents | `swb connect coding-agent --choose agent=codex` |

For a coding agent, change `codex` to the name of your client. Run `swb connect coding-agent` alone to see the list. The list has Claude Code, Codex, Gemini CLI, Qwen Code, Goose, OpenCode, Cline and Kiro.

## Ask your agent

Your agent sets up the other connections. Ask it in plain words.

| Ask | The agent does |
| - | - |
| How do I connect my Claude Projects? | It registers a Claude routine for the project and gives you one link for the token |
| Connect Slack to SwB. | It points you to the app manifest in the repository's `manifests/` folder and gets a claim link when needed |
| Connect my Discord bot. | It gives you a token link and the bot invite link |
| Send this to my Capy Captain. | It sends the task and waits for the answer |
| What can you send to? | It lists every target SwB can reach |

The agent calls the `connect` tool. SwB answers with the next step for that platform. When a step needs a token, SwB gives a one-time claim link. Open the link and paste the token there. [Credentials](/docs/credentials) explains claim links.

## Connect from the terminal

The same steps work from the `swb` command.

```bash
swb connect mcp-client
swb connect capy-captain
swb connect grok
```

## Connect with a pairing code

To pair a new agent, ask an agent signed in as the owner to call `connect_code`. Give it the name of the new agent. The code works one time for ten minutes. The new agent uses `POST /connect` to exchange the code for its own key. See [MCP client](/docs/setup/mcp-client) for the full pairing procedure.

You can also create a pairing code in Tokens. SwB sends the form to `POST /pairing/code`.

Pairing grants memory access to `agent:<name>` and to any scopes set for the agent in `auth.key_scopes`. A pairing code that names a project also grants that project's memory scope.

`POST /connect` returns the named project in `project`. Use it as the client's default project. Pass it in `project` when a tool needs the project.

The key can read messages its agent sends or receives within its [conversation scopes](/docs/security#keys-with-limits).

With a paired key, `tools/list` shows the tools for the paired agent role. The `auth.key_tools` setting can narrow the list. Use the owner's sign-in for owner tools. See [Paired keys](/docs/tools#paired-keys).

## Inbox event stream

`POST /connect` returns `inbox_events_url`, the URL for `GET /inbox/events`. Open that URL with `Authorization: Bearer <key>` using the paired agent's key. SwB sends that agent's inbox updates within the scopes of the key. These server-sent events (SSE) arrive over an open connection.

The stream starts with a `ready` event. Each `item` event has JSON data with a `cursor`, a conversation `handle` and the message data. The event ID is the cursor, which marks a position in the stream.

The stream starts at the latest position by default. To resume, send the last event ID in the `Last-Event-ID` header or the `after` query parameter. See [Messages](/docs/tools#messages) for the inputs to `reply` and `get_message`.

## Local device

Ask an agent signed in as the owner to call `companion_code`. On the device, run `swb companion connect https://swb.example.com`. Enter the pairing code at the hidden prompt.

Choose which actions the device allows at pairing. Add `--cap notify` to allow notifications. Add `--cap drop` to allow access to the device’s SwB Drop folder.

Use `swb companion run` to reconnect. Use `swb companion status` to view the device ID. Use `swb companion disconnect` to remove the device.
