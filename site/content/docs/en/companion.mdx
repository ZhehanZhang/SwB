A companion is SwB running on a device you own. It connects to your SwB deployment. Your agents can then use features on that device.

## Pair a device

Ask an agent signed in as the owner to call `companion_code`.

To get a code in the console, [sign in with a passkey](/docs/owner-login). Open Settings. In **Connections**, select **Pair a device**.

Run this command on the device. Replace the example address with your SwB HTTPS address.

```sh
uvx swb-one companion connect https://swb.example.com --cap notify
```

Enter the pairing code at the hidden prompt. The code works once and expires after 10 minutes. The audit log records who made it.

The device saves its own key in a private file.

## Choose features

Add one `--cap` option for each feature you want to enable.

| Option | Feature |
| --- | --- |
| `--cap notify` | Shows desktop notifications on the device |
| `--cap drop` | Shares files up to 10 MiB each through the `~/SwB Drop` folder |
| `--cap mcp --mcp NAME=COMMAND` | Gives your agents access to tools on an MCP server on the device |
| `--cap herdr` | Reaches coding agents in Herdr panes |
| `--cap codex` | Reaches Codex through its app server |
| `--cap opencode` | Reaches OpenCode through its server |
| `--cap dsh` | Reaches DeepSeek Harness through the SwB bridge |
| `--cap hooks` | Shares status from Claude Code, Gemini CLI and Codex |
| `--cap muse` | Pairs Muse over Bluetooth on a Mac or a Linux computer. Use the command in the [Muse guide](/docs/setup/muse) |

On Linux, notifications use `notify-send`.

For MCP, add one `--mcp` option for each server. Give a command or an HTTP address on the device. For example, use `--mcp 'notes=uvx notes-mcp'` or `--mcp notes=http://127.0.0.1:8000/mcp`.

Your agents use `companion_list` to see each paired device and its actions. They use `companion_invoke` to run an action.

## Local sessions

A local session is a coding agent that runs on the device. SwB lists each session as a target with its status.

SwB puts a message for the session in the agent's mailbox first. It then tries to deliver the message into the open session. The answer comes back in the same conversation.

For commands and supported agents, see [Local sessions](/docs/blocks/local-sessions).

## Keep it running

Pairing starts the companion. Use `swb companion run` to start it again. Use `swb companion status` to see the local device ID and features.

Use `uvx swb-one` in place of `swb` to run these commands with `uvx`. For Muse, keep the package and Python options from the [Muse guide](/docs/setup/muse).

The device starts each connection to SwB.

## Disconnect

Run `swb companion disconnect` on the device to remove its key. To revoke the key in the console, open **Connections** in Settings. Select **Disconnect** for the device.
