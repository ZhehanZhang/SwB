---
title: Channel modes
description: Choose how SwB acts in each channel.
---

A **space** is a place where messages arrive. A Slack channel, a Discord channel or thread, a Telegram group and a GitHub repository are spaces. Each space has one mode.

| Mode | Messages from other people | What the agent does | Where replies go |
| - | - | - | - |
| `off` | SwB drops them | Stays asleep | Only to the owner |
| `watch` | SwB stores them and sends you a digest | Reads only | Only to the owner |
| `assist` | They wake the assist target | Answers from context with read tools | In the thread |
| `triage` | They wake the triage target | Uses the actions of the space | In the thread, with a note to you |
| `work` | Owner messages only | Anything you can ask for | In the thread |

Your own mention or DM is always `work`, in every mode. A mode can only narrow access. Visibility still decides who reaches a target.

## Set a mode

Ask an agent, for example "Set #support to triage." The agent calls the mode tool. You can also choose a mode on the SwB page, or in the config.

```yaml
modes:
  default: watch
blocks:
  discord:
    spaces:
      home:
        mode: watch
        channels:
          "100000000000000004": {mode: triage, project: app, actions: [reply, label, comment]}
```

SwB uses the first match in this order. A mode set on the page or by an agent, then the channel, then the space, then `modes.projects.<project>`, then `modes.default`. The default of `modes.default` is `off`.

## Triage actions

The `actions` list of a space holds the actions that a triage wake can use. The actions are `reply`, `label`, `comment`, `open_issue`, `link_duplicate` and `notify_owner`. SwB enforces the list on the server. The GitHub actions use the GitHub App of the project.

Use a separate triage routine with few connectors, for example `claude-<project>-triage`. SwB wakes that routine for triage. Every triage action goes to the audit log with a link to the message.
