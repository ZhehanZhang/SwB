---
title: Owner sign-in
description: Sign in with a passkey, a one-time link, a setup code or your identity provider.
---

SwB has one owner. The owner signs in to the SwB page to see the instance, approve agent sign-ins and paste tokens. SwB uses passkeys, one-time links and OIDC in place of passwords.

| Page | Use |
| - | - |
| `/login` | Sign in as the owner. |
| `/authorize` | Review an agent's request to connect through OAuth. |

## One-time link

```bash
swb login-link
```

The command prints a link such as `https://swb.example.com/login#t=...`. Open it in your browser within five minutes. The link works once. An agent signed in as the owner can also make a link with the `login_link` tool. The token stays in the part of the link after `#`.

For a local run, set `SWITCHBOARD_PUBLIC_URL` to `http://localhost:8870` before you start SwB. Set the port in the address to match `PORT`. If the YAML config sets `public_url`, change it there. Use `--url` to select another server. Use `--dir` to read the owner key from another instance folder.

If the link shows one of these errors, run `swb login-link` again. Open the new link in your browser.

| Error | Meaning |
| - | - |
| `link_used` | Someone used the link to sign in before it expired. |
| `link_expired` | The link expired or is invalid. |

## Setup code

A setup code works once, for the first owner sign-in. Use it when SwB handles sign-in directly. The [cloud and Docker deploy scripts](/docs/deploy) create the code for you.

To set your own code, generate 32 random bytes. Encode them as 64 lowercase hexadecimal characters or standard Base64. This command adds a hexadecimal code to the private `.env` file. Run it in the instance folder after `swb init`.

```bash
(umask 077; printf 'SWB_SETUP_CODE=%s\n' "$(openssl rand -hex 32)" >> .env)
```

Start SwB with `SWB_SETUP_CODE` set. Open `/login` in your browser. Paste the code in **Setup code**.

## Passkey

After your first sign-in, the page asks you to add a passkey. Name the passkey after your device, for example MacBook. Use the passkey for the next sign-ins. Add a passkey on each device you use. Settings shows your passkeys and lets you remove one.

## OIDC

Use your own identity provider, for example Google, Okta or Authentik. Add it to the config.

```yaml
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
  oidc:
    name: Google
    issuer: https://accounts.google.com
    client_id: 1234.apps.googleusercontent.com
    client_secret_env: OIDC_CLIENT_SECRET
```

Set the redirect address in your provider to `https://swb.example.com/auth/oidc/callback`. The sign-in page then shows a button for your provider. SwB accepts an owner email with a verified address. You can also list provider subject ids in `owner_subjects`.

## Cloudflare Access

If Cloudflare Access protects your host, SwB reads the Access token and signs you in at once. Set `CLOUDFLARE_ACCESS_TEAM_DOMAIN`, `CLOUDFLARE_ACCESS_AUD` and `SWITCHBOARD_OWNER_EMAILS`. SwB checks the token signature, audience, issuer and email itself.

## Sessions

A session is a secure cookie on the SwB host. Each change on the page carries a CSRF token. Sign out from Settings.
