SwB can run with environment variables alone. The MCP block starts by default. Some blocks start when you set their variables. Use a YAML file for more settings.

## Instance

| Variable | Use |
| - | - |
| `SWITCHBOARD_KEY_OWNER` | The owner key for the `swb` command |
| `SWITCHBOARD_PUBLIC_URL` | Public address for sign-in and MCP. Use HTTPS for a remote server, for example `https://swb.example.com`. |
| `SWITCHBOARD_HOST` | Address for incoming connections. The default is `127.0.0.1`. |
| `SWITCHBOARD_DATA_DIR` | The data folder. The image uses `/data`. |
| `SWITCHBOARD_OWNER_EMAILS` | Owner emails for OIDC and Cloudflare Access, separated by commas |
| `SWITCHBOARD_KEY_<NAME>` | A bearer key for the agent `<name>` |
| `SWITCHBOARD_CONFIG` | The path of the base YAML file |
| `SWITCHBOARD_OVERLAY` | The path of a private overlay file |
| `PORT` | HTTP port. The default for `swb up` is `8870`. |

Set `PORT` in the shell or in the instance's `.env` file. For local sign-in, `swb up` uses `http://localhost:<port>` by default. SwB calculates this address at startup.

Use `swb up --public-url https://swb.example.com` to set the public URL on the command line. The command option takes priority over YAML `public_url`. YAML takes priority over `SWITCHBOARD_PUBLIC_URL`.

Use `--host` to override `SWITCHBOARD_HOST`. Set a public URL before you use `--host 0.0.0.0` or an address on your local network.

Use `swb up --dir ./my-swb` to read `.env` and `config/switchboard.yaml` from that folder. Use the same `--dir` with `swb init`. With plain `swb up`, use `SWITCHBOARD_CONFIG` to select a different config file.

`swb status`, `swb login-link`, `swb connect` and `swb claim` use `--dir` to find `.env`. They use `--url` to select the server address.

All server commands accept `--dir`. Use it with `swb serve`, `swb export`, `swb log`, `swb config migrate`, `swb blocks` and `swb targets`. SwB reads `.env` and the config from the selected folder. It also uses that folder to find the instance data for commands that use the database.

With plain `swb serve`, SwB reads the shell and the config file. The other server commands use the current folder by default.

Use `swb config migrate [file]` to print a config in version 2 format. Pass `file` to select a specific config. Otherwise, SwB uses the config from `--dir`, `SWITCHBOARD_CONFIG` or the default path.

## Data folder

`swb up` and `swb init` create a `data/` folder for a new instance. SwB uses that folder by default. Use `swb up --dir` to select a different instance folder.

Set `data_dir` in the config or overlay to change the path. That setting takes priority. SwB then checks `SWITCHBOARD_DATA_DIR` and `SWITCHBOARD_DATA` in that order. The default applies when all three settings are empty.

Plain `swb up` keeps existing config files. Older instances that use a home database keep using it. If SwB uses a home database in place of a missing `data/` folder, it logs a notice once.

On Linux and macOS, SwB sets the data folder to private mode `0700`. It sets database files to private mode `0600`.

## Blocks

| Block | Variables |
| - | - |
| Capy | `CAPY_API_KEY`, and `CAPY_API_KEY_SERVICE` or `CAPY_API_KEY_AS_<AGENT>` for sends |
| Slack | `SLACK_BOT_TOKEN` or `SLACK_USER_TOKEN`, `SLACK_TEAM_ID`, and `SLACK_APP_TOKEN` for Socket Mode |
| Discord | `DISCORD_BOT_TOKEN` |
| Telegram | `TELEGRAM_BOT_TOKEN` |
| GitHub | `GITHUB_WEBHOOK_SECRET` |
| Claude routines | `CLAUDE_ROUTINE_TOKEN` and `CLAUDE_ROUTINE_ID` |
| Grok routines | `GROK_ROUTINE_SECRET` and `GROK_ROUTINE_URL` |

For a named Slack workspace, put the name after `SLACK_`, for example `SLACK_SUPPORT_BOT_TOKEN`. Named routines work the same way, for example `CLAUDE_ROUTINE_TOKEN_DOCS`.

## The config file

`swb up` sets up a new instance in its folder. It stores the owner key in `.env` and saves a custom `PORT` there. It sets the file mode to `0600`.

Run `swb init` to create the files before you start SwB.

```bash
swb init
```

Both commands write only `version: 2` to `config/switchboard.yaml` by default. Use `--public-url` to save an address in this file. On a new instance, `swb up` also saves an address from `SWITCHBOARD_PUBLIC_URL`. To select blocks in YAML, add a `blocks` section as in this example.

```yaml
version: 2
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
blocks:
  mcp: {use: mcp}
  capy: {use: capy, identity: service}
targets:
  aliases: {}
routes:
  - {match: {}, to: capy:captain:<Capy Captain id>}
```

The `blocks` section takes priority over block selection from the environment. SwB uses the environment to select blocks when you omit `blocks`.

## Overlays

An overlay is a private YAML file for your own names, ids and paths. Put it in `config/local.yaml`, or name it with `SWITCHBOARD_OVERLAY`. The overlay wins over the base file, and the base file wins over the environment. Mappings merge. Lists replace.

In a key, `*` stands for an entry name or a list item.

## Core

| Key | Use |
| - | - |
| `version` | YAML format version. Use `2` for `blocks` |
| `public_url` | Address SwB uses for MCP and OAuth. See `SWITCHBOARD_PUBLIC_URL`. |
| `data_dir` | Path to the data folder. Set it here or with `SWITCHBOARD_DATA_DIR` |
| `timezone` | Time zone for daily counts and limits. Default `UTC` |
| `turn_cap` | Turns before SwB pauses a conversation. Default `200`. Set `null` to turn off the limit |
| `blocks` | Blocks to load, named by type or by your own label |
| `agents` | Agent definitions by name |
| `agents.*.label` | Display name for an agent |
| `targets` | Target names and their priority |
| `targets.aliases` | Map from a short name to a target name or address |
| `targets.priority` | Order to use when targets share a name. For example, `[capy:captain, agent, project]` |
| `routes` | Initial routes. SwB keeps routes that are already set |
| `routes.*.match` | Agent or project to match. Use `{}` for the global route |
| `routes.*.to` | Address to send to when the route matches |

## Sign-in and keys

| Key | Use |
| - | - |
| `auth` | Sign-in and key settings |
| `auth.owner_emails` | Email addresses that can sign in as the owner through OIDC or Cloudflare Access |
| `auth.cloudflare_access` | Cloudflare Access sign-in settings. Supply both fields and set `auth.owner_emails` |
| `auth.cloudflare_access.team_domain` | Your Cloudflare Access team domain. You can use `CLOUDFLARE_ACCESS_TEAM_DOMAIN` |
| `auth.cloudflare_access.aud` | Audience tag from the Access application. You can use `CLOUDFLARE_ACCESS_AUD` |
| `auth.redirect_uris` | Allowed OAuth return addresses. This list replaces the built-in set. Use `/*` to match a path and its subpaths |
| `auth.source_names` | Map from part of an OAuth host or client name to the agent name used for sign-in |
| `auth.key_scopes` | Scope list by key name, such as `[project:example]`. Limits routing, messages and conversations. It also limits memory for configured keys and supplies extra memory grants at pairing. SwB saves paired memory grants by key |
| `auth.key_tools` | Map from key name to allowed MCP tools, for example `[send]` |
| `auth.key_targets` | Map from key name to allowed message targets, for example `[agent:claude]` |
| `auth.inbox_keys` | Map from key name to the one agent whose inbox it can read. The built-in entry is `channel: claude-code` |

## Visibility

| Key | Use |
| - | - |
| `visibility` | Rules for who can access a resource. Tools stay private |
| `visibility.defaults` | Default rules by resource type. All types start as `private` |
| `visibility.defaults.channel` | Default rule for channels |
| `visibility.defaults.memory` | Default rule for memory scopes |
| `visibility.defaults.route` | Default rule for routes |
| `visibility.defaults.target` | Default rule for send targets |
| `visibility.resources` | Rules for specific resources such as `channel:home/#agents`. Each rule takes priority over its type default |

For Slack, `channel:home/#agents` is a channel rule. For GitHub, use `channel:github/acme/app` and `target:beta` to let outside senders reach `agent:beta`. See [channel visibility](/docs/channel-modes#allow-outside-github-senders).

Use `private` for the owner and their agents. Use `shared` to open access. List user IDs or entries such as `workspace:home` to share with selected people. Changes made with `visibility_set` take priority over this file.

## GitHub sender trust

| Key | Use |
| - | - |
| `blocks.github.owner_ids` | Default list of numeric GitHub user IDs trusted as owners |
| `blocks.github.spaces.*.owner_ids` | List of numeric GitHub user IDs that replaces the default for this space |

GitHub uses `owner` and `external` trust. On Slack, Discord and Telegram, `known` is an admission setting. It helps SwB decide whose messages to accept. Messages from other senders keep `external` trust, even when SwB admits them through `known`. See [Owner accounts](/docs/blocks/github#owner-accounts) for Work mode setup.

## MCP

| Key | Use |
| - | - |
| `blocks.mcp` | Settings for the block that serves MCP clients |
| `blocks.mcp.use` | Block type. Use `mcp` |
| `blocks.mcp.legacy_aliases` | Keeps older MCP tool names such as `agent_send`, `capy_delegate`, `capy_wait` and `capy_reply` available. Default `true` |
| `blocks.mcp.wait` | Limits for tool calls that wait for a reply |
| `blocks.mcp.wait.default_s` | Wait time in seconds when the caller leaves it blank. Default `60` |
| `blocks.mcp.wait.max_s` | Maximum wait in seconds. Default `200` |
| `blocks.mcp.wait.agents` | Map of wait limits by agent. Claude Code uses `45` seconds by default and at most `55` seconds |
| `blocks.mcp.wait.agents.*.default_s` | Default wait in seconds for this agent |
| `blocks.mcp.wait.agents.*.max_s` | Maximum wait in seconds for this agent |

## Memory and channel modes

See [Channel modes](/docs/channel-modes) to bind a project route and set triage actions.

| Key | Use |
| - | - |
| `memory` | Settings for the Markdown copy of memory |
| `memory.mirror` | Controls the Markdown copy. Set `false` to stop updates |
| `memory.mirror_dir` | Folder for the Markdown copy |
| `memory.mirror_debounce_s` | Seconds to wait after a memory change before writing the copy. Default `2` |
| `modes` | Settings for how SwB acts on incoming events |
| `modes.default` | Default mode. The default is `off` |
| `modes.projects` | Default mode for spaces assigned to each project |
| `modes.assist_max_chars` | Character limit SwB gives agents for an `assist` reply. Default `1500` |
| `modes.digest_minutes` | Minutes to collect `watch` events before a summary. Default `60`. SwB also sends a summary at `50` events |
