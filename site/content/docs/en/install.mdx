title: Install
description: Install SwB with uvx, pipx or Docker.
---

SwB runs on Linux, macOS and Windows. The uvx and pipx installs need Python 3.12 or later. The Docker install needs Docker.

## Install and start

Use an empty folder for your instance. The owner key lets the `swb` command sign in as you.

<Tabs items={['uvx', 'pipx', 'Docker']}>
  <Tab value="uvx">
    ```bash
    uvx swb-one init --public-url http://localhost:8870
    uvx swb-one up
    ```

    uvx downloads SwB and runs it. The `init` command writes a private owner key to `.env`. It writes the sign-in address to `config/switchboard.yaml`. In the other examples, replace the leading `swb` with `uvx swb-one`.
  </Tab>
  <Tab value="pipx">
    ```bash
    pipx install swb-one
    swb init --public-url http://localhost:8870
    swb up
    ```

    pipx installs the `swb` command for your user account. The `init` command writes a private owner key and the config file.
  </Tab>
  <Tab value="Docker">
    ```bash
    (umask 077; set -C; printf 'SWITCHBOARD_KEY_OWNER=%s\nSWITCHBOARD_PUBLIC_URL=http://localhost:8870\n' "$(openssl rand -hex 32)" > .env)
    docker run -d --name swb --env-file .env \
      -e PORT=8870 -p 127.0.0.1:8870:8870 -v swb-data:/data \
      ghcr.io/zhehanzhang/swb:latest
    ```

    This command creates a private `.env` file and starts the container. The image keeps its data in `/data`. In the other examples, replace the leading `swb` with `docker exec swb swb`.
  </Tab>
</Tabs>

`swb up` listens on `127.0.0.1` at port `8870` by default. The local MCP address is `http://127.0.0.1:8870/mcp`. Use `http://localhost:8870` as the browser sign-in address.

Set `PORT` in the shell or in `.env` to use a different port with `swb up`. Set the same port in the sign-in address. Use `--url` on client commands to select a different server, for example `swb status --url http://127.0.0.1:8871`.

Use `swb up --dir ./my-swb` to keep the config, `.env` and data in a separate instance folder. Use the same `--dir` with `swb init` and the client commands. See [Config](/docs/config) for the settings.

## Check the server

```bash
curl -fsS http://127.0.0.1:8870/healthz
```

The answer lists each block and its state. A block that needs a setting shows the name of the missing variable.

## Server commands

| Command | Use |
| - | - |
| `swb init` | Write a private owner key and a minimal config. |
| `swb up` | Start SwB on this computer. |
| `swb connect` | Get the steps to connect a platform. |
| `swb status` | Show the status and next steps. |
| `swb login-link` | Create a one-time owner sign-in link. |
| `swb claim` | Save a credential from a claim link or code. |
| `swb muse-bridge` | Pair and run a Muse gadget on Linux. |
| `swb serve` | Run the server with its configured host and port. |
| `swb export DIR` | Write saved memory to Markdown files in the given folder. |
| `swb log` | Print recent audit entries. |
| `swb config migrate` | Print a version 1 config in the version 2 format. |
| `swb blocks list` | List the configured blocks. |
| `swb blocks show BLOCK` | Show the settings for a block. |
| `swb blocks check` | Check the block configuration. |
| `swb targets` | List the targets for `send`. |

## Versions

After publication, use the `swb-one` package from PyPI or the `ghcr.io/zhehanzhang/swb` image from GitHub Container Registry. Use a version such as `1.0.0` to select one release. The image tag `latest` follows the newest stable release.
