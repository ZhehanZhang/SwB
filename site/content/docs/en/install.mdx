title: Install
description: Install SwB with uvx, pipx or Docker.

SwB runs on Linux, macOS and Windows. The uvx and pipx installs need Python 3.12 or later. The Docker install needs Docker.

## Install and start

Use an empty folder for your instance. The owner key lets the `swb` command sign in as you.

<Tabs items={['uvx', 'pipx', 'Docker']}>
  <Tab value="uvx">
    ```bash
    uvx swb-one up
    ```

    uvx downloads and starts SwB. Open the one-time sign-in link from your terminal within five minutes. In the other examples, replace the leading `swb` with `uvx swb-one`.
  </Tab>
  <Tab value="pipx">
    ```bash
    pipx install swb-one
    swb up
    ```

    pipx installs the `swb` command for your user account. Open the one-time sign-in link from your terminal within five minutes.

    If pipx uses an older Python, use `pipx install --python 3.12 swb-one`.
  </Tab>
  <Tab value="Docker">
    ```bash
    (umask 077; set -C; printf 'SWITCHBOARD_KEY_OWNER=%s\nSWITCHBOARD_PUBLIC_URL=http://localhost:8870\n' "$(openssl rand -hex 32)" > .env)
    docker run -d --name swb --env-file .env \
      -e PORT=8870 -p 127.0.0.1:8870:8870 -v swb-data:/data \
      ghcr.io/zhehanzhang/swb:latest
    ```

    These commands create a private `.env` file and start the container. The image keeps its data in `/data`. Run `docker exec swb swb login-link` to get a sign-in link. In the other examples, replace the leading `swb` with `docker exec swb swb`.
  </Tab>
</Tabs>

On the first local start, `swb up` creates `.env`, `config/switchboard.yaml` and `data/` in the instance folder. Run `swb login-link` later to get a new link.

To create the files before you start the server, run `swb init`. Then run `swb up`. Run `swb login-link` in a second terminal from the same folder.

`swb up` listens on `127.0.0.1` at port `8870` by default. The default local MCP address is `http://localhost:8870/mcp`. Set `PORT` in the shell or in `.env` to use a different port.

Use `swb up --dir ./my-swb` to select an instance folder. Pass the same `--dir` to the other commands. See [Config](/docs/config) for bind addresses, config files and data folders.

## Check the server

```bash
curl -fsS http://127.0.0.1:8870/healthz
```

This signed-out request shows `status` and `version`. Run `swb status` or call `/healthz` with the owner key to list blocks, their states and any missing variables.

## Server commands

Run `swb --help` to see the command groups. Add `--help` to a command to see its options.

| Command | Use |
| - | - |
| `swb init` | Write a private owner key and a minimal config. |
| `swb up` | Start SwB on this computer. |
| `swb connect` | Get the steps to connect a platform. |
| `swb status` | Show the status and next steps. |
| `swb login-link` | Create a one-time owner sign-in link. |
| `swb claim` | Save a credential from a claim link or code. |
| `swb muse-bridge` | Runs the current Muse connection. |
| `swb serve` | Run the server with its configured host and port. |
| `swb export DIR` | Write saved memory to Markdown files in the output folder `DIR`. |
| `swb log [--limit N]` | Print recent audit entries. The default limit is `50`. |
| `swb config migrate` | Print a version 1 config in the version 2 format. |
| `swb blocks list` | List the configured blocks. |
| `swb blocks show BLOCK` | Show the settings for a block. |
| `swb blocks check` | Check the block configuration. |
| `swb targets` | List the targets for `send`. |

## Versions

After publication, use the `swb-one` package from PyPI or the `ghcr.io/zhehanzhang/swb` image from GitHub Container Registry. Use a version such as `1.0.0` to select one release. The image tag `latest` follows the newest stable release.
