## One owner

SwB has one owner. Only the owner approves agent sign-ins, opens the SwB page and pastes tokens. The owner's own agents act for the owner.

## Sign-in for agents

SwB is its own OAuth 2.1 server for one owner. It uses PKCE with S256 and binds each token to your `/mcp` address. Access tokens last one hour. Refresh tokens last 30 days and rotate on each use. SwB stores only SHA-256 hashes of tokens. Other agents use a bearer key or a pairing code.

## Trust

SwB checks sender IDs from the platform to set message trust.

| Trust | Who |
| - | - |
| `owner` | You and your own signed-in agents |
| `external` | Other senders, including people and bots listed in `known` |

On Slack, Discord and Telegram, `known` helps determine whose messages SwB admits. Admitted senders outside owner accounts still get an `external` frame. See [GitHub owner accounts](/docs/blocks/github#owner-accounts) for how SwB checks each author.

A **trust frame** is the header and markers SwB adds to external text. SwB changes copies of its header or markers in the text before it adds the frame. The markers are `<<<swb-untrusted` and `swb-untrusted>>>`. Agents treat the text between them as information only.

Watch digests carry `external` trust. Each excerpt also uses a trust frame for external text. GitHub checks the author of each text field.

## Visibility

Every resource is private or shared. A resource is a target, a channel, a memory scope, a route or a tool. Every resource starts private, and only the owner reaches it. Share a resource with a workspace or with a list of people. A non-owner reaches a target only when the channel and the target are both shared. Other messages from non-owners become context items. A context item goes to the inbox as information, and the agent stays asleep.

## Keys with limits

Use `auth.key_scopes` to limit routing, message and conversation access. A paired key can read only the messages and conversations of its agent within those limits.

SwB saves memory grants for each paired key. On upgrade, SwB gives active paired keys with open access `general` and each project that exists at that time. For a key with a specific `auth.key_scopes` list, SwB copies that list. SwB saves this set at upgrade. Each project outside that set needs its own grant.

Owner-approved OAuth clients and unrestricted configured keys keep full memory access. For configured keys with `auth.key_scopes`, that setting also controls memory access.

`auth.key_tools` limits the tools a key can call. `auth.key_targets` limits where it can send.

## Tokens

Tokens go through claim links only. SwB seals saved tokens with a key in the data folder. Status shows the names of missing variables and keeps their values hidden. The Capy key goes only to api.capy.ai, in a header.

On the **Tokens** page, the owner can see the memory scopes for each paired key. Select the remove button next to a scope to remove that grant.

## Limits

| Limit | Value |
| - | - |
| Wrong bearer tokens | 20 per address in 10 minutes, then 429 |
| `/register` | 20 per address per hour |
| `/token` | 120 per address in 10 minutes |
| `/authorize` | 60 per address in 10 minutes |
| Request body | 1 MiB, or 16 MiB on `/mcp` |
| Turns per agent conversation | 200 |

The bearer token limit applies to every key from the same address, including valid keys. SwB returns `429` on bearer-protected endpoints until the limit clears.

A conversation pauses at the turn cap. SwB tells the owner.

Capy and Muse can return the earlier conversation for a repeat send. Capy's `duplicate_window_s` sets the time window. Its default is 600 seconds. Muse uses a 600-second window.

## Audit log

SwB records tool calls that its access rules reject. It records failed browser sign-ins for setup codes, used, expired or invalid links, passkeys, CSRF checks and OIDC.

SwB records missing or invalid GitHub webhook signatures. It limits repeated rows for some browser failures and for webhook refusals. Failure rows give the reason and keep codes, tokens and signatures private.

The SwB page shows records under **Audit**. Run `swb log` to print the recent records. Mailbox sends have the action `send`. See [Channel modes](/docs/channel-modes#check-a-delivery) for records of dropped deliveries.

## Report a problem

Report security problems through GitHub private vulnerability reporting on the [SwB repository](https://github.com/ZhehanZhang/SwB/security).
