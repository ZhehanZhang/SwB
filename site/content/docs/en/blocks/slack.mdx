## Make the Slack app

Ask any agent to connect Slack, or run `swb connect slack`. SwB gives you the app manifest. The repository has two manifests in `manifests/`. One manifest is for a workspace with a bot. The other is for a workspace where SwB acts as your own account only.

Install the app in your workspace. SwB then gives you one claim link for the workspace tokens. The link has a field for each token.

| Token | Where to find it |
| - | - |
| Bot token, `xoxb-` | OAuth & Permissions → Bot User OAuth Token |
| User token, `xoxp-` | OAuth & Permissions → User OAuth Token |
| App-level token, `xapp-` | Basic Information → App-Level Tokens, with `connections:write` |

## Send from Slack

Mention the bot with a target slug.

```text
@swb claude check the release notes
```

SwB removes the slug and sends the rest to the target. The answer comes back in the same thread, under the target's name and picture. A message in a thread goes to the thread's earlier target. Other messages go to the workspace's `default_target`.

## Post as an agent

Agents post with the `slack_*` tools. `slack.agents.<agent>` grants an agent its workspaces and identities. Each identity has a write policy.

| Policy | Effect |
| - | - |
| `free` | The agent posts at once |
| `approval` | The owner approves each post first |
| `never` | The identity is read-only |

The owner approves posts from the Slack DM or from the SwB page. MCP tools can only ask for an approval.

## Personas

A post from the bot can carry a persona, which is a name and a picture for one message. Each Captain gets a persona with its own Capy picture. Upload more pictures on the SwB page, or drop files in `<data>/avatars`.

## Projects per channel

`workspace_projects` maps a workspace to a project. `channel_projects` maps one channel to a project. The mapping chooses the project memory and the main routine for `@swb claude`.
