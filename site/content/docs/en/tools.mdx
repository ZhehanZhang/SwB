title: Tools
description: The MCP tools that SwB gives your agents.
---

Agents see the tools that their sign-in allows. Block tools appear when the block is on.

## Messages

| Tool | Use |
| - | - |
| `send` | Send work or a message to a target, or let the route choose the target |
| `agent_send` | Deprecated tool. Pass the agent name in `to`, for example `to="codex"`. `blocks.mcp.legacy_aliases` enables it by default. For new calls, use `send` with `to="agent:codex"` |
| `wait` | Wait for the next reply on your conversations |
| `inbox` | Read your inbox and return at once |
| `reply` | Answer a message, or add a message to a conversation |
| `status` | Show the state of one conversation. For Capy, use `messages` for the number of recent messages. Set `include_tools=true` to include tool activity |
| `switchboard_status` | Show your sign-in identity, wait limits, blocks and instance health |
| `result` | Get the final reply of a conversation. Use `tail` to set the number of recent replies or messages where supported |
| `cancel` | Stop following a conversation |
| `targets` | List everything `send` can reach |
| `get_message` | Read a stored message with the `message_id` from an MCP event callback, such as `msg_42` |

The `inbox` tool and the [inbox event stream](/docs/connect#inbox-event-stream) deliver message data directly. To read later items with `inbox`, pass the `cursor` as `since_cursor`. To reply, pass the item's `handle` as `conversation` to `reply`.

### Send options

| Option | Use |
| - | - |
| `wait_s` | Wait this many seconds for the first reply from a block that returns a conversation ID. The limit depends on the client. Use `wait` for agent mailboxes |
| `forward` | Pass the ID of an eligible conversation you received with `owner` trust. SwB sends the final reply to the original sender |
| `new_conversation` | Set `true` to start a new thread in the Capy Captain's project. Set `false` to send to the Captain's thread |
| `files` | Attach files to a Capy task. Give each file a `name` and either `text` or `base64` content. Use `media_type` to set the file type |
| `repos` | Pass the repositories for a Capy task as `owner/repo` names. Use repositories linked to the SwB project |
| `in_reply_to` | Use `reply` with `conversation` to answer a message. `send` rejects `in_reply_to` |

## Memory and projects

| Tool | Use |
| - | - |
| `context_pack` | Get the briefing for a project |
| `memory_write` | Save an entry with `scope`, `namespace`, `title` and `body`. A namespace groups entries within a scope. Use up to three lowercase levels, such as `notes/meetings`. For project memory, pass its short name in `project` and use `scope="project:<slug>"`. For general memory, set `confirm_general=true` after the owner agrees |
| `memory_search` | Search memory with `query`. The default scope is `general`. Pass the project slug in `project` to search that project first, then `general`. Set `include_general=false` to search that project alone |
| `memory_list` | List memory entries |
| `memory_read` | Read one entry with its history |
| `memory_delete` | Remove an entry |
| `memory_move` | Move an entry to a different project |
| `memory_promote` | Move an entry to general |
| `project_list` | List projects and their links |
| `project_create` | Make a project |
| `project_update` | Rename, link, archive or make a project private |
| `project_sync` | Link projects to their matches again |

For `memory_search` and `memory_list`, a private project is readable only as the current project. Set `project` to that project. When `scopes` names additional projects, choose public projects. The agent's key must allow access to each project.

| Tool | Use |
| - | - |
| `connect` | Get the next setup step for a platform |
| `connect_code` | Make a pairing code for a new agent |
| `connect_list` | List agent keys |
| `connect_revoke` | Remove an agent key |

## Routes

A route picks a target for `send`. Use a block that accepts routes, such as `capy`, `claude-routine`, `grok-routine` or `muse`. Use `send` with `to="agent:<name>"` to reach an agent mailbox directly.

| Tool | Use |
| - | - |
| `routes_list` | List all routes, mailbox routes included |
| `routes_set` | Save a route. Give `target` an agent mailbox, such as `agent:<name>`, or a block address, such as `capy:captain:<name>`. Use `agent` or `project` to limit the route |
| `routes_resolve` | Show the matching route for one destination. Pass `block`, such as `grok-routine` or `agent` |
| `routes_remove` | Remove the route for the exact `agent` and `project` on the chosen `block` |

`routes_resolve` and `routes_remove` use the first destination by default. That is the first block that accepts routes. With only mailbox routes, it is `agent`. Pass `block` to select a different one.

## Block tools

### Capy

| Tool | Use |
| - | - |
| `capy_captains` | List the Captains your Capy connection can access |
| `capy_captain_digest` | Read a Captain's summary and see which crew threads are working or need the owner's attention |
| `capy_list` | List work sent through SwB or threads in a Captain's crew or linked Capy project |
| `capy_delegate` | Send work to Capy. Use `send` with `to="capy"` in new calls |
| `capy_inbox` | Read your Capy inbox and return at once. Use `inbox` with `block="capy"` in new calls |
| `capy_wait` | Wait for the next item in your inbox. Use `wait` in new calls |
| `capy_status` | Show the state and recent messages of a Capy thread. Use `status` in new calls |
| `capy_reply` | Send a follow-up message to a Capy thread. Use `reply` in new calls |
| `capy_result` | Get the latest reply from a Capy thread with available links to files and pull requests. Use `result` in new calls |
| `capy_cancel` | Stop following work sent to Capy. The Capy thread can continue. Use `cancel` in new calls |

### Claude Code routines

These tools appear when the `claude-routine` block is on. A routine is a Claude Code task that SwB can start.

| Tool | Use |
| - | - |
| `routine_register` | Register a routine and get a link for the owner to enter its token |
| `routine_list` | List the routines SwB can start |
| `routine_pickup` | Pick up the message when a routine starts with an empty prompt |
| `routine_add` | Add a routine with its token as the owner |
| `routine_remove` | Remove a routine saved through SwB as the owner |

### Slack

| Tool | Use |
| - | - |
| `slack_workspaces` | List the Slack workspaces you can use, the accounts available in each and their posting rules |
| `slack_channels` | List channels visible to the selected Slack account. The list marks the channels SwB watches |
| `slack_search` | Search messages in a workspace through the owner's Slack account |
| `slack_history` | Read recent messages in a channel with the newest first |
| `slack_thread` | Read the first message in a thread and its replies with the oldest first |
| `slack_watched` | List the channels whose new messages go to your SwB inbox |
| `slack_events` | Read recent messages in watched channels, bot mentions and direct messages. The newest items come first |
| `slack_wait` | Wait for the next Slack item in your inbox |
| `slack_personas` | Show the names and images available for bot posts and the default choice |
| `slack_targets` | List target names to put after a bot mention in Slack |
| `slack_post` | Post as the bot or the owner's Slack account. Use `thread_ts` to post a reply in a thread. The posting rules can require owner approval |
| `slack_react` | Add an emoji reaction to a message. The same rules apply as for `slack_post` |
| `slack_request_write` | Send a proposed Slack post to the owner for approval |
| `slack_write_requests` | Check the state of your Slack approval requests. Use `request_id` to read one request |

### GitHub
