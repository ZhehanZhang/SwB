**空間**是接收訊息的地方。Slack 頻道、Discord 頻道和討論串、Telegram 群組及 GitHub 程式碼庫都是空間。

| 模式 | SwB 的行為 |
| - | - |
| `off` | 捨棄其他人傳來的訊息 |
| `watch` | 收集訊息並彙整成摘要 |
| `assist` | 喚醒代理，讓它參考上下文並在原討論串回覆 |
| `triage` | 喚醒分流代理。預設動作是在原討論串回覆 |
| `work` | 處理擁有者傳來的訊息 |

在 Slack、Discord 和 Telegram 中，擁有者的提及和私訊一律依 `work` 處理。頻道與目標的存取範圍由可見性設定決定。

若要使用 GitHub 的 `work` 模式，請將你的 GitHub 使用者 ID 加到空間的[擁有者清單](/zh-Hant/docs/blocks/github#擁有者帳號)。

## 設定模式

在連線或專案頁面的 **Modes** 設定模式。也可以在 YAML 設定。擁有者可以用 `space_mode` 指定模式、目標、專案和允許的動作。

SwB 先查看已儲存的設定，再查看頻道和空間設定。接著查看模組的舊版設定、專案模式和 `modes.default`。預設模式為 `off`。

## 繫結目標

在 GitHub、Slack、Discord 和 Telegram 中，`assist`、`triage` 和 `work` 模式可以透過專案路由喚醒代理。SwB 依下列順序選用第一個適用的目標。

| 順序 | 目標 |
| - | - |
| 首先 | 透過 `space_mode` 儲存的設定中的目標。頻道設定會整體取代空間設定 |
| 其次 | YAML 中的 `target`。依序查看頻道、空間和專案的模式設定 |
| 其次 | 在 `triage` 模式下，選用名為 `claude-<project>-triage` 的可用目標，例如 Claude routine |
| 再來 | 空間設定中的 `default_target` 或 `target` |
| 最後 | 專案路由 |

從 `targets` 回傳的清單選擇目標。以下範例將代理信箱繫結到現有的 GitHub 空間。

```python
space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")
```

使用 `mode="assist"` 可切換至協助模式。省略 `target` 可保留繫結。設為 `target=""` 可清除繫結。

呼叫 `routes_set` 為連結的專案指定備用目標位址。若要鎖定 Capy 路由，請使用 `capy:captain:<name>` 這類目標，並保留 `allow_override=false`。

## 允許外部 GitHub 使用者存取

呼叫 `visibility_list` 查看確切的資源名稱。`visibility_set` 只接受清單中的名稱。`agent:beta` 是信箱位址。`target:beta` 控制誰能存取該信箱。

```python
visibility_set(resource="channel:github/acme/app", visibility="shared")
visibility_set(resource="target:beta", visibility="shared")
```

若只開放一位傳送者，請在兩項資源填入同一個已驗證的使用者 ID，例如 `visibility=["github:1234"]`。

## 查看觀察摘要

用 `modes.digest_minutes` 設定間隔。預設間隔為 60 分鐘。間隔結束或累積到 50 個事件時，SwB 將摘要送到目標信箱。擁有者的信箱是備用的收件處。

擁有者可以在主控台的 **Inbox** 查看所有摘要，也可以呼叫 MCP 工具 `inbox` 或 `wait`。摘要列出事件總數、各事件的作者和摘錄，以及可用的連結。摘要的信任等級是 `external`。

觀察模式讓代理保持休眠。摘要僅供收件匣查詢。已設定的 GitHub 接收端仍會收到各個事件的副本。

## 分流動作

分流代理可以讀取上下文。預設是在原討論串執行 `reply`。在 GitHub 討論串中，請使用 `github_reply`。在 `handle` 填入對話 ID。在 `text` 填入回覆內容。

若要開放更多動作，請在 `space_mode` 或 YAML 中設定 `actions`。將 `reply` 加入清單即可保留回覆功能，例如 `actions=["reply", "notify_owner"]`。

| 動作 | 用途 |
| - | - |
| `label` | 為 GitHub 議題或提取要求加上標籤 |
| `comment` | 在 GitHub 上新增留言 |
| `open_issue` | 建立 GitHub 議題 |
| `link_duplicate` | 連結並關閉重複的 GitHub 議題 |
| `notify_owner` | 傳一則通知給擁有者 |

變更 GitHub 內容需要具備寫入權限的 GitHub 憑證。SwB 會將分流動作寫入稽核記錄。

## 檢查訊息傳送

呼叫 `modes_status` 查看模式、已繫結的目標、動作和設定問題。主控台的模式列會顯示已繫結的代理。分流模式採用備用目標時才會提示使用預設代理。分流需要指定目標時，`space_mode` 和 `modes_status` 都會提示選擇分流代理。

SwB 會在稽核記錄中記下捨棄 Slack、Discord 和 Telegram 事件的原因。若模組、空間、頻道和原因都相同，每 10 分鐘最多記一筆。

SwB 也會記錄捨棄 GitHub webhook 的原因。開啟 **Audit** 或執行 `swb log` 查看原因。
