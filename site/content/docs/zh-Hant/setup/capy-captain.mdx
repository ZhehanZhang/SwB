Captain 是長期運作的 Capy 代理，負責指揮一組執行緒。這項連線會把 SwB 的工作交給一個 Captain，並把每則回覆帶回給傳送方。

## 開始之前

你需要在正確組織中的 Capy 帳號、一個專案與一個 Captain。任何成員都可以建立 `read_write` 服務使用者。服務使用者是供軟體使用的 Capy 帳號，擁有自己的金鑰。

你的 SwB 伺服器需要 `capy` 模組。請把提示詞貼到已用擁有者身分連上 SwB 的代理。在 Capy 中，你可以在 **Settings** → **MCP & plugins** 加入 SwB。

## 代理的工作

代理會以擁有者身分呼叫 `connect(what="capy-captain")`。SwB 會透過領取連結要求讀取金鑰 `CAPY_API_KEY`。領取連結是 SwB 上的一次性私人頁面，一個頁面對應一個權杖。

重新啟動後，`connect` 會列出每個可用的 Captain。代理會與你確認 Captain，再呼叫 `connect(what="capy-captain", choose={"captain":"<Captain ID>"})`。如需專案路由，它會加上 `"project":"<project>"`。路由是 SwB 中指定工作去向的規則。新路由會把每則訊息送到 Captain 執行緒。

接著 SwB 會要求傳送金鑰 `CAPY_API_KEY_SERVICE`。代理會用 `capy_captains`、`routes_list` 與 `routes_resolve` 檢查路由。它會用 `send` 傳送測試工作，再用 `result` 或 `inbox` 讀取回覆。最後，如果它所在的應用程式支援 MCP 事件，它會訂閱 `switchboard.message.created`。否則它會呼叫 `wait`。

## 憑證

| 權杖 | 顯示位置 | 格式 | 存放位置 |
| - | - | - | - |
| 讀取金鑰 `CAPY_API_KEY` | **Settings** → **API**，只顯示一次 | `capy_` 加 43 個隨機字元 | 對應 SwB 領取連結的 **Token** |
| 傳送金鑰 `CAPY_API_KEY_SERVICE` | **Settings** → **API**，只顯示一次 | `capy_` 加 43 個隨機字元 | 對應 SwB 領取連結的 **Token** |

## 檢查連線

請代理再次呼叫 `connect(what="capy-captain")`。回覆會顯示狀態 `connected`。執行 `routes_list` 查看路由。傳送一項簡短的測試工作。工作會出現在 Captain 中，回覆會透過 `result` 或 `inbox` 傳回。以擁有者身分登入後，可在 `/healthz` 查看各代理使用的傳送金鑰。

## 排除問題

Capy 金鑰具備其擁有者的存取權。如果 `connect` 要求新的讀取金鑰，請授予該擁有者 Captain 的存取權。

如果傳送時出現存取錯誤，請把專案與已配對裝置分享給服務使用者。

伺服器環境中的值優先於領取連結儲存的值。請在伺服器環境中修改該值，再重新啟動 SwB。

Capy 只顯示一次金鑰。金鑰遺失時，請在 **Settings** → **API** 建立新金鑰，並撤銷舊金鑰。領取連結只能使用一次，30 分鐘後失效。
