這項連線會把 SwB 以連接器的形式加入 [grok.com](https://grok.com) 上的 Grok。連接器是 Grok 在對話中呼叫的外部工具伺服器，這裡指 MCP 伺服器。Grok 會以代理 `grok` 的身分登入 SwB。

## 開始之前

所有 Grok 使用者都可以新增連接器。在 Grok Business 與 Grok Enterprise 中，要先由具備 **Team Read-Write** 權限的團隊管理員為團隊新增連接器。

你的 SwB 伺服器需要公開的 HTTPS 位址與擁有者登入。OAuth 是一種登入方式，你會在瀏覽器的 SwB 頁面上核准存取。

Grok Bot 是另一款應用程式，設定方式另有說明。請參閱 [Grok Bot](/docs/setup/grok-bot)。

<Step>

### 登入

</Step>

## 代理的工作

Grok 會呼叫 `connect(what="grok")`。SwB 會回傳 MCP 位址與 OAuth 狀態。你登入後，`connect` 會回報用戶端已登入。

Grok 會用 `send` 傳送一則測試訊息到自己的信箱，再用 `inbox` 讀取。信箱是單一代理在 SwB 中的收件匣。[grok.com](https://grok.com) 上的 Grok 在對話中工作。為了收取新的 SwB 訊息，Grok 會在對話開始時呼叫 `wait` 或 `inbox`。如果 Grok 支援 MCP 事件，它會改為訂閱 `switchboard.message.created`。

## 憑證

| 權杖 | 顯示位置 | 格式 | 存放位置 |
| - | - | - | - |
| SwB 登入權杖 | 你登入時由 Grok 取得 | 隨機文字 | 由 Grok 保存 |

其他權杖一律透過 SwB 領取連結交給 SwB。領取連結是 SwB 上的一次性私人頁面，一個頁面對應一個權杖。

## 檢查連線

請 Grok 呼叫 `connect(what="grok")`。回覆會顯示用戶端已登入。接著請 Grok 呼叫 `inbox`。清單中會出現測試訊息。

## 排除問題

如果工作需要自動開始，請使用 [Grok Bot](/docs/setup/grok-bot)。SwB 會透過 Webhook 喚醒 Grok Bot routine。

Grok **Automations** 的 Webhook 使用另一種簽章格式，與 SwB 1.0 的格式有差異。請讓 Automations 的憑證留在 SwB 領取連結之外。
