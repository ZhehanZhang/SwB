SwB 從你註冊的 GitHub App 接收儲存庫事件。有了應用程式的私密金鑰，代理還能替 issue 加上標籤、留言和開立新 issue。

## 開始之前

你需要一個 GitHub 帳號和要接上的儲存庫。在組織中操作時，你需要組織擁有者角色或 GitHub App 管理者角色。你也需要以擁有者身分登入 SwB 伺服器，例如 `https://swb.example.com`。

GitHub 必須能連到你伺服器上的 `https://swb.example.com/github/webhook`。

## 代理的工作

代理呼叫 `connect`，參數為 `what="github"`。SwB 顯示 webhook 位址、webhook 金鑰的狀態和儲存庫路由數量。路由會把一個儲存庫的事件傳給一個目標。

代理將儲存庫加入 `config/switchboard.yaml` 中的 `blocks.github.spaces`。空間會指定儲存庫的模式、專案和目標。此範例將專案 `demo` 中儲存庫 `acme/app` 的觀察摘要送到 `agent:beta`。

```yaml
blocks:
  github:
    use: github
    spaces:
      acme/app:
        mode:
          mode: watch
          target: agent:beta
        project: demo
```

若要使用工作模式，代理會將 `mode.mode` 設為 `work`。接著把你的 GitHub 數字使用者 ID 填入空間的 `owner_ids`。查詢方式與範例請參閱[擁有者帳號](/zh-Hant/docs/blocks/github#擁有者帳號)。

GitHub 的信任等級為 `owner` 和 `external`。`known` 設定適用於 Slack、Discord 和 Telegram。存取規則使用 `github:4242` 這類寄件者 ID。

使用領取連結儲存同一組 webhook 金鑰。代理重新啟動 SwB 以載入金鑰並套用路由。

代理再次呼叫 `connect(what="github")`，取得尚待填寫的 App ID 或私密金鑰連結。若要從現有的個人存取權杖改用 GitHub App 憑證，選用 `choose={"credential":"app"}`。

重新啟動後，代理呼叫 `github_status` 檢查安裝及其權限。

代理呼叫 `space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")`，繫結分流目標。使用 `mode="assist"` 可切換至協助模式。請從 `targets` 回傳的清單中選擇目標。連結的專案路由是備用選項。分流模式預設允許 `github_reply`。

若要接收外部使用者的事件，請開放 `channel:github/acme/app` 和 `target:beta`。詳情請參閱[頻道可見度](/zh-Hant/docs/channel-modes#允許外部-github-使用者存取)。

觀察模式會依 `modes.digest_minutes` 的間隔將摘要送至目標信箱。累積到 50 個事件時，SwB 提前傳送摘要。擁有者可在主控台的 **Inbox** 查看所有摘要，也可呼叫 MCP 工具 `inbox` 或 `wait`。

## 憑證

| 權杖 | GitHub 顯示位置 | 格式 | 填寫位置 |
| --- | --- | --- | --- |
| Webhook 金鑰 | 用 `openssl rand -hex 32` 產生 | 至少 16 個字元 | SwB 領取連結 |
| App ID | 應用程式設定中的 **App ID** | 一串數字 | SwB 領取連結 |
| 私密金鑰 | 點選 **Generate a private key** 後下載一次 | `.pem` 檔案 | SwB 領取連結 |

SwB 會用私密金鑰自行產生安裝權杖。每個安裝權杖的效期是一小時。

## 檢查連線

請代理再次呼叫 `connect`。設定完成後，它會回報 `connected`。`github_status` 顯示 `secret_present` 和安裝的權限。

在 GitHub 上開啟應用程式設定 → **Advanced** → **Recent deliveries**。開啟最新一次傳遞，確認 SwB 回傳了成功代碼。

## 排解問題

簽章錯誤表示 GitHub 和 SwB 儲存的 webhook 金鑰有差異。請產生新金鑰。將新金鑰填入 GitHub。使用新的領取連結將金鑰儲存到 SwB。

如果 `connect` 要求 **Issues** 寫入權限，請開啟應用程式設定 → **Permissions & events**。把 **Issues** 設為 **Read & write**，並在安裝上接受這項變更。
