`tools/list` 依呼叫者的角色回傳工具。以擁有者身分登入後，可以查看所有已啟用模組的工具。

## 配對金鑰

配對金鑰可在擁有者授權的範圍內呼叫下列工具。

| 用途 | 工具與權限 |
| - | - |
| 訊息 | 可呼叫 `send`、`agent_send` 與 `targets`。用 `inbox`、`wait`、`reply`、`status`、`result`、`cancel` 與 `get_message` 處理金鑰授權範圍內自己的訊息和對話 |
| 記憶與專案 | 在金鑰允許的權限內呼叫 `context_pack` 和 `project_list`。在取得授權的範圍內使用記憶工具 |
| 路由 | 可呼叫 `routes_list` 與 `routes_resolve`。呼叫 `routes_set` 或 `routes_remove` 時，將自己的代理名稱填入 `agent` |
| 設定 | 用 `switchboard_status` 與 `modes_status` 查看狀態。用 `connect` 取得用戶端設定指引。設定模組和發出配對碼需要擁有者身分 |
| 模組 | 在授權範圍內使用模組工具，並執行頻道模式允許的動作 |

呼叫 `login_link`、`connect_code`、`connect_list`、`connect_revoke`、`visibility_list` 與 `visibility_set` 需要擁有者身分。呼叫 `project_create`、`project_update`、`project_sync` 與 `space_mode` 也需要擁有者身分。擁有者還可呼叫 `routine_register`、`routine_add`、`routine_remove`、`discord_provision` 與 `telegram_provision`。

擁有者可用 `auth.key_tools` 限制工具，用 `auth.key_targets` 限制傳送對象。`auth.key_scopes` 限制路由、訊息和對話的存取範圍。記憶工具使用 SwB 為各配對金鑰單獨儲存的授權。

## 訊息

| 工具 | 用途 |
| - | - |
| `send` | 將工作或訊息填入 `task`。用 `to` 指定目標，或留白以使用路由 |
| `agent_send` | 舊版工具。在 `to` 中直接填入代理名稱，例如 `to="codex"`。`blocks.mcp.legacy_aliases` 預設啟用此工具。新的呼叫請使用 `send`，例如 `to="agent:codex"` |
| `wait` | 等待新訊息或回覆 |
| `inbox` | 讀取你的收件匣並立即回傳 |
| `reply` | 將傳送結果或收件匣訊息中的 `handle` 填入 `conversation`。將回覆內容填入 `text` |
| `status` | 顯示單一對話的狀態。查看 Capy 對話時，用 `messages` 指定回傳的近期訊息則數。用 `include_tools=true` 一併查看工具呼叫記錄 |
| `switchboard_status` | 顯示你的登入身分、等待時限、模組與執行個體的運作狀況 |
| `result` | 取得對話的最終回覆。支援 `tail` 的對話可用它指定回傳的近期回覆或訊息則數 |
| `cancel` | 停止追蹤對話 |
| `targets` | 列出 `send` 能連到的所有對象 |
| `get_message` | 用收件匣或 MCP 事件中的 `message_id` 讀取已儲存的訊息 |

### 收件匣游標

游標標記收件匣中的位置。`inbox` 和 `wait` 傳回訊息後，都會更新代理的讀取位置。接著呼叫 `wait` 時，只會收到新訊息。呼叫 `inbox` 時，設定 `since_cursor=0` 可從頭讀取。將上次傳回的 `cursor` 填入 `since_cursor` 可接續讀取。

指令碼可用 bearer 金鑰呼叫 `GET /inbox/poll`，等待自己的收件匣訊息。將上次傳回的 `cursor` 填入 `after` 可接續讀取。預設從收件匣末端開始等待。訊息送達或等待時間結束時，端點會傳回結果。MCP 的讀取位置保持原樣。持續接收訊息時，請使用[收件匣事件串流](/zh-Hant/docs/connect#收件匣事件串流)。

訊息或對話超出配對金鑰的權限時，SwB 會回傳與 ID 查詢失敗時相同的錯誤。請參閱[金鑰限制](/zh-Hant/docs/security#受限金鑰)。

### 傳送選項

| 選項 | 用途 |
| - | - |
| `wait_s` | 如果模組回傳對話 ID，依指定的秒數等待第一則回覆。各用戶端的等待上限各異。代理收件匣使用 `wait` |
| `forward` | 填入收到的對話 ID。對話須允許轉交，且寄件者的信任等級須為 `owner`。SwB 會把最終回覆送給原寄件者 |
| `new_conversation` | 設為 `true` 時，在 Capy Captain 的專案中開啟新討論串。設為 `false` 時，傳送到 Captain 的討論串 |
| `files` | 為 Capy 工作附加檔案。每個檔案填寫 `name`，內容使用 `text` 或 `base64`。用 `media_type` 指定檔案類型 |
| `repos` | 用 `owner/repo` 格式指定 Capy 工作涉及的程式碼庫。請選擇已連結到 SwB 專案的程式碼庫 |
| `in_reply_to` | 回覆訊息時，呼叫 `reply` 並填寫 `conversation`。`send` 會拒絕 `in_reply_to` |

## 記憶與專案

請以擁有者身分登入，或使用已取得該記憶範圍授權的憑證。更新、移動或刪除項目時，請使用最後寫入該項目的金鑰。擁有者可以管理所有項目。只有擁有者能改動 `general` 中已有的項目。

| 工具 | 用法 |
| - | - |
| `context_pack` | 讀取專案簡報。憑證取得 `general` 存取權時，簡報會納入通用記憶。使用配對金鑰時，Capy 區段顯示該代理在對話範圍內的工作 |
| `memory_write` | 將項目儲存到已授權的範圍。填寫 `scope`、`namespace`、`title` 和 `body`。`namespace` 將同一範圍內的項目分類。名稱使用小寫，最多三層，例如 `notes/meetings`。儲存專案記憶時，在 `project` 和 `scope` 指定同一個專案。寫入 `general` 前，先請擁有者確認。接著設定 `confirm_general=true` |
| `memory_search` | 用 `query` 搜尋。填寫 `project` 可搜尋該專案和已授權的 `general` 記憶。設為 `include_general=false` 可只搜尋該專案。用 `scopes` 指定已授權的範圍，例如 `agent:<name>` |
| `memory_list` | 列出項目，範圍參數與 `memory_search` 相同 |
| `memory_read` | 讀取已授權範圍內的一筆記憶和歷史 |
| `memory_delete` | 刪除已授權範圍內的項目 |
| `memory_move` | 將項目移到專案或代理範圍。兩個範圍都須取得授權 |
| `memory_promote` | 將項目移到 `general`。請以擁有者身分登入 |
| `project_list` | 列出專案與它們的連結 |
| `project_create` | 建立專案 |
| `project_update` | 重新命名、連結、封存專案，或把專案設為私人 |
| `project_sync` | 重新把專案連結到它們的對應項目 |

在 `project_update` 的 `links` 中填入下列值。可用的專案連結鍵取決於已設定的代理和模組。

| 鍵 | 值 |
| - | - |
| `repos` | 儲存庫名稱清單，格式為 `owner/repo` |
| `claude_project` | Claude 專案名稱或 ID |
| `chatgpt_project` | ChatGPT 專案名稱或 ID |
| `capy_project` | Capy 專案名稱或 ID |

讀取私人專案需要該專案的單獨授權或擁有者權限。呼叫 `memory_search` 或 `memory_list` 時，將私人專案填入 `project`。如要加入其他已授權的公開專案，請填寫 `scopes`。

## 設定

| 工具 | 用途 |
| - | - |
| `connect` | 取得某個平台的下一個設定步驟 |
| `connect_code` | 為新代理產生配對碼 |
| `connect_list` | 列出代理金鑰 |
| `connect_revoke` | 移除代理金鑰 |
| `companion_code` | 以擁有者身分建立裝置配對碼 |
| `companion_list` | 以擁有者身分查看已配對的裝置和裝置動作 |
| `companion_invoke` | 以擁有者身分在已連線的裝置上執行動作 |
| `companion_revoke` | 以擁有者身分移除已配對的裝置 |
| `login_link` | 為擁有者產生一次性登入連結 |
| `modes_status` | 查看你可以存取的頻道和程式碼庫的模式、目標及設定問題 |
| `space_mode` | 以擁有者身分設定模式、專案與允許的動作。用 `inherit` 清除設定 |
| `visibility_list` | 以擁有者身分查看預設存取規則和各項資源的存取規則 |
| `visibility_set` | 以擁有者身分將資源設為私人或共用。工具一律為私人 |

## 路由

路由為 `send` 選擇目標。請使用支援路由的模組，例如 `capy`、`claude-routine` 或 `grok-routine`。若要直接傳到代理的收件匣，請呼叫 `send` 並指定 `to="agent:<name>"`。傳送訊息給 Muse 時，請指定 `to="agent:muse"`。

| 工具 | 用途 |
| - | - |
| `routes_list` | 列出所有路由，包括信箱路由 |
| `routes_set` | 儲存路由。將代理信箱（例如 `agent:<name>`）或模組位址（例如 `capy:captain:<name>`）填入 `target`。用 `agent` 或 `project` 限定路由的適用範圍 |
| `routes_resolve` | 查看單一目的地符合條件的路由。將名稱填入 `block`，例如 `grok-routine` 或 `agent` |
| `routes_remove` | 依 `agent` 和 `project` 移除指定 `block` 中完全符合條件的路由 |

`routes_resolve` 和 `routes_remove` 預設使用第一個目的地。它是第一個支援路由的模組。只有信箱路由時，它是 `agent`。用 `block` 選擇其他目的地。

## 模組工具

### Capy

| 工具 | 用途 |
| - | - |
| `capy_captains` | 列出目前的 Capy 連線可以存取的 Captain |
| `capy_captain_digest` | 讀取 Captain 的摘要並查看處理中或需要擁有者介入的討論串。此工具需要擁有者身分 |
| `capy_list` | 列出透過 SwB 交付的工作。也能查看 Captain 團隊或已連結 Capy 專案的討論串。使用配對金鑰時，清單只顯示該代理在授權範圍內的工作 |
| `capy_delegate` | 把工作交給 Capy。新呼叫請用 `send` 並指定 `to="capy"` |
| `capy_inbox` | 立即讀取 Capy 收件匣。新呼叫請用 `inbox` 並指定 `block="capy"` |
| `capy_wait` | 等待收件匣收到下一則訊息。新呼叫請用 `wait` |
| `capy_status` | 查看 Capy 討論串的狀態和近期訊息。新呼叫請用 `status` |
| `capy_reply` | 在 Capy 討論串中傳送訊息。新呼叫請用 `reply` |
| `capy_result` | 取得 Capy 討論串的最新回覆和可用的檔案與 Pull request 連結。新呼叫請用 `result` |
| `capy_cancel` | 停止追蹤交給 Capy 的工作。Capy 仍可繼續處理工作。新呼叫請用 `cancel` |

| 工具 | 用途 |

| `routine_register` | 登記 routine，並取得供擁有者輸入權杖的領取連結 |
| `routine_list` | 列出 SwB 可以啟動的 routine |
| `routine_pickup` | 在 routine 的啟動提示為空時，領取待處理的訊息 |
| `routine_add` | 以擁有者身分使用權杖新增 routine |
| `routine_remove` | 以擁有者身分移除透過 SwB 儲存的 routine |

### GitHub

執行 GitHub 對話動作時，將 SwB 對話 ID 填入 `conversation` 或 `handle`。呼叫 `github_reply` 或 `github_notify_owner` 時，將內文填入 `text`。

| 工具 | 用途 |
| - | - |
| `github_status` | 檢查 Webhook、程式碼庫模式與 GitHub App 權限 |
| `github_label` | 為議題或 Pull request 加上現有標籤 |
| `github_comment` | 在議題或 Pull request 新增留言 |
| `github_open_issue` | 在程式碼庫建立議題 |
| `github_link_duplicate` | 將重複議題與同一程式碼庫中的原議題連結。SwB 為重複議題加上 `duplicate` 標籤，並以 `not_planned` 狀態關閉它 |
| `github_notify_owner` | 在擁有者的收件匣留言，附上啟動對話的議題或 Pull request 連結 |
| `github_reply` | 在啟動 SwB 對話的 GitHub 討論串中回覆 |
