SwB 可以只用环境变量运行。MCP 模块默认启用。部分模块会在设置相应变量后启用。其他设置可写入 YAML 文件。

## 实例

| 变量 | 用途 |
| - | - |
| `SWITCHBOARD_KEY_OWNER` | `swb` 命令使用的所有者密钥 |
| `SWITCHBOARD_PUBLIC_URL` | 浏览器登录地址。本机运行时用 `http://localhost:8870`。远程服务器使用 HTTPS，例如 `https://swb.example.com`。 |
| `SWITCHBOARD_DATA_DIR` | 数据目录。镜像使用 `/data`。 |
| `SWITCHBOARD_OWNER_EMAILS` | 用于 OIDC 和 Cloudflare Access 的所有者邮箱，用逗号分隔 |
| `SWITCHBOARD_KEY_<NAME>` | 智能体 `<name>` 的 bearer 密钥 |
| `SWITCHBOARD_CONFIG` | 基础 YAML 文件的路径 |
| `SWITCHBOARD_OVERLAY` | 私有覆盖文件的路径 |
| `PORT` | HTTP 端口。 `swb up` 默认为 `8870`。 |

在终端或实例的 `.env` 文件中设置 `PORT`。本机登录时，公网地址填 `http://localhost:<port>`。也可以在同一个文件中设置 `SWITCHBOARD_PUBLIC_URL` 和 `SWITCHBOARD_DATA_DIR`。YAML 配置中的 `public_url` 优先于环境变量。

用 `swb up --dir ./my-swb` 读取该目录中的 `.env` 和 `config/switchboard.yaml`。运行 `swb init` 时，传入同一个 `--dir`。直接运行 `swb up` 时，可用 `SWITCHBOARD_CONFIG` 指定其他配置文件。

`swb status`、`swb login-link`、`swb connect` 和 `swb claim` 用 `--dir` 查找 `.env`。这四条命令用 `--url` 指定服务器地址。

`swb muse-bridge` 需要 `--url`。用 `--state-dir` 指定存放桥接文件的目录。

在实例目录中运行 `swb export`、`swb log`、`swb blocks` 和 `swb targets`。这些命令读取该目录中的 `.env`。它们使用 `SWITCHBOARD_CONFIG` 指定的文件或本地配置文件。

`swb serve` 读取终端中的环境变量和配置文件。

用 `swb config migrate [file]` 输出第 2 版格式的配置。省略 `file` 时，命令会使用终端中的 `SWITCHBOARD_CONFIG` 或默认配置文件。

## 数据目录

`swb init` 在新实例中创建 `data` 目录。`swb up` 默认使用这个目录。`swb up --dir` 默认使用指定目录下的 `data`。直接运行 `swb up` 并仅用环境变量配置时，默认使用 `~/.local/share/switchboard`。

在配置文件或覆盖文件中设置 `data_dir` 可更改路径。这项设置优先。SwB 接着按顺序检查 `SWITCHBOARD_DATA_DIR` 和 `SWITCHBOARD_DATA`。三项设置都为空时，SwB 使用默认路径。

旧实例已有配置文件且缺少 `data` 目录时，直接运行 `swb up` 会沿用主目录中的现有数据库。SwB 为每个实例记录一次提示。

在 Linux 和 macOS 上，SwB 将数据目录的权限设为 `0700`。数据库文件的权限设为 `0600`。

## 模块

| 模块 | 变量 |
| - | - |
| Capy | `CAPY_API_KEY`，发送另用 `CAPY_API_KEY_SERVICE` 或 `CAPY_API_KEY_AS_<AGENT>` |
| Slack | `SLACK_BOT_TOKEN` 或 `SLACK_USER_TOKEN`、`SLACK_TEAM_ID`，以及用于 Socket Mode 的 `SLACK_APP_TOKEN` |
| Discord | `DISCORD_BOT_TOKEN` |
| Telegram | `TELEGRAM_BOT_TOKEN` |
| GitHub | `GITHUB_WEBHOOK_SECRET` |
| Claude routine | `CLAUDE_ROUTINE_TOKEN` 和 `CLAUDE_ROUTINE_ID` |
| Grok routine | `GROK_ROUTINE_SECRET` 和 `GROK_ROUTINE_URL` |

对已命名的 Slack 工作区，把名称放在 `SLACK_` 之后，例如 `SLACK_SUPPORT_BOT_TOKEN`。已命名的 routine 做法相同，例如 `CLAUDE_ROUTINE_TOKEN_DOCS`。

## 配置文件

```bash
swb init
```

`swb init` 把所有者密钥写入私有文件 `.env`。基础配置存入 `config/switchboard.yaml`。也可以只靠环境变量启动 SwB。

```yaml
version: 2
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
blocks:
  mcp: {use: mcp}
  capy: {use: capy, identity: service}
targets:
  aliases: {}
routes:
  - {match: {}, to: capy:captain:<Captain id>}
```

`blocks` 一节优先决定加载哪些模块。省略 `blocks` 时，SwB 根据环境变量选择模块。

## 覆盖文件

覆盖文件是存放你自己的名称、id 和路径的私有 YAML 文件。把它放在 `config/local.yaml`，或用 `SWITCHBOARD_OVERLAY` 指定它。覆盖文件优先于基础文件，基础文件优先于环境变量。映射会合并。列表会被替换。

键中的 `*` 代表一个名称或列表项。

## 核心设置

| 配置键 | 用途 |
| - | - |
| `version` | YAML 配置格式版本。使用 `blocks` 时设为 `2` |
| `public_url` | SwB 用于 MCP 和 OAuth 的地址。请参见 `SWITCHBOARD_PUBLIC_URL`。 |
| `data_dir` | 数据目录的路径。可在此设置，也可用 `SWITCHBOARD_DATA_DIR` |
| `timezone` | 每日计数和限额所用的时区，默认为 `UTC` |
| `turn_cap` | 会话暂停前的轮数，默认为 `200`。设为 `null` 可关闭上限 |
| `blocks` | 要加载的模块，可用模块类型或自定义名称命名 |
| `agents` | 按名称设置智能体 |
| `agents.*.label` | 智能体的显示名称 |
| `targets` | 发送目标的名称和优先顺序 |
| `targets.aliases` | 将简称指向目标名称或地址 |
| `targets.priority` | 目标重名时的选择顺序，例如 `[capy:captain, agent, project]` |
| `routes` | 初始路由。SwB 保留已设置的路由 |
| `routes.*.match` | 要匹配的智能体或项目。全局路由使用 `{}` |
| `routes.*.to` | 路由匹配时的发送地址 |

## 登录和密钥

| 配置键 | 用途 |
| - | - |
| `auth` | 登录和密钥设置 |
| `auth.owner_emails` | 可通过 OIDC 或 Cloudflare Access 以所有者身份登录的邮箱地址 |
| `auth.cloudflare_access` | Cloudflare Access 登录设置。填写下方两项并设置 `auth.owner_emails` |
| `auth.cloudflare_access.team_domain` | Cloudflare Access 团队域名，也可用 `CLOUDFLARE_ACCESS_TEAM_DOMAIN` 设置 |
| `auth.cloudflare_access.aud` | Access 应用的受众标记，也可用 `CLOUDFLARE_ACCESS_AUD` 设置 |
| `auth.redirect_uris` | 允许的 OAuth 回调地址。此列表替换内置列表。用 `/*` 匹配路径及其子路径 |
| `auth.source_names` | 将 OAuth 主机名或客户端名称的片段映射到登录时所用的智能体名称 |
| `auth.key_scopes` | 按密钥名称设置可访问的记忆范围，例如 `[project:example]` |
| `auth.key_tools` | 按密钥名称设置可调用的 MCP 工具，例如 `[send]` |
| `auth.key_targets` | 按密钥名称设置可接收消息的目标，例如 `[agent:claude]` |
| `auth.inbox_keys` | 为每把密钥指定唯一可读取的智能体收件箱。内置项为 `channel: claude-code` |

## 访问权限

| 配置键 | 用途 |
| - | - |
| `visibility` | 决定谁能访问各项资源。工具始终为私有 |
| `visibility.defaults` | 按资源类型设定默认规则。各类型初始值均为 `private` |
| `visibility.defaults.channel` | 频道的默认规则 |
| `visibility.defaults.memory` | 记忆范围的默认规则 |
| `visibility.defaults.route` | 路由的默认规则 |
| `visibility.defaults.target` | 发送目标的默认规则 |
| `visibility.resources` | 设置单项资源的规则，例如 `channel:home/#agents`。单项规则优先于该类型的默认规则 |

用 `private` 将访问权限限定为所有者及其智能体。用 `shared` 开放访问。填写用户 ID 或 `workspace:home` 这样的条目，即可指定共享对象。通过 `visibility_set` 所作的更改优先于此文件。

## MCP

| 配置键 | 用途 |
| - | - |
| `blocks.mcp` | 为 MCP 客户端提供服务的模块设置 |
| `blocks.mcp.use` | 模块类型，填 `mcp` |
| `blocks.mcp.legacy_aliases` | 保留 `agent_send`、`capy_delegate`、`capy_wait` 和 `capy_reply` 等旧版 MCP 工具名称。默认为 `true` |
| `blocks.mcp.wait` | 等待答复的工具调用时限 |
| `blocks.mcp.wait.default_s` | 调用方省略等待时间时使用的秒数，默认为 `60` |
| `blocks.mcp.wait.max_s` | 最长等待秒数，默认为 `200` |
| `blocks.mcp.wait.agents` | 按智能体设置等待时限。Claude Code 默认等待 `45` 秒，最多 `55` 秒 |
| `blocks.mcp.wait.agents.*.default_s` | 该智能体默认等待的秒数 |
| `blocks.mcp.wait.agents.*.max_s` | 该智能体最长等待的秒数 |

## 记忆和频道模式

| 配置键 | 用途 |
| - | - |
| `memory` | 记忆的 Markdown 副本设置 |
| `memory.mirror` | 控制 Markdown 副本。设为 `false` 可停止更新 |
| `memory.mirror_dir` | 存放 Markdown 副本的目录 |
| `memory.mirror_debounce_s` | 记忆更新后，写入副本前等待的秒数，默认为 `2` |
| `modes` | 设置 SwB 如何处理传入事件 |
| `modes.default` | 默认模式，初始值为 `off` |
| `modes.projects` | 各项目下空间的默认模式 |
| `modes.assist_max_chars` | SwB 为智能体指定的 `assist` 答复字符上限，默认为 `1500` |
| `modes.digest_minutes` | `watch` 模式汇总事件前的等待分钟数，默认为 `60`。累计 `50` 条事件时也会发送摘要 |

## 品牌

```yaml
branding:
  display_name: SwB
  accent_color: "#64748b"
```

| 配置键 | 用途 |
| - | - |
| `branding` | 设置 SwB 显示的名称、图标和颜色 |
| `branding.display_name` | 显示名称，默认为 `SwB` |
| `branding.accent_color` | 主题强调色，格式为 `#RRGGBB` |
| `branding.icon` | 自定义图标 |
| `branding.logo_assets_dir` | 存放自定义标志的目录 |
| `branding.public_identity` | 内部字段。本版本固定为 `swb` |
