`tools/list` 根据调用者的角色返回工具。以所有者身份登录后，可以查看所有已启用模块的工具。

## 配对密钥

配对密钥可在所有者授权的范围内调用下列工具。

| 用途 | 工具和权限 |
| - | - |
| 消息 | 可调用 `send`、`agent_send` 和 `targets`。用 `inbox`、`wait`、`reply`、`status`、`result`、`cancel` 和 `get_message` 处理密钥授权范围内自己的消息和会话 |
| 记忆与项目 | 在密钥允许的权限内调用 `context_pack` 和 `project_list`。在获得授权的范围内使用记忆工具 |
| 路由 | 可调用 `routes_list` 和 `routes_resolve`。调用 `routes_set` 或 `routes_remove` 时，把自己的智能体名称填入 `agent` |
| 设置 | 用 `switchboard_status` 和 `modes_status` 查看状态。用 `connect` 获取客户端设置指引。设置模块和签发配对码需要所有者身份 |
| 模块 | 在授权范围内使用模块工具，并执行频道模式允许的操作 |

调用 `login_link`、`connect_code`、`connect_list`、`connect_revoke`、`visibility_list` 和 `visibility_set` 需要所有者身份。调用 `project_create`、`project_update`、`project_sync` 和 `space_mode` 也需要所有者身份。所有者还可调用 `routine_register`、`routine_add`、`routine_remove`、`discord_provision` 和 `telegram_provision`。

所有者可用 `auth.key_tools` 限制工具，用 `auth.key_targets` 限制发送目标。`auth.key_scopes` 限制路由、消息和会话的访问范围。记忆工具使用 SwB 为各配对密钥单独保存的授权。

## 消息

| 工具 | 用途 |
| - | - |
| `send` | 将任务或消息填入 `task`。用 `to` 指定目标，或留空以使用路由 |
| `agent_send` | 旧版工具。在 `to` 中直接填写智能体名称，例如 `to="codex"`。`blocks.mcp.legacy_aliases` 默认启用此工具。新调用请用 `send`，例如 `to="agent:codex"` |
| `wait` | 等待新消息或回复 |
| `inbox` | 读取你的收件箱并立即返回 |
| `reply` | 将发送结果或收件箱消息中的 `handle` 填入 `conversation`。将回复内容填入 `text` |
| `status` | 显示一个会话的状态。查看 Capy 会话时，用 `messages` 指定返回的近期消息条数。用 `include_tools=true` 一并查看工具调用记录 |
| `switchboard_status` | 显示你的登录身份、等待时限、模块和实例运行状况 |
| `result` | 获取一个会话的最终答复。支持 `tail` 的会话可用它指定返回的近期回复或消息条数 |
| `cancel` | 停止跟踪一个会话 |
| `targets` | 列出 `send` 能访问的所有对象 |
| `get_message` | 用收件箱或 MCP 事件中的 `message_id` 读取已存储的消息 |

### 收件箱游标

游标标记收件箱中的位置。`inbox` 和 `wait` 返回消息后，都会更新智能体的读取位置。之后调用 `wait` 时，只会收到新消息。调用 `inbox` 时，设定 `since_cursor=0` 可从头读取。将上次返回的 `cursor` 填入 `since_cursor` 可接着读取。

脚本可用 bearer 密钥调用 `GET /inbox/poll`，等待自己的收件箱消息。将上次返回的 `cursor` 填入 `after` 可接着读取。默认从收件箱末尾开始等待。消息到达或等待时间结束时，接口会返回。MCP 的读取位置保持原样。持续接收消息时，请使用[收件箱事件流](/zh-Hans/docs/connect#收件箱事件流)。

消息或会话超出配对密钥的权限时，SwB 返回与 ID 查询失败时相同的错误。参见[密钥限制](/zh-Hans/docs/security#有限制的密钥)。

### 发送选项

| 选项 | 用途 |
| - | - |
| `wait_s` | 如果模块返回会话 ID，按指定的秒数等待首条回复。等待上限因客户端而异。智能体收件箱使用 `wait` |
| `forward` | 填入收到的会话 ID。会话须允许转交，且发送方的信任标记须为 `owner`。SwB 会把最终答复交给原发送方 |
| `new_conversation` | 设为 `true` 时，在 Capy Captain 的项目中开启新话题串。设为 `false` 时，发到 Captain 的话题串 |
| `files` | 为 Capy 任务添加附件。每个文件填写 `name`，内容填入 `text` 或 `base64`。用 `media_type` 指定文件类型 |
| `repos` | 用 `owner/repo` 格式指定 Capy 任务涉及的仓库。请选择已关联到 SwB 项目的仓库 |
| `in_reply_to` | 回复消息时，调用 `reply` 并填写 `conversation`。`send` 会拒绝 `in_reply_to` |

## 记忆与项目

请以所有者身份登录，或使用已获该记忆范围授权的凭据。更新、移动或删除条目时，请使用最后写入该条目的密钥。所有者可以管理所有条目。只有所有者能改动 `general` 中已有的条目。

| 工具 | 用法 |
| - | - |
| `context_pack` | 读取项目简报。凭据获得 `general` 访问权限时，简报会包含通用记忆。使用配对密钥时，Capy 部分显示该智能体在会话范围内的工作 |
| `memory_write` | 将条目保存到已获授权的范围。填写 `scope`、`namespace`、`title` 和 `body`。`namespace` 为同一范围内的条目分类。使用小写名称，最多三级，例如 `notes/meetings`。保存项目记忆时，在 `project` 和 `scope` 中指定同一个项目。写入 `general` 前先请所有者确认。然后设置 `confirm_general=true` |
| `memory_search` | 用 `query` 搜索。填写 `project` 可搜索该项目和已获授权的 `general` 记忆。设为 `include_general=false` 可只搜索该项目。用 `scopes` 指定已获授权的范围，例如 `agent:<name>` |
| `memory_list` | 列出条目，范围参数与 `memory_search` 相同 |
| `memory_read` | 读取已获授权范围内的一条记忆及其历史 |
| `memory_delete` | 删除已获授权范围内的条目 |
| `memory_move` | 将条目移到项目或智能体范围。两个范围都需要授权 |
| `memory_promote` | 将条目移入 `general`。请以所有者身份登录 |
| `project_list` | 列出项目及其链接 |
| `project_create` | 创建项目 |
| `project_update` | 重命名、链接、归档项目，或把项目设为私有 |
| `project_sync` | 重新把项目链接到它们的匹配项 |

在 `project_update` 的 `links` 中填写下列值。可用的项目关联键取决于已配置的智能体和模块。

| 键 | 值 |
| - | - |
| `repos` | 仓库名称列表，格式为 `owner/repo` |
| `claude_project` | Claude 项目名称或 ID |
| `chatgpt_project` | ChatGPT 项目名称或 ID |
| `capy_project` | Capy 项目名称或 ID |

读取私有项目需要该项目的单独授权或所有者权限。调用 `memory_search` 或 `memory_list` 时，将私有项目填入 `project`。如需加入其他已获授权的公开项目，请填写 `scopes`。

## 设置

| 工具 | 用途 |
| - | - |
| `connect` | 获取一个平台的下一步设置 |
| `connect_code` | 为新智能体生成配对码 |
| `connect_list` | 列出智能体密钥 |
| `connect_revoke` | 删除一个智能体密钥 |
| `login_link` | 为所有者生成一次性登录链接 |
| `modes_status` | 查看你有权访问的频道和仓库的模式、目标及配置问题 |
| `space_mode` | 以所有者身份设置模式、项目和允许的操作。用 `inherit` 清除设置 |
| `visibility_list` | 以所有者身份查看默认访问规则和各个资源的访问规则 |
| `visibility_set` | 以所有者身份将资源设为私有或共享。工具始终为私有 |

## 路由

路由为 `send` 选择目标。请选择支持路由的模块，例如 `capy`、`claude-routine` 或 `grok-routine`。要直接发到智能体的收件箱，请调用 `send` 并指定 `to="agent:<name>"`。向 Muse 发送消息时，请指定 `to="agent:muse"`。

| 工具 | 用途 |
| - | - |
| `routes_list` | 列出所有路由，包括邮箱路由 |
| `routes_set` | 保存路由。将智能体邮箱（例如 `agent:<name>`）或模块地址（例如 `capy:captain:<name>`）填入 `target`。用 `agent` 或 `project` 限定路由的适用范围 |
| `routes_resolve` | 查看某个目的地匹配的路由。将名称填入 `block`，例如 `grok-routine` 或 `agent` |
| `routes_remove` | 按 `agent` 和 `project` 删除指定 `block` 中完全匹配的路由 |

`routes_resolve` 和 `routes_remove` 默认使用首个目的地。它是首个支持路由的模块。只有邮箱路由时，它是 `agent`。用 `block` 选择其他目的地。

## 模块工具

### Capy

| 工具 | 用途 |
| - | - |
| `capy_captains` | 列出当前 Capy 连接有权访问的 Captain |
| `capy_captain_digest` | 读取 Captain 的摘要并查看正在处理或需要所有者介入的话题串。此工具需要所有者身份 |
| `capy_list` | 列出通过 SwB 发送的任务。也可查看 Captain 团队或已关联 Capy 项目中的话题串。使用配对密钥时，列表只显示该智能体在授权范围内的工作 |
| `capy_delegate` | 将任务发给 Capy。新调用请用 `send` 并指定 `to="capy"` |
| `capy_inbox` | 立即读取 Capy 收件箱。新调用请用 `inbox` 并指定 `block="capy"` |
| `capy_wait` | 等待收件箱中的下一条消息。新调用请用 `wait` |
| `capy_status` | 查看 Capy 话题串的状态和近期消息。新调用请用 `status` |
| `capy_reply` | 向 Capy 话题串发消息。新调用请用 `reply` |
| `capy_result` | 获取 Capy 话题串的最新答复以及可用的文件和拉取请求链接。新调用请用 `result` |
| `capy_cancel` | 停止跟踪发给 Capy 的任务。Capy 仍可继续处理任务。新调用请用 `cancel` |

| 工具 | 用途 |

| `routine_list` | 列出 SwB 可以启动的 routine |
| `routine_pickup` | 在 routine 的启动提示为空时，领取待处理的消息 |
| `routine_add` | 以所有者身份使用令牌添加 routine |
| `routine_remove` | 以所有者身份删除通过 SwB 保存的 routine |

### Slack

| `slack_channels` | 列出所选 Slack 账号可见的频道。结果会标明 SwB 正在关注的频道 |
| `slack_search` | 使用所有者的 Slack 账号搜索工作区中的消息 |
| `slack_history` | 读取频道近期的消息。最新消息排在前面 |
| `slack_thread` | 按时间顺序读取话题串的首条消息及其回复 |
| `slack_watched` | 列出会将新消息送到你的 SwB 收件箱的频道 |
| `slack_events` | 查看关注频道中的近期消息、对机器人的提及和私信。最新消息排在前面 |
| `slack_wait` | 等待你的收件箱收到下一条 Slack 消息 |
| `slack_personas` | 查看机器人发消息时可用的名称和头像以及默认选项 |
| `slack_targets` | 列出在 Slack 提及机器人后可填写的目标名称 |
| `slack_post` | 以机器人或所有者的 Slack 账号发消息。用 `thread_ts` 在话题串中回复。发消息的规则可能要求所有者审批 |

### GitHub

执行 GitHub 会话操作时，将 SwB 会话 ID 填入 `conversation` 或 `handle`。调用 `github_reply` 或 `github_notify_owner` 时，将正文填入 `text`。

| 工具 | 用途 |
| - | - |
| `github_status` | 检查 Webhook、仓库模式和 GitHub App 权限 |
| `github_label` | 给议题或拉取请求添加已有标签 |
| `github_comment` | 在议题或拉取请求下发表评论 |
| `github_open_issue` | 在仓库中创建议题 |
| `github_link_duplicate` | 将重复议题与同一仓库中的原议题关联。SwB 给重复议题添加 `duplicate` 标签，并以 `not_planned` 状态关闭它 |
| `github_notify_owner` | 在所有者的收件箱中留下说明，附上发起会话的议题或拉取请求链接 |
| `github_reply` | 在发起 SwB 会话的 GitHub 话题串中回复 |
