## Docker Compose

以拥有数据目录的用户身份运行这些命令。

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

请在五分钟内打开终端显示的一次性登录链接。

所有者在浏览器中通过 `http://localhost:8870` 登录。容器内的命令使用 `8000` 端口。Compose 将数据保存在 `./data`。修改 `.env` 后，再次运行 `docker compose up -d`。

运行 `docker compose exec switchboard swb login-link` 获取 `http://localhost:8870` 的登录链接。

退出登录后，`/healthz` 只返回 `status` 和 `version` 两个字段。以所有者身份登录或使用所有者密钥，即可查看完整的运行状态。

## Cloudflare Tunnel [#cloudflare-tunnel]

Cloudflare 隧道为 SwB 提供公网 HTTPS 地址。Cloudflare 的免费套餐包含隧道服务。

### 临时隧道

用快速隧道的临时地址试用 SwB。`cloudflared` 是把 SwB 接入 Cloudflare 的程序。在 SwB 主机上运行此命令。

```bash
cloudflared tunnel --url http://localhost:8870
```

将 `SWB_PUBLIC_URL` 设为终端显示的 HTTPS 地址。如果配置文件含有 `public_url`，也更新该配置项。重启 SwB。每次启动隧道时，地址都会改变。OAuth 登录和通行密钥都绑定到该地址。使用命名隧道可保留固定地址。

### 命名隧道

使用免费 Cloudflare 账号和自己的域名。按 [Cloudflare 设置指南](/zh-Hans/docs/setup/cloudflare) 创建隧道并配置 Access。将 `SWB_PUBLIC_URL` 设为公网地址，例如 `https://swb.example.com`。如果配置文件含有 `public_url`，也更新该配置项。

若隧道运行在 SwB 主机上，将服务地址设为 `http://localhost:8870`。将 `SWB_TRUSTED_PROXIES` 设为连接器的地址。IPv4 环回连接可用 `127.0.0.1/32`。

若使用 Compose 隧道，将服务地址设为 `http://switchboard:8000`。把隧道令牌作为 `TUNNEL_TOKEN` 写入 `.env`。将连接器的地址或专用网段添加到 `trusted_proxies`。用隧道配置启动 Compose。

```bash
docker compose --profile tunnel up -d
```

## 受信任的代理

反向代理把请求转发给 SwB。在 `config/switchboard.yaml` 的 `trusted_proxies` 中添加代理的地址或专用网段。用 CIDR 格式填写地址范围。

也可以在 `.env` 中设置 `SWB_TRUSTED_PROXIES`。用逗号分隔各项。SwB 优先使用 YAML 中的设置。

如果 Cloudflare 隧道和 SwB 共用主机或 Docker 网络，请添加隧道连接器的地址或专用网段。连接器直接连接 SwB。如果 Cloudflare 边缘服务器直接连接 SwB，请添加 `cloudflare`。

## Cloudflare Access

参照 [Cloudflare 设置指南](/zh-Hans/docs/setup/cloudflare) 配置所有者策略和放行策略。

| 路径 | 策略 |
| --- | --- |
| `/mcp`、`/register`、`/token`、`/revoke`、`/.well-known/*` | 放行 |
| `/healthz`、`/connect`、`/avatars/*` | 放行 |
| `/inbox/poll`、`/inbox/events` | 放行 |
| `/github/webhook` | 为 GitHub 放行 |
| 其余路径，包括 `/`、`/authorize`、`/inbox` 和会话页面 | 所有者 |

从所有者应用取得 `CLOUDFLARE_ACCESS_TEAM_DOMAIN` 和 `CLOUDFLARE_ACCESS_AUD`。SwB 会对放行路径上的请求执行相应检查。

## Fly.io [#fly]

使用 [SwB 发布分支的本地副本](#docker-compose)。安装 [Fly.io 命令行工具](https://docs.fly.io/flyctl/)并登录。

在 SwB 文件夹中运行 `sh deploy/fly.sh my-swb`。将 `my-swb` 换成唯一的应用名。脚本用 `fly deploy --ha=false` 启动一台虚拟机。

打开本地副本中的 `.env.swb-setup-fly-my-swb`。用 `SWB_SETUP_CODE` 登录。

在 [Fly.io 免费套餐](https://docs.fly.io/about/free-plan)中添加银行卡后，每月有 5 美元的用量额度。绑卡前，账户有 1 美元的初始额度，有效期为 7 天。

在阿什本（`iad`），一台内存为 512 MB 的 `shared-cpu-1x` 虚拟机每月费用为 3.69 美元。1 GB 存储卷每月费用为 0.15 美元。

用量费用超过 5 美元时，Fly.io 将组织切换到按量付费。Fly.io 按[标准费率](https://fly.io/docs/about/pricing/)收取当月的全部费用。

## 备份与升级

所有状态都在数据目录中。升级前先备份。请把 `mcp-events.key` 和 `claim-key` 与数据库放在一起，因为它们加密已存储的密钥。升级时，安装新版本并启动 SwB。数据库变更只会增加表和列。

## 导出记忆

```bash
swb export /data/export
```

导出会为每个范围写出一个 Markdown 文件夹，并写出一个 `INDEX.md`。设置 `memory.mirror_dir`，可在一个文件夹中保留实时副本。
