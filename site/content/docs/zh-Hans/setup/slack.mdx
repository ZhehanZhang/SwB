title: Slack

SwB 通过一个 Slack 应用读取和发送 Slack 消息。你用清单创建这个应用。清单是一个文件，里面写好了应用的全部设置。

这个应用使用 Socket Mode。Socket Mode 是 SwB 主动向 Slack 建立的连接，所以 SwB 服务器可以留在私有地址上。

## 开始之前

你需要目标工作区中的 Slack 账号，并且有权在该工作区创建和安装应用。在 Enterprise Grid 组织中，应用需要 Org Owner 或 Org Admin 批准。你还需要以所有者身份登录 SwB 服务器，例如 `https://swb.example.com`。

<Steps>

选择你的工作区。点击 **Next**。

<Step>

<Step>
### 创建应用

点击 **Next** → **Create**。
</Step>
<Step>
### 创建应用级令牌

如果 Slack 要求批准，请把应用交给 Org Owner。Org Owner 在 **Organization settings** → **Integrations** → **Manage Apps** → **Approve an app** 中批准它。
</Step>

## 应用清单

### 机器人和你的账号

```yaml
# Example Slack app for an agent-to-agent workspace: a bot user and the owner's user token.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
# The bot's @handle and member-list profile come from features.bot_user.display_name and the
# app icon; they do not change per message. Per-message name/avatar = personas (chat:write.customize).
display_information:
  name: Switchboard
  description: Agent switchboard for the owner's assistants
  background_color: "#1d2733"
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: switchboard
    always_online: true
oauth_config:
  scopes:
    bot:
      - app_mentions:read      # @mentions -> push kind "mention"
      - channels:history       # watched public channels the bot is in
      - channels:read
      - groups:history         # watched private channels the bot is in
      - groups:read
      - im:history             # DMs to the bot -> push kind "dm"
      - im:read
      - im:write               # approval DMs to the owner
      - chat:write
      - chat:write.customize   # personas: per-message username + icon
      - reactions:write        # ack reaction on mentions/DMs
      - users:read             # names in pushed events
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # posts as the owner (policy-gated)
      - reactions:write
      - search:read            # search_messages
      - users:read
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.channels
      - message.groups
      - message.im
  interactivity:
    is_enabled: true           # Approve/Reject buttons, delivered over Socket Mode
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

### 只用你的账号

```yaml
# Example Slack app for a user-only workspace. No bot user, bot scopes, bot events, or interactivity.
# It never joins or invites; every post appears as the owner.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
display_information:
  name: Switchboard (personal)
  description: Lets the owner's agents read on their behalf; writes need approval
  background_color: "#333333"
oauth_config:
  scopes:
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # only ever used after the owner approves a request
      - reactions:write        # same
      - search:read
      - users:read
settings:
  event_subscriptions:
    user_events:
      - message.channels
      - message.groups
      - message.im
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

## 智能体的工作

智能体调用 `connect`，参数为 `what="slack"`。SwB 列出每个工作区还缺哪些令牌，并返回一个领取链接，一次收齐这些令牌。

智能体把工作区写入 `config/switchboard.yaml` 的 `blocks.slack.workspaces`，包括 `team_id` 和令牌名称。如果智能体能访问服务器，它会直接修改。否则它把 YAML 交给你添加。

此示例用机器人和你的账号连接一个工作区。把 `T0DEMO0001` 换成你的工作区 ID。

```yaml
blocks:
  slack:
    use: slack
    enabled: true
    workspaces:
      example:
        team_id: T0DEMO0001
        app_token_env: SLACK_EXAMPLE_APP_TOKEN
        identities:
          bot:
            token_env: SLACK_EXAMPLE_BOT_TOKEN
          user:
            token_env: SLACK_EXAMPLE_USER_TOKEN
```

如果只用你的账号，在 `team_id` 同级添加 `user_only: true`。删除 `identities` 下的 `bot` 项。

SwB 要求重启时，智能体会告诉你。重启后，它用 `slack_workspaces` 检查每个身份。身份指机器人或你自己的账号。最后，它用 `slack_post` 发送一条测试消息。

## 凭据

| 令牌 | Slack 显示位置 | 格式 | 填写位置 |
| --- | --- | --- | --- |
| 应用级令牌 | **Basic Information** → **App-Level Tokens** | 以 `xapp-` 开头 | SwB 领取链接 |
| 机器人令牌 | **OAuth & Permissions** → **OAuth Tokens** → **Bot User OAuth Token** | 以 `xoxb-` 开头 | SwB 领取链接 |
| 用户令牌 | **OAuth & Permissions** → **OAuth Tokens** → **User OAuth Token** | 以 `xoxp-` 开头 | SwB 领取链接 |

工作区 ID 和频道 ID 只是 Slack 中位置的名称，可以放心写进配置文件。

## 检查连接

请智能体再次调用 `connect`。设置完成后，它会报告 `connected`。`slack_workspaces` 中每个身份显示 `ready`，Socket Mode 显示 `connected`。

在频道中提及机器人，并写上目标名称。智能体用 `slack_events` 或 `slack_wait` 可以看到这条消息。

## 解决问题

如果 SwB 报告 Socket Mode 有问题，请在应用设置中打开 **Socket Mode**。打开 **Enable Socket Mode**。

如果你修改了应用的权限范围，请重新安装应用。然后通过新的领取链接保存新令牌。

`slack_search` 用你自己的账号搜索。它需要带有 `search:read` 权限范围的用户令牌。
