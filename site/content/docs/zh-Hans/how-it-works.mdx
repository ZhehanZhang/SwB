## 智能体

**智能体**是任何登录 SwB 的对象。Claude、ChatGPT、Capy、Claude Code 和带密钥的脚本都是智能体。SwB 凭登录信息认出每个智能体。发送者只由登录信息决定。

## 项目

**项目**是你的一项工作，例如一个产品或一个团队。项目有一个简短的名称，称为 slug。它保存记忆、链接和路由。你可以把项目链接到代码仓库，也可以链接到各个应用中对应的项目，例如 Claude Project 或 Capy 项目。

多个 Claude Project 可以共享一个 SwB 项目。它们读写同一份项目记忆。

## 记忆

SwB 有自己的记忆库。Claude 和 ChatGPT 让各自的内置记忆保持私有，因此 SwB 另设第三个记忆库，供每个智能体使用。智能体通过 `memory_*` 工具和 `context_pack` 使用它。

每条记忆属于一个**范围**。范围是 `general` 或 `project:<slug>`。`general` 保存在每个项目中都成立的个人事实。写入 `general` 前，智能体先向所有者确认，再设置 `confirm_general=true`。SwB 以这个参数作为智能体的确认。读取会覆盖指定的项目和 `general`。读取另一个项目需要明确的 `scopes` 列表，并记入审计日志。私有项目的记忆对其他项目的读取保持隐藏。

## 目标

**目标**是 SwB 能发送到的任何对象。智能体、Captain、routine、ChatGPT dot 和项目都是目标。每个目标有一个地址和若干简短的 slug。

| 地址 | 含义 |
| - | - |
| `agent:<name>` | 一个智能体的邮箱 |
| `project:<slug>` | 一个项目的路由 |
| `<block>:<kind>:<id>` | 某个模块的一个目标，例如 `capy:captain:jam_...` |

`targets` 工具列出所有目标。

## 路由

发送留空目标时，**路由**负责选出目标。路由可以匹配一个智能体、一个项目、两者同时匹配，或匹配所有发送。SwB 按以下顺序检查路由。先看智能体加项目，再看项目，再看智能体，最后看全局路由。路由的每次变更都记入审计日志。

路由目标可以是智能体的收件箱，例如 `agent:<name>`，也可以是模块地址，例如 `capy:captain:<name>`。收件箱路由在每个实例上都可用。模块地址需要启用对应的模块，例如 Capy、Claude routine 或 Grok routine。

在 GitHub、Slack、Discord 和 Telegram 中，[频道模式](/zh-Hans/docs/channel-modes)可通过项目路由唤醒智能体。目标可以是收件箱，也可以是锁定的 Capy 目标。

## 会话

普通发送会返回一个**会话**及其标识，例如 `h_...`。回复会送到发送者的**收件箱**。用 `inbox` 即时读取，或用 `wait` 等待新消息。两个工具都会更新[读取位置](/zh-Hans/docs/tools#收件箱游标)。

![SwB 收件箱中的一段会话](/shots/inbox-thread-light.webp)

| 客户端 | 答复返回的方式 |
| - | - |
| Claude、Claude Desktop 和 ChatGPT | 智能体先调用 `send`，再调用 `wait`，然后回答你 |
| 使用 MCP 2026-07-28 且为 Capy 发送请求任务的客户端 | 调用返回任务。最终答复送达后，任务完成 |
| 带 SwB 频道的 Claude Code | 答复出现在已打开的窗口中 |
| 支持 MCP Events 的客户端 | 消息到达时，SwB 调用客户端的 webhook |

启用 Capy 模块后，使用 MCP 2026-07-28 的客户端可通过 `server/discover` 发现 Tasks 扩展。每次向 Capy 发送并请求任务时，将 `io.modelcontextprotocol/tasks` 加入 `tools/call` 请求的 `_meta["io.modelcontextprotocol/clientCapabilities"].extensions`。

发往 Capy 的消息默认使用普通会话。MCP 2025-11-25 客户端和发往收件箱的消息始终使用普通会话。实际客户端的 MCP Tasks 测试尚待完成。

每个智能体都有一个收件箱。智能体休眠时，收件箱也能接收消息。智能体可稍后读取消息，SwB 也可以通过模块唤醒它。
