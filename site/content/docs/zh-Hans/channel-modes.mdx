title: 频道模式
description: 设置 SwB 在各频道中的行为。
---

**空间**是接收消息的地方。Slack 频道、Discord 频道和话题串、Telegram 群组及 GitHub 仓库都是空间。

| 模式 | SwB 的行为 |
| - | - |
| `off` | 丢弃其他人发来的消息 |
| `watch` | 收集消息并汇总成摘要 |
| `assist` | 唤醒智能体，让它参考上下文并在原话题串回复 |
| `triage` | 唤醒分流智能体。默认操作是在原话题串回复 |
| `work` | 处理所有者发来的消息 |

在 Slack、Discord 和 Telegram 中，所有者的提及和私信始终按 `work` 处理。频道和目标的访问范围由可见性设置决定。

## 设置模式

可在 SwB 页面或 YAML 中设置模式。所有者也可调用 `space_mode`，指定模式、项目和允许的操作。

SwB 先查找已保存的设置，再查找频道和空间设置。接着查找模块的旧版设置、项目模式和 `modes.default`。默认模式为 `off`。

## 绑定目标

在 GitHub、Slack、Discord 和 Telegram 中，`assist`、`triage` 和 `work` 模式可以通过项目路由唤醒智能体。SwB 按以下顺序选择第一个适用的目标。

| 顺序 | 目标 |
| - | - |
| 首先 | YAML 中的 `target`。依次查看频道、空间和项目的模式设置 |
| 其次 | 在 `triage` 模式下，选用名为 `claude-<project>-triage` 的可用目标，例如 Claude 例程 |
| 再次 | 空间设置中的 `default_target` 或 `target` |
| 最后 | 项目路由 |

调用 `routes_set` 时指定项目简称和目标地址。在模式设置中将 `project` 设为同一项目。以下示例使用已有的 GitHub 空间、项目和已配对的智能体。

```python
routes_set(project="app", target="agent:alpha")
space_mode(block="github", space="example-org/app", mode="triage", project="app")
```

若要启用协助模式，请改用 `mode="assist"`。若要使用锁定的 Capy 路由，请指定 `capy:captain:<name>` 这样的目标，并保留 `allow_override=false`。共享空间和目标，即可让其他人访问该智能体。

## 分流操作

分流智能体可以读取上下文。默认操作是在原话题串中执行 `reply`。在 GitHub 话题串中，请使用 `github_reply`。

要开放更多操作，请在 `space_mode` 或 YAML 中设置 `actions`。将 `reply` 加入列表可保留回复功能，例如 `actions=["reply", "notify_owner"]`。

| 操作 | 用途 |
| - | - |
| `label` | 为 GitHub 议题或拉取请求添加标签 |
| `comment` | 在 GitHub 上添加评论 |
| `open_issue` | 创建 GitHub 议题 |
| `link_duplicate` | 关联并关闭重复的 GitHub 议题 |
| `notify_owner` | 给所有者发一条说明 |

修改 GitHub 内容需要具有写入权限的 GitHub 凭据。SwB 将分流操作记入审计日志。

## 检查消息投递

调用 `modes_status` 查看模式、目标、操作和配置问题。分流需要指定目标时，`space_mode` 和 `modes_status` 都会提示选择分流智能体。

SwB 会记录每个被丢弃的 GitHub webhook 的原因。打开 **Audit** 或运行 `swb log` 查看原因。
