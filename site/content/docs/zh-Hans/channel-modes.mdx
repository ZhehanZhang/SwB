**空间**是接收消息的地方。Slack 频道、Discord 频道和话题串、Telegram 群组及 GitHub 仓库都是空间。

| 模式 | SwB 的行为 |
| - | - |
| `off` | 丢弃其他人发来的消息 |
| `watch` | 收集消息并汇总成摘要 |
| `assist` | 唤醒智能体，让它参考上下文并在原话题串回复 |
| `triage` | 唤醒分流智能体。默认操作是在原话题串回复 |
| `work` | 处理所有者发来的消息 |

在 Slack、Discord 和 Telegram 中，所有者的提及和私信始终按 `work` 处理。频道和目标的访问范围由可见性设置决定。

要使用 GitHub 的 `work` 模式，请把你的 GitHub 用户 ID 加入空间的[所有者列表](/zh-Hans/docs/blocks/github#所有者账号)。

## 设置模式

在连接或项目页面的 **Modes** 中设置模式。也可以在 YAML 中设置。所有者可以用 `space_mode` 指定模式、目标、项目和允许的操作。

SwB 先查找已保存的设置，再查找频道和空间设置。接着查找模块的旧版设置、项目模式和 `modes.default`。默认模式为 `off`。

## 绑定目标

在 GitHub、Slack、Discord 和 Telegram 中，`assist`、`triage` 和 `work` 模式可以通过项目路由唤醒智能体。SwB 按以下顺序选择第一个适用的目标。

| 顺序 | 目标 |
| - | - |
| 首先 | 通过 `space_mode` 保存的设置中的目标。频道设置会整体替代空间设置 |
| 其次 | YAML 中的 `target`。依次查看频道、空间和项目的模式设置 |
| 其次 | 在 `triage` 模式下，选用名为 `claude-<project>-triage` 的可用目标，例如 Claude routine |
| 再次 | 空间设置中的 `default_target` 或 `target` |
| 最后 | 项目路由 |

从 `targets` 返回的列表中选择目标。以下示例将智能体邮箱绑定到已有的 GitHub 空间。

```python
space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")
```

使用 `mode="assist"` 可切换到协助模式。省略 `target` 可保留绑定。设为 `target=""` 可清除绑定。

调用 `routes_set` 为关联项目指定备用目标地址。若要锁定 Capy 路由，请使用 `capy:captain:<name>` 这样的目标，并保留 `allow_override=false`。

## 允许外部 GitHub 用户访问

调用 `visibility_list` 查看准确的资源名称。`visibility_set` 只接受列表中的名称。`agent:beta` 是邮箱地址。`target:beta` 控制谁能访问该邮箱。

```python
visibility_set(resource="channel:github/acme/app", visibility="shared")
visibility_set(resource="target:beta", visibility="shared")
```

如果只允许一位发送者访问，请为两项资源填写同一个已验证的用户 ID，例如 `visibility=["github:1234"]`。

## 查看观察摘要

用 `modes.digest_minutes` 设置间隔。默认间隔为 60 分钟。间隔结束或累积到 50 个事件时，SwB 将摘要送入目标邮箱。所有者邮箱是备用收件处。

所有者可以在控制台的 **Inbox** 中查看所有摘要，也可以调用 MCP 工具 `inbox` 或 `wait`。摘要列出事件总数、各事件的作者和节选，以及可用的链接。摘要的信任等级为 `external`。

观察模式让智能体保持休眠。摘要仅供收件箱查询。已配置的 GitHub 接收端仍会收到各个事件的副本。

## 分流操作

分流智能体可以读取上下文。默认操作是在原话题串中执行 `reply`。在 GitHub 话题串中，请使用 `github_reply`。在 `handle` 中填入会话 ID。在 `text` 中填入回复内容。

要开放更多操作，请在 `space_mode` 或 YAML 中设置 `actions`。将 `reply` 加入列表可保留回复功能，例如 `actions=["reply", "notify_owner"]`。

| 操作 | 用途 |
| - | - |
| `label` | 为 GitHub 议题或拉取请求添加标签 |
| `comment` | 在 GitHub 上添加评论 |
| `open_issue` | 创建 GitHub 议题 |
| `link_duplicate` | 关联并关闭重复的 GitHub 议题 |
| `notify_owner` | 给所有者发一条说明 |

修改 GitHub 内容需要具有写入权限的 GitHub 凭据。SwB 将分流操作记入审计日志。

## 检查消息投递

调用 `modes_status` 查看模式、已绑定的目标、操作和配置问题。控制台的模式一栏显示已绑定的智能体。分流模式启用备用目标时才会提示使用默认智能体。分流需要指定目标时，`space_mode` 和 `modes_status` 都会提示选择分流智能体。

SwB 会在审计日志中记录 Slack、Discord 和 Telegram 事件被丢弃的原因。同一模块、空间、频道和原因的组合每 10 分钟最多记一条。

SwB 也会记录丢弃 GitHub webhook 的原因。打开 **Audit** 或运行 `swb log` 查看原因。
