title: 메모리

---

**메모리**는 에이전트가 SwB을 통해 함께 쓰는 노트 모음입니다. 노트 하나가 **항목** 하나입니다. 항목에는 제목, Markdown 본문, 모든 변경의 기록이 있습니다.

## 범위

**범위**는 같은 접근 규칙을 따르는 항목의 묶음입니다. 각 항목은 범위 하나에 속합니다.

| 범위 | 폴더 | 용도 |
| --- | --- | --- |
| `general` | `/memories/general/` | 모든 프로젝트에 적용되는 사용자 정보 |
| `project:<slug>` | `/memories/projects/<slug>/` | 프로젝트 하나에 대한 정보 |
| `agent:<name>` | `/memories/agents/<name>/` | 에이전트 하나의 비공개 노트 |

소유자로 로그인한 에이전트는 모든 범위를 읽을 수 있습니다. 페어링 키는 사용자가 권한을 준 범위만 읽고 씁니다. 페어링 키는 항상 자기 에이전트 범위를 받습니다.

## 파일과 폴더

에이전트에게 메모리는 `/memories` 아래의 파일로 보입니다. 범위 안의 폴더는 **주제**입니다. `decisions`와 `notes/meetings`가 그 예입니다. 파일 이름이 항목의 키입니다.

이 도구들은 Claude 메모리 도구와 같은 명령을 씁니다. Claude 모델은 이 명령을 이미 알고 있습니다.

| 도구 | 용도 |
| --- | --- |
| `memory_summary` | 세션을 시작할 때 메모리의 짧은 색인을 불러옵니다 |
| `memory_view` | 폴더를 보여 주거나, 파일을 줄 번호와 함께 보여 줍니다 |
| `memory_create` | 파일을 만듭니다 |
| `memory_str_replace` | 파일에서 정확히 일치하는 구절 하나를 바꿉니다 |
| `memory_insert` | 줄 뒤에 텍스트를 추가합니다 |
| `memory_rename` | 파일을 새 이름, 주제, 범위로 옮깁니다 |
| `memory_delete` | 파일을 제거합니다 |
| `memory_search` | 단어로 항목을 찾고, 가장 잘 맞는 항목을 먼저 보여 줍니다 |
| `memory_list` | 항목을 최신순으로 보여 줍니다 |
| `memory_history` | 항목의 변경 내용을 모두 보여 줍니다 |
| `memory_restore` | 항목을 이전 버전으로 되돌립니다 |

이전 도구인 `memory_write`, `memory_read`, `memory_move`, `memory_promote`도 계속 사용할 수 있습니다.

SwB은 범위마다 같은 사실을 한 번만 저장합니다. 에이전트가 같은 텍스트를 다시 저장하면 기존 항목을 받습니다.

## 메모리 동기화

**메모리 동기화**는 에이전트가 자기 메모리에 저장한 내용을 SwB에 복사합니다. 그러면 모든 에이전트가 그 내용을 쓸 수 있습니다. Claude, ChatGPT, Grok, Muse, Claude Code와 그 밖의 메모리 시스템에서 동작합니다. Muse는 `muse-memory`를 출처로 사용합니다.

각 설정 프롬프트는 에이전트에게 동기화를 요청합니다. 설정이 끝나면 에이전트는 사용자에 대해 기억하는 내용을 `memory_sync`로 보냅니다. 모든 에이전트가 알아야 할 사실만 보냅니다. 비밀번호, 키, 민감한 개인 정보는 자기 메모리에 둡니다. 그 뒤로 에이전트는 새 기억을 같은 응답 안에서 동기화합니다.

`memory_sync`는 여러 번 실행해도 안전합니다. 매번 같은 항목을 업데이트합니다. SwB에서 사용자가 한 편집과 삭제가 우선합니다. 나중에 동기화해도 사용자의 버전이 남고, 에이전트에게 충돌을 알립니다.

`--cap hooks`를 켠 [컴패니언](/ko/docs/companion)은 Claude Code 메모리 파일을 저장할 때마다 동기화합니다.

SwB은 세션 폴더 이름으로 범위를 고릅니다. 먼저 짧은 이름인 slug가 같은 프로젝트를 찾습니다. 그다음 연결된 저장소 이름이 하나로 일치하는 프로젝트를 찾습니다. 일치하는 프로젝트의 `private` 설정이 `false`이면 SwB은 그 프로젝트로 동기화합니다. 비공개 프로젝트와 일치하면 동기화를 건너뜁니다. 그 밖의 폴더는 `agent:claude-code`로 동기화합니다.

메모리 동기화는 기본으로 켜져 있습니다. 끄려면 콘솔에서 **Memory**를 열고 **Memory sync**를 끄세요. 소유자로 로그인한 에이전트는 `memory_settings`로 같은 스위치를 바꿀 수 있습니다.

## 출처

**출처**는 누가 언제 항목을 썼는지에 대한 기록입니다. SwB은 항목을 만든 에이전트와 마지막으로 바꾼 에이전트를 기록합니다.

SwB은 에이전트가 쓴 텍스트를 다른 에이전트에게 줄 때 표시를 붙입니다. 표시에는 작성자와 날짜가 들어 있습니다. 에이전트는 표시된 텍스트를 정보로만 씁니다. 에이전트는 사용자의 지시만 따릅니다.

## 메모리 관리

콘솔에서 **Memory**를 열면 모든 항목을 볼 수 있습니다. 항목을 선택하면 편집할 수 있습니다. **History**를 선택하면 모든 변경 내용을 볼 수 있습니다. 변경 내용에서 **Restore**를 선택하면 그 버전으로 되돌립니다. 항목을 옮기거나 삭제할 수도 있습니다.

에이전트가 바꾼 내용은 모두 **History**와 감사 로그에 나옵니다. 모든 변경 내용을 되돌릴 수 있습니다.

## 다운로드와 복원

**Memory** 페이지에서 **Download**를 선택하면 메모리 전체를 zip 파일로 저장합니다. 이 파일에는 항목마다 Markdown 파일이 하나씩 범위별, 주제별 폴더로 들어 있습니다. 각 항목의 기록과 출처를 담은 `manifest.json`도 들어 있습니다.

**Restore from file**을 선택하면 zip 파일을 불러옵니다. 복원은 빠진 항목을 추가하고 기존 항목을 그대로 둡니다. SwB은 가져온 텍스트를 정보로 표시하고 가져온 사람을 기록합니다.

소유자로 로그인한 에이전트는 같은 작업에 `memory_export`와 `memory_import`를 쓸 수 있습니다.

바뀐 항목을 교체하고 이전 버전을 기록에 남기려면 `overwrite`를 `true`로 설정하세요. 해당하는 항목의 소유자 신뢰를 유지하려면 `trust_owner`를 `true`로 설정하세요. 다른 에이전트 범위의 항목은 계속 정보로 표시됩니다. 두 옵션의 기본값은 `false`입니다. 콘솔 업로드 `POST /api/memory/import`에는 이 옵션을 쿼리 매개변수로 넘기세요.

## Git에 백업

SwB은 사용자가 소유한 비공개 Git 저장소에 메모리를 복사할 수 있습니다. 커밋은 변경 내용 묶음을 기록합니다. SwB은 `2 memory changes by SwB, claude-code` 같은 제목을 씁니다. 콘솔에서 한 변경에는 제목에 `SwB`을 씁니다.

메모리의 모든 내용이 이 저장소로 갑니다. 비공개 저장소를 사용하세요.

백업 저장소의 푸시 권한은 신뢰하는 사람에게만 주세요. 푸시 권한이 있는 사람은 커밋 작성자를 정할 수 있고, SwB은 그 작성자로 신뢰 수준을 고릅니다.

콘솔에서 **Memory**를 여세요. **Git backup**에 HTTPS 또는 SSH 저장소 주소와 브랜치를 입력하세요. HTTPS 주소에는 그 저장소에 쓰기 권한이 있는 토큰을 붙여 넣으세요. SSH 주소에는 쓰기 권한이 있는 배포 키를 붙여 넣으세요. SwB은 토큰이나 키를 암호화해서 보관합니다.

`file://` 주소는 HTTPS 또는 SSH 주소로 바꾸세요.

기본 백업 작성자는 `SwB <swb@localhost>`입니다. 바꾸려면 콘솔에서 **Author name**과 **Author email**을 사용하세요. `memory_backup_configure`에서는 `author_name`과 `author_email`을 사용하세요.

SwB은 변경 후 30초를 기다린 뒤, 그동안의 변경 내용을 커밋 하나로 만듭니다. 바로 커밋하려면 **Back up now**를 선택하세요. 푸시가 실패하면 SwB이 나중에 다시 시도합니다. 상태 줄에 마지막 백업과 마지막 오류가 나옵니다.

**Restore from repository**를 선택하면 최신 커밋에서 메모리를 불러옵니다. SwB은 가져온 텍스트를 정보로 표시하고 가져온 사람을 기록합니다.

소유자로 로그인한 에이전트는 `memory_backup_configure`, `memory_backup_status`, `memory_backup_now`, `memory_backup_restore`를 쓸 수 있습니다. `memory_backup_configure`는 토큰이나 키를 위한 등록 링크를 돌려줍니다.

Git 복원에도 같은 `overwrite`와 `trust_owner` 옵션을 씁니다. 콘솔 엔드포인트 `POST /api/memory/backup/restore`에는 이 옵션을 JSON 필드로 넘기세요. SwB은 다른 작성자의 커밋에서 온 내용을 외부 정보로 표시합니다.
