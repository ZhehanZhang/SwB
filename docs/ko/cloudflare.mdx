Cloudflare Tunnel은 SwB에 공개 HTTPS 주소를 줍니다. **터널**은 서버를 Cloudflare에 연결합니다. Cloudflare는 무료 플랜에서 터널을 제공합니다.

[Docker Compose](/ko/docs/deploy#docker-compose)를 따라 SwB을 시작하세요.

<span id="임시-터널" />

## 임시 터널 [#quick-tunnel]

임시 주소가 필요하면 임시 터널을 사용하세요. SwB 서버에 [cloudflared](https://developers.cloudflare.com/tunnel/downloads/)를 설치하세요. 이 프로그램은 SwB을 Cloudflare에 연결합니다. 서버에서 이 명령을 실행하세요.

```sh
cloudflared tunnel --url http://localhost:8870
```

`.env`의 `SWB_PUBLIC_URL`을 터미널에 나온 HTTPS 주소로 설정하세요. 설정 파일에 `public_url`이 있으면 같은 주소로 업데이트하세요. 커넥터를 [신뢰할 수 있는 프록시](#trusted-proxies)에 추가하세요. 설정을 적용하려면 `docker compose up -d`를 실행하세요.

터널을 시작할 때마다 주소가 바뀝니다. OAuth 로그인과 패스키는 이 주소를 사용합니다. 고정 주소가 필요하면 이름 있는 터널을 사용하세요.

<span id="이름-있는-터널" />

## 이름 있는 터널 [#named-tunnel]

내 도메인에서 고정 주소를 쓰려면 이름 있는 터널을 사용하세요.

### 시작하기 전에

내 도메인의 터널과 Access 애플리케이션을 관리할 수 있는 Cloudflare 계정을 사용하세요. 서버가 7844번 포트로 Cloudflare에 연결할 수 있게 허용하세요.

### 터널 만들기

[Create a tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/)을 따르세요. 설치 명령에서 터널 토큰을 복사하세요. 토큰은 비공개로 보관하세요.

Compose로 커넥터를 실행하려면 토큰을 `.env`에 `TUNNEL_TOKEN`으로 넣으세요. 커넥터를 시작하세요.

```sh
docker compose --profile tunnel up -d
```

호스트에서 커넥터를 직접 실행하려면 내 시스템용 Cloudflare 설치 명령을 따르세요.

Cloudflare에 커넥터가 나타나면 **Continue**를 선택하세요.

<span id="콘솔-보호" />

### 콘솔 보호 [#cloudflare-access]

Cloudflare Access는 SwB 콘솔 접근을 내 계정으로 한정합니다. SwB 호스트 이름용 [Access 애플리케이션을 만드세요](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/). 정책 동작을 **Allow**로 설정하세요. **Include**에서 **Emails**를 선택하세요. 내 이메일 주소를 입력하세요.

같은 호스트 이름에 **Bypass**로 표시된 경로용 Access 애플리케이션을 하나 더 만드세요. 정책 동작을 **Bypass**로 설정하세요. **Include**에서 **Everyone**을 선택하세요.

| 경로 | Access 정책 |
| --- | --- |
| `/mcp`, `/register`, `/token`, `/revoke`, `/.well-known/*` | Bypass |
| `/healthz`, `/connect`, `/avatars/*` | Bypass |
| `/inbox/poll`, `/inbox/events` | Bypass |
| `/companion/*` | Bypass |
| `/github/webhook` | GitHub용 Bypass |
| `/hooks/*` | 웹훅과 Muse 훅용 Bypass |
| `/pairing/companion`, `/authorize`, `/inbox`를 포함한 나머지 모든 경로 | Owner |

SwB은 `/companion/pair`에서 페어링 코드를 확인합니다. 그 밖의 컴패니언 요청에서는 기기 키를 확인합니다. Access를 쓴다면 소유자 권한이 있는 에이전트에게 `companion_code` 호출을 요청하세요.

### 에이전트의 HTTP 요청 허용

Browser Integrity Check가 에이전트의 요청을 막을 수 있습니다. Cloudflare 영역에 이 SwB 경로용 [Configuration Rule](https://developers.cloudflare.com/rules/configuration-rules/)을 추가하세요.

`swb.example.com`을 내 SwB 호스트 이름으로 바꾸세요. 이 규칙 표현식을 사용하세요.

```text
(http.host eq "swb.example.com" and (
  starts_with(http.request.uri.path, "/mcp") or
  starts_with(http.request.uri.path, "/hooks/") or
  starts_with(http.request.uri.path, "/.well-known/") or
  http.request.uri.path in {"/register" "/token" "/revoke" "/connect"} or
  starts_with(http.request.uri.path, "/inbox/") or
  starts_with(http.request.uri.path, "/companion/")
))
```

규칙에서 `Browser Integrity Check: Off`를 설정하세요. SwB은 자체 접근 규칙을 그대로 적용합니다.

### SwB 주소 설정

`.env`의 `SWB_PUBLIC_URL`을 공개 주소로 설정하세요.

```dotenv
SWB_PUBLIC_URL=https://swb.example.com
```

설정 파일에 `public_url`이 있으면 같은 주소로 업데이트하세요.

팀 도메인과 소유자 애플리케이션의 Audience 태그를 `config/switchboard.yaml`에 추가하세요. 이 태그는 어느 애플리케이션이 토큰을 발급했는지 SwB에 알려 줍니다.

| 값 | 찾는 곳 | 설정 키 |
| --- | --- | --- |
| 팀 도메인 | **Zero Trust** → **Settings** | `auth.cloudflare_access.team_domain` |
| Application Audience (AUD) Tag | 소유자 애플리케이션 → **Additional settings** | `auth.cloudflare_access.aud` |
| 내 이메일 주소 | 소유자 정책 → **Emails** | `auth.owner_emails` |

```yaml
auth:
  owner_emails: [owner@swb.example.com]
  cloudflare_access:
    team_domain: example.cloudflareaccess.com
    aud: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

SwB은 먼저 `Cf-Access-Jwt-Assertion` 헤더에서 토큰을 읽습니다. 두 번째 출처로 `CF_Authorization` 쿠키를 사용합니다. 쿠키는 브라우저가 요청과 함께 보내는 값입니다. SwB은 `team_domain`의 공개 키로 RS256 서명을 확인합니다. 토큰 발급자는 `team_domain`의 HTTPS 주소와 같아야 합니다. 토큰의 대상(audience)에 `aud`가 들어 있어야 합니다. 토큰에 발급, 시작, 만료 시각이 있으면 SwB은 그 시각을 확인합니다. SwB은 이메일을 소문자로 바꿔 `owner_emails`와 비교합니다.

<span id="신뢰할-수-있는-프록시" />

### 신뢰할 수 있는 프록시 [#trusted-proxies]

리버스 프록시는 요청을 SwB으로 넘겨줍니다. `config/switchboard.yaml`의 `trusted_proxies`에 프록시 주소나 전용 네트워크를 추가하세요. 네트워크 범위는 `192.0.2.0/24` 같은 CIDR 형식으로 쓰세요.

`.env`에 `SWB_TRUSTED_PROXIES`를 설정해도 됩니다. 항목은 쉼표로 구분하세요. YAML 설정이 우선합니다.

Cloudflare Tunnel에는 커넥터의 주소나 전용 네트워크를 추가하세요. IPv4 루프백 연결이면 `127.0.0.1/32`를 사용하세요. Cloudflare 엣지 서버에서 직접 들어오는 연결에는 `cloudflare` 항목을 사용하세요.

Compose 커넥터로 설정을 적용하려면 `docker compose --profile tunnel up -d`를 실행하세요. 호스트의 커넥터라면 `docker compose up -d`를 실행하세요.

### 호스트 이름 게시

터널의 **Routes** 탭을 여세요. **Add route**를 선택하세요. **Published application**을 고르세요. 공개 호스트 이름을 입력하세요.

Compose 커넥터라면 **Service URL**을 `http://switchboard:8000`으로 설정하세요. 호스트의 커넥터라면 `http://localhost:8870`을 사용하세요. **Add route**를 선택해 저장하세요.

### 연결 확인

브라우저에서 공개 주소를 여세요. Cloudflare Access에 로그인하세요. SwB이 응답하는지 보려면 [공개 주소를 확인](https://swb.example.com/healthz)하세요.

비공개 브라우저 창에서 `https://swb.example.com/mcp`를 여세요. SwB은 `WWW-Authenticate` 헤더와 함께 `401`을 돌려줍니다. Cloudflare 로그인 페이지가 나오면 Bypass 정책을 확인하세요.

## 앱 설정

호스트 이름이 작동하면 [연결](/ko/docs/connect)을 따라 앱을 설정하세요. `https://swb.example.com/mcp` 같은 공개 MCP 주소를 사용하세요. 에이전트의 SwB 신원을 확인하려면 에이전트에게 `switchboard_status` 호출을 요청하세요.
