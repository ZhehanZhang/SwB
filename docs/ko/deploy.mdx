## 내 서버에서 실행

### Docker Compose [#docker-compose]

Docker Compose 2.24 이상을 설치하세요. Docker Compose는 컨테이너 안에서 SwB을 실행합니다. 데이터 폴더를 소유한 사용자로 이 명령을 실행하세요.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

원격 서버라면 서버의 `8870` 포트를 내 컴퓨터의 `8870` 포트로 포워딩하세요. 일회용 로그인 링크를 5분 안에 여세요. 링크는 비공개로 유지하세요.

브라우저는 로그인에 `http://localhost:8870`을 사용합니다. 컨테이너 안의 명령은 `8000` 포트를 사용합니다. Compose는 데이터를 `./data`에 저장합니다. `.env`를 바꾼 뒤에는 `docker compose up -d`를 실행하세요.

로그인 전에 `/healthz`에 요청하면 `status`와 `version`을 돌려받습니다. 전체 상태 정보는 소유자 세션이나 소유자 키로 확인하세요.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

터널은 서버를 Cloudflare에 연결하고 SwB에 공개 HTTPS 주소를 줍니다. 터널을 설정하려면 [Cloudflare](/ko/docs/cloudflare)를 따르세요.

## 클라우드에서 실행

`/data`에 디스크를 마운트한 SwB 인스턴스 하나를 사용하세요. 이 디스크는 인스턴스가 다시 시작해도 데이터를 보존합니다. 플랫폼 템플릿과 스크립트는 [배포 가이드](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy)에서 찾으세요.

### Fly.io [#fly]

[Docker Compose 예제](#docker-compose)의 SwB 파일을 사용하세요. Python 3.11 이상을 설치하거나 [uv](https://docs.astral.sh/uv/)를 설치하세요. [Fly.io 명령줄 도구](https://docs.fly.io/flyctl/)를 설치하세요. Fly.io에 로그인하세요.

결제 카드를 등록하면 [Fly.io Free plan](https://docs.fly.io/about/free-plan)에서 매달 5달러 상당의 사용량을 받습니다. 이 플랜에는 개인 조직을 사용하세요. 5달러를 모두 쓰면 Fly는 그달 전체를 표준 요금으로 청구합니다. 이 구성은 Ashburn에서 30일에 약 3.84달러가 듭니다. 데이터 전송 요금은 별도입니다.

SwB 폴더에서 `sh deploy/fly.sh my-swb`를 실행하세요. `my-swb`는 고유한 앱 이름으로 바꾸세요. 이 스크립트는 `fly deploy --ha=false`로 Machine 하나를 시작합니다. 스크립트는 Machine, 볼륨, 주소를 확인합니다.

앱의 로그인 페이지를 여세요. SwB 폴더의 `.env.swb-setup-fly-my-swb`에서 `SWB_SETUP_CODE`를 복사하세요. 그 값을 **Setup code**에 입력하세요. 로그인한 뒤 이 파일을 삭제하세요.

요금 정보는 [현재 요금](https://fly.io/docs/about/pricing/)을 참고하세요.

### Render [#render]

[Render Blueprint](https://render.com/deploy?repo=https://github.com/ZhehanZhang/SwB/tree/release/1.0)를 여세요. Blueprint는 유료 웹 서비스와 1 GB 디스크를 만듭니다. 서비스에서 **Environment**를 여세요. `SWB_SETUP_CODE`를 복사하세요.

### Railway [#railway]

[Railway의 SwB 템플릿](https://railway.com/deploy/swb)으로 배포하세요. 레플리카는 하나로 유지하세요. `/data`에 1 GB 볼륨 하나를 마운트하세요.

SwB을 항상 실행해 두려면 Hobby 플랜을 사용하세요. Hobby 플랜은 월 5달러이며 5달러 상당의 사용량이 포함됩니다.

[Free 플랜](https://docs.railway.com/pricing/free-plan)은 0.5 GB 볼륨을 지원합니다. Free 서비스는 유휴 상태가 되면 잠듭니다. 이 플랜에는 매달 1달러 상당의 사용량이 포함됩니다. 이 금액으로 약 100 MB의 RAM을 항상 쓸 수 있습니다. SwB 테스트에서는 유휴 상태에서 약 107 MiB의 RAM을 사용했습니다.

## 로그인

서비스 로그에 나온 로그인 주소를 여세요. 서비스 설정이나 배포 명령이 알려 준 비공개 파일에서 `SWB_SETUP_CODE`를 복사하세요. 그 값을 **Setup code**에 붙여 넣으세요. **Sign in**을 선택하세요. 다음 로그인부터 쓸 수 있게 [패스키](/ko/docs/owner-login#패스키)를 추가하세요.

## 에이전트 연결

[에이전트 하나에 SwB을 연결](/ko/docs/connect)하세요. 그다음 이 프롬프트를 그 에이전트에 붙여 넣으세요. 나머지 앱도 연결해 달라고 요청하세요.
