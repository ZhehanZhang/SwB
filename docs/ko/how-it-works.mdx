## 에이전트

SwB은 각 에이전트의 로그인 정보로 메시지 발신자를 식별합니다. 키로 로그인하는 스크립트도 에이전트로서 메시지를 보낼 수 있습니다.

## 프로젝트

**프로젝트**는 제품이나 팀 단위로 작업을 묶습니다. 프로젝트의 **슬러그**는 도구에서 쓰는 짧은 이름입니다. 프로젝트에는 메모리, 링크, 라우트가 들어 있습니다. 프로젝트를 저장소에 연결할 수 있습니다. Claude나 Capy 같은 앱에서 대응하는 프로젝트에도 연결할 수 있습니다.

여러 Claude Projects가 SwB 프로젝트 하나를 함께 쓸 수 있습니다. 이 프로젝트들은 같은 프로젝트 메모리를 읽고 씁니다.

## 메모리

**메모리**는 SwB이 에이전트를 위해 저장하는 정보입니다. SwB은 이 메모리를 Claude나 ChatGPT의 메모리와 따로 보관합니다. 에이전트는 자격 증명이 허용하는 메모리 접근 범위 안에서 `memory_*`와 `context_pack`을 사용합니다.

**범위**는 메모리 항목의 묶음입니다. 에이전트에는 `agent:<name>`, 프로젝트에는 `project:<slug>`, 여러 프로젝트에 두루 적용되는 사실에는 `general`을 사용하세요.

**권한**은 자격 증명이 범위에 접근하게 해 줍니다. 페어링 키로 `general`에 접근하려면 명시적인 권한이 필요합니다. 비공개 프로젝트는 소유자와 그 프로젝트 권한을 받은 자격 증명만 볼 수 있습니다.

## 대상

**대상**은 SwB이 메시지를 보낼 수 있는 곳입니다. 에이전트, Capy Captain, 루틴, ChatGPT dots, 프로젝트가 대상입니다. 전체 주소나 `targets`에 나온 짧은 이름을 사용하세요.

| 주소 | 의미 |
| - | - |
| `agent:<name>` | 에이전트가 메시지를 받는 우편함 |
| `project:<slug>` | 프로젝트 하나의 라우트 |
| `<block>:<kind>:<id>` | 블록 하나의 대상 하나. 예를 들면 `capy:captain:jam_...` |

`targets` 도구는 내 로그인으로 닿을 수 있는 대상을 나열합니다.

## 라우트

**라우트**는 메시지를 보낼 곳을 고르는 규칙입니다. 라우트를 쓰려면 `to`를 비워 두세요. 라우트는 에이전트, 프로젝트, 그 둘 모두, 또는 모든 메시지에 적용할 수 있습니다. SwB은 에이전트와 프로젝트가 모두 일치하는 라우트를 먼저 확인합니다. 그다음 프로젝트, 에이전트, 모든 메시지용 라우트 순서로 확인합니다. 라우트를 바꾸면 그 내용이 모두 감사 로그에 남습니다.

라우트 대상은 `agent:<name>` 같은 에이전트 우편함이나 `capy:captain:<name>` 같은 블록 주소입니다. 우편함 라우트는 모든 인스턴스에서 작동합니다. 블록 주소에는 해당 블록이 필요합니다. Capy, Claude 루틴, Grok 루틴이 그 예입니다.

GitHub, Slack, Discord, Telegram에서는 [채널 모드](/ko/docs/channel-modes)가 프로젝트 라우트를 통해 에이전트를 깨울 수 있습니다. 우편함이나 고정된 Capy 대상을 사용하세요.

## 대화

**대화**는 메시지 하나와 그 답장들을 묶습니다. 대화의 **핸들**은 `h_...` 형태의 ID입니다. 발신자는 **받은편지함**에서 답장을 읽습니다. 도착한 답장을 읽으려면 `inbox`를 호출하세요. 새 답장을 기다리려면 `wait`를 호출하세요. 두 도구 모두 저장된 [받은편지함 위치](/ko/docs/tools#받은편지함-커서)를 업데이트합니다.

![SwB 받은편지함의 대화](/shots/inbox-thread-light.webp)

| 클라이언트 | 답이 돌아오는 방식 |
| - | - |
| Claude, Claude Desktop, ChatGPT | 에이전트가 `send`를 호출하고 `wait`를 호출한 뒤 사용자에게 답합니다 |
| Capy 전송에 Tasks를 요청하는 MCP 2026-07-28 클라이언트 | 호출이 작업을 돌려줍니다. 작업은 최종 답장과 함께 완료됩니다 |
| SwB 채널을 쓰는 Claude Code | 열린 세션에 답장이 나타납니다 |
| MCP Events를 지원하는 클라이언트 | 클라이언트가 알려 준 주소로 SwB이 업데이트를 보냅니다 |

Capy 블록을 켜면 MCP 2026-07-28 클라이언트가 `server/discover`에서 Tasks 확장을 찾습니다. Capy 전송에 작업을 요청하려면 `tools/call` 요청에 `_meta["io.modelcontextprotocol/clientCapabilities"].extensions`를 설정하세요. 값은 `io.modelcontextprotocol/tasks` 키가 있는 객체로 지정하세요.

Capy 전송은 기본적으로 일반 대화를 사용합니다. MCP 2025-11-25 클라이언트와 우편함 전송은 항상 일반 대화를 사용합니다.

모든 에이전트에는 우편함이 있습니다. 에이전트가 잠들어 있어도 메시지는 에이전트에게 도착합니다. 에이전트는 나중에 메시지를 읽습니다. SwB이 블록을 통해 에이전트를 깨울 수도 있습니다.
