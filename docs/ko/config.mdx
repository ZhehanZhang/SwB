SwB은 환경 변수만으로도 실행할 수 있습니다. MCP 블록은 기본적으로 시작됩니다. 일부 블록은 해당 변수를 설정하면 시작됩니다. 더 많은 설정에는 YAML 파일을 사용하세요. YAML은 설정을 적는 텍스트 형식입니다.

## 인스턴스

| 변수 | 용도 |
| - | - |
| `SWB_KEY_OWNER` | SwB 도구와 명령에 쓰는 소유자 키 |
| `SWB_PUBLIC_URL` | 로그인과 MCP에 쓰는 공개 주소. 원격 서버에는 `https://swb.example.com`처럼 HTTPS를 사용하세요. |
| `SWB_HOST` | 들어오는 연결을 받을 주소. 기본값은 `127.0.0.1`입니다. |
| `SWB_DATA_DIR` | 데이터 폴더. 이미지에서는 `/data`를 사용합니다. |
| `SWB_OWNER_EMAILS` | OIDC(OpenID Connect)와 Cloudflare Access에 쓰는 소유자 이메일 주소. 주소는 쉼표로 구분합니다 |
| `SWB_KEY_<NAME>` | 에이전트 `<name>`의 키. 에이전트는 이 키를 `Authorization` 헤더에 bearer 키로 담아 보냅니다 |
| `SWB_CONFIG` | 기본 YAML 파일의 경로 |
| `SWB_OVERLAY` | 비공개 오버레이 파일의 경로 |
| `SWB_PORT` | HTTP 포트. `swb up`의 기본값은 `8870`입니다. |

`SWB_PORT`는 셸이나 인스턴스 `.env` 파일에 설정하세요. 호스팅 플랫폼이 다른 포트를 지정하면 클라이언트 명령에서 `--url`로 실행 중인 서버를 고르세요.

명령줄에서 공개 URL을 지정하려면 `swb up --public-url https://swb.example.com`을 사용하세요. 이 옵션은 해당 실행에서 YAML의 `public_url`보다 우선합니다. YAML은 `SWB_PUBLIC_URL`보다 우선합니다.

`SWB_HOST` 대신 다른 값을 쓰려면 `--host`를 사용하세요. `--host 0.0.0.0`이나 로컬 네트워크 주소를 쓰기 전에 공개 URL을 설정하세요.

그 폴더의 `.env`와 `config/switchboard.yaml`을 읽으려면 `swb up --dir ./my-swb`를 사용하세요. `swb init`에도 같은 `--dir`를 사용하세요. `swb up`만 실행할 때 다른 설정 파일을 고르려면 `SWB_CONFIG`를 사용하세요.

`swb status`, `swb login-link`, `swb connect`, `swb claim`은 `--dir`로 `.env`를 찾습니다. 서버 주소는 `--url`로 고릅니다.

서버 명령도 `--dir`를 받습니다. 서버 명령은 `swb serve`, `swb export`, `swb log`, `swb config migrate`, `swb blocks`, `swb targets`입니다. SwB은 고른 폴더에서 `.env`와 설정을 읽습니다. 데이터베이스를 쓰는 명령은 그 폴더에서 인스턴스 데이터도 찾습니다.

`swb serve`만 실행하면 SwB은 셸과 설정 파일을 읽습니다. 나머지 서버 명령은 기본적으로 현재 폴더를 사용합니다.

설정을 버전 2 형식으로 출력하려면 `swb config migrate [file]`을 사용하세요. 특정 설정을 고르려면 `file`을 넘기세요. `file`을 생략하면 SwB은 `--dir`, `SWB_CONFIG`, 기본 경로 중 하나의 설정을 사용합니다.

## 데이터 폴더

`swb up`과 `swb init`은 새 인스턴스용 `data/` 폴더를 만듭니다. SwB은 기본적으로 이 폴더를 사용합니다. 다른 인스턴스 폴더를 고르려면 `swb up --dir`를 사용하세요.

경로를 바꾸려면 설정 파일이나 오버레이에 `data_dir`를 설정하세요. 이 설정이 가장 우선합니다. 그다음 SwB은 `SWB_DATA_DIR`, `SWB_DATA` 순서로 확인합니다. 세 설정이 모두 비어 있으면 기본값을 씁니다.

`swb up`만 실행하면 기존 설정 파일을 그대로 둡니다. 인스턴스에 설정 파일이 있고 `data/`가 없으면 SwB은 `~/.local/share/switchboard`에서 이전 데이터베이스를 찾습니다. 그 데이터베이스를 쓰게 되면 SwB은 안내 메시지를 한 번 남깁니다.

Linux와 macOS에서 SwB은 데이터 폴더를 비공개 모드 `0700`으로 설정합니다. 데이터베이스 파일은 비공개 모드 `0600`으로 설정합니다.

## 블록

일부 블록은 환경 변수의 자격 증명으로 시작할 수 있습니다. 설정 방법은 [블록](/ko/docs/blocks)을 참고하세요. 이름을 붙인 워크스페이스와 루틴의 자격 증명 이름은 [릴리스 환경 변수 예제](https://github.com/ZhehanZhang/SwB/blob/release/1.0/.env.example)에 나와 있습니다.

## 소유자 메시지 [#owner-messages]

SwB은 먼저 지난 30분 동안 소유자 로그인으로 가장 최근에 활동한 에이전트를 시도합니다. 그다음 프로젝트 라우트나 `default_target`으로 정한 프로젝트의 기본 에이전트를 시도합니다. 전역 소유자 라우트는 마지막 선택지입니다.

선택된 에이전트는 받은편지함으로 메시지를 받습니다. 세 선택지가 모두 실패하면 SwB은 상태 화면에 전달 대기 중이라고 알립니다.

전역 소유자 라우트는 에이전트 주소로 설정하세요.

```python
routes_set(agent="owner", target="agent:claude")
```

## 설정 파일 작성

`swb up`은 새 인스턴스를 그 폴더에 설정합니다. 소유자 키는 `.env`에 저장하고, 따로 지정한 `SWB_PORT`도 그곳에 저장합니다. 파일 모드는 `0600`으로 설정합니다.

SwB을 시작하기 전에 파일을 만들려면 `swb init`을 실행하세요.

```bash
swb init
```

두 명령 모두 기본적으로 `config/switchboard.yaml`에 `version: 2`를 씁니다. 주소를 그곳에 저장하려면 `swb init --public-url`에 주소를 넘기세요. 처음 실행할 때 `swb up`은 `--public-url`이나 `SWB_PUBLIC_URL`의 주소를 저장합니다. 불러올 블록을 고르려면 `blocks`를 추가하세요. `CAPTAIN_ID`는 내 Capy Captain ID로 바꾸세요.

```yaml
version: 2
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
blocks:
  mcp: {use: mcp}
  capy: {use: capy, identity: service}
targets:
  aliases: {}
routes:
  - {match: {}, to: capy:captain:CAPTAIN_ID}
```

`blocks` 섹션이 있으면 SwB은 블록을 자동으로 고르는 대신 이 섹션을 따릅니다. MCP 블록을 끄려면 `enabled: false`를 설정하세요. 블록 설정은 이때에도 환경 변수에서 자격 증명을 읽을 수 있습니다.

## 오버레이

오버레이는 내 인스턴스에만 해당하는 설정을 담는 YAML 파일입니다. 기본 설정 파일 옆에 `local.yaml`로 저장하거나 `SWB_OVERLAY`로 경로를 지정하세요. 오버레이는 기본 파일보다 우선합니다. 기본 파일은 환경 기본값보다 우선합니다. 이름으로 묶인 설정은 병합됩니다. 목록은 오버레이의 값으로 바뀝니다.

키에서 `*`는 항목 이름이나 목록 항목을 뜻합니다.

## 코어

| 키 | 용도 |
| - | - |
| `version` | YAML 형식 버전. `blocks`를 쓰려면 `2`를 사용합니다 |
| `public_url` | MCP와 로그인에 쓰는 공개 주소. OAuth는 내 승인을 받아 앱이 로그인하게 합니다 |
| `data_dir` | 데이터 폴더 경로. 여기서 설정하거나 `SWB_DATA_DIR`로 설정합니다 |
| `timezone` | 일별 집계와 한도에 쓰는 시간대. 기본값 `UTC` |
| `turn_cap` | SwB이 대화를 일시 중지하기까지의 턴 수. 기본값 `200`. 한도를 끄려면 `null`로 설정합니다 |
| `blocks` | 불러올 블록. 유형이나 직접 붙인 이름으로 지정합니다 |
| `agents` | 이름별 에이전트 정의 |
| `agents.*.label` | 에이전트의 표시 이름 |
| `targets` | 대상 이름과 우선순위 |
| `targets.aliases` | 짧은 이름을 대상 이름이나 주소에 대응시킵니다 |
| `targets.priority` | 대상끼리 이름이 같을 때 쓸 순서. 예를 들면 `[capy:captain, agent, project]` |
| `routes` | 초기 라우트. 이미 설정된 라우트는 그대로 유지됩니다 |
| `routes.*.match` | 일치 조건. 에이전트, 프로젝트 또는 둘 다를 지정합니다. 전역 라우트에는 `{}`를 사용합니다 |
| `routes.*.to` | 라우트 조건이 일치할 때 보낼 주소 |

## 로그인과 키

| 키 | 용도 |
| - | - |
| `auth` | 로그인과 키 설정 |
| `auth.owner_emails` | OIDC나 Cloudflare Access로 소유자 로그인을 할 수 있는 이메일 주소 |
| `auth.cloudflare_access` | Cloudflare Access 로그인 설정. 두 필드를 모두 채우고 `auth.owner_emails`를 설정합니다 |
| `auth.cloudflare_access.team_domain` | Cloudflare Access 팀 도메인 |
| `auth.cloudflare_access.aud` | Access 애플리케이션을 식별하는 Audience 태그 |
| `auth.redirect_uris` | 허용할 OAuth 복귀 주소. 이 목록이 기본 제공 목록을 대신합니다. 경로와 하위 경로를 모두 허용하려면 `/*`를 사용합니다 |
| `auth.source_names` | OAuth 호스트나 클라이언트 이름의 일부를 로그인에 쓸 에이전트 이름에 대응시킵니다 |
| `auth.key_scopes` | 키 이름이나 에이전트 이름별 접근 범위. 예를 들면 `[project:example]`. 이 범위는 라우트, 메시지, 대화를 제한합니다. 설정된 키와 OAuth 클라이언트가 메모리를 쓸 때도 제한합니다. 페어링 키에는 페어링할 때 지정된 메모리 범위가 권한으로 추가됩니다 |
| `auth.key_tools` | 키 이름별로 허용할 MCP 도구. 예를 들면 `[send]` |
| `auth.key_targets` | 키 이름별로 허용할 메시지 대상. 예를 들면 `[agent:claude]`. 이 제한이 있는 키는 허용된 대상을 지정해야 합니다 |
| `auth.inbox_keys` | 키 이름을 그 키가 받은편지함을 읽을 수 있는 에이전트 하나에 대응시킵니다. 기본 항목은 `channel: claude-code`입니다 |

## 공개 범위

| 키 | 용도 |
| - | - |
| `visibility` | 리소스에 접근할 수 있는 사람을 정하는 규칙. 도구는 항상 비공개입니다 |
| `visibility.defaults` | 리소스 유형별 기본 규칙. 모든 유형은 `private`으로 시작합니다 |
| `visibility.defaults.channel` | 채널의 기본 규칙 |
| `visibility.defaults.memory` | 메모리 범위의 기본 규칙 |
| `visibility.defaults.route` | 라우트의 기본 규칙 |
| `visibility.defaults.target` | 전송 대상의 기본 규칙 |
| `visibility.resources` | `channel:home/#agents` 같은 개별 리소스의 규칙. 각 규칙은 유형 기본값보다 우선합니다 |

Slack에서 `channel:home/#agents`는 채널 규칙입니다. GitHub에서 외부 발신자가 `agent:beta`에 닿게 하려면 `channel:github/acme/app`과 `target:beta`를 모두 공유하세요. [채널 공개 범위](/ko/docs/channel-modes#외부-github-발신자-허용)를 참고하세요.

소유자와 소유자의 에이전트만 접근하게 하려면 `private`을 사용하세요. 접근을 열려면 `shared`를 사용하세요. 선택한 사람들과 공유하려면 사용자 ID나 `workspace:home` 같은 항목을 나열하세요. `visibility_set`으로 바꾼 값은 이 파일보다 우선합니다.

## GitHub 발신자 신뢰

| 키 | 용도 |
| - | - |
| `blocks.github.owner_ids` | 소유자로 신뢰할 GitHub 숫자 사용자 ID의 기본 목록 |
| `blocks.github.spaces.*.owner_ids` | 이 공간에서 기본 목록 대신 쓸 GitHub 숫자 사용자 ID 목록 |

GitHub는 `owner`와 `external` 신뢰 수준을 사용합니다. Slack, Discord, Telegram에서 SwB은 `known`을 보고 어떤 발신자의 메시지를 받을지 고릅니다. 그 밖의 발신자가 보낸 메시지는 계속 `external` 신뢰 수준을 가집니다. Work 모드 설정은 [소유자 계정](/ko/docs/blocks/github#소유자-계정)을 참고하세요.

## MCP

| 키 | 용도 |
| - | - |
| `blocks.mcp` | MCP 클라이언트를 처리하는 블록의 설정 |
| `blocks.mcp.use` | 블록 유형. `mcp`를 사용합니다 |
| `blocks.mcp.legacy_aliases` | `agent_send`, `capy_delegate`, `capy_wait`, `capy_reply` 같은 이전 MCP 도구 이름을 계속 쓸 수 있게 합니다. 기본값 `true` |
| `blocks.mcp.wait` | 답장을 기다리는 도구 호출의 한도 |
| `blocks.mcp.wait.default_s` | 호출자가 비워 둘 때의 대기 시간(초). 기본값 `60` |
| `blocks.mcp.wait.max_s` | 최대 대기 시간(초). 기본값 `200` |
| `blocks.mcp.wait.agents` | 에이전트별 대기 한도. Claude Code는 기본 `45`초, 최대 `55`초를 사용합니다 |
| `blocks.mcp.wait.agents.*.default_s` | 이 에이전트의 기본 대기 시간(초) |
| `blocks.mcp.wait.agents.*.max_s` | 이 에이전트의 최대 대기 시간(초) |

## 메모리와 채널 모드

프로젝트 라우트를 연결하고 triage 동작을 설정하려면 [채널 모드](/ko/docs/channel-modes)를 참고하세요.

| 키 | 용도 |
| - | - |
| `memory` | 메모리의 Markdown 사본 설정 |
| `memory.mirror` | Markdown 사본을 제어합니다. 업데이트를 멈추려면 `false`로 설정합니다 |
| `memory.mirror_dir` | Markdown 사본을 둘 폴더 |
| `memory.mirror_debounce_s` | 메모리가 바뀐 뒤 사본을 쓰기까지 기다릴 시간(초). 기본값 `2` |
| `memory.sync` | 에이전트가 `memory_sync`로 자기 메모리를 SwB에 복사하게 합니다. 기본값 `true`. 콘솔의 **Memory sync** 스위치가 이 값보다 우선합니다 |
| `memory.backup` | 메모리의 Git 백업 설정 |
| `memory.backup.debounce_s` | 메모리가 바뀐 뒤 백업 커밋까지 기다릴 시간(초). 기본값 `30` |
| `memory.backup.max_delay_s` | 변경이 많을 때 백업 커밋까지 기다릴 최대 시간(초). 기본값 `300` |
| `modes` | 들어오는 이벤트를 SwB이 처리하는 방식의 설정 |
| `modes.default` | 기본 모드. 기본값은 `off`입니다 |
| `modes.projects` | 프로젝트별로 배정된 공간의 기본 모드 |
| `modes.assist_max_chars` | SwB이 에이전트에게 주는 `assist` 답장의 글자 수 한도. 기본값 `1500` |
| `modes.digest_minutes` | 요약본을 만들기 전에 `watch` 이벤트를 모을 시간(분). 기본값 `60`. 이벤트가 `50`개가 되어도 요약본을 보냅니다 |

## 브랜딩

```yaml
branding:
  display_name: SwB
  accent_color: "#64748b"
```

| 키 | 용도 |
| - | - |
| `branding` | SwB이 보여 주는 이름, 아이콘, 색상 설정 |
| `branding.display_name` | 표시 이름. 기본값 `SwB` |
| `branding.accent_color` | `#RRGGBB` 형식의 강조 색상 |
| `branding.icon` | 사용자 지정 아이콘 |
