## 앱 만들기

내 계정에 GitHub App을 만드세요. 웹훅 주소는 공개 SwB 주소 뒤에 `/github/webhook`을 붙인 값으로 설정하세요. 예를 들면 `https://swb.example.com/github/webhook`을 사용하세요. 웹훅 시크릿을 생성해 비공개 파일에 저장하세요. SwB은 16자 이상의 시크릿을 받아들입니다.

```bash
(umask 077; set -C; openssl rand -hex 32 > ~/.swb-github-secret)
```

**Webhook secret**에 시크릿을 입력하세요. 에이전트에게 GitHub 연결을 요청하세요. 같은 시크릿을 등록 링크로 저장하세요. 비공개 파일을 삭제하세요. 시크릿을 불러오려면 SwB을 다시 시작하세요. 남은 App ID나 개인 키 링크를 받으려면 에이전트에게 `connect`를 다시 호출하도록 요청하세요. 개인 키 필드에는 `.pem` 파일의 전체 내용을 붙여 넣으세요.

## 권한

**Repository permissions**에서 표에 나온 접근 수준을 사용하세요.

| 저장소 리소스 | 접근 | 이벤트 |
| - | - | - |
| **Issues** | **Read & write** | `issues`, `issue_comment` |
| **Pull requests** | **Read & write** | `pull_request`, `pull_request_review`, `pull_request_review_comment`, `pull_request_review_thread` |
| **Contents** | **Read-only** | `push` |
| **Checks** | **Read-only** | `check_run`, `check_suite` |
| **Actions** | **Read-only** | `workflow_run` |
| **Metadata** | 자동으로 **Read-only** | |

원하는 저장소에 앱을 설치하세요.

## 이벤트 라우팅

```yaml
blocks:
  github:
    use: github
    sinks:
      team: {url_env: SWB_EXAMPLE_GITHUB_SINK_URL}
    routes:
      "acme/app": [team]
      "acme/*": [team]
```

서버 환경에서 `SWB_EXAMPLE_GITHUB_SINK_URL`을 수신처의 주소로 설정하세요.

**싱크**는 이벤트 사본을 받는 URL입니다. SwB은 `watch` 모드에서 조건에 맞는 싱크마다 간결한 JSON 이벤트를 보냅니다. 싱크 라우트가 있는 저장소는 기본적으로 `watch`를 사용합니다. 채널 모드와 공간 모드가 이보다 우선합니다. SwB은 추가 정보를 `metadata`에 인용해 담습니다. 각 요청은 이벤트의 전달 ID를 `Idempotency-Key`로 사용합니다. SwB은 연결 실패, 시간 초과, HTTP 5xx 응답이 오면 다시 시도합니다.

Cloudflare Access가 호스트를 보호하고 있다면 `/github/webhook`은 통과하게 하세요. 이 경로는 GitHub 서명이 보호합니다.

## 소유자 계정

`off` 모드에서 SwB은 그 공간의 GitHub 이벤트를 소유자 계정의 이벤트까지 모두 버립니다.

설정된 소유자 계정의 이벤트만 받으려면 `work` 모드를 사용하세요. `https://api.github.com/users/USERNAME`에서 `USERNAME`을 내 GitHub 사용자 이름으로 바꾸세요. 그 URL을 여세요. 숫자로 된 `id`를 공간의 `owner_ids` 목록에 복사하세요. 설정을 적용하려면 SwB을 다시 시작하세요.

```yaml
blocks:
  github:
    use: github
    spaces:
      acme/app:
        owner_ids: [4242]
        mode:
          mode: work
          target: agent:beta
```

기본 소유자 ID는 `blocks.github.owner_ids`로 설정하세요. 공간의 `owner_ids` 목록은 이 기본값을 대신합니다. 공간 목록을 비우면 기본값이 지워집니다.

SwB은 제목, 본문, 댓글마다 작성자를 확인합니다. 텍스트를 쓴 사람이 `owner_ids`에 있고 실제 사람일 때만 그 텍스트를 `owner`로 인정합니다. SwB은 브랜치 이름, ref, 워크플로 제목, 검사 이름을 `external`로 인용합니다.

검사 이름이 있는 `check_run`은 소유자가 실행했더라도 `external` 신뢰 수준을 가집니다. 포크에서 온 풀 리퀘스트가 검사 이름을 정할 수 있기 때문입니다. 접근 규칙에는 `github:4242` 같은 ID를 사용하세요. 이 규칙은 신뢰 수준과 별개로 접근 권한을 줍니다.

GitHub 대화 동작에서는 SwB 대화 ID를 `conversation`이나 `handle`에 넘기세요.

## 설정

| 키 | 용도 |
| - | - |
| `blocks.github` | GitHub 이벤트와 동작 설정 |
| `blocks.github.use` | 블록 유형. `github`를 사용합니다 |
| `blocks.github.enabled` | 이 블록을 건너뛰려면 `false`로 설정합니다 |
| `blocks.github.app_id_env` | App ID를 담은 변수의 이름 |
| `blocks.github.private_key_env` | App 개인 키를 담은 변수의 이름 |
| `blocks.github.token_env` | App 자격 증명 대신 쓸 세분화된 토큰을 담은 변수의 이름 |
| `blocks.github.secret_env` | 웹훅 시크릿을 담은 변수의 이름 |
| `blocks.github.sinks` | 이벤트 수신처 이름별 설정 |
| `blocks.github.sinks.*.url_env` | 수신처 주소를 담은 변수의 이름 |
| `blocks.github.routes` | 저장소 이름이나 `owner/*`를 이벤트 수신처 목록에 연결합니다 |
| `blocks.github.owner_ids` | 소유자로 신뢰할 GitHub 숫자 사용자 ID의 기본 목록 |
| `blocks.github.spaces` | 설정을 함께 쓰는 저장소 묶음. `acme/app` 같은 이름은 해당 저장소를 고릅니다 |
| `blocks.github.spaces.*.repo` | `owner/repo` 형식의 저장소 이름 |
| `blocks.github.spaces.*.owner_ids` | 이 공간에서 기본 목록 대신 쓸 GitHub 숫자 사용자 ID 목록 |
| `blocks.github.spaces.*.mode` | 이 공간에 있는 저장소의 기본 [채널 모드](/ko/docs/channel-modes) |
| `blocks.github.spaces.*.mode.target` | 모드 설정의 대상. `agent:beta` 같은 주소를 고릅니다 |
| `blocks.github.spaces.*.project` | 이 공간에서 온 이벤트의 기본 SwB 프로젝트 |

저장소에 에이전트를 연결하려면 `space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")`를 사용하세요. assist 모드에는 `mode="assist"`를 사용하세요. 대상은 `targets`에서 고르세요. 연결된 프로젝트 라우트가 대체 대상입니다.

외부 발신자에게는 `channel:github/acme/app`과 `target:beta` 모두에 접근 권한을 주세요. 접근 규칙은 [채널 공개 범위](/ko/docs/channel-modes#외부-github-발신자-허용)를 참고하세요.

`watch` 모드에서 SwB은 `modes.digest_minutes`가 지나거나 그 우편함과 공간에 이벤트가 50개 모이면 대상 우편함으로 요약본을 보냅니다. [Watch 요약본](/ko/docs/channel-modes#watch-요약본-읽기)을 참고하세요.
