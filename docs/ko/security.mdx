## 소유자는 한 명

SwB의 소유자는 한 명입니다. 소유자는 에이전트 로그인을 승인합니다. 소유자는 SwB 콘솔에서 접근 권한을 관리하고 토큰을 저장합니다.

## 에이전트 로그인

OAuth는 소유자의 승인을 받아 앱이 로그인하게 해 줍니다. SwB은 S256 방식의 PKCE로 로그인을 시작한 앱과 마친 앱이 같은지 확인합니다. SwB은 각 OAuth 토큰을 `/mcp` 주소 하나에 묶습니다. 기본적으로 액세스 토큰은 1시간, 갱신 토큰은 30일 동안 유효합니다. SwB은 갱신 토큰을 한 번 쓸 때마다 새 토큰으로 바꿉니다. SwB은 OAuth 토큰의 SHA-256 해시를 저장합니다. 해시는 토큰을 확인하는 데 쓰는 지문입니다. 에이전트는 설정된 키를 쓰거나 페어링 코드를 키로 교환할 수도 있습니다.

## 신뢰 수준

SwB은 플랫폼이 알려 준 발신자 ID로 메시지의 신뢰 수준을 정합니다.

| 신뢰 수준 | 대상 |
| - | - |
| `owner` | 나와 로그인한 내 에이전트 |
| `external` | 그 밖의 발신자. `known`에 등록한 사람과 봇도 여기에 속합니다 |

Slack, Discord, Telegram에서 SwB은 `known`을 보고 어떤 발신자의 메시지를 받을지 고릅니다. 이 외부 발신자의 메시지는 계속 `external` 신뢰 수준을 가집니다. SwB이 GitHub 작성자를 확인하는 방법은 [GitHub 소유자 계정](/ko/docs/blocks/github#소유자-계정)을 참고하세요.

**신뢰 프레임**은 SwB이 외부 텍스트에 붙이는 머리말과 표시입니다. 프레임을 붙이기 전에 SwB은 텍스트 안에 있는 머리말이나 표시의 사본을 바꿔 둡니다. 표시는 `<<<swb-untrusted`와 `swb-untrusted>>>`입니다. 에이전트는 두 표시 사이의 텍스트를 참고 정보로만 다룹니다.

Watch 모드의 요약본은 `external` 신뢰 수준을 가집니다. 각 발췌문에는 외부 텍스트용 신뢰 프레임이 붙습니다. SwB은 GitHub 텍스트 필드마다 작성자를 확인합니다.

[컴패니언](/ko/docs/companion) 키는 자기 기기 연결에만 쓸 수 있습니다. SwB은 키를 확인하려고 키의 해시만 보관합니다. SwB은 기기에서 온 결과를 `external`로 표시하고 자유 텍스트를 신뢰 프레임에 넣습니다.

## 공개 범위

리소스는 대상, 채널, 메모리 범위, 라우트, 도구를 말합니다. 기본 접근 규칙은 `private`입니다. 이 규칙에서는 소유자와 소유자의 에이전트만 접근합니다. 리소스를 워크스페이스나 선택한 사람들과 공유할 수 있습니다. 도구는 항상 비공개입니다. 채널 규칙과 대상 규칙이 모두 허용하면 외부 발신자가 대상에 닿을 수 있습니다. SwB이 메시지를 맥락 정보로 저장하면 그 메시지는 참고 정보로 받은편지함에 들어갑니다. 이때 에이전트는 잠든 상태를 유지합니다.

## 제한이 있는 키

라우팅, 메시지, 대화 접근을 제한하려면 `auth.key_scopes`를 사용하세요. 페어링 키는 이 제한 안에서 자기 에이전트의 메시지와 대화만 읽을 수 있습니다.

SwB은 페어링 키마다 메모리 권한을 저장합니다. 이전 권한을 업그레이드할 때 SwB은 넓은 접근 권한을 가진 활성 페어링 키에 `general`과 그 시점에 있는 프로젝트를 줍니다. `auth.key_scopes`에 범위 이름이 지정된 키는 그 범위를 그대로 복사합니다.

전체 권한을 가진 OAuth 클라이언트나 설정된 키는 소유자로서 모든 메모리에 접근합니다. 에이전트 이름별로 메모리 접근을 제한하려면 `auth.key_scopes`를 사용하세요. 제한된 자격 증명으로 비공개 프로젝트에 접근하려면 그 프로젝트를 지정한 권한이 필요합니다.

`auth.key_tools`는 키가 호출할 수 있는 도구를 제한합니다. `auth.key_targets`는 키가 메시지를 보낼 수 있는 곳을 제한합니다.

## 토큰

토큰은 각 등록 페이지에서 입력하세요. SwB은 데이터 폴더의 키로 저장하는 토큰을 암호화합니다. 상태 화면은 빠진 변수의 이름을 보여 주고 값은 가립니다. Capy 키는 기본적으로 `api.capy.ai`로 가는 요청 헤더에 담깁니다.

페어링 키별 메모리 범위를 보려면 **Tokens**를 여세요. 범위 옆의 **Remove scope**를 선택하면 그 권한이 제거됩니다.

새 페어링 키는 페어링 코드를 교환할 때 자기 에이전트 범위를 받습니다. 코드에 지정된 프로젝트와 `auth.key_scopes.<agent>`에 지정된 범위도 받습니다. 접근 범위를 넓히려면 추가 범위를 설정하거나 페어링 코드에 프로젝트를 넣으세요. 그다음 새 키를 페어링하세요.

## 한도

| 한도 | 값 |
| - | - |
| 잘못된 bearer 키 | 주소당 10분에 20회. 넘으면 HTTP `429` |
| 소유자 계정 외부 발신자에게서 라우팅된 GitHub 이벤트 | 발신자당 최근 10분에 5개 |
| `/register` | 주소당 1시간에 20회 |
| `/token` | 주소당 10분에 120회 |
| `/authorize` | 주소당 10분에 60회 |
| `/companion/pair`의 틀린 코드 | 주소당 10분에 10회. 넘으면 HTTP `429` |
| `/connect`의 틀린 코드 | 주소당 10분에 10회. 넘으면 HTTP `429` |
| 기본 요청 본문 한도 | 1 MiB |
| `/mcp`와 `/companion/results`의 요청 본문 | 16 MiB |
| `/companion/emit`의 요청 본문 | 16,640바이트 |
| `/auth/setup`의 요청 본문 | 1,024바이트 |
| 에이전트 대화당 턴 수 | 200 |

bearer 키 한도는 같은 주소에서 온 올바른 키에도 적용됩니다. 한도가 풀릴 때까지 SwB은 해당 엔드포인트에서 HTTP `429`를 돌려줍니다.

대화가 턴 한도에 이르면 SwB은 대화를 일시 중지합니다. 일시 중지는 감사 로그에 기록됩니다. Slack이 켜져 있으면 소유자에게 다이렉트 메시지를 보냅니다.

Capy 블록은 같은 작업과 대상에 대해 이전 대화를 돌려줄 수 있습니다. 이 시간 범위는 `blocks.capy.duplicate_window_s`로 설정하세요. 기본값은 600초입니다.

## 클라이언트 주소

SwB은 기본적으로 연결 주소로 한도를 적용하고 감사 기록을 남깁니다. `trusted_proxies`나 `SWB_TRUSTED_PROXIES`에 프록시를 추가하세요. 그러면 SwB은 프록시가 보내는 클라이언트 주소를 사용합니다. 프록시가 검증한 출처의 값으로 클라이언트 주소 헤더를 설정하도록 프록시를 구성하세요.

Docker 네트워크에 Cloudflare Tunnel 커넥터나 리버스 프록시를 추가하려면 [Cloudflare 설정 가이드](/ko/docs/cloudflare#신뢰할-수-있는-프록시)를 따르세요.

## 감사 로그

SwB은 접근 규칙이 거부한 도구 호출을 기록합니다. 설정 코드, 이미 쓴 링크, 만료된 링크, 잘못된 링크, 패스키, CSRF 확인, OIDC에서 실패한 브라우저 로그인도 기록합니다.

SwB은 GitHub 웹훅 서명이 빠졌거나 잘못된 경우를 기록합니다. 일부 브라우저 실패와 웹훅 거부는 반복 기록 수가 제한됩니다. 실패 기록에는 이유가 나오고 코드, 토큰, 서명은 비공개로 유지됩니다.

SwB 페이지의 **Audit**에서 기록을 볼 수 있습니다. 최근 기록을 출력하려면 `swb log`를 실행하세요. 우편함 전송의 동작 이름은 `send`입니다. 버려진 전달 기록은 [채널 모드](/ko/docs/channel-modes#전달-확인)를 참고하세요.
