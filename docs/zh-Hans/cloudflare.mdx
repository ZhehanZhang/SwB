Cloudflare Tunnel 为 SwB 提供公网 HTTPS 地址。**隧道**把你的服务器连接到 Cloudflare。Cloudflare 的免费套餐包含隧道。

按 [Docker Compose](/zh-Hans/docs/deploy#docker-compose) 中的步骤启动 SwB。

<span id="快速隧道" />

## 快速隧道 [#quick-tunnel]

快速隧道提供一个临时地址。在 SwB 服务器上安装 [cloudflared](https://developers.cloudflare.com/tunnel/downloads/)，它是把 SwB 连接到 Cloudflare 的程序。在服务器上运行下面的命令。

```sh
cloudflared tunnel --url http://localhost:8870
```

把 `.env` 中的 `SWB_PUBLIC_URL` 设为终端中显示的 HTTPS 地址。如果配置中有 `public_url`，也改成同一个地址。把连接器添加到[受信任的代理](#trusted-proxies)。运行 `docker compose up -d`，让设置生效。

每次启动隧道，地址都会变化。OAuth 登录和通行密钥都使用这个地址。要使用固定地址，改用命名隧道。

<span id="命名隧道" />

## 命名隧道 [#named-tunnel]

命名隧道在你的域名上提供固定地址。

### 开始之前

使用一个能为你的域名管理隧道和 Access 应用的 Cloudflare 账号。允许服务器通过 7844 端口连接 Cloudflare。

### 创建隧道

按[创建隧道](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/)操作。从安装命令中复制隧道令牌。妥善保管这个令牌。

要用 Compose 运行连接器，把令牌以 `TUNNEL_TOKEN` 为名写入 `.env`，然后启动连接器。

```sh
docker compose --profile tunnel up -d
```

要在主机上直接运行连接器，运行 Cloudflare 为你的系统提供的安装命令。

连接器出现在 Cloudflare 中后，选择 **Continue**。

### 保护控制台 [#cloudflare-access]

Cloudflare Access 只允许你的账号访问 SwB 控制台。为你的 SwB 主机名[创建一个 Access 应用](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)。把策略操作设为 **Allow**。在 **Include** 下选择 **Emails**，填写你的电子邮件地址。

在同一个主机名上再创建一个 Access 应用，用于标为 **Bypass** 的路径。把它的策略操作设为 **Bypass**。在 **Include** 下选择 **Everyone**。

| 路径 | Access 策略 |
| --- | --- |
| `/mcp`、`/register`、`/token`、`/revoke`、`/.well-known/*` | Bypass |
| `/healthz`、`/connect`、`/avatars/*` | Bypass |
| `/inbox/poll`、`/inbox/events` | Bypass |
| `/companion/*` | Bypass |
| `/github/webhook` | Bypass（供 GitHub 调用） |
| `/hooks/*` | Bypass（供 Webhooks 模块和 Muse 钩子调用） |
| 其余所有路径，包括 `/pairing/companion`、`/authorize` 和 `/inbox` | 所有者 |

SwB 在 `/companion/pair` 检查配对码，在其他 Companion 请求中检查设备密钥。如果使用 Access，让一个拥有所有者权限的智能体调用 `companion_code`。

### 放行智能体的 HTTP 请求

浏览器完整性检查（Browser Integrity Check）可能会拦截智能体发出的请求。在你的 Cloudflare 区域中，为下面这些 SwB 路径添加一条[配置规则](https://developers.cloudflare.com/rules/configuration-rules/)。

把 `swb.example.com` 换成你的 SwB 主机名，然后使用下面的规则表达式。

```text
(http.host eq "swb.example.com" and (
  starts_with(http.request.uri.path, "/mcp") or
  starts_with(http.request.uri.path, "/hooks/") or
  starts_with(http.request.uri.path, "/.well-known/") or
  http.request.uri.path in {"/register" "/token" "/revoke" "/connect"} or
  starts_with(http.request.uri.path, "/inbox/") or
  starts_with(http.request.uri.path, "/companion/")
))
```

在规则中设置 `Browser Integrity Check: Off`。SwB 仍会执行自己的访问规则。

### 设置 SwB 地址

把 `.env` 中的 `SWB_PUBLIC_URL` 设为你的公网地址。

```dotenv
SWB_PUBLIC_URL=https://swb.example.com
```

如果配置中有 `public_url`，也改成同一个地址。

把团队域名和所有者应用的受众标签添加到 `config/switchboard.yaml`。这个标签告诉 SwB 令牌由哪个应用签发。

| 值 | 查找位置 | 配置键 |
| --- | --- | --- |
| 团队域名 | **Zero Trust** → **Settings** | `auth.cloudflare_access.team_domain` |
| Application Audience (AUD) Tag | 所有者应用 → **Additional settings** | `auth.cloudflare_access.aud` |
| 你的电子邮件地址 | 所有者策略 → **Emails** | `auth.owner_emails` |

```yaml
auth:
  owner_emails: [owner@swb.example.com]
  cloudflare_access:
    team_domain: example.cloudflareaccess.com
    aud: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

SwB 优先从 `Cf-Access-Jwt-Assertion` 请求头读取令牌，其次读取 `CF_Authorization` Cookie。Cookie 是浏览器随请求发送的一个值。SwB 用 `team_domain` 提供的公钥校验 RS256 签名。令牌的签发者必须与 `team_domain` 的 HTTPS 地址一致，令牌的受众中必须包含 `aud`。令牌带有签发时间、生效时间或过期时间时，SwB 会检查对应的时间。SwB 把电子邮件地址转成小写，再与 `owner_emails` 比对。

<span id="受信任的代理" />

### 受信任的代理 [#trusted-proxies]

反向代理把请求转发给 SwB。在 `config/switchboard.yaml` 的 `trusted_proxies` 中添加它的地址或专用网络。网段使用 CIDR 表示法，例如 `192.0.2.0/24`。

也可以在 `.env` 中设置 `SWB_TRUSTED_PROXIES`，多个条目用逗号分隔。YAML 中的设置优先级更高。

使用 Cloudflare Tunnel 时，添加连接器的地址或专用网络。IPv4 回环连接使用 `127.0.0.1/32`。来自 Cloudflare 边缘服务器的直接连接使用 `cloudflare` 条目。

如果使用 Compose 中的连接器，运行 `docker compose --profile tunnel up -d` 让设置生效。如果连接器运行在主机上，运行 `docker compose up -d`。

### 发布主机名

打开隧道的 **Routes** 标签页，选择 **Add route**。选择 **Published application**，填写你的公网主机名。

使用 Compose 中的连接器时，把 **Service URL** 设为 `http://switchboard:8000`。连接器运行在主机上时，使用 `http://localhost:8870`。选择 **Add route** 保存。

### 检查连接

在浏览器中打开你的公网地址，登录 Cloudflare Access。打开[公网地址的健康检查](https://swb.example.com/healthz)，确认 SwB 有响应。

在无痕窗口中打开 `https://swb.example.com/mcp`。SwB 返回 `401`，并带有 `WWW-Authenticate` 响应头。如果 Cloudflare 显示它的登录页面，检查 Bypass 策略。

## 设置应用

主机名可用后，按[连接](/zh-Hans/docs/connect)设置应用。使用公网 MCP 地址，例如 `https://swb.example.com/mcp`。让智能体调用 `switchboard_status`，检查它的 SwB 身份。
