Cloudflare Tunnel 为 SwB 提供固定的公网 HTTPS 地址。**隧道**把你的服务器连接到 Cloudflare。Cloudflare Access 只允许你的账号访问 SwB 控制台。

<span id="快速隧道" />

## 快速隧道 [#quick-tunnel]

快速隧道提供一个临时地址，适合试用 SwB。`cloudflared` 是把 SwB 连接到 Cloudflare 的程序。在装有它的主机上运行下面的命令。

```bash
cloudflared tunnel --url http://localhost:8870
```

把 `SWB_PUBLIC_URL` 设为终端中显示的 HTTPS 地址。如果配置中有 `public_url`，也一并更新。然后重启 SwB。每次启动隧道，地址都会变化。OAuth 登录和通行密钥都使用这个地址。要长期使用同一个地址，改用命名隧道。

<span id="命名隧道" />

## 命名隧道 [#named-tunnel]

准备一个免费的 Cloudflare 账号和你自己的域名。

### 开始之前

按 [Docker Compose](/zh-Hans/docs/deploy#docker-compose) 启动 SwB。使用能为你的域名管理隧道和 Access 应用的 Cloudflare 账号。允许服务器连接 Cloudflare 的 7844 端口。

### 创建隧道

按[创建隧道](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/)操作。从安装命令中复制隧道令牌，填入 [Compose 文件](https://github.com/ZhehanZhang/SwB/blob/273e0a9f2cb35ed929404ef23d7aca9d25ade44d/compose.yaml#L32-L39)指定的 SwB `.env` 条目。令牌需要保密。

如果使用 Compose 中的隧道，把它的服务地址指向 `http://switchboard:8000`，并把隧道令牌以 `TUNNEL_TOKEN` 为名写入 `.env`。把连接器的地址或专用网络添加到 `trusted_proxies`。

在 SwB 服务器上启动隧道连接器。

```sh
docker compose --profile tunnel up -d
```

如果隧道运行在 SwB 所在的主机上，把它的服务地址指向 `http://localhost:8870`，并把 `SWB_TRUSTED_PROXIES` 设为连接器的地址，例如 IPv4 回环连接使用 `127.0.0.1/32`。

连接器出现在 Cloudflare 中后，选择 **Continue**。

<span id="保护控制台" />

### 保护控制台 [#cloudflare-access]

为你的 SwB 主机名[创建一个 Access 应用](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)。把策略操作设为 **Allow**。在 **Include** → **Emails** 下填你的电子邮件地址。

在同一个主机名上再创建一个 Access 应用，覆盖标为 **Bypass** 的路径。把它的策略操作设为 **Bypass**。在 **Include** 下选择 **Everyone**。

| 路径 | Access 策略 |
| --- | --- |
| `/mcp`、`/register`、`/token`、`/revoke`、`/.well-known/*` | Bypass |
| `/healthz`、`/connect`、`/avatars/*` | Bypass |
| `/inbox/poll`、`/inbox/events` | Bypass |
| `/companion/*` | Bypass |
| `/github/webhook` | 对 GitHub 设为 Bypass |
| `/hooks/*` | 对 Webhooks 设为 Bypass |
| 其余所有路径，包括 `/pairing/companion`、`/authorize` 和 `/inbox` | 所有者 |

SwB 在 `/companion/pair` 检查配对码，对其他 Companion 请求则检查设备密钥。如果使用 Access，让一个以所有者身份登录的智能体调用 `companion_code`。

### 设置 SwB 地址

把 `.env` 中的 `SWB_PUBLIC_URL` 设为你的公网地址，例如 `https://swb.example.com`。把团队域名和所有者应用的受众标签（AUD）添加到 `config/switchboard.yaml`。这个标签告诉 SwB 令牌由哪个应用签发。

如果配置中有 `public_url`，也更新其中的地址。

| 值 | 查找位置 | 配置键 |
| --- | --- | --- |
| 团队域名 | **Zero Trust** → **Settings** | `auth.cloudflare_access.team_domain` |
| Application Audience (AUD) Tag | 所有者应用 → **Additional settings** | `auth.cloudflare_access.aud` |
| 你的电子邮件地址 | 所有者策略 → **Emails** | `auth.owner_emails` |

```yaml
auth:
  owner_emails: [owner@swb.example.com]
  cloudflare_access:
    team_domain: example.cloudflareaccess.com
    aud: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

使用 Cloudflare Access 登录时，SwB 取 `Cf-Access-Jwt-Assertion` 请求头中的令牌。如果这个请求头为空或缺失，SwB 改从 `CF_Authorization` Cookie 中读取令牌。Cookie 是浏览器随请求发送的一个值。SwB 用 `team_domain` 提供的公钥校验 RS256 签名。令牌的签发者必须与 `team_domain` 的 HTTPS 地址一致。令牌的受众中必须包含 `aud`。如果令牌带有签发时间、生效时间和过期时间，SwB 会逐一检查。SwB 把电子邮件地址转成小写，再与 `owner_emails` 比对。

再次运行 `docker compose --profile tunnel up -d`，让设置生效。

<span id="受信任的代理" />

### 受信任的代理 [#trusted-proxies]

反向代理把请求转发给 SwB。在 `config/switchboard.yaml` 的 `trusted_proxies` 中添加代理的地址或专用网络。网段用 CIDR 格式书写，例如 `192.0.2.0/24`。

也可以在 `.env` 中设置 `SWB_TRUSTED_PROXIES`，多个条目用逗号分隔。YAML 中的设置优先。

如果 Cloudflare Tunnel 运行在 SwB 所在的主机或 Docker 网络中，添加隧道连接器的地址或专用网络。连接器直接连接 SwB。来自 Cloudflare 边缘服务器的直接连接使用 `cloudflare` 条目。

### 发布主机名

打开隧道的 **Routes** 标签页，选择 **Add route**。选择 **Published application**。填写你的公网主机名。把 **Service URL** 设为 `http://switchboard:8000`。选择 **Add route** 保存。

### 检查连接

在浏览器中打开 `https://swb.example.com`，登录 Cloudflare Access。打开 `https://swb.example.com/healthz`，确认 SwB 有响应。

在无痕窗口中打开 `https://swb.example.com/mcp`。SwB 返回 `401`，并带有 `WWW-Authenticate` 响应头。如果 Cloudflare 显示它的登录页面，检查 Bypass 策略。

## 设置应用

主机名可用后，按[连接](/zh-Hans/docs/connect)设置应用。使用公网 MCP 地址，例如 `https://swb.example.com/mcp`。让智能体调用 `switchboard_status`，检查它的 SwB 身份。
