title: Slack
description: 用机器人和你自己的 Slack 账号把 Slack 工作区连接到 SwB。

SwB 通过一个 Slack 应用读取和发送 Slack 消息。你用清单创建这个应用。清单是一个文件，里面写好了应用的全部设置。

应用使用 Socket Mode。SwB 主动连接 Slack，因此服务器可以使用私网地址。

## 开始之前

请使用有权在工作区创建和安装应用的 Slack 账号。你的组织可能要求审批应用。请以所有者身份登录 SwB。

## 复制设置提示词

<SetupPrompt name="slack" lang="zh-Hans" />

把提示词粘贴到 SwB 所有者客户端。

## 设置 Slack 应用

### 打开 Slack 应用设置

打开 [Slack 应用设置](https://api.slack.com/apps)。点击 **Create New App** → **From a manifest**。
### 选择工作区

选择你的工作区。点击 **Next**。
### 粘贴清单

选择 **YAML**。复制下方的一份应用清单。粘贴完整内容。
### 创建应用

点击 **Next** → **Create**。
### 创建应用级令牌

点击 **Basic Information** → **App-Level Tokens** → **Generate Token and Scopes**。输入令牌名称。
### 添加权限范围

点击 **Add Scope** → `connections:write`。点击 **Generate**。
### 安装应用

点击 **Install App** → **Install to Workspace**。以 SwB 代表的 Slack 用户身份点击 **Allow**。
### 在 Enterprise Grid 中获得批准

如果 Slack 要求审批，请把应用交给工作区或组织管理员。

### 保存令牌

打开该工作区的领取链接。把每个 Slack 令牌粘贴到对应字段。
### 邀请机器人

如果使用机器人，请在每个要接入 SwB 的频道发送 `/invite @<bot name>`。
### 找到工作区 ID

在浏览器中打开 Slack。把地址中的工作区 ID 发给智能体。ID 以 `T` 开头。

## 应用清单

### 机器人和你的账号

```yaml
# Example Slack app for an agent-to-agent workspace: a bot user and the owner's user token.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
# The bot's @handle and member-list profile come from features.bot_user.display_name and the
# app icon; they do not change per message. Per-message name/avatar = personas (chat:write.customize).
display_information:
  name: SwB
  description: Agent switchboard for the owner's assistants
  background_color: "#1d2733"
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: swb
    always_online: true
oauth_config:
  scopes:
    bot:
      - app_mentions:read      # @mentions -> push kind "mention"
      - channels:history       # watched public channels the bot is in
      - channels:read
      - groups:history         # watched private channels the bot is in
      - groups:read
      - im:history             # DMs to the bot -> push kind "dm"
      - im:read
      - im:write               # approval DMs to the owner
      - chat:write
      - chat:write.customize   # personas: per-message username + icon
      - reactions:write        # ack reaction on mentions/DMs
      - users:read             # names in pushed events
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # posts as the owner (policy-gated)
      - reactions:write
      - search:read            # search_messages
      - users:read
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.channels
      - message.groups
      - message.im
  interactivity:
    is_enabled: true           # Approve/Reject buttons, delivered over Socket Mode
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

### 只用你的账号

```yaml
# Example Slack app for a user-only workspace. No bot user, bot scopes, bot events, or interactivity.
# It never joins or invites; every post appears as the owner.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
display_information:
  name: SwB (personal)
  description: Lets the owner's agents read on their behalf; writes need approval
  background_color: "#333333"
oauth_config:
  scopes:
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # only ever used after the owner approves a request
      - reactions:write        # same
      - search:read
      - users:read
settings:
  event_subscriptions:
    user_events:
      - message.channels
      - message.groups
      - message.im
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

## 智能体的工作

智能体调用 `connect(what="slack")`。SwB 检查缺少哪些令牌，再为对应的工作区返回领取链接。

智能体在 `config/switchboard.yaml` 的 `blocks.slack.workspaces` 下添加工作区。它填写工作区 ID 和令牌名称，然后在 `blocks.slack.agents` 下授予访问权限。

此示例用机器人和你的账号连接一个工作区。把 `T0DEMO0001` 换成你的工作区 ID。

```yaml
blocks:
  slack:
    use: slack
    enabled: true
    workspaces:
      example:
        team_id: T0DEMO0001
        app_token_env: SWB_SLACK_EXAMPLE_APP_TOKEN
        identities:
          bot:
            token_env: SWB_SLACK_EXAMPLE_BOT_TOKEN
          user:
            token_env: SWB_SLACK_EXAMPLE_USER_TOKEN
    agents:
      claude:
        workspaces:
          example: [bot, user]
```

使用 `switchboard_status` 显示的智能体名称。每个智能体添加一项授权。工作区配置和授权使用同一个工作区名称。如果只用你的账号，在 `team_id` 同一级添加 `user_only: true`。删除 `identities` 中的 `bot`。把授权中的身份设为 `[user]`。

`connect` 提示后，重启 SwB。智能体可以用 `slack_workspaces` 检查每个身份。身份指机器人或你的账号。

## 凭据

| 令牌 | Slack 显示位置 | 格式 | 填写位置 |
| --- | --- | --- | --- |
| 应用级令牌 | **Basic Information** → **App-Level Tokens** | 以 `xapp-` 开头 | SwB 领取链接 |
| 机器人令牌 | **OAuth & Permissions** → **OAuth Tokens** → **Bot User OAuth Token** | 以 `xoxb-` 开头 | SwB 领取链接 |
| 用户令牌 | **OAuth & Permissions** → **OAuth Tokens** → **User OAuth Token** | 以 `xoxp-` 开头 | SwB 领取链接 |

## 检查连接

再次调用 `connect(what="slack")`，确认结果为 `connected`。调用 `slack_workspaces`。确认各身份的 `ready` 和工作区的 `connected` 均为 `true`。

使用机器人时，在频道中提及机器人并写上目标名称。请智能体用 `slack_events` 或 `slack_wait` 查看消息。要测试发送，请让有写入权限的身份用 `slack_post` 发消息。

## 解决问题

如果 SwB 报告 Socket Mode 有问题，请在应用设置中打开 **Socket Mode**。打开 **Enable Socket Mode**。

如果你修改了应用的权限范围，请重新安装应用。然后通过新的领取链接保存新令牌。

`slack_search` 用你自己的账号搜索。它需要带有 `search:read` 权限范围的用户令牌。
