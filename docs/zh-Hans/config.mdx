SwB 可以只用环境变量运行。MCP 模块默认启用。有些模块在设置对应变量后才启用。其他设置可写进 YAML 文件。YAML 是一种用文本记录设置的格式。

## 实例

| 变量 | 用途 |
| - | - |
| `SWB_KEY_OWNER` | SwB 工具和命令使用的所有者密钥 |
| `SWB_PUBLIC_URL` | 登录和 MCP 使用的公开地址。远程服务器使用 HTTPS，例如 `https://swb.example.com`。 |
| `SWB_HOST` | 监听地址，默认为 `127.0.0.1`。 |
| `SWB_DATA_DIR` | 数据目录。镜像使用 `/data`。 |
| `SWB_OWNER_EMAILS` | OpenID Connect（OIDC）和 Cloudflare Access 使用的所有者邮箱地址。用逗号分隔各地址 |
| `SWB_KEY_<NAME>` | 智能体 `<name>` 的密钥。智能体把它作为 bearer 密钥放入 `Authorization` 请求头 |
| `SWB_CONFIG` | 基础 YAML 文件的路径 |
| `SWB_OVERLAY` | 私有覆盖文件的路径 |
| `SWB_PORT` | HTTP 端口。`swb up` 默认为 `8870`。 |

在终端或实例的 `.env` 文件中设置 `SWB_PORT`。如果托管平台设置了其他端口，用 `--url` 为客户端命令指定服务器的实际地址。

用 `swb up --public-url https://swb.example.com` 在命令行中设置公开地址。本次运行时，该选项优先于 YAML 中的 `public_url`。YAML 设置优先于 `SWB_PUBLIC_URL`。

用 `--host` 覆盖 `SWB_HOST`。监听 `0.0.0.0` 或局域网地址之前，请先设置公开地址。

用 `swb up --dir ./my-swb` 读取该目录中的 `.env` 和 `config/switchboard.yaml`。运行 `swb init` 时，传入同一个 `--dir`。直接运行 `swb up` 时，可用 `SWB_CONFIG` 指定其他配置文件。

`swb status`、`swb login-link`、`swb connect` 和 `swb claim` 用 `--dir` 查找 `.env`。这四条命令用 `--url` 指定服务器地址。

服务器命令都接受 `--dir`，包括 `swb serve`、`swb export`、`swb log`、`swb config migrate`、`swb blocks` 和 `swb targets`。SwB 从指定目录读取 `.env` 和配置。需要访问数据库的命令也从该目录查找实例数据。

直接运行 `swb serve` 时，SwB 读取终端环境和配置文件。其他服务器命令默认使用当前目录。

用 `swb config migrate [file]` 输出第 2 版格式的配置。可传入 `file` 指定配置文件。省略时，SwB 依次查找 `--dir`、`SWB_CONFIG` 和默认路径指定的配置。

## 数据目录

`swb up` 和 `swb init` 都会为新实例创建 `data/` 目录。SwB 默认使用这个目录。用 `swb up --dir` 可指定其他实例目录。

在配置文件或覆盖文件中设置 `data_dir` 可更改路径。这项设置优先。SwB 接着按顺序检查 `SWB_DATA_DIR` 和 `SWB_DATA`。三项设置都为空时，SwB 使用默认路径。

直接运行 `swb up` 会保留已有配置文件。实例已有配置文件且 `data/` 目录缺失时，SwB 会到 `~/.local/share/switchboard` 查找旧数据库。如果用了旧数据库，SwB 会在日志中提示一次。

在 Linux 和 macOS 上，SwB 将数据目录的权限设为 `0700`。数据库文件的权限设为 `0600`。

## 模块

有些模块可以根据环境中的凭据启动。请参阅[模块](/zh-Hans/docs/blocks)了解设置方法。[发布版环境示例](https://github.com/ZhehanZhang/SwB/blob/release/1.0/.env.example)列出了带名称的工作区和 routine 使用的凭据名称。

## 配置文件

`swb up` 在实例目录中初始化新实例。SwB 在 `.env` 中保存所有者密钥和自定义的 `SWB_PORT`。文件权限为 `0600`。

如需在启动 SwB 前创建文件，请运行 `swb init`。

```bash
swb init
```

这两条命令默认会把 `version: 2` 写入 `config/switchboard.yaml`。用 `swb init --public-url` 可将地址保存到该文件。首次运行 `swb up` 时，它会保存 `--public-url` 或 `SWB_PUBLIC_URL` 中的地址。添加 `blocks` 可选择加载的模块。把 `CAPTAIN_ID` 换成你的 Capy Captain ID。

```yaml
version: 2
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
blocks:
  mcp: {use: mcp}
  capy: {use: capy, identity: service}
targets:
  aliases: {}
routes:
  - {match: {}, to: capy:captain:CAPTAIN_ID}
```

SwB 优先按 `blocks` 选择模块。将 MCP 模块的 `enabled` 设为 `false` 可关闭它。模块仍可从环境变量读取凭据。

## 覆盖文件

覆盖文件是存放实例专用设置的 YAML 文件。在基础配置文件旁创建 `local.yaml`，或用 `SWB_OVERLAY` 指定路径。覆盖文件优先于基础文件。基础文件优先于环境变量中的默认设置。按名称分组的设置会合并。覆盖文件中的列表会取代原有列表。

键中的 `*` 代表一个名称或列表项。

## 核心设置

| 配置键 | 用途 |
| - | - |
| `version` | YAML 配置格式版本。使用 `blocks` 时设为 `2` |
| `public_url` | MCP 和登录使用的公开地址。OAuth 让应用在你批准后登录 |
| `data_dir` | 数据目录的路径。可在此设置，也可用 `SWB_DATA_DIR` |
| `timezone` | 每日计数和限额所用的时区，默认为 `UTC` |
| `turn_cap` | 会话暂停前的轮数，默认为 `200`。设为 `null` 可关闭上限 |
| `blocks` | 要加载的模块，可用模块类型或自定义名称命名 |
| `agents` | 按名称设置智能体 |
| `agents.*.label` | 智能体的显示名称 |
| `targets` | 发送目标的名称和优先顺序 |
| `targets.aliases` | 将简称指向目标名称或地址 |
| `targets.priority` | 目标重名时的选择顺序，例如 `[capy:captain, agent, project]` |
| `routes` | 初始路由。SwB 保留已设置的路由 |
| `routes.*.match` | 匹配智能体、项目，或两者都匹配。全局路由使用 `{}` |
| `routes.*.to` | 路由匹配时的发送地址 |

## 登录和密钥

| 配置键 | 用途 |
| - | - |
| `auth` | 登录和密钥设置 |
| `auth.owner_emails` | 可通过 OIDC 或 Cloudflare Access 以所有者身份登录的邮箱地址 |
| `auth.cloudflare_access` | Cloudflare Access 登录设置。填写下方两项并设置 `auth.owner_emails` |
| `auth.cloudflare_access.team_domain` | Cloudflare Access 团队域名 |
| `auth.cloudflare_access.aud` | Access 应用的受众标记 |
| `auth.redirect_uris` | 允许的 OAuth 回调地址。此列表替换内置列表。用 `/*` 匹配路径及其子路径 |
| `auth.source_names` | 将 OAuth 主机名或客户端名称的片段映射到登录时所用的智能体名称 |
| `auth.key_scopes` | 按密钥或智能体名称设置访问范围，例如 `[project:example]`。这些范围限制路由、消息和会话。通过配置密钥或 OAuth 客户端访问记忆时也受这些范围限制。在配对时，SwB 会将指定的记忆范围加入授权 |
| `auth.key_tools` | 按密钥名称设置可调用的 MCP 工具，例如 `[send]` |
| `auth.key_targets` | 按密钥名称设置允许发送的目标，例如 `[agent:claude]`。使用受此限制的密钥时，须指定一个允许的目标 |
| `auth.inbox_keys` | 为每把密钥指定唯一可读取的智能体收件箱。内置项为 `channel: claude-code` |

## 访问权限

| 配置键 | 用途 |
| - | - |
| `visibility` | 决定谁能访问各项资源。工具始终为私有 |
| `visibility.defaults` | 按资源类型设定默认规则。各类型初始值均为 `private` |
| `visibility.defaults.channel` | 频道的默认规则 |
| `visibility.defaults.memory` | 记忆范围的默认规则 |
| `visibility.defaults.route` | 路由的默认规则 |
| `visibility.defaults.target` | 发送目标的默认规则 |
| `visibility.resources` | 设置单项资源的规则，例如 `channel:home/#agents`。单项规则优先于该类型的默认规则 |

在 Slack 中，`channel:home/#agents` 是一条频道规则。在 GitHub 中，同时共享 `channel:github/acme/app` 和 `target:beta`，外部发送者才可联系 `agent:beta`。详情见[频道可见性](/zh-Hans/docs/channel-modes#允许外部-github-用户访问)。

用 `private` 将访问权限限定为所有者及其智能体。用 `shared` 开放访问。填写用户 ID 或 `workspace:home` 这样的条目，即可指定共享对象。通过 `visibility_set` 所作的更改优先于此文件。

## GitHub 发件人信任等级

| 配置键 | 用途 |
| - | - |
| `blocks.github.owner_ids` | 默认认定为所有者的 GitHub 数字用户 ID 列表 |
| `blocks.github.spaces.*.owner_ids` | 覆盖此空间默认列表的 GitHub 数字用户 ID 列表 |

GitHub 的信任等级为 `owner` 和 `external`。Slack、Discord 和 Telegram 用 `known` 帮助 SwB 判断接收哪些发送者的消息。其他发送者的消息仍标为 `external`。工作模式的配置方法见[所有者账号](/zh-Hans/docs/blocks/github#所有者账号)。

## MCP

| 配置键 | 用途 |
| - | - |
| `blocks.mcp` | 为 MCP 客户端提供服务的模块设置 |
| `blocks.mcp.use` | 模块类型，填 `mcp` |
| `blocks.mcp.legacy_aliases` | 保留 `agent_send`、`capy_delegate`、`capy_wait` 和 `capy_reply` 等旧版 MCP 工具名称。默认为 `true` |
| `blocks.mcp.wait` | 等待答复的工具调用时限 |
| `blocks.mcp.wait.default_s` | 调用方省略等待时间时使用的秒数，默认为 `60` |
| `blocks.mcp.wait.max_s` | 最长等待秒数，默认为 `200` |
| `blocks.mcp.wait.agents` | 按智能体设置等待时限。Claude Code 默认等待 `45` 秒，最多 `55` 秒 |
| `blocks.mcp.wait.agents.*.default_s` | 该智能体默认等待的秒数 |
| `blocks.mcp.wait.agents.*.max_s` | 该智能体最长等待的秒数 |

## 记忆和频道模式

请参阅[频道模式](/zh-Hans/docs/channel-modes)，了解如何绑定项目路由和设置分流操作。

| 配置键 | 用途 |
| - | - |
| `memory` | 记忆的 Markdown 副本设置 |
| `memory.mirror` | 控制 Markdown 副本。设为 `false` 可停止更新 |
| `memory.mirror_dir` | 存放 Markdown 副本的目录 |
| `memory.mirror_debounce_s` | 记忆更新后，写入副本前等待的秒数，默认为 `2` |
| `memory.sync` | 允许智能体用 `memory_sync` 把自身记忆复制到 SwB。默认为 `true`。控制台中的 **Memory sync** 开关优先 |
| `memory.backup` | 记忆 Git 备份的设置 |
| `memory.backup.debounce_s` | 从记忆变更到提交备份的等待时间，单位为秒。默认为 `30` |
| `memory.backup.max_delay_s` | 记忆连续变更时，提交备份前的最长等待时间，单位为秒。默认为 `300` |
| `modes` | 设置 SwB 如何处理传入事件 |
| `modes.default` | 默认模式，初始值为 `off` |
| `modes.projects` | 各项目下空间的默认模式 |
| `modes.assist_max_chars` | SwB 为智能体指定的 `assist` 答复字符上限，默认为 `1500` |
| `modes.digest_minutes` | `watch` 模式汇总事件前的等待分钟数，默认为 `60`。累计 `50` 条事件时也会发送摘要 |

```yaml
branding:

```

| - | - |
