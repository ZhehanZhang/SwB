## 创建 App

在你的账号下创建一个 GitHub App。把 Webhook 地址设为你的公网 SwB 地址加 `/github/webhook`，例如 `https://swb.example.com/github/webhook`。在一个仅自己可读的文件中生成 Webhook 密钥。SwB 接受至少 16 个字符的密钥。

```bash
(umask 077; set -C; openssl rand -hex 32 > ~/.swb-github-secret)
```

把密钥填入 **Webhook secret**，再让智能体连接 GitHub，并用对应的认领链接保存同一个密钥。然后删除这个私有文件，重启 SwB 以加载密钥。让智能体再次调用 `connect`，获取其余的 App ID 或私钥链接。把 `.pem` 文件的全部内容粘贴到私钥字段中。

## 权限

在 **Repository permissions** 下，按表中的访问权限设置。

| 仓库资源 | 访问权限 | 事件 |
| - | - | - |
| **Issues** | **Read & write** | `issues`、`issue_comment` |
| **Pull requests** | **Read & write** | `pull_request`、`pull_request_review`、`pull_request_review_comment`、`pull_request_review_thread` |
| **Contents** | **Read-only** | `push` |
| **Checks** | **Read-only** | `check_run`、`check_suite` |
| **Actions** | **Read-only** | `workflow_run` |
| **Metadata** | 自动设为 **Read-only** | |

把 App 安装到需要的仓库上。

## 路由事件

```yaml
blocks:
  github:
    use: github
    sinks:
      team: {url_env: SWB_EXAMPLE_GITHUB_SINK_URL}
    routes:
      "acme/app": [team]
      "acme/*": [team]
```

在服务器环境中，把 `SWB_EXAMPLE_GITHUB_SINK_URL` 设为接收端的地址。

**sink** 是接收事件副本的 URL。在 `watch` 模式下，SwB 向每个匹配的 sink 发送一个精简的 JSON 事件。带 sink 路由的仓库默认使用 `watch` 模式。频道模式和空间模式优先。SwB 把其他细节作为引用内容放在 `metadata` 中。每个请求用事件的投递 ID 作为 `Idempotency-Key`。遇到连接失败、超时和 HTTP 5xx 响应时，SwB 会重试。

如果你的主机由 Cloudflare Access 保护，放行 `/github/webhook`。这个路径由 GitHub 签名保护。

## 所有者账号

在 `off` 模式下，SwB 丢弃空间的全部 GitHub 事件，包括所有者账号的事件。

使用 `work` 模式，可以只接受已配置的所有者账号的事件。把 `https://api.github.com/users/USERNAME` 中的 `USERNAME` 换成你的 GitHub 用户名，然后打开这个 URL。把数字 `id` 复制到空间的 `owner_ids` 列表中。重启 SwB，让设置生效。

```yaml
blocks:
  github:
    use: github
    spaces:
      acme/app:
        owner_ids: [4242]
        mode:
          mode: work
          target: agent:beta
```

用 `blocks.github.owner_ids` 设置默认的所有者 ID。空间的 `owner_ids` 列表会取代这个默认值。把空间的列表设为空，就会清除这个默认值。

SwB 会核对每个标题、正文或评论的作者。只有文本自己的作者在 `owner_ids` 中并且是真人时，文本才算作 `owner`。SwB 把分支名、ref、工作流标题和检查名称作为 `external` 内容引用。

带检查名称的 `check_run`，信任等级为 `external`，由所有者触发时也是如此。来自 fork 的 Pull Request 可以设置检查名称。在访问规则中使用 `github:4242` 这样的 ID。这些规则授予访问权限，与信任等级相互独立。

执行 GitHub 对话操作时，在 `conversation` 或 `handle` 中传入 SwB 对话标识。

## 配置

| 键 | 用途 |
| - | - |
| `blocks.github` | GitHub 事件和操作的设置 |
| `blocks.github.use` | 模块类型。填 `github` |
| `blocks.github.enabled` | 设为 `false` 可跳过这个模块 |
| `blocks.github.app_id_env` | 保存 App ID 的变量名 |
| `blocks.github.private_key_env` | 保存 App 私钥的变量名 |
| `blocks.github.token_env` | 保存细粒度令牌的变量名，这个令牌可以替代 App 凭据 |
| `blocks.github.secret_env` | 保存 Webhook 密钥的变量名 |
| `blocks.github.sinks` | 按事件接收端名称组织的设置 |
| `blocks.github.sinks.*.url_env` | 保存接收端地址的变量名 |
| `blocks.github.routes` | 仓库名称或 `owner/*` 到事件接收端列表的映射 |
| `blocks.github.owner_ids` | 视为所有者的 GitHub 数字用户 ID 的默认列表 |
| `blocks.github.spaces` | 共用一套设置的具名仓库集合。`acme/app` 这样的名称会选中对应的仓库 |
| `blocks.github.spaces.*.repo` | 仓库名称，格式为 `owner/repo` |
| `blocks.github.spaces.*.owner_ids` | GitHub 数字用户 ID 列表，在这个空间中取代默认值 |
| `blocks.github.spaces.*.mode` | 这个空间中各仓库的默认[频道模式](/zh-Hans/docs/channel-modes) |
| `blocks.github.spaces.*.mode.target` | 模式设置中的目标。填 `agent:beta` 这样的地址 |
| `blocks.github.spaces.*.project` | 这个空间的事件所用的默认 SwB 项目 |

用 `space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")` 把智能体绑定到仓库。要使用 assist 模式，传入 `mode="assist"`。从 `targets` 中选择目标。关联的项目路由作为后备。

要允许外部发送方，同时授予 `channel:github/acme/app` 和 `target:beta` 的访问权限。访问规则见[频道可见性](/zh-Hans/docs/channel-modes#允许外部-github-发送方)。

在 `watch` 模式下，经过 `modes.digest_minutes` 分钟后，或同一个邮箱和空间累计满 50 个事件时，SwB 向目标邮箱发送一份摘要。参阅 [Watch 摘要](/zh-Hans/docs/channel-modes#阅读-watch-摘要)。
