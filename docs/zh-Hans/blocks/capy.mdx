## 启用模块

按 [Capy Captain 设置](/zh-Hans/docs/setup/capy-captain)操作。SwB 用 Capy 账号密钥查找 Capy Captain 并跟踪话题串。

## 把 Capy 连接为智能体

在 Capy 中将 SwB 添加为自定义 MCP 服务器。用 OAuth 以 `capy` 身份登录 SwB。

## 发送给 Capy Captain

请任意智能体把工作发送给 Capy Captain。

> 把这个发给我的 Capy Captain。

项目路由决定工作发往哪里。SwB 跟踪 Capy 话题串，并将更新送到发送者的邮箱。重启后，SwB 从上次保存的位置继续跟踪近期工作。

| 路由模式 | 发送的效果 |
| - | - |
| `captain_thread` | 向 Capy Captain 发送一条消息 |
| `new_thread` | 启动一个新的团队话题串 |

## MCP Tasks

Capy 模块为使用 MCP 2026-07-28 的客户端启用 [MCP Tasks](/zh-Hans/docs/how-it-works#会话)。客户端通过 `server/discover` 查找此扩展。每次用 `send` 向 Capy 发送时，可选择使用该扩展。其他消息使用普通会话。

## 发送密钥

Capy 显示发送密钥所属的账号。SwB 先尝试智能体的密钥，再尝试服务密钥。在 `personal` 模式下，Capy 账号密钥是最后的选项。以所有者身份登录后，在 `/healthz` 查看各智能体优先使用的密钥名称和检查结果。

## 项目自动链接

智能体创建 SwB 项目时，Capy 模块会查找对应的 Capy 项目。仓库匹配优先于名称匹配。找到唯一匹配时，SwB 会关联这两个项目。如果关联的项目恰好有一位活跃的 Capy Captain，SwB 会自动把路由指向这位 Captain。

## 配置

| 配置键 | 用途 |
| - | - |
| `blocks.capy` | Capy 消息发送和话题串跟踪设置 |
| `blocks.capy.use` | 模块类型，填 `capy` |
| `blocks.capy.enabled` | 设为 `false` 可跳过此模块 |
| `blocks.capy.api_base` | Capy API 的基础地址，默认为 `https://api.capy.ai/api/v1` |
| `blocks.capy.identity` | `service` 使用智能体密钥或服务密钥。`personal` 还允许最后改用 Capy 账号密钥 |
| `blocks.capy.send_key_env` | 存放服务传送密钥的变量名 |
| `blocks.capy.default_route` | 仅在首次设置时写入全局 Capy 路由。填写 Capy 目标，例如 `captain:<id>` |
| `blocks.capy.captain_delivery` | 向忙碌的 Capy Captain 或话题串投递消息的方式。可选 `queue`、`steer` 或 `interrupt`，默认为 `queue` |
| `blocks.capy.daily_cap` | 每天委派给 Capy 的次数上限。设为 `null` 可关闭上限 |
| `blocks.capy.duplicate_window_s` | 在这段时间内，发送者、目标、标题和任务都相同的发送会沿用原会话 ID。单位为秒，默认值为 `600` |
| `blocks.capy.max_file_bytes` | 每次发送的附件总大小上限，以字节计，默认为 `10485760` |
| `blocks.capy.handle_ttl_days` | 启动时，只恢复跟踪在指定天数内委派的任务。此设置也决定 MCP 任务的有效期，默认为 `7` 天 |
| `blocks.capy.avatars` | 允许 SwB 获取 Capy Captain 头像。设为 `false` 则显示首字母 |
