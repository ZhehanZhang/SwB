SwB 可以在 Linux、macOS 和 Windows 上运行。要从源码构建 SwB，参阅 [Docker Compose](/zh-Hans/docs/deploy#docker-compose)。软件包或镜像发布后，使用下面的方法。

## 安装并启动

准备一个空文件夹，存放 SwB 的文件。`swb` 命令凭所有者密钥以你的身份登录。

<Tabs items={['uvx', 'pipx', 'Docker']}>
  <Tab value="uvx">
    先[安装 uv](https://docs.astral.sh/uv/getting-started/installation/)。SwB 需要 Python 3.12 或更高版本。

    ```bash
    uvx swb-one up
    ```

    uvx 会下载并启动 SwB。在 5 分钟内打开终端里的一次性登录链接。在其他示例中，把开头的 `swb` 换成 `uvx swb-one`。
  </Tab>
  <Tab value="pipx">
    先[安装 pipx](https://pipx.pypa.io/stable/how-to/install-pipx.html)。SwB 需要 Python 3.12 或更高版本。

    ```bash
    pipx install swb-one
    swb up
    ```

    pipx 会为你的用户账号安装 `swb` 命令。在 5 分钟内打开终端里的一次性登录链接。

    如果 pipx 使用的 Python 版本较旧，改用 `pipx install --python 3.12 swb-one`。
  </Tab>
  <Tab value="Docker">
    先[安装 Docker](https://docs.docker.com/get-started/get-docker/)。

    ```bash
    (umask 077; set -C; printf 'SWB_KEY_OWNER=%s\nSWB_PUBLIC_URL=http://localhost:8870\n' "$(openssl rand -hex 32)" > .env)
    docker run -d --name swb --env-file .env \
      -p 127.0.0.1:8870:8000 -v swb-data:/data \
      ghcr.io/zhehanzhang/swb:latest
    ```

    这些命令会创建一个私有的 `.env` 文件并启动容器。镜像把数据保存在 `/data` 中。运行 `docker exec swb swb login-link` 获取登录链接。要在容器内运行其他 SwB 命令，以 `docker exec -it swb swb` 开头。
  </Tab>
</Tabs>

首次在本地启动时，`swb up` 会在实例文件夹中创建 `.env`、`config/switchboard.yaml` 和 `data/`。以后需要新链接时，运行 `swb login-link`。

要在启动服务器之前先创建这些文件，运行 `swb init`，然后运行 `swb up`。再打开第二个终端，在同一文件夹中运行 `swb login-link`。

`swb up` 默认监听 `127.0.0.1` 的 `8870` 端口。本地 MCP 地址默认为 `http://localhost:8870/mcp`。要换用其他端口，在 shell 或 `.env` 中设置 `SWB_PORT`。

用 `swb up --dir ./my-swb` 指定实例文件夹。运行 `swb init`、`swb status`、`swb login-link`、`swb connect` 和 `swb claim` 时，传入相同的 `--dir`。监听地址、配置文件和数据目录的说明见[配置](/zh-Hans/docs/config)。

## 检查服务器

```bash
curl -fsS http://127.0.0.1:8870/healthz
```

这个匿名请求返回 `status` 和 `version`。运行 `swb status`，或带上所有者密钥调用 `/healthz`，可以列出各个模块、模块状态和缺少的变量。

如果 SwB 服务器在公网上，使用它的 HTTPS 地址。

```bash
curl -fsS https://swb.example.com/healthz
```

## 服务器命令

运行 `swb --help` 查看命令分组。在某条命令后加上 `--help`，可以查看它的选项。

| 命令 | 用途 |
| - | - |
| `swb init` | 写入私有的所有者密钥和一份最小配置。 |
| `swb up` | 在这台电脑上启动 SwB。 |
| `swb connect PLATFORM` | 获取连接某个平台的步骤。 |
| `swb companion` | 配对、运行或断开 Companion。 |
| `swb hook HARNESS` | 把本地智能体的事件转发给 Companion。 |
| `swb status` | 显示状态和后续步骤。 |
| `swb login-link` | 创建一次性的所有者登录链接。 |
| `swb claim` | 凭认领链接或认领码保存凭据。 |
| `swb serve` | 按配置的主机和端口运行服务器。 |
| `swb export DIR` | 把已保存的记忆写成 Markdown 文件，放入输出文件夹 `DIR`。 |
| `swb log [--limit N]` | 输出最近的审计记录。默认最多输出 `50` 条。 |
| `swb config migrate` | 把版本 1 的配置按版本 2 的格式输出。 |
| `swb blocks list` | 列出已配置的模块。 |
| `swb blocks show BLOCK` | 显示某个模块的设置。 |
| `swb blocks check` | 检查模块配置。 |
| `swb targets` | 列出 `send` 可用的目标。 |

## 版本

{/* prepublication */}

发布后，`swb-one` 软件包托管在 PyPI 上，`ghcr.io/zhehanzhang/swb` 镜像托管在 GitHub Container Registry 上。要选用某个发布版本，指定 `1.0.0` 这样的版本号。镜像标签 `latest` 始终指向最新的稳定版。
