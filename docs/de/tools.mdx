`tools/list` zeigt die Tools, die Ihre Anmeldung erlaubt. Eine uneingeschränkte Inhaber-Anmeldung zeigt die Tools aller aktiven Blöcke.

## Gekoppelte Schlüssel

Ein gekoppelter Schlüssel kann diese Tools im Rahmen des Zugriffs nutzen, den der Inhaber ihm gewährt.

| Zweck | Tools und Limits |
| - | - |
| Nachrichten | Verwenden Sie `send` und `targets`. Bei aktiven Legacy-Namen verwenden Sie `agent_send`. Verwenden Sie `inbox`, `wait`, `reply`, `status`, `result`, `cancel` und `get_message` im Rahmen des Unterhaltungszugriffs Ihres Schlüssels |
| Gedächtnis und Projekte | Verwenden Sie `context_pack` und `project_list` im Rahmen des Zugriffs Ihres Schlüssels. Verwenden Sie die Gedächtnis-Tools in freigegebenen Bereichen |
| Routen | Verwenden Sie `routes_list` und `routes_resolve`. Für `routes_set` und `routes_remove` setzen Sie `agent` auf Ihren eigenen Agentennamen. Verwenden Sie ein Projekt aus den Bereichen Ihres Schlüssels |
| Einrichtung | Prüfen Sie den Status mit `switchboard_status` und `modes_status`. Client-Anleitungen erhalten Sie mit `connect`. Für die Einrichtung von Blöcken und für Kopplungscodes verwenden Sie die Anmeldung des Inhabers |
| Blöcke | Verwenden Sie Block-Tools im Rahmen Ihres freigegebenen Zugriffs und der Aktionen, die der Kanalmodus erlaubt |

`login_link`, `connect_code`, `connect_list`, `connect_revoke`, `visibility_list` und `visibility_set` erfordern die uneingeschränkte Anmeldung des Inhabers. Verwenden Sie diese Anmeldung auch für `project_create`, `project_update`, `project_sync` und `space_mode`. Sie gibt außerdem Zugriff auf `memory_promote`, `routine_register`, `routine_add`, `routine_remove`, `discord_provision` und `telegram_provision`.

Der Inhaber kann Tools mit `auth.key_tools` und Sendeziele mit `auth.key_targets` begrenzen. Die Einstellung `auth.key_scopes` begrenzt Routing, Nachrichten und Unterhaltungen. Gedächtnis-Tools nutzen die Freigaben, die SwB für jeden gekoppelten Schlüssel speichert.

## Nachrichten

| Tool | Zweck |
| - | - |
| `send` | Schreiben Sie die Aufgabe oder Nachricht in `task`. Mit `to` wählen Sie ein Ziel. Lassen Sie `to` leer, um eine Route zu verwenden, sofern der Schlüssel es erlaubt |
| `agent_send` | Veraltetes Tool. Übergeben Sie den Agentennamen in `to`, zum Beispiel `to="codex"`. `blocks.mcp.legacy_aliases` aktiviert es standardmäßig. Für neue Aufrufe verwenden Sie `send` mit `to="agent:codex"` |
| `wait` | Wartet auf neue Nachrichten oder Antworten |
| `inbox` | Liest Ihren Posteingang und kehrt sofort zurück. Mit `peek=true` lesen Sie und behalten Ihre Position |
| `inbox_ack` | Setzt Ihre Position im Posteingang nach einem Lesen mit `peek` auf `cursor`. Einträge bis zu diesem Cursor gelten als gelesen |
| `reply` | Übergeben Sie das `handle` aus einem `send`-Aufruf oder einem Posteingangseintrag in `conversation`. Schreiben Sie die Antwort in `text` |
| `status` | Zeigt den Zustand einer Unterhaltung. Für Capy legen Sie mit `messages` die Anzahl der letzten Nachrichten fest. Mit `include_tools=true` erscheinen auch Tool-Aktivitäten |
| `switchboard_status` | Zeigt Ihre Anmeldeidentität, Wartelimits, Blöcke und den Zustand der Instanz |
| `result` | Holt die abschließende Antwort einer Unterhaltung. Mit `tail` legen Sie, wo unterstützt, die Anzahl der letzten Antworten oder Nachrichten fest |
| `cancel` | Beendet die Verfolgung einer Unterhaltung |
| `targets` | Listet die verfügbaren Zieladressen auf. Ihr Schlüssel und die Regeln des Ziels bestimmen, wohin Sie senden dürfen |
| `get_message` | Liest eine gespeicherte Nachricht mit der `message_id` aus Ihrem Posteingang oder einem MCP-Ereignis |

Mit `to="agent:owner"` in `send` richten Sie eine Nachricht an den Inhaber. SwB wählt den empfangenden Agenten nach den [Regeln für Inhabernachrichten](/de/docs/config#owner-messages).

### Posteingangsposition

Ein Cursor markiert eine Position im Posteingang. `inbox` und `wait` speichern eine neue Position, wenn sie Einträge zurückgeben. Mit `peek=true` behält `inbox` die Position. Rufen Sie `inbox_ack` mit dem höchsten Cursor auf, den Sie bearbeitet haben. Filter können eine separate Position weiterschieben. Ein späteres `wait` liest ab der gespeicherten Position. Übergeben Sie `since_cursor=0` an `inbox`, um von Anfang an zu lesen. Übergeben Sie einen zurückgegebenen `cursor` als `since_cursor`, um ab dieser Position fortzufahren.

Skripte können `GET /inbox/poll` mit einem Bearer-Schlüssel aufrufen, um auf Einträge im eigenen Posteingang zu warten. Übergeben Sie den zurückgegebenen `cursor` als `after`, um fortzufahren. Standardmäßig beginnt der Aufruf am aktuellen Ende des Posteingangs. Der Aufruf kehrt zurück, sobald Einträge eintreffen oder die Wartezeit endet. Den MCP-Cursor lässt er unverändert. Mit dem [Ereignisstrom des Posteingangs](/de/docs/connect#ereignisstrom-des-posteingangs) empfangen Sie Nachrichten, sobald sie eintreffen. Mit `inbox` lesen Sie Kontexteinträge und Watch-Zusammenfassungen, die Ihre Anmeldung sehen darf.

Bei einem gekoppelten Schlüssel liefert eine Nachricht oder Unterhaltung außerhalb seines Zugriffs denselben Fehler wie eine fehlende ID. Lesen Sie [Schlüssel mit Beschränkungen](/de/docs/security#schlüssel-mit-beschränkungen).

### Sendeoptionen

| Option | Zweck |
| - | - |
| `wait_s` | Zeit in Sekunden, die SwB auf die erste Antwort eines Blocks wartet. SwB wendet das Wartelimit des Agenten an. Für Agentenpostfächer verwenden Sie `wait` |
| `forward` | Übergeben Sie die ID einer passenden Unterhaltung, die Sie mit der Vertrauensstufe `owner` erhalten haben. SwB sendet die abschließende Antwort an den ursprünglichen Absender |
| `new_conversation` | `true` startet einen neuen Thread im Projekt des Capy Captain. `false` sendet an den Thread des Capy Captain |
| `files` | Hängt Dateien an eine Capy-Aufgabe an. Geben Sie jeder Datei einen `name` und entweder `text` oder `base64` als Inhalt. Mit `media_type` legen Sie den Dateityp fest |
| `repos` | Übergeben Sie die Repositories für eine Capy-Aufgabe als Namen im Format `owner/repo`. Verwenden Sie Repositories, die mit dem SwB-Projekt verknüpft sind |
| `in_reply_to` | Um auf eine Nachricht zu antworten, verwenden Sie statt dieser Option `reply` mit `conversation` |

## Gedächtnis und Projekte

Verwenden Sie die Anmeldung des Inhabers oder Zugangsdaten mit einer Freigabe für den Gedächtnisbereich. Um als Agent einen Eintrag zu aktualisieren, zu verschieben oder zu löschen, verwenden Sie die Zugangsdaten, die ihn zuletzt geschrieben haben. Der Inhaber kann jeden Eintrag verwalten. Änderungen an einem vorhandenen Eintrag in `general` erfordern Inhaberzugriff.

| Tool | Zweck |
| - | - |
| `context_pack` | Liest eine Projektübersicht. Sie enthält `general` nur, wenn die Zugangsdaten diesen Zugriff haben. Bei einem gekoppelten Schlüssel zeigt der Capy-Abschnitt die Aufgaben seines Agenten innerhalb seiner Unterhaltungsbereiche |
| `memory_write` | Speichert in einem freigegebenen Bereich. Übergeben Sie `scope`, `namespace`, `title` und `body`. Ein Namespace gruppiert Einträge innerhalb eines Bereichs. Verwenden Sie bis zu drei Ebenen in Kleinbuchstaben, zum Beispiel `notes/meetings`. Für Projektgedächtnis übergeben Sie dasselbe Projekt in `project` und `scope`. Bevor Sie in `general` schreiben, bitten Sie den Inhaber um Bestätigung. Setzen Sie danach `confirm_general=true` |
| `memory_search` | Sucht mit `query`. Mit `project` durchsucht SwB dieses Projekt und freigegebenes Gedächtnis in `general`. Mit `include_general=false` durchsucht SwB nur dieses Projekt. Mit `scopes` nennen Sie genaue Freigaben wie `agent:<name>` |
| `memory_list` | Listet Einträge mit denselben Bereichsangaben wie `memory_search` auf |
| `memory_read` | Liest einen Eintrag mit seinem Verlauf in einem freigegebenen Bereich |
| `memory_delete` | Entfernt einen Eintrag in einem freigegebenen Bereich |
| `memory_move` | Verschiebt einen Eintrag in einen Projekt- oder Agentenbereich. Sie brauchen Freigaben für beide Bereiche |
| `memory_promote` | Verschiebt einen Eintrag nach `general`. Verwenden Sie die Anmeldung des Inhabers |
| `memory_summary` | Lädt zu Beginn einer Sitzung einen kurzen Index des freigegebenen Gedächtnisses |
| `memory_view` | Zeigt einen Ordner oder eine Datei unter `/memories`. Siehe [Gedächtnis](/de/docs/memory) |
| `memory_create` | Erstellt eine Datei in einem Themenordner |
| `memory_str_replace` | Ändert eine genaue Textstelle in einer Datei |
| `memory_insert` | Fügt Text nach einer Zeile ein |
| `memory_rename` | Verschiebt eine Datei oder einen Themenordner an einen neuen Pfad |
| `memory_history` | Zeigt jede Änderung an einem Eintrag |
| `memory_restore` | Stellt eine frühere Version eines Eintrags wieder her |
| `memory_sync` | Kopiert Erinnerungen aus dem eigenen Gedächtnis des Agenten in SwB |
| `memory_settings` | Schaltet die Gedächtnissynchronisierung ein oder aus. Verwenden Sie die Anmeldung des Inhabers |
| `memory_export` | Lädt das gesamte Gedächtnis als ZIP-Datei herunter. Verwenden Sie die Anmeldung des Inhabers |
| `memory_import` | Lädt das Gedächtnis aus einer ZIP-Datei. Verwenden Sie die Anmeldung des Inhabers |
| `memory_backup_configure` | Legt das Repository für die Git-Sicherung fest. Verwenden Sie die Anmeldung des Inhabers |
| `memory_backup_status` | Zeigt den Status der Git-Sicherung. Verwenden Sie die Anmeldung des Inhabers |
| `memory_backup_now` | Startet sofort eine Git-Sicherung. Verwenden Sie die Anmeldung des Inhabers |
| `memory_backup_restore` | Lädt das Gedächtnis aus der Git-Sicherung. Verwenden Sie die Anmeldung des Inhabers |
| `project_list` | Listet Projekte und ihre Verknüpfungen auf |
| `project_create` | Erstellt ein Projekt |
| `project_update` | Benennt ein Projekt um, verknüpft oder archiviert es oder macht es privat |
| `project_sync` | Verknüpft Projekte erneut mit ihren Gegenstücken |

Mit `links` in `project_update` setzen Sie diese Werte. SwB bietet die Verknüpfungsschlüssel für die konfigurierten Agenten und Blöcke an.

| Schlüssel | Wert |
| - | - |
| `repos` | Liste von Repository-Namen im Format `owner/repo` |
| `claude_project` | Name oder ID des Claude-Projekts |
| `chatgpt_project` | Name oder ID des ChatGPT-Projekts |
| `capy_project` | Name oder ID des Capy-Projekts |

Für ein privates Projekt brauchen Sie eine Freigabe, die dieses Projekt nennt, oder Inhaberzugriff. Für `memory_search` und `memory_list` nennen Sie das private Projekt in `project`. Mit `scopes` nennen Sie weitere öffentliche Projekte, auf die Sie Zugriff haben.

## Routen

Eine Route wählt ein Ziel für `send`. Verwenden Sie einen Block, der Routen annimmt, zum Beispiel `capy`, `claude-routine` oder `grok-routine`. Mit `to="agent:<name>"` erreichen Sie das Postfach eines Agenten direkt. Mit `to="agent:muse"` senden Sie an das Postfach von Muse.

| Tool | Zweck |
| - | - |
| `routes_list` | Listet alle Routen auf, auch Postfachrouten |
| `routes_set` | Speichert eine Route. Geben Sie als `target` ein Agentenpostfach wie `agent:<name>` oder eine Blockadresse wie `capy:captain:<name>` an. Mit `agent` oder `project` grenzen Sie die Route ein |
| `routes_resolve` | Zeigt die passende Route für ein Ziel. Übergeben Sie `block`, zum Beispiel `grok-routine` oder `agent` |
| `routes_remove` | Entfernt die Route für genau dieses `agent` und `project` im gewählten `block` |

Mit `block` prüfen oder entfernen Sie eine Route für ein einzelnes Ziel. Standardmäßig prüft `routes_resolve` zuerst Agent und Projekt zusammen, dann das Projekt, dann den Agenten und zuletzt die globale Route. Auf jeder Ebene prüft es die Blöcke der Reihe nach und danach `agent`. Standardmäßig prüft `routes_remove` dieselbe Reihenfolge für genau diesen Agenten und dieses Projekt.

### [Webhooks](/de/docs/blocks/webhooks)

| Tool | Zweck |
| - | - |
| `webhook_create` | Erstellt einen benannten eingehenden oder ausgehenden Webhook |
| `webhook_list` | Listet Webhooks mit ihren Adressen, Zählern und dem Status des Secrets auf |
| `webhook_rotate` | Holt einen Claim-Link für ein neues Secret und legt optional eine Übergangsfrist fest |
| `webhook_revoke` | Stoppt einen Webhook und löscht seine gespeicherten Secrets |
| `webhook_test` | Sendet ein Beispielereignis an SwB oder eine Testnachricht an den Empfänger |

Für ausgehende Webhooks akzeptieren `webhook_create` und `webhook_rotate` die Felder `allow_private` und `senders`. Setzen Sie `allow_private` auf `true` für private HTTPS-Empfänger oder andere Ports als 443. Tragen Sie verbundene Agenten in `senders` ein, damit sie senden können. Standardmäßig kann nur der Inhaber senden. Lassen Sie beide Felder in `webhook_rotate` weg, um ihre aktuellen Werte zu behalten.

Wenn SwB eine Nachricht an ein Ziel `webhook:out` ablehnt, gibt SwB einen MCP-Tool-Fehler zurück. Bei HTTP-Aufrufen hat die Antwort den Status `200`, und im Tool-Ergebnis ist `isError` auf `true` gesetzt.

Für andere Aufrufer als den Inhaber gibt SwB `No such target.` zurück, wenn das Ziel fehlt oder außerhalb ihrer Freigaben liegt.
