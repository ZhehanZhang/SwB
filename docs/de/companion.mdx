Ein **Companion** ist ein Gerät, das sich mit Ihrem SwB-Server verbindet. Agenten können danach Funktionen auf diesem Gerät nutzen.

## Gerät koppeln

Bitten Sie einen Agenten, der als Inhaber angemeldet ist, `companion_code` aufzurufen. Bitten Sie den Agenten, den Code in einer Datei mit den Berechtigungen `0600` zu speichern. Mit diesen Berechtigungen hat nur der Eigentümer der Datei Zugriff.

Um einen Code in der Konsole zu erhalten, [melden Sie sich mit einem Passkey an](/de/docs/owner-login#passkey). Öffnen Sie **Settings**. Wählen Sie unter **Connections** die Option **Pair a device** aus. Wenn Sie Cloudflare Access verwenden, nutzen Sie das Tool `companion_code`.

Führen Sie diesen Befehl auf dem Gerät aus. Ersetzen Sie die Beispieladresse durch Ihre HTTPS-Adresse von SwB. Für SwB auf diesem Gerät verwenden Sie `http://127.0.0.1:8870`.

```sh
uvx swb-one companion connect https://swb.example.com --cap notify
```

Geben Sie den Kopplungscode an der verdeckten Eingabeaufforderung ein. Der Code gilt einmalig und läuft nach 10 Minuten ab. Das Audit-Protokoll vermerkt, wer ihn erstellt hat.

Das Gerät speichert seinen eigenen Schlüssel in einer privaten Datei.

## Funktionen wählen

Fügen Sie für jede Funktion, die Sie aktivieren möchten, eine Option `--cap` hinzu.

| Option | Funktion |
| --- | --- |
| `--cap notify` | Zeigt Desktop-Benachrichtigungen auf dem Gerät |
| `--cap drop` | Teilt Dateien bis 10 MiB pro Datei über den Ordner `~/SwB Drop` |
| `--cap mcp --mcp NAME=COMMAND` | Gibt Ihren Agenten Zugriff auf die Tools eines MCP-Servers auf dem Gerät |
| `--cap herdr` | [Herdr](/de/docs/blocks/local-sessions#herdr) |
| `--cap codex` | [Codex-App-Server](/de/docs/blocks/local-sessions#codex) |
| `--cap opencode` | [OpenCode-Server](/de/docs/blocks/local-sessions#opencode) |
| `--cap dsh` | [DeepSeek Harness](/de/docs/blocks/local-sessions#deepseek-harness) |
| `--cap hooks` | [Status-Hooks](/de/docs/blocks/local-sessions#status-hooks) |
| `--cap muse` | Koppelt Muse über Bluetooth auf einem Mac oder einem Linux-Computer |

Unter Linux nutzen Benachrichtigungen `notify-send`. Unter Debian und Ubuntu installieren Sie es mit dem Paket `libnotify-bin`.

Verwenden Sie Python 3.13, um das Muse-Gadget zu koppeln. Folgen Sie der [Anleitung zur Muse-Kopplung](/de/docs/setup/muse). Nach der Kopplung hält der SwB-Server die Verbindung zu Muse offen.

```sh
uvx --python 3.13 --from 'swb-one[companion]' swb companion connect https://swb.example.com --cap muse
```

Fügen Sie für jeden MCP-Server eine Option `--mcp` hinzu. Für ein Programm verwenden Sie `--mcp 'NAME=COMMAND'`. Ersetzen Sie `NAME` durch einen Namen für Ihren Server. Ersetzen Sie `COMMAND` durch den Startbefehl des Programms. Für einen HTTP-Server auf dem Gerät verwenden Sie seine lokale Adresse, zum Beispiel `--mcp notes=http://127.0.0.1:8000/mcp`.

Ihre Agenten sehen mit `companion_list` jedes gekoppelte Gerät und seine Aktionen. Mit `companion_invoke` führen sie eine Aktion aus.

Textergebnisse eines Companions sind auf 1 MiB begrenzt. Lesen Sie die Dateidaten von Drop aus `structuredContent.result.content_b64`.

## Lokale Sitzungen

Eine **lokale Sitzung** ist die offene Unterhaltung eines Coding-Agenten auf dem Gerät. SwB zeigt ihren Status zusammen mit ihrer Adresse `local:session:<companion>:<harness>:<session>` an.

Verwenden Sie den Link für Ihren Coding-Agenten in der Funktionstabelle. Richten Sie den Agenten vor der Kopplung ein. Lassen Sie den Companion nach der Kopplung laufen. Bitten Sie einen Agenten, der als Inhaber angemeldet ist, `targets(block="local")` aufzurufen. Prüfen Sie, ob Ihre Sitzungsadresse erscheint.

SwB versucht, jede Nachricht an die offene Sitzung zuzustellen. Die Nachricht landet im Postfach des Agenten, wenn der Absender dieses Postfach nutzen darf. Die Antwort kommt in derselben Unterhaltung zurück.

Verwenden Sie die Sitzungsadresse aus `targets`. Suchen Sie die Ressource für diese Adresse in `visibility_list`. Geben Sie die Ressource mit `visibility_set` frei.

Befehle und unterstützte Agenten beschreibt [Lokale Sitzungen](/de/docs/blocks/local-sessions).

## In Betrieb halten

Die Kopplung startet den Companion. Mit `swb companion run` starten Sie ihn erneut. Mit `swb companion status` sehen Sie die lokale Geräte-ID und die Funktionen.

Ersetzen Sie `swb` durch `uvx swb-one`, um diese Befehle mit `uvx` auszuführen. Für Muse behalten Sie die Paket- und Python-Optionen aus der [Muse-Anleitung](/de/docs/setup/muse) bei.

Das Gerät baut jede Verbindung zu SwB selbst auf.

## Trennen

Führen Sie `swb companion disconnect` auf dem Gerät aus, um seinen Schlüssel zu entfernen. Um den Schlüssel in der Konsole zu widerrufen, öffnen Sie **Connections** unter **Settings**. Wählen Sie für das Gerät **Disconnect** aus.

Ein laufender Companion entfernt seinen lokalen Schlüssel, sobald er den Widerruf erkennt. Wenn noch ein Schlüssel auf dem Gerät liegt, führen Sie `swb companion disconnect` aus, bevor Sie es erneut koppeln.
