## Auf dem eigenen Server

### Docker Compose [#docker-compose]

Installieren Sie Docker Compose 2.24 oder neuer. Docker Compose führt SwB in einem Container aus. Führen Sie diese Befehle als der Benutzer aus, dem der Datenordner gehört.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Bei einem entfernten Server leiten Sie dessen Port `8870` auf Port `8870` Ihres Computers weiter. Öffnen Sie den Einmal-Anmeldelink innerhalb von fünf Minuten. Behandeln Sie den Link vertraulich.

Ihr Browser verwendet `http://localhost:8870` für die Anmeldung. Der Befehl im Container verwendet Port `8000`. Compose speichert die Daten in `./data`. Führen Sie `docker compose up -d` aus, nachdem Sie `.env` geändert haben.

Eine Anfrage ohne Anmeldung an `/healthz` gibt `status` und `version` zurück. Für vollständige Statusdetails verwenden Sie eine Inhabersitzung oder den Inhaberschlüssel.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

Ein Tunnel verbindet Ihren Server mit Cloudflare und gibt SwB eine öffentliche HTTPS-Adresse. Folgen Sie der Anleitung unter [Cloudflare](/de/docs/cloudflare), um einen Tunnel einzurichten.

## In der Cloud

Verwenden Sie eine einzelne SwB-Instanz mit einem Datenträger unter `/data`. Der Datenträger bewahrt Ihre Daten, wenn die Instanz neu startet. Vorlagen und Skripte für die Plattformen finden Sie in der [Bereitstellungsanleitung](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy).

### Fly.io [#fly]

Verwenden Sie die SwB-Dateien aus dem [Docker-Compose-Beispiel](#docker-compose). Installieren Sie Python 3.11 oder neuer oder installieren Sie [uv](https://docs.astral.sh/uv/). Installieren Sie das [Kommandozeilenwerkzeug von Fly.io](https://docs.fly.io/flyctl/). Melden Sie sich bei Fly.io an.

Hinterlegen Sie eine Zahlungskarte, um im [Free-Plan von Fly.io](https://docs.fly.io/about/free-plan) jeden Monat Nutzung im Wert von 5 $ zu erhalten. Verwenden Sie für diesen Plan Ihre persönliche Organisation. Wenn Sie die vollen 5 $ verbrauchen, rechnet Fly den ganzen Monat zu Standardpreisen ab. Diese Einrichtung kostet in Ashburn etwa 3,84 $ für 30 Tage, zuzüglich Datenübertragung.

Führen Sie `sh deploy/fly.sh my-swb` im SwB-Ordner aus. Ersetzen Sie `my-swb` durch einen eindeutigen App-Namen. Das Skript startet mit `fly deploy --ha=false` eine einzelne Machine. Das Skript prüft die Machine, das Volume und die Adressen.

Öffnen Sie die Anmeldeseite Ihrer App. Kopieren Sie `SWB_SETUP_CODE` aus `.env.swb-setup-fly-my-swb` im SwB-Ordner. Geben Sie den Code in **Setup code** ein. Löschen Sie die Datei nach der Anmeldung.

Details zur Abrechnung finden Sie in den [aktuellen Preisen](https://fly.io/docs/about/pricing/).

### Render [#render]

Öffnen Sie das [Render Blueprint](https://render.com/deploy?repo=https://github.com/ZhehanZhang/SwB/tree/release/1.0). Das Blueprint erstellt einen kostenpflichtigen Webdienst und einen Datenträger mit 1 GB. Öffnen Sie im Dienst **Environment**. Kopieren Sie `SWB_SETUP_CODE`.

### Railway [#railway]

Stellen Sie SwB über die [SwB-Vorlage auf Railway](https://railway.com/deploy/swb) bereit. Verwenden Sie genau ein Replikat. Hängen Sie ein Volume mit 1 GB unter `/data` ein.

Mit dem Hobby-Plan läuft SwB dauerhaft. Er kostet 5 $ im Monat und enthält Nutzung im Wert von 5 $.

Der [Free-Plan](https://docs.railway.com/pricing/free-plan) unterstützt ein Volume mit 0,5 GB. Dienste im Free-Plan schlafen im Leerlauf. Der Plan enthält Nutzung im Wert von 1 $ pro Monat. Das reicht für etwa 100 MB RAM rund um die Uhr. Ein SwB-Test belegte im Leerlauf etwa 107 MiB RAM.

## Anmelden

Öffnen Sie die Anmeldeadresse aus dem Dienstprotokoll. Kopieren Sie `SWB_SETUP_CODE` aus den Diensteinstellungen oder aus der privaten Datei, die der Bereitstellungsbefehl nennt. Fügen Sie den Code in **Setup code** ein. Wählen Sie **Sign in** aus. Fügen Sie einen [Passkey](/de/docs/owner-login#passkey) für spätere Anmeldungen hinzu.
