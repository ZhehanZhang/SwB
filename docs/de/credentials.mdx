---
title: Zugangsdaten
description: Speichern Sie Zugangsdaten für Verbindungen auf einer Einmal-Seite.
---

**Zugangsdaten** sind Werte, die Zugriff auf eine App geben. Ihr Agent sendet einen **Claim-Link**, wenn SwB Zugangsdaten braucht. Der Link öffnet ein Einmal-Formular. Das Formular sendet den Wert aus Ihrem Browser an SwB.

## So funktioniert ein Claim-Link

Melden Sie sich als Inhaber an, um das Formular zu öffnen. Wenn das Formular **SwB owner key** zeigt, geben Sie den Schlüssel auf dieser Seite ein. Der Link gilt einmalig und läuft nach 30 Minuten ab.

![Eine Claim-Seite für ein Token](/shots/token-handoff-light.webp)

SwB verschlüsselt den Wert mit einem Schlüssel in seinem Datenordner. Der Block kann den gespeicherten Wert anstelle einer Umgebungsvariablen nutzen. Wenn Sie beide Werte setzen, verwendet SwB zuerst die Umgebungsvariable.

| Seite | Zweck |
| - | - |
| `/claim/{code}` | Speichert die Zugangsdaten für eine Verbindung. |
| `/routines/claim/{code}` | Speichert ein Token für eine Claude-Routine über einen Einmal-Claim-Link. |
| `/routines/claim/owner/{registration}` | Speichert ein ausstehendes Token für eine Claude-Routine über die Seite **Agents**. |

## Zugangsdaten speichern

Fügen Sie das Token für Discord, Telegram, eine Claude-Routine oder Grok Bot in das Formular ein. Wählen Sie **Save token** aus. Im Webhook-Formular für Grok Bot geben Sie die Adresse ein. Wählen Sie **Save webhook url** aus.

Für die Einrichtung einer GitHub App gibt Ihnen SwB für jeden fehlenden Wert einen eigenen Link. Füllen Sie **App ID**, **Private key** oder **Webhook secret** im jeweiligen Formular aus. Für **Private key** wählen Sie **Upload .pem file** aus oder fügen den vollständigen Inhalt der Datei `.pem` ein. Wählen Sie in jedem Formular **Save** aus.

Starten Sie SwB neu, nachdem Sie das Webhook-Secret von GitHub geändert haben.

Für Slack gibt Ihnen SwB einen Claim-Link pro Workspace, wenn ein Token fehlt. Füllen Sie die Felder im gemeinsamen Formular aus. Wählen Sie **Save** aus.

## Über das Terminal speichern

```bash
swb claim 'https://swb.example.com/claim/...'
```

Verwenden Sie den Befehl für ein einzelnes Textfeld unter `/claim/{code}` oder `/routines/claim/{code}`. Für ein Formular mit mehreren Feldern oder einer Datei verwenden Sie den Browser. Der Befehl verbirgt Ihre Eingabe. Er verwendet standardmäßig den lokalen Server. Für einen entfernten Server setzen Sie `--url` auf dessen SwB-Basisadresse.

## Zugangsdaten ersetzen


| Block | So ersetzen Sie einen Wert |
| - | - |
| Grok Bot | Bitten Sie einen Agenten, `connect` für `grok-bot` mit dem Routinennamen und `replace=url` oder `replace=secret` aufzurufen. |
| Slack | SwB gibt einen Claim-Link für einen Workspace aus, wenn ein konfiguriertes Token fehlt. |
| GitHub | Bitten Sie Ihren Agenten, `connect(what="github", choose={"replace":"secret"})` aufzurufen, um das Webhook-Secret zu ersetzen. `webhook_secret` bewirkt dasselbe. Mit `all` ersetzen Sie zusätzlich die Zugangsdaten der App oder das Personal Access Token. |

Um einen Wert aus der Serverumgebung zu ersetzen, aktualisieren Sie die Umgebungsvariable. Eine App ID aus `blocks.github.app_id` ändern Sie in der Konfigurationsdatei. Starten Sie SwB neu, nachdem Sie die Konfiguration oder das Webhook-Secret von GitHub geändert haben.
