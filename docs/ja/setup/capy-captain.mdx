Capy Captain とは、複数のスレッドをまとめて指揮する Capy のエージェントです。SwB は Captain にタスクを送り、各返信を送信者に返します。

## 始める前に

同じ組織に、Capy のアカウント、プロジェクト、Captain が必要です。サービスユーザーとは、ソフトウェア用の Capy アカウントです。

`capy` ブロックを有効にしてください。Capy の **Settings** → **MCP & plugins** で SwB を追加してください。オーナーの全権限を持つ SwB クライアントを使ってください。

## Captain へのルートを設定する

### API の設定を開く

Capy で **Settings** → **API** を開いてください。正しい組織が開いていることを確認してください。

### 読み取り用のキーを作成する

Captain にアクセスできる個人用の API キーを作成してください。Capy にキーが表示されている間にコピーしてください。

### 読み取り用のキーを保存する

エージェントから届いた受け取りリンクを開いてください。**Token** にキーを貼り付けてください。**Save token** を選択してください。

### SwB を再起動する

エージェントに頼まれたら、SwB を再起動してください。再起動すると、SwB がキーを読み込みます。

### Capy Captain を作成する

必要に応じて Capy Captain を作成してください。Captain が使うプロジェクトと、Captain が動くマシンを選んでください。

### Capy Captain を選ぶ

作業を受け取る Capy Captain をエージェントに伝えてください。

### 送信用のキーを作成する

**Settings** → **API** で、ロールが `read_write` のサービスユーザーを作成してください。そのサービスユーザーにプロジェクトへのアクセスを与えてください。サービスユーザー用のキーを作成してください。

### Capy Captain を共有する

Capy Captain のメニューを開いてください。**Share** を選択してください。サービスユーザーにアクセスを与えてください。ペアリング済みのデバイスで動く Captain の場合は、サービスユーザーにそのデバイスへのアクセスも与えてください。{/* unverified */}

### 送信用のキーを保存する

2 つ目の受け取りリンクを開いてください。**Token** にキーを貼り付けてください。**Save token** を選択してください。

### もう一度 SwB を再起動する

SwB を再起動してください。そのあと、完了したことをエージェントに伝えてください。

## エージェントの動作

エージェントは、オーナーの全権限を持つクライアントから `connect(what="capy-captain")` を呼び出します。SwB が読み取り用のキーを必要とするときは、受け取りリンクを返します。受け取りリンクとは、認証情報を入力するための非公開のページです。

再起動後、`connect` は使える Captain を一覧表示します。エージェントは、作業を受け取る Captain をユーザーに確認します。次に `connect(what="capy-captain", choose={"captain":"<Capy Captain ID>"})` を呼び出します。プロジェクトのルートでは、`choose` に `"project":"<project>"` を追加します。ルートは、作業の送り先を SwB に伝えるものです。

送信にサービスキーが必要な場合、SwB はエージェントにそのキーを求めます。ルートの確認には、`capy_captains`、`routes_list`、`routes_resolve` を使います。

アプリが MCP Events に対応している場合は、`switchboard.message.created` を購読します。必要なときに読む場合は、`wait` か `inbox` を呼び出します。

## 認証情報

| トークン | 表示される場所 | 形式 | 入力する場所 |
| - | - | - | - |
| 読み取り用のキー | **Settings** → **API**。1 回だけ表示 | `capy_` と 43 文字のランダムな文字列 | SwB の受け取りリンクの **Token** |
| 送信用のキー | **Settings** → **API**。1 回だけ表示 | `capy_` と 43 文字のランダムな文字列 | SwB の受け取りリンクの **Token** |

## 接続を確認する

もう一度 `connect(what="capy-captain")` を呼び出すよう、エージェントに頼んでください。`connected` と表示されることを確認してください。ルートに短いテストのタスクを送ってください。Captain のスレッドにタスクが届いたことを確認してください。返信は `result` か `inbox` で読んでください。設定済みの送信キーの名前と状態は、オーナーとして `/healthz` で確認してください。

## 問題を解決する

Capy のキーは、そのアカウントの権限を使います。`connect` が新しい読み取り用のキーを求めたら、Captain にアクセスできるキーを作成してください。

送信がアクセスのエラーで失敗したら、サービスユーザーがプロジェクト、Captain、ペアリング済みのデバイスにアクセスできるかを確認してください。

サーバーの環境にある値は、受け取りリンクで保存した値より優先されます。その値はサーバーの環境で変更し、SwB を再起動してください。

紛失したキーを置き換えるときは、**Settings** → **API** でそのキーを取り消してください。新しいキーを作成してください。受け取りリンクはどれも 1 回だけ使えて、30 分で期限が切れます。
