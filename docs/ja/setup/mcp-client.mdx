MCP は、アプリが外部のツールを使うための標準の方式です。このガイドでは、キーを使ってアプリを SwB とペアリングします。

## 始める前に

Streamable HTTP によるリモート MCP に対応したアプリを使ってください。この方式では、アプリが Web 経由でツールを呼び出します。キーを送るために、アプリが独自のリクエストヘッダーにも対応している必要があります。SwB のオーナー用クライアントか、SwB のパソコンのターミナルが必要です。

アプリと同じパソコンで SwB を起動するときは、空のフォルダーで `uvx swb-one up` を実行してください。ターミナルに表示されるワンタイムのサインインリンクを開いてください。ほかの方法は[インストール](/ja/docs/install)をご覧ください。

Claude、ChatGPT、Grok、コーディングエージェントには、OAuth でサインインする専用のページがあります。これらのアプリには、それぞれのページを使ってください。

このプロンプトを、SwB のオーナー用クライアントか、接続したいアプリに貼り付けてください。

## ローカルのオーナークライアント

ほかのアプリを設定するには、SwB のパソコンにある非公開のクライアントを使ってください。起動時に表示されるローカルの `/mcp` アドレスを使ってください。インスタンスの `.env` にある `SWB_KEY_OWNER` を、`Authorization: Bearer <key>` として使ってください。このキーはオーナーの全権限を与えます。キーは、クライアントの非公開のローカル設定に保存してください。設定ファイルの権限は `0600` にしてください。このキーはローカルの SwB にだけ送ってください。

## クライアントをペアリングする

エージェントがローカルで設定を編集できる場合は、アプリの設定をエージェントに任せてください。キーは、アプリの非公開の設定に保存してください。設定ファイルの権限は `0600` にしてください。

### アプリに名前を付ける

`notes-bot` のような、アプリの短い名前をエージェントに伝えてください。SwB は、そのアプリからのメッセージにこの名前を表示します。
### ペアリングコードを取得する

SwB のオーナーのエージェントに、アプリ名を指定して `connect_code` を呼び出すよう頼んでください。SwB のインスタンスフォルダーで `uvx swb-one connect mcp-client --choose agent=notes-bot` を実行することもできます。`notes-bot` を、実際のアプリの名前に置き換えてください。
### キーを取得する

アプリを動かすパソコンで、ターミナルから非公開のフォルダーを開いてください。`https://swb.example.com` を、実際の SwB のアドレスに置き換えてください。末尾の `/connect` はそのまま残してください。ローカルの SwB では、起動時に表示されるポートを使い、`http://localhost:8870/connect` を使ってください。入力内容を隠すプロンプトに、10 分以内にペアリングコードを入力してください。

```bash
bash -c '
  umask 077
  set -C
  read -rsp "Pairing code: " code || exit
  printf "\n"
  printf "{\"code\":\"%s\"}" "$code" |
    curl -fsS https://swb.example.com/connect -H "Content-Type: application/json" \
      --data-binary @- > .swb-pairing.json
'
```
### キーを安全に保管する

ローカルのエディターで `.swb-pairing.json` を開いてください。コマンドは、応答を権限 `0600` のファイルに保存します。その中の `key` をアプリの設定に使ってください。SwB がキーを返すのは 1 回だけです。
### アプリに SwB を追加する

アプリの MCP 設定に、`swb` という名前のサーバーを追加してください。Streamable HTTP を選んでください。公開された SwB サーバーでは、ファイルにある `mcp_url` を使ってください。ローカルの SwB では、起動時に表示される MCP アドレスを使ってください。
### キーを追加する

アプリの非公開の設定に、`Authorization: Bearer <key>` ヘッダーを追加してください。キーを保存したら、`.swb-pairing.json` を削除してください。

## エージェントの動作

エージェントは、オーナーのサインインで `connect(what="mcp-client")` を呼び出します。SwB は MCP アドレスを返し、アプリ名を尋ねます。エージェントは `choose={"agent":"notes-bot"}` を付けて、もう一度 `connect` を呼び出します。

SwB はその名前用のペアリングコードを作り、`POST /connect` の手順を返します。ペアリングコードとは、10 分間だけ有効な 1 回限りのコードです。アプリがすでにキーを持っている場合、SwB はそのことを伝え、`connect_revoke` のあとでだけ新しいコードを作ります。

SwB サーバーのターミナルで `swb connect mcp-client --choose agent=notes-bot` を実行しても、同じ手順が表示されます。

## 認証情報

| 項目 | 表示される場所 | 形式 | 入力する場所 |
| - | - | - | - |
| ペアリングコード | `connect` か `connect_code` の結果 | `XXXXX-XXXXX`。10 分間有効で 1 回だけ使えます | `POST /connect` のリクエスト |
| エージェントのキー | `POST /connect` の応答。1 回だけ表示 | `swb_` で始まります | アプリの非公開の設定にある `Authorization` ヘッダー |

キーはアプリの非公開の設定に保存してください。SwB は、キーそのものの代わりにキーのハッシュを保存します。

## 接続を確認する

新しいエージェントに `inbox` の呼び出しを頼んでください。オーナーとしてサインインしたエージェントに `connect_list` を呼び出してもらい、新しいキーの最終呼び出し時刻を確認してください。オーナーのエージェントから `agent:notes-bot` にテストメッセージを送ってもらってください。新しいエージェントに、`inbox` で読んで `reply` で回答してもらってください。

## 問題を解決する

`POST /connect` が失敗したら、SwB のアドレスを確認してください。コードの期限が切れたか使用済みの場合は、オーナーに新しいコードを頼んでください。キーが漏れたら、`connect_revoke` で取り消してください。取り消すと、SwB はそのキーを使う呼び出しを拒否します。
