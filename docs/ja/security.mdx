## オーナーは 1 人

SwB のオーナーは 1 人です。オーナーはエージェントのサインインを承認し、SwB のコンソールでアクセスを管理してトークンを保存します。

## エージェントのサインイン

OAuth を使うと、アプリはオーナーの承認を得てサインインできます。SwB は PKCE（S256）を使い、サインインを始めたアプリと完了したアプリが同じであることを確認します。SwB は、各 OAuth トークンを `/mcp` のアドレスに結び付けます。既定では、アクセストークンの有効期間は 1 時間、リフレッシュトークンの有効期間は 30 日です。SwB は、リフレッシュトークンを使うたびに新しいものに置き換えます。OAuth トークンは SHA-256 ハッシュで保存します。ハッシュとは、トークンの確認に使う指紋のような値です。エージェントは、設定済みのキーを使うことも、ペアリングコードをキーに交換することもできます。

## 信頼

SwB は、プラットフォームから届く送信者 ID を確認して、メッセージの信頼レベルを決めます。

| 信頼レベル | 対象 |
| - | - |
| `owner` | オーナー本人と、オーナーがサインインさせたエージェント |
| `external` | ほかの送信者。`known` に登録した人やボットも含みます |

Slack、Discord、Telegram では、`known` を使って、SwB が受け入れるメッセージの送信者を選びます。これらの外部の送信者からのメッセージは `external` のままです。SwB が GitHub の作成者をどう確認するかは、[GitHub のオーナーのアカウント](/ja/docs/blocks/github#オーナーのアカウント)をご覧ください。

**信頼フレーム**とは、SwB が外部のテキストに付けるヘッダーとマーカーです。フレームを付ける前に、SwB は、テキスト内にある SwB のヘッダーやマーカーと同じ文字列を書き換えます。マーカーは `<<<swb-untrusted` と `swb-untrusted>>>` です。エージェントは、その間のテキストを情報としてだけ扱います。

Watch モードの要約の信頼レベルは `external` です。各抜粋には、外部のテキスト用の信頼フレームが付きます。SwB は、GitHub のテキストの項目ごとに作成者を確認します。

[コンパニオン](/ja/docs/companion)のキーは、そのデバイスの接続にだけ使えます。SwB は、キーの確認用にハッシュだけを保存します。SwB はデバイスからの結果を `external` とし、その自由記述のテキストを信頼フレームに入れます。

## 公開範囲

リソースとは、送信先、チャンネル、メモリスコープ、ルート、ツールのことです。既定のアクセスルールは `private` で、オーナーとそのエージェントだけが使えます。リソースは、ワークスペースや特定の人と共有できます。ツールは常に非公開です。外部の送信者が送信先にメッセージを送れるのは、チャンネルと送信先の両方のルールが許可するときです。SwB がメッセージをコンテキストとして保存すると、そのメッセージは情報としてインボックスに入ります。エージェントは眠ったままです。

## 制限付きのキー

ルーティング、メッセージ、会話へのアクセスを制限するときは、`auth.key_scopes` を使います。ペアリング済みのキーが読めるのは、その制限の範囲にある、自分のエージェントのメッセージと会話だけです。

SwB は、ペアリング済みのキーごとにメモリのグラントを保存します。古いグラントを更新するとき、SwB は広いアクセスを持つ有効なペアリング済みのキーに、`general` と、その時点にあるプロジェクトを与えます。`auth.key_scopes` で名前付きのスコープを持つキーには、そのスコープをコピーします。

無制限の OAuth クライアントや設定済みのキーは、オーナーとしてすべてのメモリにアクセスできます。エージェント名ごとにメモリへのアクセスを制限するときは、`auth.key_scopes` を使います。制限付きの認証情報が非公開のプロジェクトを使うには、そのプロジェクトを指定したグラントが必要です。

`auth.key_tools` は、キーが呼び出せるツールを制限します。`auth.key_targets` は、キーの送り先を制限します。

## トークン

トークンは、それぞれの受け取りページで入力してください。SwB は、データフォルダーにあるキーで、保存するトークンを暗号化します。ステータスには、不足している変数の名前だけを表示し、値は隠します。Capy のキーは、既定でリクエストヘッダーに入れて `api.capy.ai` に送ります。

ペアリング済みの各キーのメモリスコープは、**Tokens** を開くと確認できます。グラントを外すときは、スコープの横にある **Remove scope** を選択してください。

新しいペアリング済みのキーは、ペアリングコードを交換したときに、自分のエージェントのスコープを受け取ります。コードで指定したプロジェクトと、`auth.key_scopes.<agent>` で指定したスコープも受け取ります。アクセスを広げるときは、追加のスコープを設定するか、ペアリングコードにプロジェクトを含めてください。そのあと、新しいキーをペアリングしてください。

## 上限

| 上限の対象 | 値 |
| - | - |
| 無効なベアラーキー | 10 分間にアドレスごとに 20 回。超えると HTTP `429` |
| オーナーのアカウント以外の送信者からルーティングされる GitHub イベント | 直近 10 分間に送信者ごとに 5 件 |
| `/register` | 1 時間にアドレスごとに 20 回 |
| `/token` | 10 分間にアドレスごとに 120 回 |
| `/authorize` | 10 分間にアドレスごとに 60 回 |
| `/companion/pair` での誤ったコード | 10 分間にアドレスごとに 10 回。超えると HTTP `429` |
| `/connect` での誤ったコード | 10 分間にアドレスごとに 10 回。超えると HTTP `429` |
| リクエスト本文の既定の上限 | 1 MiB |
| `/mcp` と `/companion/results` のリクエスト本文 | 16 MiB |
| `/companion/emit` のリクエスト本文 | 16,640 バイト |
| `/auth/setup` のリクエスト本文 | 1,024 バイト |
| エージェントの会話あたりのターン数 | 200 |

ベアラーキーの上限は、同じアドレスからの有効なキーにも適用されます。上限が解除されるまで、SwB は対象のエンドポイントで HTTP `429` を返します。

ターン数が上限に達すると、SwB は会話を一時停止します。一時停止は監査ログに記録します。Slack が有効な場合は、オーナーにダイレクトメッセージを送ります。

Capy ブロックは、同じタスクと送信先の以前の会話を返すことがあります。この期間は `blocks.capy.duplicate_window_s` で設定します。既定値は 600 秒です。

## クライアントのアドレス

SwB は、既定で接続元のアドレスを上限と監査記録に使います。`trusted_proxies` か `SWB_TRUSTED_PROXIES` にプロキシを追加すると、SwB はプロキシが送るクライアントのアドレスを使います。クライアントのアドレスを示すヘッダーは、プロキシが確認した情報をもとに設定するよう、プロキシを構成してください。

Cloudflare Tunnel のコネクターや、Docker ネットワーク上のリバースプロキシを追加するときは、[セルフホスティングのガイド](/ja/docs/self-hosting#信頼済みプロキシ)をご覧ください。

## 監査ログ

SwB は、アクセスルールで拒否したツールの呼び出しを記録します。ブラウザーでのサインインの失敗も記録します。対象は、セットアップコード、リンク（使用済み、期限切れ、無効）、パスキー、CSRF の確認、OIDC です。

SwB は、欠落した GitHub Webhook の署名や無効な署名を記録します。一部のブラウザーの失敗と Webhook の拒否では、同じ行の繰り返しを抑えます。失敗の行には理由が表示されます。コード、トークン、署名は伏せたまま記録します。

記録は SwB のページの **Audit** に表示されます。最近の記録は `swb log` で表示できます。メールボックスへの送信の操作名は `send` です。破棄した配信の記録については、[チャンネルモード](/ja/docs/channel-modes#配信を確認する)をご覧ください。

## 問題を報告する

セキュリティの問題は、[SwB の GitHub Security Advisories](https://github.com/ZhehanZhang/SwB/security/advisories) から非公開で報告してください。
