## このパソコンで実行する

{/* prepublication */}

パッケージの公開後、空のフォルダーで `uvx swb-one up` を実行してください。ターミナルに表示されるワンタイムのサインインリンクを 5 分以内に開いてください。SwB は既定で `http://localhost:8870` を使います。`SWB_PORT` を設定すると、SwB はそのポートをアドレスに使います。ソースからのビルドなど、ほかの起動方法は[インストール](/ja/docs/install)をご覧ください。

## 公開アドレスを取得する

Claude、ChatGPT、Grok はクラウドで動きます。SwB にアクセスするには、公開 HTTPS アドレスが必要です。トンネルは、ローカルの SwB サーバーに公開アドレスを与えるしくみです。

[cloudflared](https://developers.cloudflare.com/tunnel/downloads/) をインストールしてください。ターミナルで `cloudflared --version` を実行できることを確認してください。SwB が動いている場合は、先に停止してください。SwB のインスタンスフォルダーで、このコマンドを実行してください。

```bash
uvx swb-one up --tunnel cloudflare
```

SwB が Cloudflare Quick Tunnel を開き、公開 MCP アドレスを表示します。このオプションで再起動するたびに、新しいアドレスになります。アプリに登録したアドレスを更新してください。

Tailscale を使うときは、[Tailscale をインストール](https://tailscale.com/download)してください。Tailscale にサインインしてください。[Funnel](https://tailscale.com/docs/features/tailscale-funnel) を有効にしてください。ターミナルで `tailscale version` を実行できることを確認してください。上のコマンドで `--tunnel tailscale` を使ってください。

独自ドメインの固定アドレスを使うときは、[名前付きトンネル](/ja/docs/cloudflare#named-tunnel)をお読みください。

## 次の手順を確認する

```bash
swb status
```

このコマンドは、サーバーの状態と有効なブロックを表示します。残りのセットアップ作業は **Next steps** で確認してください。`switchboard_status` ツールも次の手順を報告します。

別のアドレスのサーバーを確認するときは、`--url` を指定します。たとえば `swb status --url http://127.0.0.1:8871` を実行します。CLI は、シェルかインスタンスの `.env` にある `SWB_PORT` の値を、既定のローカルアドレスに使います。`swb up` で `--dir` を使った場合は、同じインスタンスフォルダーを `--dir` で渡してください。

## Web ページにサインインする

Web ページには、プロジェクト、エージェント、インボックス、メモリ、監査ログが表示されます。トークンを安全に貼り付ける場所でもあります。

![SwB のサインインページ](/shots/login-light.webp)

新しいリンクを取得するときは、同じインスタンスフォルダーで別のターミナルを開き、このコマンドを実行してください。

```bash
swb login-link
```

このコマンドは、ワンタイムのサインインリンクを表示します。5 分以内にブラウザーで開いてください。`swb status` と同じように、ここでも `--url` と `--dir` を使えます。初めてサインインしたあとは、[パスキー](/ja/docs/owner-login#パスキー)を追加してください。次回からはパスキーでサインインします。セットアップコードとほかの方法については、[オーナーのサインイン](/ja/docs/owner-login)をご覧ください。

## Web コンソール

| ページ | 用途 |
| - | - |
| `/` | サーバーの状態とプロジェクトの一覧を表示します。 |
| `/agents/*` | 登録済みのエージェントを表示し、各エージェントの詳細を開きます。 |
| `/audit` | 変更などのイベントのログを絞り込みます。 |
| `/inbox` | 対応が必要な会話とリクエストを表示します。 |
| `/inbox/:handle` | 1 つの会話のメッセージを読みます。 |
| `/memory/*` | 保存済みのメモを閲覧して検索します。 |
| `/projects/:slug` | 1 つのプロジェクトのルート、履歴、会話、メモリを表示します。 |
| `/connections/:platform` | Slack、Discord、Telegram、GitHub の接続状態と [**Channel modes**](/ja/docs/channel-modes) を表示します。 |
| `/settings` | サーバーの設定を表示し、パスキーを管理します。 |
| `/tokens` | トークンのリクエストと保存済みの認証情報を表示します。 |
| `/about` | SwB のバージョンと有効なブロックの一覧を表示します。 |

## 最初のエージェントを接続する

最初のエージェントにほかのアプリを設定させるときは、オーナー権限を与えてください。サーバーで動くアプリの場合は、ブラウザーでその [OAuth サインイン](/ja/docs/owner-login#エージェントのサインイン)を承認してください。SwB のすべてのツールにアクセスできる接続を使ってください。

SwB を実行しているパソコンで、[ローカルのオーナークライアント](/ja/docs/setup/mcp-client#ローカルのオーナークライアント)を設定してください。クライアントのサインインには、インスタンスの `.env` にある `SWB_KEY_OWNER` を使ってください。このキーは、ローカルの `/mcp` アドレスにだけ送ってください。

最初のエージェントがペアリング済みのキーを使う場合は、オーナー専用の各手順に対応するターミナルコマンドをエージェントに尋ねてください。そのコマンドは SwB のインスタンスフォルダーで実行してください。たとえば `swb connect slack` を実行します。ほかのアプリについては、[エージェントを接続する](/ja/docs/connect)をご覧ください。
