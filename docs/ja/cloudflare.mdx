Cloudflare Tunnel を使うと、SwB に公開 HTTPS アドレスを用意できます。**トンネル**とは、サーバーを Cloudflare につなぐ経路です。トンネルは Cloudflare の無料プランで使えます。

[Docker Compose](/ja/docs/deploy#docker-compose) の手順に従って SwB を起動してください。

<span id="クイックトンネル" />

## クイックトンネル [#quick-tunnel]

一時的なアドレスには、クイックトンネルを使ってください。SwB のサーバーに [cloudflared](https://developers.cloudflare.com/tunnel/downloads/) をインストールしてください。このプログラムは、SwB を Cloudflare につなぎます。サーバーでこのコマンドを実行してください。

```sh
cloudflared tunnel --url http://localhost:8870
```

`.env` の `SWB_PUBLIC_URL` に、ターミナルに表示される HTTPS アドレスを設定してください。設定ファイルに `public_url` がある場合は、同じ値に更新してください。コネクターを[信頼済みプロキシ](#trusted-proxies)に追加してください。設定を反映するために、`docker compose up -d` を実行してください。

アドレスは、トンネルを起動するたびに変わります。OAuth のサインインとパスキーは、このアドレスを使います。固定のアドレスには、名前付きトンネルを使ってください。

<span id="名前付きトンネル" />

## 名前付きトンネル [#named-tunnel]

自分のドメインで固定のアドレスを使うときは、名前付きトンネルを使ってください。

### 始める前に

自分のドメインのトンネルと Access アプリケーションを管理できる Cloudflare アカウントを使ってください。サーバーからポート 7844 で Cloudflare に接続できるようにしてください。

### トンネルを作成する

[Create a tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/) の手順に従ってください。インストールコマンドからトンネルのトークンをコピーしてください。トークンは安全に保管してください。

Compose でコネクターを動かすときは、トークンを `TUNNEL_TOKEN` として `.env` に入れてください。コネクターを起動してください。

```sh
docker compose --profile tunnel up -d
```

ホストで直接コネクターを動かすときは、お使いのシステム向けの Cloudflare のインストールコマンドに従ってください。

Cloudflare にコネクターが表示されたら、**Continue** を選択してください。

<span id="コンソールを保護する" />

### コンソールを保護する [#cloudflare-access]

Cloudflare Access は、SwB のコンソールへのアクセスを自分のアカウントだけに制限します。SwB のホスト名に対して [Access アプリケーションを作成](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)してください。ポリシーのアクションを **Allow** にしてください。**Include** で **Emails** を選択してください。自分のメールアドレスを入力してください。

同じホスト名に、下の表で **Bypass** としているパス用の Access アプリケーションをもう 1 つ作成してください。そのポリシーのアクションを **Bypass** にしてください。**Include** で **Everyone** を選択してください。

| パス | Access ポリシー |
| --- | --- |
| `/mcp`、`/register`、`/token`、`/revoke`、`/.well-known/*` | Bypass |
| `/healthz`、`/connect`、`/avatars/*` | Bypass |
| `/inbox/poll`、`/inbox/events` | Bypass |
| `/companion/*` | Bypass |
| `/github/webhook` | GitHub 向けに Bypass |
| `/hooks/*` | Webhooks と Muse のフック向けに Bypass |
| `/pairing/companion`、`/authorize`、`/inbox` を含む、ほかのすべてのパス | Owner |

SwB は、`/companion/pair` でペアリングコードを確認します。ほかのコンパニオンのリクエストでは、デバイスのキーを確認します。Access を使う場合は、オーナー権限を持つエージェントに `companion_code` の呼び出しを頼んでください。

### エージェントからの HTTP リクエストを許可する

Browser Integrity Check は、エージェントからのリクエストをブロックすることがあります。Cloudflare のゾーンに、これらの SwB のパス用の [Configuration Rule](https://developers.cloudflare.com/rules/configuration-rules/) を追加してください。

`swb.example.com` を、実際の SwB のホスト名に置き換えてください。次のルール式を使ってください。

```text
(http.host eq "swb.example.com" and (
  starts_with(http.request.uri.path, "/mcp") or
  starts_with(http.request.uri.path, "/hooks/") or
  starts_with(http.request.uri.path, "/.well-known/") or
  http.request.uri.path in {"/register" "/token" "/revoke" "/connect"} or
  starts_with(http.request.uri.path, "/inbox/") or
  starts_with(http.request.uri.path, "/companion/")
))
```

ルールで `Browser Integrity Check: Off` を設定してください。SwB は自身のアクセスルールをそのまま適用します。

### SwB のアドレスを設定する

`.env` の `SWB_PUBLIC_URL` に、SwB の公開アドレスを設定してください。

```dotenv
SWB_PUBLIC_URL=https://swb.example.com
```

設定ファイルに `public_url` がある場合は、同じ値に更新してください。

`config/switchboard.yaml` に、チームのドメインと、オーナー用アプリケーションの Audience タグを追加してください。このタグは、トークンを発行したアプリケーションを SwB に伝えます。

| 値 | 確認する場所 | 設定キー |
| --- | --- | --- |
| チームのドメイン | **Zero Trust** → **Settings** | `auth.cloudflare_access.team_domain` |
| Application Audience (AUD) Tag | オーナー用アプリケーション → **Additional settings** | `auth.cloudflare_access.aud` |
| 自分のメールアドレス | オーナー用ポリシー → **Emails** | `auth.owner_emails` |

```yaml
auth:
  owner_emails: [owner@swb.example.com]
  cloudflare_access:
    team_domain: example.cloudflareaccess.com
    aud: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

SwB は、まず `Cf-Access-Jwt-Assertion` ヘッダーからトークンを読みます。次の読み取り元として `CF_Authorization` Cookie を使います。Cookie とは、ブラウザーがリクエストとともに送る値です。SwB は、`team_domain` の公開鍵で RS256 の署名を確認します。トークンの発行者は、`team_domain` の HTTPS アドレスと一致する必要があります。トークンは、`aud` を対象者として指定している必要があります。トークンに発行時刻、開始時刻、有効期限があれば、SwB はそれらを確認します。SwB は、メールアドレスを小文字にして `owner_emails` と比べます。

<span id="信頼済みプロキシ" />

### 信頼済みプロキシ [#trusted-proxies]

リバースプロキシは、リクエストを SwB に渡すサーバーです。`config/switchboard.yaml` の `trusted_proxies` に、プロキシのアドレスか専用のネットワークを追加してください。ネットワークの範囲は、`192.0.2.0/24` のような CIDR 形式で書いてください。

`.env` で `SWB_TRUSTED_PROXIES` を設定することもできます。複数の項目はカンマで区切ってください。YAML の設定が優先されます。

Cloudflare Tunnel では、コネクターのアドレスか専用のネットワークを追加してください。IPv4 のループバック接続では `127.0.0.1/32` を使ってください。Cloudflare のエッジサーバーからの直接の接続には、`cloudflare` の項目を使ってください。

Compose のコネクターで設定を反映するときは、`docker compose --profile tunnel up -d` を実行してください。ホスト上のコネクターでは、`docker compose up -d` を実行してください。

### ホスト名を公開する

トンネルの **Routes** タブを開いてください。**Add route** を選択してください。**Published application** を選択してください。公開するホスト名を入力してください。

Compose のコネクターでは、**Service URL** を `http://switchboard:8000` に設定してください。ホスト上のコネクターでは、`http://localhost:8870` を使ってください。**Add route** を選択して保存してください。

### 接続を確認する

ブラウザーで公開アドレスを開いてください。Cloudflare Access にサインインしてください。[公開アドレスを確認](https://swb.example.com/healthz)して、SwB が応答することを確かめてください。

プライベートウィンドウで `https://swb.example.com/mcp` を開いてください。SwB は、`WWW-Authenticate` ヘッダー付きで `401` を返します。Cloudflare のサインインページが表示された場合は、Bypass のポリシーを確認してください。

## アプリを設定する

ホスト名にアクセスできるようになったら、[接続](/ja/docs/connect)の手順でアプリを設定してください。`https://swb.example.com/mcp` のような公開 MCP アドレスを使ってください。SwB での ID を確認するために、`switchboard_status` を呼び出すようエージェントに頼んでください。
