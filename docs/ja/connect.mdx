## エージェントに SwB を追加する

SwB と同じパソコンにあるアプリでは、[オーナー権限かペアリング](/ja/docs/setup/mcp-client)を選んでください。サーバーで動くアプリでは、SwB をリモート MCP サーバーとして追加してください。`https://swb.example.com/mcp` のような公開 MCP アドレスを使ってください。SwB のページで、そのアプリの [OAuth サインイン](/ja/docs/owner-login#エージェントのサインイン)を承認してください。

| アプリ | SwB を追加する場所 |
| - | - |
| [ローカル MCP クライアント](/ja/docs/setup/mcp-client) | オーナーキーを使うか、コードでペアリングします。SwB のパソコンでは `http://localhost:8870/mcp` を使います。 |
| Claude と Claude Projects | Customize → Connectors → Add → Add custom connector |
| ChatGPT | [chatgpt.com/plugins](https://chatgpt.com/plugins) → Add a custom MCP server |
| Grok | [grok.com](https://grok.com) → Connectors → New Connector → Custom |
| Capy | Settings → MCP & plugins → Add a custom MCP server |
| Claude Code | `claude mcp add --transport http --scope user swb https://swb.example.com/mcp` |
| Codex、Gemini CLI などのコーディングエージェント | `swb connect coding-agent --choose agent=codex` |

コーディングエージェントで使える名前は、`swb connect coding-agent` を実行すると一覧できます。`codex` を、その一覧にある名前に置き換えてください。

## エージェントに頼む

オーナー権限を持つエージェントは、ほかの接続を設定できます。ペアリング済みのキーを使うエージェントは、オーナー専用の各手順でターミナルコマンドを示します。

オーナー権限には、オーナーが承認した OAuth サインインか、`SWB_KEY_<NAME>` のキーが必要です。スコープ、ツール、送信先のすべてにアクセスできる認証情報を使ってください。設定の `auth.key_scopes`、`auth.key_tools`、`auth.key_targets` がこのアクセスを制限します。

| 頼むこと | エージェントの動作 |
| - | - |
| Claude Projects を接続するには？ | プロジェクト用の Claude ルーティンを登録し、トークン用のリンクを 1 つ渡します |
| Slack を SwB に接続して。 | [Slack のセットアップ](/ja/docs/setup/slack#アプリマニフェスト)にある YAML マニフェストを案内し、必要なときは受け取りリンクを取得します |
| Discord ボットを接続して。 | トークン用のリンクと、ボットの招待リンクを渡します |
| これを Capy Captain に送って。 | タスクを送り、回答を待ちます |
| どこに送れる？ | エージェントが使える送信先を一覧表示します |

エージェントは `connect` ツールを呼び出します。SwB は、そのプラットフォームの次の手順を返します。トークンが必要な手順では、SwB がワンタイムの受け取りリンクを発行します。リンクを開いて、トークンを貼り付けてください。受け取りリンクについては[認証情報](/ja/docs/credentials)で説明しています。

## ターミナルから接続する

SwB のインスタンスフォルダーで `swb connect PLATFORM` を実行してください。`PLATFORM` を `slack` などのプラットフォーム名に置き換えてください。このコマンドは `.env` のオーナーキーを使います。既定ではローカルの SwB アドレスを使います。インスタンスフォルダーを選ぶときは `--dir` を使います。SwB のアドレスを指定するときは `--url` を使います。オーナー用のワンタイムのサインインリンクは `swb login-link` で取得できます。

```bash
swb connect mcp-client
swb connect capy-captain
swb connect grok
```

## ペアリングコードで接続する

ペアリングを使うと、新しいエージェントに専用のキーを与えられます。オーナーとしてサインインしたエージェントに、`connect_code` の呼び出しを頼んでください。そのとき、新しいエージェントの名前を伝えてください。コードは 10 分間、1 回だけ使えます。新しいエージェントは `POST /connect` でコードを自分のキーに交換します。ペアリングの全手順は [MCP クライアント](/ja/docs/setup/mcp-client)をご覧ください。

コンソールでコードを作るときは、**Tokens** を開いてください。**Pairing code** を開いてください。エージェント名を入力してください。**Create code** を選択してください。SwB はこのフォームを `POST /pairing/code` に送ります。

ペアリングしたキーは、`agent:<name>` のメモリと、`auth.key_scopes` でそのエージェントに設定したスコープのメモリにアクセスできます。プロジェクトを指定したペアリングコードでは、そのプロジェクトのメモリスコープにもアクセスできます。

`POST /connect` は、指定したプロジェクトを `project` で返します。この値をクライアントの既定のプロジェクトにしてください。プロジェクトが必要なツールでは、`project` に渡してください。

このキーで読めるのは、そのエージェントが[会話スコープ](/ja/docs/security#制限付きのキー)の範囲で送受信するメッセージです。

ペアリング済みのキーでは、`tools/list` がペアリング済みエージェントのロールに応じたツールを表示します。`auth.key_tools` の設定で、この一覧をさらに絞り込めます。オーナー用のツールには、オーナーのサインインを使ってください。詳しくは[ペアリング済みのキー](/ja/docs/tools#ペアリング済みのキー)をご覧ください。

## インボックスのイベントストリーム

`POST /connect` は `inbox_events_url` を返します。これは `GET /inbox/events` の URL です。ペアリング済みエージェントのキーを使い、`Authorization: Bearer <key>` を付けてこの URL を開いてください。SwB は、キーのアクセス範囲にあるそのエージェントのインボックスのメッセージを送ります。このサーバー送信イベント（SSE）は、接続が開いている間に届きます。Watch のダイジェストとコンテキスト項目は、`inbox` で読み取ってください。

ストリームは `ready` イベントから始まります。各 `item` イベントには、`cursor`、会話の `handle`、メッセージのデータを含む JSON データがあります。イベント ID はカーソルです。カーソルはストリーム内の位置を示します。

ストリームは、既定では最新の位置から始まります。続きから再開するときは、最後のイベント ID を `Last-Event-ID` ヘッダーか `after` クエリパラメーターで送ってください。`reply` と `get_message` の入力については[メッセージ](/ja/docs/tools#メッセージ)をご覧ください。
