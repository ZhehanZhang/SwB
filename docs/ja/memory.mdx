title: メモリ
description: エージェントが学んだことを共有し、すべてを自分で管理します。

**メモリ**は、エージェントが SwB を通じて共有するノートの集まりです。1 件のノートが 1 つの**項目**です。項目には、タイトル、Markdown の本文、すべての変更の履歴があります。

## スコープ

**スコープ**は、同じアクセスルールを持つ項目のグループです。各項目は 1 つのスコープに属します。

| スコープ | フォルダー | 用途 |
| --- | --- | --- |
| `general` | `/memories/general/` | すべてのプロジェクトに当てはまる、オーナーについての情報 |
| `project:<slug>` | `/memories/projects/<slug>/` | 1 つのプロジェクトについての情報 |
| `agent:<name>` | `/memories/agents/<name>/` | 1 つのエージェント専用のメモ |

オーナーとしてサインインしたエージェントは、すべてのスコープを読めます。ペアリング済みのキーが読み書きできるのは、オーナーがグラントを与えたスコープだけです。ペアリング済みのキーには、必ず専用のエージェントスコープが付きます。

## ファイルとフォルダー

エージェントには、メモリが `/memories` の下のファイルとして見えます。スコープ内のフォルダーが**トピック**です。たとえば `decisions` や `notes/meetings` です。ファイル名が項目のキーです。

これらのツールは、Claude のメモリツールと同じコマンドを使います。Claude のモデルは、これらのコマンドをすでに知っています。

| ツール | 用途 |
| --- | --- |
| `memory_summary` | セッションの開始時に、メモリの短い索引を読み込みます |
| `memory_view` | フォルダーを表示します。ファイルは行番号付きで表示します |
| `memory_create` | ファイルを作成します |
| `memory_str_replace` | ファイル内の 1 か所の文字列を、完全一致で置き換えます |
| `memory_insert` | 指定した行の後にテキストを追加します |
| `memory_rename` | ファイルを新しい名前、トピック、スコープに移します |
| `memory_delete` | ファイルを削除します |
| `memory_search` | 単語で項目を探し、一致度の高い順に返します |
| `memory_list` | 項目を新しい順に表示します |
| `memory_history` | 項目の変更をすべて表示します |
| `memory_restore` | 項目を以前のバージョンに戻します |

以前のツールの `memory_write`、`memory_read`、`memory_move`、`memory_promote` も引き続き使えます。

SwB は、1 つのスコープに同じ事実を 1 件だけ保存します。エージェントが同じテキストをもう一度保存すると、既存の項目が返ります。

## メモリ同期

**メモリ同期**は、エージェントが自分のメモリに保存した内容を SwB にコピーします。これで、すべてのエージェントがその内容を使えます。Claude、ChatGPT、Grok、Muse、Claude Code、そのほかのメモリシステムで動作します。Muse は、読み取り元として `muse-memory` を使います。

各セットアップ用プロンプトは、エージェントに同期を求めます。セットアップの後、エージェントはオーナーについて覚えている内容を `memory_sync` で送ります。送るのは、すべてのエージェントに知らせたい事実だけです。パスワード、キー、機密性の高い個人情報は、エージェント自身のメモリに残します。その後は、新しい記憶を同じターンの中で同期します。

`memory_sync` は何度実行しても安全です。毎回同じ項目を更新します。SwB でのオーナーの編集と削除が優先されます。後の同期ではオーナーのバージョンが残り、エージェントに競合が報告されます。

`--cap hooks` を付けた[コンパニオン](/ja/docs/companion)は、Claude Code のメモリファイルを保存のたびに同期します。

SwB は、セッションのフォルダー名を使ってスコープを選びます。まず、slug（プロジェクトの短い名前）が一致するプロジェクトを探します。次に、リンク済みのリポジトリ名で一意に一致するプロジェクトを探します。一致したプロジェクトの `private` 設定が `false` のとき、SwB はそのプロジェクトに同期します。一致したプロジェクトが非公開の場合は、同期を行いません。一致するプロジェクトがないフォルダーは、`agent:claude-code` に同期します。

メモリ同期は、既定でオンです。オフにするときは、コンソールで **Memory** を開き、**Memory sync** をオフにしてください。オーナーとしてサインインしたエージェントは、`memory_settings` で同じ設定を切り替えられます。

## 来歴

**来歴**は、だれがいつ項目を書いたかの記録です。SwB は、項目を作ったエージェントと、最後に変更したエージェントを記録します。

SwB は、エージェントが書いたテキストを別のエージェントに渡すとき、そのテキストに印を付けます。印には、書いたエージェントと日付が入ります。エージェントは、印の付いたテキストを情報としてだけ使います。エージェントに指示できるのは、オーナー自身の指示だけです。

## メモリを管理する

コンソールで **Memory** を開くと、すべての項目を確認できます。項目を選択すると、編集できます。**History** を選択すると、すべての変更を確認できます。変更の **Restore** を選択すると、そのバージョンに戻せます。項目の移動と削除もできます。

エージェントによる変更は、すべて **History** と監査ログに記録されます。どの変更も元に戻せます。

## ダウンロードと復元

**Memory** ページで **Download** を選択すると、すべてのメモリを zip ファイルに保存できます。このファイルには、項目ごとに 1 つの Markdown ファイルが、スコープとトピックごとのフォルダーに入っています。各項目の履歴と来歴を記録した `manifest.json` も入っています。

zip ファイルを読み込むときは、**Restore from file** を選択してください。復元では、欠けている項目を追加し、既存の項目はそのまま残します。SwB は、読み込んだテキストに情報としての印を付け、読み込んだ人を記録します。

オーナーとしてサインインしたエージェントは、同じ作業に `memory_export` と `memory_import` を使えます。

変更された項目を置き換え、以前のバージョンを履歴に残すときは、`overwrite` を `true` にしてください。対象の項目でオーナーの信頼レベルを保つときは、`trust_owner` を `true` にしてください。ほかのエージェントのスコープにある項目は、情報としてのフレームが付いたままです。どちらのオプションも既定値は `false` です。コンソールからのアップロードでは、`POST /api/memory/import` のクエリパラメーターとして渡してください。

## Git にバックアップする

SwB は、オーナーが所有する非公開の Git リポジトリにメモリをコピーできます。コミットは、一連の変更を記録します。SwB は、`2 memory changes by SwB, claude-code` のようなタイトルを使います。コンソールでの変更には、タイトルに `SwB` を使います。

メモリの内容は、すべてこのリポジトリに入ります。非公開のリポジトリを使ってください。

バックアップ用リポジトリへのプッシュ権限は、信頼できる人にだけ与えてください。プッシュ権限を持つ人は、コミットの作成者を設定できます。SwB は、その作成者をもとに信頼レベルを決めます。

コンソールで **Memory** を開いてください。**Git backup** に、HTTPS か SSH のリポジトリのアドレスと、ブランチを入力してください。HTTPS のアドレスでは、そのリポジトリへの書き込み権限があるトークンを貼り付けてください。SSH のアドレスでは、書き込み権限があるデプロイキーを貼り付けてください。SwB は、トークンやキーを暗号化して保存します。

`file://` のアドレスは、HTTPS か SSH のアドレスに置き換えてください。

バックアップの既定の作成者は `SwB <swb@localhost>` です。変更するときは、コンソールの **Author name** と **Author email** を使ってください。`memory_backup_configure` では、`author_name` と `author_email` を使ってください。

SwB は、変更の後 30 秒待ってから、その間の変更をまとめて 1 つのコミットにします。すぐにコミットするときは、**Back up now** を選択してください。プッシュに失敗したときは、SwB が後で再試行します。ステータス行には、最後のバックアップと最後のエラーが表示されます。

最新のコミットからメモリを読み込むときは、**Restore from repository** を選択してください。SwB は、読み込んだテキストに情報としての印を付け、読み込んだ人を記録します。

オーナーとしてサインインしたエージェントは、`memory_backup_configure`、`memory_backup_status`、`memory_backup_now`、`memory_backup_restore` を使えます。`memory_backup_configure` は、トークンやキー用の受け取りリンクを返します。

Git からの復元でも、同じ `overwrite` と `trust_owner` のオプションを使えます。コンソールのエンドポイント `POST /api/memory/backup/restore` に、JSON のフィールドとして渡してください。SwB は、ほかの作成者のコミットから来た内容に、外部の情報としてのフレームを付けます。
