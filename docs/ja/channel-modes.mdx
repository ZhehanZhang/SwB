title: チャンネルモード
description: スペースごとに、SwB がメッセージをどう扱うかを選びます。
---

**スペース**とは、メッセージが届く場所です。Slack のチャンネル、Discord のチャンネルとスレッド、Telegram のグループ、GitHub のリポジトリがスペースです。

| モード | SwB の動作 |
| - | - |
| `off` | オーナーのものも含め、GitHub のイベントをすべて破棄します。Slack、Discord、Telegram では、ほかの人からのメッセージを破棄します |
| `watch` | メッセージをダイジェストにまとめます。ダイジェストとは、最近のイベントの要約です |
| `assist` | エージェントを起こし、コンテキストを読んでスレッドで返信させます |
| `triage` | エージェントを起こし、イベントを確認して対応を選ばせます。既定の対応はスレッドでの返信です |
| `work` | オーナーからのメッセージを処理します |

Slack、Discord、Telegram では、オーナーが送るメンションとダイレクトメッセージは、どのモードでも `work` を使います。チャンネルと送信先へのアクセスは、引き続き公開範囲の設定で管理します。

GitHub で `work` モードを使うときは、スペースの[オーナー一覧](/ja/docs/blocks/github#オーナーのアカウント)に自分のアカウント番号を追加してください。

## モードを設定する

接続ページかプロジェクトページの **Channel modes** でモードを設定してください。YAML でも設定できます。オーナーは `space_mode` で、モード、送信先、プロジェクト、許可する操作を設定できます。

YAML は、SwB の設定ファイルのテキスト形式です。YAML では、`"off"` を引用符で囲んで書いてください。

```yaml
blocks:
  github:
    use: github
    spaces:
      example-org/app:
        mode: "off"
```

SwB はまず保存済みの設定を確認し、次にチャンネルとスペースの設定を確認します。その後、以前のブロック設定、プロジェクトのモード、`modes.default` を確認します。既定値は `off` です。

## 送信先を割り当てる

GitHub、Slack、Discord、Telegram では、`assist`、`triage`、`work` の各モードで、プロジェクトのルートがエージェントを起こせます。SwB は、当てはまる最初の送信先を使います。

| 順番 | 送信先 |
| - | - |
| 最初 | 保存済みの `space_mode` 設定の送信先。チャンネルの設定は、スペース全体の設定を置き換えます |
| 次 | チャンネル、スペース、プロジェクトのモード設定にある YAML の `target`。この順で確認します |
| 次 | `triage` では、`claude-<project>-triage` という名前の使える送信先。Claude のルーティンなどです |
| 次 | スペースの `default_target`、またはその別名の `target` |
| 最後 | プロジェクトのルート |

送信先は `targets` から選んでください。この例では、既存の GitHub スペースにエージェントのメールボックスを割り当てます。

```python
space_mode(block="github", space="acme/app", mode="triage", target="agent:beta")
```

assist モードには `mode="assist"` を使います。割り当てをそのまま残すときは、`target` を省略します。割り当てを消すときは、`target=""` を設定します。

予備の送信先を設定するときは、リンク済みのプロジェクトと送信先のアドレスを指定して `routes_set` を呼び出してください。ロックした Capy のルートには、`capy:captain:<name>` のような送信先を使い、`allow_override=false` のままにしてください。

## 外部の GitHub 送信者を許可する

`visibility_set` で使える名前は、`visibility_list` を呼び出すと確認できます。アドレス `agent:beta` はメールボックスを指します。ルール `target:beta` は、そのメールボックスに送信できる相手を決めます。

```python
visibility_set(resource="channel:github/acme/app", visibility="shared")
visibility_set(resource="target:beta", visibility="shared")
```

アクセスを 1 人の送信者に限るときは、両方のリソースに同じ確認済みの送信者 ID を使ってください。たとえば、両方に `visibility=["github:1234"]` を設定します。

## Watch のダイジェストを読む

間隔は `modes.digest_minutes` で設定します。既定値は 60 分です。間隔が終わるか、イベントが 50 件たまると、SwB はダイジェストを送信先のメールボックスに入れます。オーナー宛てのダイジェストでは、SwB は[オーナー宛てメッセージのルール](/ja/docs/config#owner-messages)に従ってエージェントを選びます。

受け取ったエージェントは、`inbox` か `wait` でダイジェストを読みます。SwB は、同じスペースと送信先の最新の未読ダイジェストに、新しいイベントを追加します。ダイジェストは、合計の件数と、最新の 200 件のイベントを保持します。各イベントには、作成者、抜粋、リンク（ある場合）が表示されます。ダイジェストの信頼レベルは `external` です。

Watch では、エージェントは眠ったままです。ダイジェストはインボックスで読んでください。[GitHub イベントの配信先](/ja/docs/blocks/github)には、引き続き各イベントのコピーが届きます。

## トリアージの操作

トリアージのエージェントは、イベントの情報を読めます。既定で使える操作は、同じスレッドでの `reply` だけです。GitHub のスレッドには `github_reply` を使います。会話 ID を `handle` に渡してください。返信の本文を `text` に入れてください。

エージェントに使わせる操作を増やすときは、`space_mode` か YAML で `actions` を設定してください。返信を続けて使うときは `reply` も含めてください。たとえば `actions=["reply", "notify_owner"]` を使います。

| 操作 | 内容 |
| - | - |
| `label` | GitHub の Issue かプルリクエストにラベルを付けます |
| `comment` | GitHub にコメントを追加します |
| `open_issue` | GitHub の Issue を作成します |
| `link_duplicate` | 重複した GitHub の Issue をリンクしてクローズします |
| `notify_owner` | [オーナー宛てメッセージのルール](/ja/docs/config#owner-messages)に従ってメッセージをルーティングします |

GitHub を変更するには、書き込み権限を持つ GitHub の認証情報が必要です。SwB は、トリアージの操作を監査ログに記録します。

## 配信を確認する

モード、その送信先、その操作、セットアップの問題を確認するときは、`modes_status` を使います。コンソールのモードの行には、割り当て済みのエージェントが表示されます。トリアージでは、SwB が予備の送信先を使うときだけ、既定のエージェントのヒントが表示されます。トリアージに送信先が必要なとき、`space_mode` と `modes_status` はどちらも、トリアージのエージェントを選ぶよう促します。

SwB は、Slack、Discord、Telegram でメッセージを破棄した理由を監査ログに記録します。同じブロック、スペース、チャンネル、理由の組み合わせについて、記録は 10 分ごとに最大 1 件です。

SwB は、破棄した GitHub の Webhook の理由も記録します。理由は **Audit** を開くか、`swb log` を実行して確認してください。
