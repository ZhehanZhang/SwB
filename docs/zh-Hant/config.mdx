SwB 可以只靠環境變數執行。MCP 模組預設啟用。有些模組會在你設定對應的變數後啟用。其他設定可寫進 YAML 檔。YAML 是用純文字記錄設定的格式。

## 執行個體

| 變數 | 用途 |
| - | - |
| `SWB_KEY_OWNER` | SwB 工具與指令使用的擁有者金鑰 |
| `SWB_PUBLIC_URL` | 登入與 MCP 使用的公開位址。遠端伺服器請用 HTTPS，例如 `https://swb.example.com`。 |
| `SWB_HOST` | 接收連線的位址，預設為 `127.0.0.1`。 |
| `SWB_DATA_DIR` | 資料夾。映像檔使用 `/data`。 |
| `SWB_OWNER_EMAILS` | OpenID Connect（OIDC）與 Cloudflare Access 使用的擁有者電子郵件地址。用逗號隔開各地址 |
| `SWB_KEY_<NAME>` | 代理 `<name>` 的金鑰。代理把它當作 bearer 金鑰放在 `Authorization` 要求標頭內 |
| `SWB_CONFIG` | 基礎 YAML 檔的路徑 |
| `SWB_OVERLAY` | 私人覆寫檔的路徑 |
| `SWB_PORT` | HTTP 連接埠。`swb up` 預設為 `8870`。 |

在終端機或執行個體的 `.env` 中設定 `SWB_PORT`。如果託管平台設定了其他連接埠，請用 `--url` 讓用戶端指令連到實際的伺服器位址。

用 `swb up --public-url https://swb.example.com` 指定公開位址。這次執行時，這個選項優先於 YAML 的 `public_url`。YAML 設定優先於 `SWB_PUBLIC_URL`。

用 `--host` 覆寫 `SWB_HOST`。若要在 `0.0.0.0` 或區域網路位址接收連線，請先設定公開位址。

用 `swb up --dir ./my-swb` 讀取該資料夾內的 `.env` 和 `config/switchboard.yaml`。執行 `swb init` 時，請指定同一個 `--dir`。直接執行 `swb up` 時，可用 `SWB_CONFIG` 指定其他設定檔。

`swb status`、`swb login-link`、`swb connect` 和 `swb claim` 用 `--dir` 尋找 `.env`。這四個指令用 `--url` 指定伺服器位址。

伺服器指令都接受 `--dir`，包括 `swb serve`、`swb export`、`swb log`、`swb config migrate`、`swb blocks` 和 `swb targets`。SwB 從指定的資料夾讀取 `.env` 和設定。需要存取資料庫的指令也從該資料夾尋找執行個體的資料。

直接執行 `swb serve` 時，SwB 會讀取終端機環境和設定檔。其他伺服器指令預設採用目前的資料夾。

用 `swb config migrate [file]` 印出第 2 版格式的設定。可傳入 `file` 指定設定檔。省略時，SwB 依序查看 `--dir`、`SWB_CONFIG` 和預設路徑所指定的設定。

## 資料夾

`swb up` 和 `swb init` 都會為新的執行個體建立 `data/` 資料夾。SwB 預設使用這個資料夾。用 `swb up --dir` 可選取其他執行個體的資料夾。

在設定檔或覆寫檔中設定 `data_dir`，即可更改路徑。這項設定優先。SwB 接著依序檢查 `SWB_DATA_DIR` 和 `SWB_DATA`。三項設定都是空值時，SwB 會採用預設路徑。

直接執行 `swb up` 會保留現有設定檔。執行個體已有設定檔而 `data/` 資料夾缺少時，SwB 會到 `~/.local/share/switchboard` 找舊資料庫。如果用了舊資料庫，SwB 會在記錄中提示一次。

在 Linux 與 macOS 上，SwB 將資料夾的權限設為 `0700`。資料庫檔案的權限設為 `0600`。

## 模組

有些模組可以依環境中的憑證啟動。設定方式請參閱[模組](/zh-Hant/docs/blocks)。[發行版環境範例](https://github.com/ZhehanZhang/SwB/blob/release/1.0/.env.example)列出有名稱的工作區和 routine 所用的憑證名稱。

## 設定檔

`swb up` 在執行個體的資料夾內完成初始設定。SwB 將擁有者金鑰和自訂的 `SWB_PORT` 存在 `.env`。檔案權限為 `0600`。

若要在啟動 SwB 前建立檔案，請執行 `swb init`。

```bash
swb init
```

這兩個指令預設會將 `version: 2` 寫入 `config/switchboard.yaml`。用 `swb init --public-url` 可將位址存入此檔。首次執行 `swb up` 時，SwB 會儲存 `--public-url` 或 `SWB_PUBLIC_URL` 的位址。加入 `blocks` 即可指定要載入的模組。將 `CAPTAIN_ID` 換成你的 Capy Captain ID。

```yaml
version: 2
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
blocks:
  mcp: {use: mcp}
  capy: {use: capy, identity: service}
targets:
  aliases: {}
routes:
  - {match: {}, to: capy:captain:CAPTAIN_ID}
```

SwB 優先依 `blocks` 選擇模組。將 MCP 模組的 `enabled` 設為 `false` 即可關閉它。模組仍可從環境變數讀取憑證。

## 覆寫檔

覆寫檔是存放執行個體專用設定的 YAML 檔。把 `local.yaml` 放在基礎設定檔旁，或用 `SWB_OVERLAY` 指定路徑。覆寫檔優先於基礎檔。基礎檔優先於環境變數中的預設值。依名稱分組的設定會合併。覆寫檔中的清單會取代原有清單。

鍵中的 `*` 代表一個名稱或清單項目。

## 核心設定

| 設定鍵 | 用途 |
| - | - |
| `version` | YAML 設定格式版本。使用 `blocks` 時設為 `2` |
| `public_url` | MCP 和登入使用的公開位址。OAuth 讓應用程式在你核准後登入 |
| `data_dir` | 資料目錄的路徑。可在此設定，也可用 `SWB_DATA_DIR` |
| `timezone` | 每日計數與限額使用的時區，預設為 `UTC` |
| `turn_cap` | 對話暫停前的輪數，預設為 `200`。設為 `null` 可關閉上限 |
| `blocks` | 要載入的模組，可用模組類型或自訂名稱命名 |
| `agents` | 依名稱設定代理 |
| `agents.*.label` | 代理的顯示名稱 |
| `targets` | 傳送目標的名稱與優先順序 |
| `targets.aliases` | 將簡稱指向目標名稱或位址 |
| `targets.priority` | 目標同名時的選擇順序，例如 `[capy:captain, agent, project]` |
| `routes` | 初始路由。SwB 保留已設定的路由 |
| `routes.*.match` | 比對代理、專案，或同時比對兩者。全域路由使用 `{}` |
| `routes.*.to` | 路由相符時的傳送位址 |

## 登入與金鑰

| 設定鍵 | 用途 |
| - | - |
| `auth` | 登入與金鑰設定 |
| `auth.owner_emails` | 可透過 OIDC 或 Cloudflare Access 以擁有者身分登入的電子郵件位址 |
| `auth.cloudflare_access` | Cloudflare Access 登入設定。填寫下方兩項並設定 `auth.owner_emails` |
| `auth.cloudflare_access.team_domain` | Cloudflare Access 團隊網域 |
| `auth.cloudflare_access.aud` | Access 應用程式的對象標記 |
| `auth.redirect_uris` | 允許的 OAuth 回呼位址。這份清單會取代內建清單。用 `/*` 比對路徑及其子路徑 |
| `auth.source_names` | 將 OAuth 主機名稱或用戶端名稱的片段對應到登入時使用的代理名稱 |
| `auth.key_scopes` | 依金鑰或代理名稱設定存取範圍，例如 `[project:example]`。這些範圍限制路由、訊息與對話。用設定檔金鑰或 OAuth 用戶端存取記憶時，也適用這些限制。配對時，SwB 會把指定的記憶範圍加到授權中 |
| `auth.key_tools` | 依金鑰名稱設定可呼叫的 MCP 工具，例如 `[send]` |
| `auth.key_targets` | 依金鑰名稱設定可傳送的目標，例如 `[agent:claude]`。使用有這項限制的金鑰時，須指定一個允許的目標 |
| `auth.inbox_keys` | 為每把金鑰指定唯一可讀取的代理收件匣。內建項目為 `channel: claude-code` |

透過 Cloudflare Access 登入時，SwB 先從 `Cf-Access-Jwt-Assertion` 標頭讀取權杖。標頭為空值或缺少時，SwB 會從 `CF_Authorization` Cookie 讀取權杖。Cookie 是瀏覽器隨請求送出的值。SwB 會用 `team_domain` 的公開金鑰驗證 RS256 簽章。權杖的簽發者必須符合 `team_domain` 的 HTTPS 位址。`aud` 必須是權杖的對象之一。權杖若附有簽發時間、生效時間或到期時間，SwB 會檢查該時間。SwB 將電子郵件位址轉成小寫，再與 `owner_emails` 比對。

## 存取權限

| 設定鍵 | 用途 |
| - | - |
| `visibility` | 決定誰能存取各項資源。工具一律維持私有 |
| `visibility.defaults` | 依資源類型設定預設規則。各類型的初始值均為 `private` |
| `visibility.defaults.channel` | 頻道的預設規則 |
| `visibility.defaults.memory` | 記憶範圍的預設規則 |
| `visibility.defaults.route` | 路由的預設規則 |
| `visibility.defaults.target` | 傳送目標的預設規則 |
| `visibility.resources` | 針對指定資源設定規則，例如 `channel:home/#agents`。這些規則優先於該類型的預設規則 |

在 Slack 中，`channel:home/#agents` 是一條頻道規則。在 GitHub 中，同時共用 `channel:github/acme/app` 和 `target:beta`，外部寄件者才可聯絡 `agent:beta`。請參閱[頻道可見度](/zh-Hant/docs/channel-modes#允許外部-github-使用者存取)。

用 `private` 將存取權限限於擁有者及其代理。用 `shared` 開放存取。填入使用者 ID 或 `workspace:home` 這類項目，即可指定共用對象。透過 `visibility_set` 所做的變更優先於此檔。

## GitHub 寄件者信任等級

| 設定鍵 | 用途 |
| - | - |
| `blocks.github.owner_ids` | 預設視為擁有者的 GitHub 數字使用者 ID 清單 |
| `blocks.github.spaces.*.owner_ids` | 取代此空間預設清單的 GitHub 數字使用者 ID 清單 |

GitHub 的信任等級是 `owner` 和 `external`。在 Slack、Discord 和 Telegram，`known` 幫助 SwB 判斷要接受哪些寄件者的訊息。其他寄件者的訊息仍標為 `external`。工作模式的設定方式請參閱[擁有者帳號](/zh-Hant/docs/blocks/github#擁有者帳號)。

## MCP

| 設定鍵 | 用途 |
| - | - |
| `blocks.mcp` | 為 MCP 用戶端提供服務的模組設定 |
| `blocks.mcp.use` | 模組類型，填 `mcp` |
| `blocks.mcp.legacy_aliases` | 保留 `agent_send`、`capy_delegate`、`capy_wait` 和 `capy_reply` 等舊版 MCP 工具名稱。預設為 `true` |
| `blocks.mcp.wait` | 等待回覆的工具呼叫時限 |
| `blocks.mcp.wait.default_s` | 呼叫端省略等待時間時使用的秒數，預設為 `60` |
| `blocks.mcp.wait.max_s` | 最長等待秒數，預設為 `200` |
| `blocks.mcp.wait.agents` | 依代理設定等待時限。Claude Code 預設等待 `45` 秒，最長 `55` 秒 |
| `blocks.mcp.wait.agents.*.default_s` | 該代理預設等待的秒數 |
| `blocks.mcp.wait.agents.*.max_s` | 該代理最長等待的秒數 |

## 記憶與頻道模式

請參閱[頻道模式](/zh-Hant/docs/channel-modes)，了解如何繫結專案路由並設定分流動作。

| 設定鍵 | 用途 |
| - | - |
| `memory` | 記憶的 Markdown 副本設定 |
| `memory.mirror` | 控制 Markdown 副本。設為 `false` 可停止更新 |
| `memory.mirror_dir` | 存放 Markdown 副本的目錄 |
| `memory.mirror_debounce_s` | 記憶更新後，寫入副本前等待的秒數，預設為 `2` |
| `modes` | 設定 SwB 如何處理傳入事件 |
| `modes.default` | 預設模式，初始值為 `off` |
| `modes.projects` | 各專案下空間的預設模式 |
| `modes.assist_max_chars` | SwB 為代理指定的 `assist` 回覆字元上限，預設為 `1500` |
| `modes.digest_minutes` | `watch` 模式彙整事件前的等待分鐘數，預設為 `60`。累計 `50` 則事件時也會傳送摘要 |

## 品牌

```yaml
branding:
  display_name: SwB
  accent_color: "#64748b"
```

| 設定鍵 | 用途 |
| - | - |
| `branding` | 設定 SwB 顯示的名稱、圖示與色彩 |
| `branding.display_name` | 顯示名稱，預設為 `SwB` |
| `branding.accent_color` | 主題強調色，格式為 `#RRGGBB` |
| `branding.icon` | 自訂圖示 |
| `branding.logo_assets_dir` | 存放自訂標誌的目錄 |
| `branding.public_identity` | 內部欄位。本版本固定為 `swb` |
