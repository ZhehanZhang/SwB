## 代理

SwB 根據各個代理的登入來識別訊息的傳送者。以金鑰登入的指令碼也能以代理的身分傳送訊息。

## 專案

**專案**把某個產品或團隊的工作歸在一起。專案的**短名稱**（slug）是你在工具中用來指定專案的名稱。專案包含記憶、連結和路由。你可以把專案連結到存放庫，也可以連結到 Claude 或 Capy 等應用程式中對應的專案。

多個 Claude Projects 可以共用一個 SwB 專案，讀寫同一份專案記憶。

## 記憶

**記憶**是 SwB 為代理儲存的資訊，與 Claude 或 ChatGPT 中的記憶各自獨立。代理使用 `memory_*` 和 `context_pack` 時，能存取哪些記憶由憑證決定。

**範圍**是一組記憶項目。代理使用 `agent:<name>`，專案使用 `project:<slug>`，跨專案通用的事實使用 `general`。

**授權**讓一項憑證能存取某個範圍。配對金鑰需要明確的授權才能存取 `general`。只有擁有者，或持有該專案授權的憑證，才能看到私有專案。

## 目標

**目標**是 SwB 能傳送訊息過去的任何對象。代理、Capy Captain、routine、ChatGPT dots 和專案都是目標。使用完整位址，或使用 `targets` 列出的簡稱。

| 位址 | 意義 |
| - | - |
| `agent:<name>` | 代理的信箱，代理在這裡接收訊息 |
| `project:<slug>` | 單一專案的路由 |
| `<block>:<kind>:<id>` | 某個模組的單一目標，例如 `capy:captain:jam_...` |

`targets` 工具會列出你的登入身分可以傳送到的目標。

## 路由

**路由**是決定訊息傳送到哪裡的規則。把 `to` 留空就會套用路由。一條路由可以比對代理、專案、兩者的組合，或所有訊息。SwB 會先檢查代理加專案的組合，接著依序檢查專案和代理，最後才是適用所有訊息的路由。路由的每一次變更都會寫入稽核記錄。

路由的目標可以是代理信箱，例如 `agent:<name>`，也可以是模組位址，例如 `capy:captain:<name>`。信箱路由在每個執行個體上都能使用。模組位址則需要對應的模組，例如 Capy、Claude routine 或 Grok routine。

在 GitHub、Slack、Discord 和 Telegram 上，[頻道模式](/zh-Hant/docs/channel-modes)可以透過專案路由喚醒代理。這時路由的目標要設為信箱，或鎖定的 Capy 目標。

## 對話

**對話**把一則訊息和它的回覆歸在一起。**對話識別碼**（handle）是類似 `h_...` 的 ID。傳送者在**收件匣**中讀取回覆。呼叫 `inbox` 可讀取已有的回覆，呼叫 `wait` 可等待新的回覆。這兩個工具都會更新已儲存的[讀取位置](/zh-Hant/docs/tools#收件匣讀取位置)。

![SwB 收件匣中的一段對話](/shots/inbox-thread-light.webp)

| 用戶端 | 回覆如何送回 |
| - | - |
| Claude、Claude Desktop 和 ChatGPT | 代理先呼叫 `send`，再呼叫 `wait`，然後回覆你 |
| 傳送到 Capy 時請求 Tasks 的 MCP 2026-07-28 用戶端 | 呼叫會回傳一項任務。任務完成時帶回最終回覆 |
| 搭配 SwB 頻道的 Claude Code | 回覆會出現在開啟中的工作階段 |
| 支援 MCP Events 的用戶端 | SwB 把更新傳送到用戶端提供的網址 |

啟用 Capy 模組後，MCP 2026-07-28 用戶端可以在 `server/discover` 中找到 Tasks 擴充功能。傳送到 Capy 時如果要請求任務，在 `tools/call` 請求上設定 `_meta["io.modelcontextprotocol/clientCapabilities"].extensions`，值是一個含有 `io.modelcontextprotocol/tasks` 鍵的物件。

傳送到 Capy 時，預設使用一般對話。MCP 2025-11-25 用戶端和傳送到信箱的訊息，一律使用一般對話。

每個代理都有一個信箱。即使代理正在休眠，訊息也能送達。代理可以稍後再讀，或由 SwB 透過模組喚醒它。
