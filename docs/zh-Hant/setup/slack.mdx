title: Slack
description: 用機器人和你自己的 Slack 帳號，把 Slack 工作區連接到 SwB。

SwB 透過一個 Slack 應用程式讀取和傳送 Slack 訊息。你用資訊清單建立這個應用程式。資訊清單是一個檔案，裡面寫好應用程式的全部設定。

應用程式使用 Socket Mode。SwB 主動連線到 Slack，因此伺服器可以使用私人網路位址。

## 開始之前

請使用可在工作區建立和安裝應用程式的 Slack 帳號。你的組織可能要求核准應用程式。請以擁有者身分登入 SwB。

## 複製設定提示詞

<SetupPrompt name="slack" lang="zh-Hant" />

把提示詞貼到 SwB 擁有者用戶端。

## 設定 Slack 應用程式

### 開啟 Slack 應用程式設定

開啟 [Slack 應用程式設定](https://api.slack.com/apps)。點選 **Create New App** → **From a manifest**。
### 選擇工作區

選擇你的工作區。點選 **Next**。
### 貼上資訊清單

選擇 **YAML**。複製下方其中一份應用程式資訊清單。貼上完整內容。
### 建立應用程式

點選 **Next** → **Create**。
### 建立應用程式層級權杖

點選 **Basic Information** → **App-Level Tokens** → **Generate Token and Scopes**。輸入權杖名稱。
### 加入權限範圍

點選 **Add Scope** → `connections:write`。點選 **Generate**。
### 安裝應用程式

點選 **Install App** → **Install to Workspace**。以 SwB 代表的 Slack 使用者身分點選 **Allow**。
### 在 Enterprise Grid 中取得核准

如果 Slack 要求核准，請將應用程式交給工作區或組織管理員。

### 儲存權杖

開啟該工作區的領取連結。把每個 Slack 權杖貼到對應欄位。
### 邀請機器人

如果使用機器人，請在每個要接上 SwB 的頻道傳送 `/invite @<bot name>`。
### 找出工作區 ID

在瀏覽器開啟 Slack。把網址中的工作區 ID 交給代理。ID 以 `T` 開頭。

## 應用程式資訊清單

### 機器人和你的帳號

```yaml
# Example Slack app for an agent-to-agent workspace: a bot user and the owner's user token.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
# The bot's @handle and member-list profile come from features.bot_user.display_name and the
# app icon; they do not change per message. Per-message name/avatar = personas (chat:write.customize).
display_information:
  name: SwB
  description: Agent switchboard for the owner's assistants
  background_color: "#1d2733"
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: swb
    always_online: true
oauth_config:
  scopes:
    bot:
      - app_mentions:read      # @mentions -> push kind "mention"
      - channels:history       # watched public channels the bot is in
      - channels:read
      - groups:history         # watched private channels the bot is in
      - groups:read
      - im:history             # DMs to the bot -> push kind "dm"
      - im:read
      - im:write               # approval DMs to the owner
      - chat:write
      - chat:write.customize   # personas: per-message username + icon
      - reactions:write        # ack reaction on mentions/DMs
      - users:read             # names in pushed events
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # posts as the owner (policy-gated)
      - reactions:write
      - search:read            # search_messages
      - users:read
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.channels
      - message.groups
      - message.im
  interactivity:
    is_enabled: true           # Approve/Reject buttons, delivered over Socket Mode
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

### 只用你的帳號

```yaml
# Example Slack app for a user-only workspace. No bot user, bot scopes, bot events, or interactivity.
# It never joins or invites; every post appears as the owner.
# Create at https://api.slack.com/apps -> Create New App -> From a manifest -> select your workspace.
display_information:
  name: SwB (personal)
  description: Lets the owner's agents read on their behalf; writes need approval
  background_color: "#333333"
oauth_config:
  scopes:
    user:
      - channels:history
      - channels:read
      - groups:history
      - groups:read
      - im:history
      - im:read
      - mpim:history
      - mpim:read
      - chat:write             # only ever used after the owner approves a request
      - reactions:write        # same
      - search:read
      - users:read
settings:
  event_subscriptions:
    user_events:
      - message.channels
      - message.groups
      - message.im
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

## 代理的工作

代理呼叫 `connect(what="slack")`。SwB 會檢查缺少哪些權杖，再為對應的工作區傳回領取連結。

代理在 `config/switchboard.yaml` 的 `blocks.slack.workspaces` 下新增工作區。代理填入工作區 ID 和權杖名稱，再在 `blocks.slack.agents` 授予存取權。

這個範例用機器人和你的帳號連線到一個工作區。把 `T0DEMO0001` 換成你的工作區 ID。

```yaml
blocks:
  slack:
    use: slack
    enabled: true
    workspaces:
      example:
        team_id: T0DEMO0001
        app_token_env: SWB_SLACK_EXAMPLE_APP_TOKEN
        identities:
          bot:
            token_env: SWB_SLACK_EXAMPLE_BOT_TOKEN
          user:
            token_env: SWB_SLACK_EXAMPLE_USER_TOKEN
    agents:
      claude:
        workspaces:
          example: [bot, user]
```

使用 `switchboard_status` 顯示的代理名稱。每個代理加入一項授權。工作區設定和授權使用相同的工作區名稱。若只用你的帳號，在 `team_id` 同一層加入 `user_only: true`。移除 `identities` 的 `bot`。將授權的身分設為 `[user]`。

`connect` 提示時，請重新啟動 SwB。代理可以用 `slack_workspaces` 檢查每個身分。身分指機器人或你的帳號。

## 憑證

| 權杖 | Slack 顯示位置 | 格式 | 填寫位置 |
| --- | --- | --- | --- |
| 應用程式層級權杖 | **Basic Information** → **App-Level Tokens** | 以 `xapp-` 開頭 | SwB 領取連結 |
| 機器人權杖 | **OAuth & Permissions** → **OAuth Tokens** → **Bot User OAuth Token** | 以 `xoxb-` 開頭 | SwB 領取連結 |
| 使用者權杖 | **OAuth & Permissions** → **OAuth Tokens** → **User OAuth Token** | 以 `xoxp-` 開頭 | SwB 領取連結 |

## 檢查連線

再次呼叫 `connect(what="slack")`，確認結果為 `connected`。呼叫 `slack_workspaces`。確認各身分的 `ready` 和工作區的 `connected` 都是 `true`。

使用機器人時，在頻道提及機器人並寫上目標名稱。請代理用 `slack_events` 或 `slack_wait` 查看訊息。若要測試傳送，請讓有寫入權限的身分用 `slack_post` 傳送訊息。

## 排解問題

如果 SwB 回報 Socket Mode 有問題，請在應用程式設定中開啟 **Socket Mode**。開啟 **Enable Socket Mode**。

如果你修改了應用程式的權限範圍，請重新安裝應用程式。接著透過新的領取連結儲存新權杖。

`slack_search` 用你自己的帳號搜尋。它需要具備 `search:read` 權限範圍的使用者權杖。
