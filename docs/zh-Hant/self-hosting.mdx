## Docker Compose

安裝 Docker Compose 2.24 或更新版本。用擁有資料夾的一般使用者帳號執行以下指令。

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

在五分鐘內開啟終端機顯示的一次性登入連結。請妥善保管連結。

擁有者在瀏覽器中透過 `http://localhost:8870` 登入。容器內的指令使用 `8000` 連接埠。Compose 將資料存放在 `./data`。修改 `.env` 後，請再次執行 `docker compose up -d`。

如果 SwB 在遠端伺服器上執行，先將伺服器的 `8870` 連接埠轉送至本機的 `8870` 連接埠，再開啟連結。

直接存取 `/healthz` 會傳回 `status` 和 `version`。以擁有者身分登入或使用擁有者金鑰，可查看完整的運作狀態。

## <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

Cloudflare 通道讓 SwB 有公開的 HTTPS 位址。Cloudflare 的免費方案包含通道服務。

### 暫時通道

用快速通道提供的暫時位址試用 SwB。`cloudflared` 是將 SwB 接上 Cloudflare 的程式。在 SwB 主機上執行此指令。

```bash
cloudflared tunnel --url http://localhost:8870
```

將 `SWB_PUBLIC_URL` 設為終端機顯示的 HTTPS 位址。若設定檔含有 `public_url`，也更新這個設定項目。重新啟動 SwB。每次啟動通道時，位址都會變更。OAuth 登入和通行金鑰都會綁定這個位址。使用具名通道可保留固定位址。

### 具名通道

使用免費的 Cloudflare 帳號和自己的網域。依照 [Cloudflare 設定指南](/zh-Hant/docs/setup/cloudflare) 建立通道並設定 Access。在 `.env` 中將 `SWB_PUBLIC_URL` 設為公開位址。

```dotenv
SWB_PUBLIC_URL=https://swb-your-team.example.net
```

若設定檔含有 `public_url`，也更新這個設定項目。啟動 SwB 後，[檢查公開位址](https://swb-your-team.example.net/healthz)。

如果通道在 SwB 主機上執行，將服務位址設為 `http://localhost:8870`。將 `SWB_TRUSTED_PROXIES` 設為連接器的位址。IPv4 本機迴路可用 `127.0.0.1/32`。

如果使用 Compose 通道，將服務位址設為 `http://switchboard:8000`。將通道權杖以 `TUNNEL_TOKEN` 為名稱寫入 `.env`。將連接器的位址或專用網路加入 `trusted_proxies`。用通道設定啟動 Compose。

```bash
docker compose --profile tunnel up -d
```

## 信任的代理

反向代理會將要求轉送給 SwB。在 `config/switchboard.yaml` 的 `trusted_proxies` 加入代理的位址或專用網段。以 CIDR 格式填寫網段，例如 `192.0.2.0/24`。

也可以在 `.env` 設定 `SWB_TRUSTED_PROXIES`。請用逗號分隔各項。SwB 優先採用 YAML 內的設定。

如果 Cloudflare 通道與 SwB 共用主機或 Docker 網路，請加入通道連接器的位址或專用網段。連接器會直接連到 SwB。如果 Cloudflare 邊緣伺服器直接連到 SwB，請加入 `cloudflare`。

## Cloudflare Access

依照 [Cloudflare 設定指南](/zh-Hant/docs/setup/cloudflare)設定 SwB，並為擁有者和用戶端要求設定存取規則。

## 託管平台

執行一個 SwB 執行個體。將持久磁碟掛載到 `/data`。[部署指南](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy)說明 Railway、Render 和 Fly.io 的範本及 Koyeb 指令稿。

## Railway [#railway]

使用 [Railway 上的 SwB 範本](https://railway.com/deploy/swb)部署。保留一個執行個體。範本會把儲存磁碟區掛載到 `/data`。

使用 Hobby 方案讓 SwB 持續上線。Hobby 方案每月 5 美元，內含 5 美元的用量額度。

[免費方案](https://docs.railway.com/reference/pricing/free-trial)每月提供 1 美元的用量額度。這筆額度約可全天使用 100 MB 記憶體。測試中的 SwB 執行個體在閒置時約使用 107 MiB 記憶體。用完額度後，免費方案的服務會停止。

## Fly.io [#fly]

使用 [Docker Compose 範例](#docker-compose)下載的 SwB 發行分支。安裝 [Fly.io 命令列工具](https://docs.fly.io/flyctl/)。登入 Fly.io。

在 SwB 資料夾中執行 `sh deploy/fly.sh my-swb`。將 `my-swb` 換成唯一的應用程式名稱。指令稿以 `fly deploy --ha=false` 啟動一部虛擬機器。

開啟應用程式的登入頁。從本機的 `.env.swb-setup-fly-my-swb` 檔案複製 `SWB_SETUP_CODE`。將設定碼填入 **Setup code**。登入後刪除此檔。

計費詳情請參閱 [Fly.io 免費方案](https://docs.fly.io/about/free-plan)和[目前費率](https://fly.io/docs/about/pricing/)。

## 備份與升級

複製資料夾前，先停止 SwB。完整保留資料夾、資料庫和 `mcp-events.key`、`claim-key` 等金鑰。也要備份設定檔和 `.env`。妥善保管備份。安裝或建置新版本。使用原本的資料夾啟動 SwB。

## 匯出記憶

在 Compose 容器中執行匯出。

```bash
docker compose exec -T switchboard swb export /data/export
```

匯出的 Markdown 檔會依範圍存放在主機的 `./data/export` 裡。目錄內還有一份 `INDEX.md`。設定 `memory.mirror_dir` 即可保留隨記憶更新的 Markdown 副本。
