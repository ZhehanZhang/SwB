## 單一擁有者

SwB 只有一位擁有者。擁有者負責核准代理的登入，並在 SwB 主控台管理存取權、儲存權杖。

## 代理的登入方式

OAuth 讓應用程式在擁有者核准後登入。SwB 使用 PKCE 搭配 S256，確認發起登入和完成登入的是同一個應用程式。SwB 把每個 OAuth 權杖綁定到一個 `/mcp` 網址。存取權杖預設有效 1 小時，重新整理權杖預設有效 30 天。每個重新整理權杖使用後，SwB 都會換發新的。SwB 儲存的是 OAuth 權杖的 SHA-256 雜湊值，也就是用來核對權杖的指紋。代理也可以使用已設定的金鑰，或用配對碼兌換一把金鑰。

## 信任

SwB 會核對平台提供的傳送者 ID，據此設定訊息的信任等級。

| 信任等級 | 對象 |
| - | - |
| `owner` | 你本人，以及你自己已登入的代理 |
| `external` | 其他傳送者，包括列在 `known` 中的人和機器人 |

在 Slack、Discord 和 Telegram 上，`known` 協助 SwB 決定接受哪些人的訊息。這些外部傳送者的訊息，信任等級仍為 `external`。SwB 如何核對 GitHub 作者，見 [GitHub 擁有者帳號](/zh-Hant/docs/blocks/github#擁有者帳號)。

**信任框架**是 SwB 加在外部文字上的標頭和標記。加上框架前，SwB 會先改寫文字中與這些標頭或標記相同的內容。標記是 `<<<swb-untrusted` 和 `swb-untrusted>>>`。代理只把兩個標記之間的文字當作資訊。

Watch 模式產生的摘要，信任等級為 `external`。每段摘錄中的外部文字都加上信任框架。SwB 會核對每個 GitHub 文字欄位的作者。

[Companion](/zh-Hant/docs/companion) 金鑰僅適用於所屬裝置的連線。SwB 只保留金鑰的雜湊值，用來核對金鑰。SwB 把裝置回傳的結果標為 `external`，並把其中的自由文字放進信任框架。

## 可見性

資源是指目標、頻道、記憶範圍、路由或工具。預設的存取規則是 `private`，僅限擁有者及其代理存取。你可以把資源分享給某個工作空間或選定的人。工具一律維持私有。頻道規則和目標規則都允許時，外部傳送者才能傳送到目標。SwB 把訊息存為脈絡時，訊息會以資訊的形式進入收件匣，代理則維持休眠。

## 受限的金鑰

用 `auth.key_scopes` 限制路由、訊息和對話的存取權。在這些限制內，配對金鑰只能讀取所屬代理的訊息和對話。

SwB 會為每把配對金鑰儲存記憶授權。升級舊授權時，仍在使用且原本擁有廣泛存取權的配對金鑰，會獲得 `general` 和當時已存在的專案。如果金鑰在 `auth.key_scopes` 中有具名範圍，SwB 會複製這些範圍。

擁有完整權限的 OAuth 用戶端或已設定的金鑰，可以用擁有者的身分存取所有記憶。用 `auth.key_scopes` 可依代理名稱限制記憶存取權。受限的憑證要存取私有專案，需要一項指明該專案的授權。

`auth.key_tools` 限制金鑰可以呼叫的工具，`auth.key_targets` 限制金鑰可以傳送到的目標。

## 權杖

權杖要在對應的認領頁面上輸入。SwB 用資料目錄中的金鑰加密它儲存的權杖。狀態資訊會顯示缺少的變數名稱，並隱藏變數的值。Capy 金鑰預設放在請求標頭中，傳送到 `api.capy.ai`。

開啟 **Tokens** 可查看每把配對金鑰的記憶範圍。選取範圍旁的 **Remove scope**，即可移除該項授權。

新的配對金鑰在兌換配對碼時，會取得自己的代理範圍，以及配對碼中指定的專案和 `auth.key_scopes.<agent>` 中列出的範圍。要擴大存取權，先設定額外的範圍，或在配對碼中加入專案，再配對一把新金鑰。

## 限制

| 限制 | 值 |
| - | - |
| 無效的 Bearer 金鑰 | 每個位址 10 分鐘內 20 次嘗試，之後回傳 HTTP `429` |
| 由擁有者帳號以外的傳送者觸發並經路由處理的 GitHub 事件 | 每位傳送者在最近 10 分鐘內 5 個 |
| `/register` | 每個位址每小時 20 次 |
| `/token` | 每個位址 10 分鐘內 120 次 |
| `/authorize` | 每個位址 10 分鐘內 60 次 |
| `/companion/pair` 的錯誤配對碼 | 每個位址 10 分鐘內 10 次，之後回傳 HTTP `429` |
| `/connect` 的錯誤配對碼 | 每個位址 10 分鐘內 10 次，之後回傳 HTTP `429` |
| 預設的請求主體上限 | 1 MiB |
| `/mcp` 和 `/companion/results` 的請求主體 | 16 MiB |
| `/companion/emit` 的請求主體 | 16,640 位元組 |
| `/auth/setup` 的請求主體 | 1,024 位元組 |
| 每段代理對話的輪數 | 200 |

Bearer 金鑰的限制同樣適用於來自同一位址的有效金鑰。在限制解除前，SwB 會在受影響的端點上回傳 HTTP `429`。

對話達到輪數上限時，SwB 會暫停對話，並把這次暫停寫入稽核記錄。如果 Slack 已啟用，SwB 還會傳私訊給擁有者。

任務和目標都相同時，Capy 模組可以回傳先前的對話。用 `blocks.capy.duplicate_window_s` 設定時間區間，預設為 600 秒。

## 用戶端位址

SwB 預設以連線位址來計算限制和寫入稽核記錄。把你的代理伺服器加進 `trusted_proxies` 或 `SWB_TRUSTED_PROXIES` 後，SwB 就會改用代理伺服器傳來的用戶端位址。代理伺服器要依據它驗證過的來源設定用戶端位址標頭。

用戶端位址解析失敗時，SwB 依轉送標頭分開計算上限。含有無效位址的標頭採用 `invalid-forwarded`。只含受信任代理伺服器位址的標頭採用 `trusted-only-forwarded`。

要加入 Cloudflare Tunnel 連接器或 Docker 網路上的反向代理伺服器，參閱[Cloudflare 設定指南](/zh-Hant/docs/cloudflare#受信任的代理伺服器)。

## 稽核記錄

存取規則拒絕的工具呼叫，SwB 都會記錄。瀏覽器登入失敗也會記錄，涵蓋設定碼、連結（已使用、過期或無效）、密碼金鑰、CSRF 檢查和 OIDC。

GitHub Webhook 缺少簽章或簽章無效時，SwB 也會記錄。部分瀏覽器登入失敗和 Webhook 遭拒的情況重複發生時，SwB 會限制記錄的列數。失敗記錄會列出原因，並隱藏代碼、權杖和簽章。

Cloudflare Access 憑證遭拒時，SwB 每 10 分鐘為每個用戶端位址記錄一次。

SwB 頁面在 **Audit** 下顯示這些記錄。執行 `swb log` 可印出近期的記錄。傳送到信箱的訊息，動作是 `send`。訊息遭到捨棄時會留下哪些記錄，見[頻道模式](/zh-Hant/docs/channel-modes#檢查傳遞狀況)。
