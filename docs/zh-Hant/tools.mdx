`tools/list` 會顯示你的登入身分可以使用的工具。擁有者以完整權限登入時，會看到所有已啟用模組的工具。

## 配對金鑰

配對金鑰可以使用下列工具，以擁有者授予的存取權為限。

| 用途 | 工具與限制 |
| - | - |
| 訊息 | 使用 `send` 和 `targets`。啟用舊版名稱時，使用 `agent_send`。使用 `inbox`、`wait`、`reply`、`status`、`result`、`cancel` 和 `get_message` 時，以金鑰的對話存取權為限 |
| 記憶與專案 | 使用 `context_pack` 和 `project_list`，能存取多少由金鑰決定。記憶工具用在已授權的範圍 |
| 路由 | 使用 `routes_list` 和 `routes_resolve`。使用 `routes_set` 和 `routes_remove` 時，把 `agent` 設為你自己的代理名稱，並使用金鑰範圍內的專案 |
| 設定 | 用 `switchboard_status` 和 `modes_status` 檢查狀態。用 `connect` 取得用戶端的操作說明。設定模組和核發配對碼時，要以擁有者身分登入 |
| 模組 | 使用模組工具，以你獲授予的存取權和頻道模式允許的動作為限 |

`login_link`、`connect_code`、`connect_list`、`connect_revoke`、`visibility_list` 和 `visibility_set` 需要擁有者以完整權限登入。`project_create`、`project_update`、`project_sync` 和 `space_mode` 也一樣。這樣登入後，還能使用 `memory_promote`、`routine_register`、`routine_add`、`routine_remove`、`discord_provision` 和 `telegram_provision`。

擁有者可以用 `auth.key_tools` 限制工具，用 `auth.key_targets` 限制傳送目標。`auth.key_scopes` 設定則限制路由、訊息和對話。記憶工具依據 SwB 為每把配對金鑰儲存的授權運作。

## 訊息

| 工具 | 用途 |
| - | - |
| `send` | 把工作或訊息放進 `task`。設定 `to` 來選擇目標。金鑰允許時，把 `to` 留空即可套用路由 |
| `agent_send` | 已淘汰的工具。把代理名稱傳入 `to`，例如 `to="codex"`。`blocks.mcp.legacy_aliases` 預設會啟用它。新的呼叫改用 `send` 並設定 `to="agent:codex"` |
| `wait` | 等待新的訊息或回覆 |
| `inbox` | 讀取你的收件匣並立即返回 |
| `reply` | 把傳送結果或收件匣項目中的 `handle` 傳入 `conversation`，回覆內容放進 `text` |
| `status` | 顯示單一對話的狀態。在 Capy 上，用 `messages` 指定近期訊息的數量。設定 `include_tools=true` 可包含工具活動 |
| `switchboard_status` | 顯示你的登入身分、等待限制、模組和執行個體的健康狀態 |
| `result` | 取得對話的最終回覆。在支援的情況下，用 `tail` 設定近期回覆或訊息的數量 |
| `cancel` | 停止追蹤某段對話 |
| `targets` | 列出可用的目標位址。能傳送到哪裡，由你的金鑰和目標的規則決定 |
| `get_message` | 用收件匣或 MCP 事件中的 `message_id` 讀取已儲存的訊息 |

### 收件匣讀取位置

讀取位置（cursor）標示收件匣中的一個位置。`inbox` 和 `wait` 工具回傳項目時，會儲存新的位置。篩選條件可以推進另一個獨立的位置。之後的 `wait` 會從已儲存的位置開始讀取。把 `since_cursor=0` 傳給 `inbox`，可以從頭讀取。把回傳的 `cursor` 當作 `since_cursor` 傳入，可以從該位置繼續。

指令碼可以帶著 Bearer 金鑰呼叫 `GET /inbox/poll`，等待自己收件匣中的項目。把回傳的 `cursor` 當作 `after` 傳入即可接續。預設從收件匣目前的結尾開始。有項目抵達或等待時間結束時，呼叫就會返回。MCP 的讀取位置維持原狀。要在訊息抵達時立即接收，使用[收件匣事件串流](/zh-Hant/docs/connect#收件匣事件串流)。要讀取你的登入身分可見的脈絡項目和 Watch 摘要，使用 `inbox`。

對配對金鑰來說，存取權以外的訊息或對話，回傳的錯誤與查無 ID 時相同。詳見[受限的金鑰](/zh-Hant/docs/security#受限的金鑰)。

### 傳送選項

| 選項 | 用途 |
| - | - |
| `wait_s` | 設定等待模組第一則回覆的秒數。SwB 會套用該代理的等待限制。代理信箱改用 `wait` |
| `forward` | 傳入對話識別碼。這段對話要符合條件，而且是你以 `owner` 信任等級收到的。SwB 會把最終回覆傳給原始傳送者 |
| `new_conversation` | 設為 `true` 會在 Capy Captain 的專案中開啟新的討論串。設為 `false` 則傳送到 Capy Captain 的討論串 |
| `files` | 為 Capy 任務附加檔案。每個檔案要提供 `name`，以及 `text` 或 `base64` 內容。用 `media_type` 設定檔案類型 |
| `repos` | 以 `owner/repo` 名稱傳入 Capy 任務的存放庫。使用已連結到 SwB 專案的存放庫 |
| `in_reply_to` | 要回覆訊息時，改用 `reply` 搭配 `conversation`，取代這個選項 |

## 記憶與專案

以擁有者身分登入，或使用持有該記憶範圍授權的憑證。代理要更新、移動或刪除某個項目時，使用最後寫入該項目的憑證。擁有者可以管理任何項目。變更 `general` 中既有的項目需要擁有者存取權。

| 工具 | 用途 |
| - | - |
| `context_pack` | 讀取專案概要。只有憑證獲得存取權時，概要才包含 `general`。配對金鑰看到的 Capy 區段，會顯示所屬代理在對話範圍內的工作 |
| `memory_write` | 儲存到已授權的範圍。傳入 `scope`、`namespace`、`title` 和 `body`。命名空間用來在範圍內將項目分組，最多可用 3 層小寫名稱，例如 `notes/meetings`。寫入專案記憶時，在 `project` 和 `scope` 中傳入同一個專案。要寫入 `general`，先請擁有者確認，再設定 `confirm_general=true` |
| `memory_search` | 用 `query` 搜尋。傳入 `project` 可搜尋該專案和已授權的 `general` 記憶。設定 `include_general=false` 則只搜尋該專案。用 `scopes` 指定確切的授權，例如 `agent:<name>` |
| `memory_list` | 列出項目，範圍參數與 `memory_search` 相同 |
| `memory_read` | 讀取已授權範圍內的單一項目及其歷史記錄 |
| `memory_delete` | 移除已授權範圍內的項目 |
| `memory_move` | 把項目移到專案範圍或代理範圍。兩個範圍的授權都要具備 |
| `memory_promote` | 把項目移到 `general`。要以擁有者身分登入 |
| `memory_summary` | 在工作階段開始時載入已授權記憶的簡短索引 |
| `memory_view` | 顯示 `/memories` 底下的資料夾或檔案。參閱[記憶](/zh-Hant/docs/memory) |
| `memory_create` | 在主題資料夾中建立檔案 |
| `memory_str_replace` | 取代檔案中一段完全相符的文字 |
| `memory_insert` | 在某一行後加入文字 |
| `memory_rename` | 把檔案或主題資料夾移到新路徑 |
| `memory_history` | 顯示項目的每次修改 |
| `memory_restore` | 還原項目的較早版本 |
| `memory_sync` | 把代理自身記憶中的內容複製到 SwB |
| `memory_settings` | 開啟或關閉記憶同步。要以擁有者身分登入 |
| `memory_export` | 把全部記憶下載為 zip 檔。要以擁有者身分登入 |
| `memory_import` | 從 zip 檔載入記憶。要以擁有者身分登入 |
| `memory_backup_configure` | 設定 Git 備份存放庫。要以擁有者身分登入 |
| `memory_backup_status` | 顯示 Git 備份狀態。要以擁有者身分登入 |
| `memory_backup_now` | 立即開始 Git 備份。要以擁有者身分登入 |
| `memory_backup_restore` | 從 Git 備份載入記憶。要以擁有者身分登入 |
| `project_list` | 列出專案及其連結 |
| `project_create` | 建立專案 |
| `project_update` | 重新命名、連結或封存專案，或把它設為私有 |
| `project_sync` | 重新把專案連結到各應用程式中對應的專案 |

在 `project_update` 中用 `links` 設定下列值。SwB 會依已設定的代理和模組，提供對應的專案連結鍵。

| 鍵 | 值 |
| - | - |
| `repos` | 存放庫名稱清單，格式為 `owner/repo` |
| `claude_project` | Claude 專案的名稱或 ID |
| `chatgpt_project` | ChatGPT 專案的名稱或 ID |
| `capy_project` | Capy 專案的名稱或 ID |

私有專案需要指明該專案的授權，或擁有者存取權。使用 `memory_search` 和 `memory_list` 時，在 `project` 中指定私有專案。你有權存取的其他公開專案，用 `scopes` 指定。

## 路由

路由為 `send` 選出目標。使用接受路由的模組，例如 `capy`、`claude-routine` 或 `grok-routine`。用 `to="agent:<name>"` 可以直接傳送到代理的信箱，用 `to="agent:muse"` 傳送到 Muse 信箱，用 `to="muse:gadget:muse"` 則會[喚醒 Muse](/zh-Hant/docs/setup/muse#即時喚醒-muse)。

| 工具 | 用途 |
| - | - |
| `routes_list` | 列出所有路由，包括信箱路由 |
| `routes_set` | 儲存一條路由。`target` 可以是代理信箱，例如 `agent:<name>`，也可以是模組位址，例如 `capy:captain:<name>`。用 `agent` 或 `project` 限定路由的適用對象 |
| `routes_resolve` | 顯示某個目的地適用的路由。傳入 `block`，例如 `grok-routine` 或 `agent` |
| `routes_remove` | 在選定的 `block` 上，移除與 `agent` 和 `project` 完全相符的路由 |

用 `block` 可檢查或移除單一目的地的路由。`routes_resolve` 預設先檢查代理加專案的組合，再依序檢查專案、代理和全域路由。在每一層，它會先依序檢查各個模組，再檢查 `agent`。`routes_remove` 預設也依相同的目的地順序，尋找與代理和專案完全相符的路由。

### [Webhooks](/zh-Hant/docs/blocks/webhooks)

| 工具 | 用途 |
| - | - |
| `webhook_create` | 建立一個具名的傳入或傳出 Webhook |
| `webhook_list` | 列出 Webhook，以及各自的網址、計數和密鑰狀態 |
| `webhook_rotate` | 取得用來設定新密鑰的認領連結，並可選擇設定寬限期 |
| `webhook_revoke` | 停止某個 Webhook，並刪除它已儲存的密鑰 |
| `webhook_test` | 傳送一個範例傳入事件或一則範例傳出訊息 |

如果是傳出 Webhook，`webhook_create` 和 `webhook_rotate` 都接受 `allow_private` 和 `senders`。HTTPS 接收端位於私有網路，或使用 443 以外的連接埠時，把 `allow_private` 設為 `true`。在 `senders` 填入已連接代理的位址，授予傳送權限。預設只有擁有者可以傳送。呼叫 `webhook_rotate` 時，省略的欄位會保留原值。

如果 SwB 拒絕傳送訊息給 `webhook:out` 目標，就會回傳 MCP 工具錯誤。透過 HTTP 呼叫時，回應狀態為 `200`，工具結果中的 `isError` 為 `true`。

對擁有者以外的呼叫者，目標缺失或超出授權範圍時，SwB 一律回傳 `No such target.` 錯誤。
