## Un solo propietario

SwB tiene un solo propietario. El propietario aprueba los inicios de sesión de los agentes y usa la consola de SwB para gestionar el acceso y guardar tokens.

## Inicio de sesión de los agentes

OAuth permite que una app inicie sesión con la aprobación del propietario. SwB usa PKCE con S256 para verificar que la misma app empieza y termina el inicio de sesión. SwB vincula cada token OAuth a una dirección de `/mcp`. De forma predeterminada, los tokens de acceso duran una hora y los tokens de renovación duran 30 días. SwB sustituye cada token de renovación después de usarlo. Guarda hashes SHA-256 de los tokens OAuth. Un hash es una huella que SwB usa para comprobar el token. Los agentes también pueden usar una clave configurada o canjear un código de emparejamiento por una clave.

## Confianza

SwB comprueba los IDs de remitente que da la plataforma para asignar el nivel de confianza de cada mensaje.

| Confianza | Quién |
| - | - |
| `owner` | Tú y tus propios agentes con sesión iniciada |
| `external` | Los demás remitentes, incluidos las personas y los bots que figuran en `known` |

En Slack, Discord y Telegram, `known` ayuda a SwB a elegir de quién acepta mensajes. Los mensajes de estos remitentes externos conservan el nivel de confianza `external`. Consulta [Cuentas de propietario de GitHub](/es/docs/blocks/github#cuentas-de-propietario) para ver cómo comprueba SwB a los autores de GitHub.

Un **marco de confianza** es la cabecera y los marcadores que SwB añade al texto externo. SwB modifica las copias de su cabecera o de sus marcadores en el texto antes de añadir el marco. Los marcadores son `<<<swb-untrusted` y `swb-untrusted>>>`. Los agentes tratan el texto entre ellos solo como información.

Un resumen del modo Watch tiene el nivel de confianza `external`. Cada fragmento incluye un marco de confianza para el texto externo. SwB comprueba el autor de cada campo de texto de GitHub.

La clave de un [companion](/es/docs/companion) sirve solo para la conexión de su dispositivo. SwB guarda solo un hash de la clave para comprobarla. SwB marca los resultados del dispositivo como `external` y pone su texto libre en un marco de confianza.

## Visibilidad

Un recurso es un destino, un canal, un ámbito de memoria, una ruta o una herramienta. La regla de acceso predeterminada es `private`, para el propietario y sus agentes. Puedes compartir recursos con un espacio de trabajo o con personas concretas. Las herramientas siguen siendo privadas. Los remitentes externos llegan a un destino cuando lo permiten las reglas del canal y del destino. Cuando SwB guarda un mensaje como contexto, el mensaje va a la bandeja de entrada como información. El agente sigue dormido.

## Claves con límites

Usa `auth.key_scopes` para limitar el acceso a las rutas, los mensajes y las conversaciones. Una clave emparejada puede leer solo los mensajes y las conversaciones de su agente dentro de esos límites.

SwB guarda las concesiones de memoria de cada clave emparejada. Cuando actualiza concesiones antiguas, SwB da `general` y los proyectos que existen en ese momento a las claves emparejadas activas con acceso amplio. Para las claves con ámbitos nombrados en `auth.key_scopes`, SwB copia esos ámbitos.

Un cliente OAuth o una clave configurada con acceso completo puede acceder a toda la memoria como el propietario. Usa `auth.key_scopes` para limitar el acceso a la memoria por nombre de agente. Una credencial limitada necesita una concesión que nombre el proyecto privado.

`auth.key_tools` limita las herramientas a las que puede llamar una clave. `auth.key_targets` limita adónde puede enviar.

## Tokens

Escribe los tokens en sus páginas de entrega. SwB usa una clave de la carpeta de datos para cifrar los tokens que guarda. El estado muestra los nombres de las variables que faltan y oculta sus valores. La clave de Capy va en una cabecera de petición a `api.capy.ai` de forma predeterminada.

Abre **Tokens** para ver los ámbitos de memoria de cada clave emparejada. Selecciona **Remove scope** junto a un ámbito para quitar esa concesión.

Una clave emparejada nueva recibe su propio ámbito de agente al canjear su código de emparejamiento. También recibe el proyecto nombrado en el código y los ámbitos nombrados en `auth.key_scopes.<agent>`. Para ampliar el acceso, define los ámbitos adicionales o incluye un proyecto en el código de emparejamiento. Después empareja una clave nueva.

## Límites

| Límite | Valor |
| - | - |
| Claves bearer inválidas | 20 intentos por dirección en 10 minutos, después HTTP `429` |
| Eventos de GitHub enrutados desde remitentes ajenos a las cuentas de propietario | 5 por remitente en los últimos 10 minutos |
| `/register` | 20 por dirección y hora |
| `/token` | 120 por dirección en 10 minutos |
| `/authorize` | 60 por dirección en 10 minutos |
| Códigos erróneos en `/companion/pair` | 10 por dirección en 10 minutos, después HTTP `429` |
| Códigos erróneos en `/connect` | 10 por dirección en 10 minutos, después HTTP `429` |
| Límite predeterminado del cuerpo de petición | 1 MiB |
| Cuerpo de petición en `/mcp` y `/companion/results` | 16 MiB |
| Cuerpo de petición en `/companion/emit` | 16.640 bytes |
| Cuerpo de petición en `/auth/setup` | 1.024 bytes |
| Turnos por conversación entre agentes | 200 |

El límite de claves bearer también se aplica a las claves válidas desde la misma dirección. SwB devuelve HTTP `429` en los endpoints afectados hasta que el límite se restablece.

SwB pausa una conversación al llegar al límite de turnos. Anota la pausa en el registro de auditoría. Si Slack está activo, envía un mensaje directo al propietario.

El bloque de Capy puede devolver la conversación anterior para la misma tarea y el mismo destino. Define el intervalo de tiempo con `blocks.capy.duplicate_window_s`. El valor predeterminado es 600 segundos.

## Direcciones de cliente

SwB usa la dirección de la conexión para los límites y los registros de auditoría de forma predeterminada. Añade tu proxy a `trusted_proxies` o a `SWB_TRUSTED_PROXIES`. Así SwB usa la dirección de cliente que envía el proxy. Configura el proxy para que defina las cabeceras de dirección de cliente a partir de una fuente que verifique.

Usa la [guía de configuración de Cloudflare](/es/docs/cloudflare#proxies-de-confianza) para añadir un conector de Cloudflare Tunnel o un proxy inverso en tu red de Docker.

## Registro de auditoría

SwB anota las llamadas a herramientas que rechazan sus reglas de acceso. Anota los inicios de sesión fallidos en el navegador con códigos de configuración, enlaces usados, caducados o inválidos, llaves de acceso, comprobaciones CSRF y OIDC.

SwB anota las firmas de webhooks de GitHub ausentes o inválidas. Limita las filas repetidas de algunos fallos del navegador y de los webhooks rechazados. Las filas de fallos dan el motivo y mantienen privados los códigos, los tokens y las firmas.

La página de SwB muestra los registros en **Audit**. Ejecuta `swb log` para mostrar los registros recientes. Los envíos a buzones tienen la acción `send`. Consulta [Modos de canal](/es/docs/channel-modes#comprobar-una-entrega) para los registros de entregas descartadas.
