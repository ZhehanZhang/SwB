---
title: Cloudflare
description: Usa Cloudflare Tunnel para tener una dirección pública de SwB y Cloudflare Access para el inicio de sesión del propietario.
---

Cloudflare Tunnel da a SwB una dirección HTTPS pública fija. Un **túnel** conecta tu servidor con Cloudflare. Cloudflare Access limita la consola de SwB a tu cuenta.

## Antes de empezar

Sigue [Docker Compose](/es/docs/self-hosting#docker-compose) para iniciar SwB. Usa una cuenta de Cloudflare que pueda gestionar túneles y aplicaciones de Access para tu dominio. Permite que tu servidor se conecte a Cloudflare por el puerto 7844.

## Crear el túnel

Sigue [Create a tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/). Copia el token del túnel del comando de instalación. Ponlo en la entrada de `.env` de SwB que indica [el archivo Compose](https://github.com/ZhehanZhang/SwB/blob/273e0a9f2cb35ed929404ef23d7aca9d25ade44d/compose.yaml#L32-L39). Mantén el token en privado.

Inicia el conector del túnel en el servidor de SwB.

```sh
docker compose --profile tunnel up -d
```

Selecciona **Continue** cuando el conector aparezca en Cloudflare.

## Proteger la consola

[Crea una aplicación de Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/) para el nombre de host de SwB. Elige **Allow** como acción de la política. En **Include** → **Emails**, escribe tu dirección de correo.

Crea otra aplicación de Access en el mismo nombre de host para las rutas marcadas como **Bypass**. Elige **Bypass** como acción de su política. En **Include**, selecciona **Everyone**.

| Ruta | Política de Access |
| --- | --- |
| `/mcp`, `/register`, `/token`, `/revoke`, `/.well-known/*` | Bypass |
| `/healthz`, `/connect`, `/avatars/*` | Bypass |
| `/inbox/poll`, `/inbox/events` | Bypass |
| `/companion/*` | Bypass |
| `/github/webhook` | Bypass para GitHub |
| `/hooks/*` | Bypass para Webhooks |
| Todas las demás rutas, incluidas `/pairing/companion`, `/authorize` e `/inbox` | Propietario |

SwB comprueba los códigos de emparejamiento en `/companion/pair`. Comprueba la clave del dispositivo en las demás peticiones del companion. Si usas Access, pide a un agente con acceso de propietario que llame a `companion_code`.

## Definir la dirección de SwB

Define `SWB_PUBLIC_URL` en `.env` con tu dirección pública. Por ejemplo, usa `https://swb.example.com`. Añade el dominio de tu equipo y la etiqueta de audiencia de la aplicación del propietario a `config/switchboard.yaml`. La etiqueta indica a SwB qué aplicación emitió el token.

| Valor | Dónde encontrarlo | Clave de configuración |
| --- | --- | --- |
| Dominio del equipo | **Zero Trust** → **Settings** | `auth.cloudflare_access.team_domain` |
| Application Audience (AUD) Tag | Aplicación del propietario → **Additional settings** | `auth.cloudflare_access.aud` |
| Tu dirección de correo | Política del propietario → **Emails** | `auth.owner_emails` |

```yaml
auth:
  owner_emails: [owner@swb.example.com]
  cloudflare_access:
    team_domain: example.cloudflareaccess.com
    aud: "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
```

Ejecuta `docker compose --profile tunnel up -d` otra vez para aplicar los ajustes.

## Publicar el nombre de host

Abre la pestaña **Routes** del túnel. Selecciona **Add route**. Elige **Published application**. Escribe tu nombre de host público. En **Service URL**, escribe `http://switchboard:8000`. Selecciona **Add route** para guardar la ruta.

## Comprobar la conexión

Abre `https://swb.example.com` en un navegador. Inicia sesión en Cloudflare Access. Abre `https://swb.example.com/healthz` para comprobar que SwB responde.

Abre `https://swb.example.com/mcp` en una ventana privada del navegador. SwB devuelve `401` con una cabecera `WWW-Authenticate`. Si Cloudflare muestra su página de inicio de sesión, revisa la política de bypass.

## Configurar una app

Cuando el nombre de host funcione, usa [Conectar tus agentes](/es/docs/connect) para configurar una app. Usa la dirección MCP pública, por ejemplo `https://swb.example.com/mcp`. Pide a tu agente que llame a `switchboard_status` para comprobar su identidad en SwB.
