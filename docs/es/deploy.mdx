## Ejecutar en tu ordenador [#run-on-your-computer]

Sigue [Instalación](/es/docs/install). Abre el enlace de inicio de sesión de un solo uso que SwB muestra en el primer arranque local. Para obtener un enlace nuevo, ejecuta `swb login-link`. El prompt de despliegue también sirve para la configuración local.

## Desplegar SwB

Pega este prompt en un agente de programación como Claude Code o Codex. El agente te guía en la configuración local o alojada.

## En tu servidor

### Docker Compose [#docker-compose]

Instala Docker Compose 2.24 o una versión posterior. Ejecuta estos comandos como un usuario normal que sea propietario de la carpeta de datos.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Abre en un plazo de cinco minutos el enlace de inicio de sesión de un solo uso que aparece en la terminal. Mantén el enlace en privado.

El navegador usa `http://localhost:8870` para el inicio de sesión del propietario. El comando dentro del contenedor usa el puerto `8000`. Compose guarda los datos en `./data`. Después de cambiar `.env`, ejecuta `docker compose up -d` de nuevo.

Para un servidor remoto, reenvía su puerto `8870` al puerto local `8870` antes de abrir el enlace.

Una petición anónima a `/healthz` devuelve `status` y `version`. Usa una sesión de propietario o la clave de propietario para ver todos los detalles de estado.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

Un Cloudflare Tunnel da a SwB una dirección HTTPS pública. Los túneles están incluidos en el plan gratuito de Cloudflare.

Sigue la [guía de configuración de Cloudflare](/es/docs/cloudflare) para configurar SwB y definir las reglas de acceso del propietario y de las peticiones de clientes.

### Fly.io [#fly]

Usa la copia local de SwB que clonaste en el [ejemplo de Docker Compose](#docker-compose). Instala la [herramienta de línea de comandos de Fly.io](https://docs.fly.io/flyctl/). Inicia sesión en Fly.io.

Ejecuta `sh deploy/fly.sh my-swb` desde la carpeta de SwB. Cambia `my-swb` por un nombre de app único. El script usa `fly deploy --ha=false` para iniciar una Machine.

Abre la página de inicio de sesión de tu app. Copia `SWB_SETUP_CODE` de `.env.swb-setup-fly-my-swb` en tu copia local. Escríbelo en **Setup code**. Borra el archivo después de iniciar sesión.

Consulta el [plan Free de Fly.io](https://docs.fly.io/about/free-plan) y las [tarifas actuales](https://fly.io/docs/about/pricing/) para los detalles de facturación.

### Railway [#railway]

Despliega desde la [plantilla de SwB en Railway](https://railway.com/deploy/swb). Mantén una sola réplica. La plantilla monta un volumen en `/data`.

Usa el plan Hobby para tener SwB siempre en marcha. Hobby cuesta 5 USD al mes e incluye 5 USD de uso.

El [plan Free](https://docs.railway.com/reference/pricing/free-trial) incluye 1 USD de uso al mes. Esa cantidad cubre unos 100 MB de RAM las 24 horas. Una instancia de prueba de SwB usó unos 107 MiB en reposo. Los servicios del plan Free se detienen cuando se agota ese dólar.

## Iniciar sesión

Abre la dirección de inicio de sesión que aparece en el registro del servicio. Copia `SWB_SETUP_CODE` de los ajustes del servicio o del archivo privado que indica el comando de despliegue. Pégalo en **Setup code**. Selecciona **Sign in**. Añade una [llave de acceso](/es/docs/owner-login#llave-de-acceso) para los próximos inicios de sesión.
