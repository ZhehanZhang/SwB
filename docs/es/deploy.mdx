## En tu servidor

### Docker Compose [#docker-compose]

Instala Docker Compose 2.24 o una versión posterior. Docker Compose ejecuta SwB en un contenedor. Ejecuta estos comandos con el usuario propietario de la carpeta de datos.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Para un servidor remoto, reenvía su puerto `8870` al puerto `8870` de tu ordenador. Abre el enlace de inicio de sesión de un solo uso en un plazo de cinco minutos. Mantén el enlace en privado.

Tu navegador usa `http://localhost:8870` para iniciar sesión. El comando dentro del contenedor usa el puerto `8000`. Compose guarda los datos en `./data`. Ejecuta `docker compose up -d` después de cambiar `.env`.

Una petición anónima a `/healthz` devuelve `status` y `version`. Usa una sesión de propietario o la clave de propietario para ver todos los detalles de estado.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

## En la nube

Usa una sola instancia de SwB con un disco montado en `/data`. El disco conserva tus datos cuando la instancia se reinicia. Encontrarás plantillas y scripts para cada plataforma en la [guía de despliegue](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy).

### Fly.io [#fly]

Usa los archivos de SwB del [ejemplo de Docker Compose](#docker-compose). Instala Python 3.11 o una versión posterior, o instala [uv](https://docs.astral.sh/uv/). Instala la [herramienta de línea de comandos de Fly.io](https://docs.fly.io/flyctl/). Inicia sesión en Fly.io.

Añade una tarjeta de pago para recibir 5 USD de uso al mes con el [plan Free de Fly.io](https://docs.fly.io/about/free-plan). Usa tu organización personal para este plan. Si gastas los 5 USD completos, Fly factura el mes entero con las tarifas estándar. Esta configuración cuesta unos 3,84 USD por 30 días en Ashburn, más la transferencia de datos.

Ejecuta `sh deploy/fly.sh my-swb` desde la carpeta de SwB. Cambia `my-swb` por un nombre de app único. El script usa `fly deploy --ha=false` para iniciar una Machine. El script comprueba la Machine, el volumen y las direcciones.

Abre la página de inicio de sesión de tu app. Copia `SWB_SETUP_CODE` de `.env.swb-setup-fly-my-swb` en la carpeta de SwB. Escríbelo en **Setup code**. Borra el archivo después de iniciar sesión.

Consulta las [tarifas actuales](https://fly.io/docs/about/pricing/) para ver los detalles de facturación.

### Render [#render]

Abre el [Render Blueprint](https://render.com/deploy?repo=https://github.com/ZhehanZhang/SwB/tree/release/1.0). El Blueprint crea un servicio web de pago y un disco de 1 GB. Abre **Environment** en el servicio. Copia `SWB_SETUP_CODE`.

### Railway [#railway]

Despliega desde la [plantilla de SwB en Railway](https://railway.com/deploy/swb). Mantén una sola réplica. Monta un volumen de 1 GB en `/data`.

Usa el plan Hobby para tener SwB siempre en marcha. Cuesta 5 USD al mes e incluye 5 USD de uso.

El [plan Free](https://docs.railway.com/pricing/free-plan) admite un volumen de 0,5 GB. Los servicios gratuitos entran en reposo cuando están inactivos. El plan incluye 1 USD de uso al mes. Esa cantidad cubre unos 100 MB de RAM de forma continua. Una prueba de SwB usó unos 107 MiB de RAM en reposo.

## Iniciar sesión

Abre la dirección de inicio de sesión que aparece en el registro del servicio. Copia `SWB_SETUP_CODE` de los ajustes del servicio o del archivo privado que indica el comando de despliegue. Pégalo en **Setup code**. Selecciona **Sign in**. Añade una [llave de acceso](/es/docs/owner-login#llave-de-acceso) para los próximos inicios de sesión.
