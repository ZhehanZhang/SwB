## Sur votre serveur

### Docker Compose [#docker-compose]

Installez Docker Compose 2.24 ou une version ultérieure. Il exécute SwB dans un conteneur. Exécutez ces commandes avec l'utilisateur propriétaire du dossier de données.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

Pour un serveur distant, redirigez son port `8870` vers le port `8870` de votre ordinateur. Ouvrez le lien de connexion à usage unique dans les cinq minutes. Gardez ce lien privé.

Votre navigateur utilise `http://localhost:8870` pour la connexion. La commande dans le conteneur utilise le port `8000`. Compose stocke les données dans `./data`. Après une modification de `.env`, exécutez `docker compose up -d`.

Une requête anonyme vers `/healthz` renvoie `status` et `version`. Utilisez une session propriétaire ou la clé propriétaire pour obtenir l'état de santé détaillé.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

Un tunnel connecte votre serveur à Cloudflare et donne à SwB une adresse HTTPS publique. Suivez [Cloudflare](/fr/docs/cloudflare) pour configurer un tunnel.

## Dans le cloud

Utilisez une seule instance SwB avec un disque monté sur `/data`. Le disque conserve vos données quand l'instance redémarre. Vous trouverez les modèles et les scripts de chaque plateforme dans le [guide de déploiement](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy).

### Fly.io [#fly]

Utilisez les fichiers SwB de l'[exemple Docker Compose](#docker-compose). Installez Python 3.11 ou une version ultérieure, ou installez [uv](https://docs.astral.sh/uv/). Installez l'[outil en ligne de commande Fly.io](https://docs.fly.io/flyctl/). Connectez-vous à Fly.io.

Ajoutez une carte de paiement pour obtenir 5 $ d'utilisation par mois avec l'[offre gratuite de Fly.io](https://docs.fly.io/about/free-plan). Utilisez votre organisation personnelle pour cette offre. Si vous consommez les 5 $ en entier, Fly facture le mois complet au tarif standard. Cette configuration coûte environ 3,84 $ pour 30 jours à Ashburn, hors transfert de données.

Exécutez `sh deploy/fly.sh my-swb` depuis le dossier SwB. Remplacez `my-swb` par un nom d'application unique. Le script utilise `fly deploy --ha=false` pour démarrer une seule Machine. Le script vérifie la Machine, le volume et les adresses.

Ouvrez la page de connexion de votre application. Copiez `SWB_SETUP_CODE` depuis le fichier `.env.swb-setup-fly-my-swb` du dossier SwB. Saisissez-le dans **Setup code**. Supprimez le fichier après la connexion.

Consultez les [tarifs actuels](https://fly.io/docs/about/pricing/) pour la facturation.

### Render [#render]

Ouvrez le [Render Blueprint](https://render.com/deploy?repo=https://github.com/ZhehanZhang/SwB/tree/release/1.0). Le Blueprint crée un service web payant et un disque de 1 Go. Ouvrez **Environment** dans le service. Copiez `SWB_SETUP_CODE`.

### Railway [#railway]

Déployez depuis le [modèle SwB sur Railway](https://railway.com/deploy/swb). Gardez une seule réplique. Montez un volume de 1 Go sur `/data`.

Pour garder SwB actif en permanence, choisissez l'offre Hobby. Elle coûte 5 $ par mois et inclut 5 $ d'utilisation.

L'[offre gratuite](https://docs.railway.com/pricing/free-plan) prend en charge un volume de 0,5 Go. Les services gratuits se mettent en veille quand ils sont inactifs. L'offre inclut 1 $ d'utilisation par mois. Ce montant couvre environ 100 Mo de RAM en continu. Un test de SwB utilisait environ 107 Mio de RAM au repos.

## Se connecter

Ouvrez l'adresse de connexion indiquée dans le journal du service. Copiez `SWB_SETUP_CODE` depuis les paramètres du service ou depuis le fichier privé qu'indique la commande de déploiement. Collez-le dans **Setup code**. Sélectionnez **Sign in**. Ajoutez une [clé d'accès](/fr/docs/owner-login#clé-daccès) pour vos prochaines connexions.
