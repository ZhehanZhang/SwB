---
title: Connexion du propriétaire
description: Connectez-vous avec une clé d'accès, un lien à usage unique, un code de configuration ou votre fournisseur d'identité.
---

Le propriétaire se connecte pour gérer SwB. Cet accès lui permet d'approuver les connexions des agents et d'enregistrer des jetons.

| Page | Usage |
| - | - |
| `/login` | Se connecter en tant que propriétaire. |
| `/authorize` | Examiner la demande de connexion d'un agent. |

## Lien à usage unique

```bash
swb login-link
```

La commande affiche un lien comme `https://swb.example.com/login#t=...`. Dans les cinq minutes, ouvrez-le dans votre navigateur. Le lien fonctionne une seule fois. Un agent connecté en tant que propriétaire peut aussi créer un lien avec l'outil `login_link`. Le jeton reste dans la partie du lien qui suit `#`.

Au premier démarrage local, `swb up` affiche un lien à usage unique. L'adresse locale par défaut est `http://localhost:8870`. Si vous définissez `SWB_PORT`, SwB utilise ce port dans l'adresse. Avec `swb login-link`, utilisez `--url` pour choisir un autre serveur. Utilisez `--dir` pour lire la clé propriétaire dans un autre dossier d'instance.

Si la connexion par le lien échoue, exécutez de nouveau `swb login-link`. Ouvrez le nouveau lien dans votre navigateur.

## Code de configuration

Un code de configuration fonctionne une seule fois, pour la première connexion du propriétaire. Utilisez-le quand SwB gère lui-même la connexion. Le [guide de déploiement](/fr/docs/deploy) indique où trouver le code pour un serveur hébergé.

Pour définir votre propre code, générez 32 octets aléatoires. Encodez-les en 64 caractères hexadécimaux minuscules ou en Base64 standard. Cette commande ajoute un code hexadécimal au fichier privé `.env`. Exécutez-la dans le dossier de l'instance après `swb init`.

```bash
(umask 077; printf 'SWB_SETUP_CODE=%s\n' "$(openssl rand -hex 32)" >> .env)
```

Démarrez SwB avec `SWB_SETUP_CODE` défini. Ouvrez `/login` dans votre navigateur. Collez le code dans **Setup code**. Sélectionnez **Sign in**.

## Clé d'accès

Une **clé d'accès** utilise votre appareil pour confirmer votre connexion. Après votre première connexion, saisissez le nom de votre appareil dans **Passkey name**. Sélectionnez **Add a passkey**.

Pour un autre appareil, ouvrez **Settings**. Sous **Sign-in**, sélectionnez **Add a passkey**. Saisissez un nom. Sélectionnez **Add passkey** pour l'enregistrer. Utilisez votre clé d'accès pour vos prochaines connexions.

## OIDC

OpenID Connect (OIDC) permet à un service de connexion comme Google de confirmer votre identité. Ajoutez votre service au fichier de configuration. Donnez à `SWB_OIDC_CLIENT_SECRET` la valeur du secret fourni par ce service.

```yaml
public_url: https://swb.example.com
auth:
  owner_emails: [owner@swb.example.com]
  oidc:
    name: Google
    issuer: https://accounts.google.com
    client_id: 1234.apps.googleusercontent.com
    client_secret_env: SWB_OIDC_CLIENT_SECRET
```

Chez votre fournisseur, définissez l'adresse de redirection `https://swb.example.com/auth/oidc/callback`. La page de connexion affiche un bouton pour votre service. SwB accepte une adresse e-mail vérifiée listée dans `auth.owner_emails`. Vous pouvez aussi indiquer les ID de compte de votre service dans `auth.oidc.owner_subjects`.

## Cloudflare Access

Suivez [Configuration de Cloudflare](/fr/docs/cloudflare#cloudflare-access) pour protéger la console avec Cloudflare Access. SwB vérifie le jeton Access et compare l'adresse e-mail à `auth.owner_emails` ou à `SWB_OWNER_EMAILS`.

## Connexion des agents

OAuth permet à une application de se connecter à SwB avec votre accord. Approuvez la connexion sur `/authorize`. L'application reçoit la portée OAuth `switchboard`, c'est-à-dire le nom de l'accès qu'elle demande. L'application utilise `/token` pour obtenir ou renouveler ses jetons.

Quand l'application reçoit une erreur OAuth, consultez `error_description` pour les détails.

| Erreur | Signification |
| - | - |
| `access_denied` | Le propriétaire a refusé la connexion. |
| `invalid_client` | SwB a refusé l'identité ou les identifiants de l'application. |
| `invalid_client_metadata` | SwB a refusé les paramètres d'enregistrement de l'application. |
| `invalid_redirect_uri` | SwB exige une adresse de rappel autorisée à l'enregistrement. |
| `invalid_request` | Le format de la requête ou une valeur obligatoire est invalide. |
| `invalid_grant` | SwB a refusé le code d'autorisation ou le jeton d'actualisation. |
| `invalid_target` | La requête indique une mauvaise adresse MCP. |
| `unsupported_response_type` | Utilisez `response_type=code`. |
| `unsupported_grant_type` | Utilisez `grant_type=authorization_code` ou `grant_type=refresh_token`. |
| `temporarily_unavailable` | Définissez `public_url` ou vérifiez la limite d'enregistrement des clients. |

`/connect` renvoie aussi `invalid_grant` quand SwB refuse un [code d'appairage](/fr/docs/connect#connecter-un-agent-avec-un-code-dappairage).

## Sessions

Un **cookie** est une valeur que votre navigateur enregistre pour que vous restiez connecté. SwB active l'option `Secure` sur ce cookie. Utilisez HTTPS pour une adresse publique.

Quand vous modifiez un paramètre, le navigateur envoie un jeton. SwB l'utilise pour vérifier la requête. Déconnectez-vous depuis **Settings**.

Le navigateur lit l'état de votre connexion sur `/auth/session`.

## Erreurs de connexion

SwB enregistre les échecs de connexion du navigateur sous **Audit**. Chaque ligne indique la raison et garde les codes et les jetons privés. Pour certains échecs, SwB limite les lignes répétées.

| Erreur | Signification |
| - | - |
| `link_used` | Quelqu'un a déjà utilisé le lien avant son expiration. |
| `link_expired` | Le lien a expiré. |
| `link_invalid` | SwB a refusé le lien. |
| `setup_failed` | Le code de configuration a un mauvais format ou diffère de `SWB_SETUP_CODE`. |
| `setup_closed` | La connexion par code de configuration est fermée. Utilisez une autre méthode de connexion. |
| `passkey_failed` | La création ou la vérification de la clé d'accès a échoué. |
| `last_method` | SwB garde la dernière clé d'accès quand OIDC et Cloudflare Access sont tous deux inactifs. |
| `not_found` | L'ID de la clé d'accès est incorrect, ou la clé a été supprimée. |
| `oidc_failed` | La connexion par le fournisseur d'identité a échoué. |
| `signed_out` | La requête nécessite une session propriétaire. |
| `csrf` | SwB a refusé l'adresse de la page ou le jeton de sécurité. |
| `slow_down` | Les tentatives de connexion ont atteint une limite. Attendez la durée indiquée dans `Retry-After`. |
