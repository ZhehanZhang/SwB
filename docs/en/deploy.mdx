## On your server

### Docker Compose [#docker-compose]

Install Docker Compose 2.24 or later. It runs SwB in a container. Run these commands as the user who owns the data folder.

```bash
git clone --branch release/1.0 https://github.com/ZhehanZhang/SwB.git
cd SwB
(umask 077; cp .env.example .env)
{
  printf 'SWB_UID=%s\n' "$(id -u)"
  printf 'SWB_KEY_OWNER='
  openssl rand -hex 32
} >> .env
printf 'SWB_PUBLIC_URL=http://localhost:8870\n' >> .env
mkdir -p data
docker compose up -d --build --wait
curl -fsS http://127.0.0.1:8870/healthz
docker compose exec -T switchboard swb login-link --url http://127.0.0.1:8000
```

For a remote server, forward its port `8870` to port `8870` on your computer. Open the one-time sign-in link within five minutes. Keep the link private.

Your browser uses `http://localhost:8870` for sign-in. The command inside the container uses port `8000`. Compose stores the data in `./data`. Run `docker compose up -d` after you change `.env`.

A signed-out request to `/healthz` returns `status` and `version`. Use an owner session or the owner key for full health details.

### <ProviderMark name="cloudflare" /> Cloudflare Tunnel [#cloudflare-tunnel]

A tunnel connects your server to Cloudflare and gives SwB a public HTTPS address. Follow [Cloudflare](/docs/cloudflare) to set up a tunnel.

## In the cloud

Use one SwB instance with a disk mounted at `/data`. The disk keeps your data when the instance restarts. Find platform templates and scripts in the [deployment guide](https://github.com/ZhehanZhang/SwB/tree/release/1.0/deploy).

### Fly.io [#fly]

Use the SwB files from the [Docker Compose example](#docker-compose). Install Python 3.11 or later, or install [uv](https://docs.astral.sh/uv/). Install the [Fly.io command line tool](https://docs.fly.io/flyctl/). Sign in to Fly.io.

Add a payment card to get $5 of usage each month on the [Fly.io Free plan](https://docs.fly.io/about/free-plan). Use your personal organization for this plan. If you use the full $5, Fly bills the full month at standard rates. This setup costs about $3.84 for 30 days in Ashburn before data transfer.

Run `sh deploy/fly.sh my-swb` from the SwB folder. Replace `my-swb` with a unique app name. The script uses `fly deploy --ha=false` to start one Machine. The script checks the Machine, volume and addresses.

Open your app's sign-in page. Copy `SWB_SETUP_CODE` from `.env.swb-setup-fly-my-swb` in the SwB folder. Enter it in **Setup code**. Delete the file after sign-in.

See the [current rates](https://fly.io/docs/about/pricing/) for billing details.

### Render [#render]

Open the [Render Blueprint](https://render.com/deploy?repo=https://github.com/ZhehanZhang/SwB/tree/release/1.0). The Blueprint creates a paid web service and a 1 GB disk. Open **Environment** in the service. Copy `SWB_SETUP_CODE`.

### Railway [#railway]

Deploy from the [SwB template on Railway](https://railway.com/deploy/swb). Keep one replica. Mount one 1 GB volume at `/data`.

Use the Hobby plan to keep SwB running at all times. It costs $5 a month and includes $5 of usage.

The [Free plan](https://docs.railway.com/pricing/free-plan) supports a 0.5 GB volume. Free services sleep when idle. The plan includes $1 of usage a month. That amount covers about 100 MB of RAM at all times. A SwB test used about 107 MiB of RAM while idle.

## Sign in

Open the sign-in address from the service log. Copy `SWB_SETUP_CODE` from the service settings or the private file named by the deploy command. Paste it in **Setup code**. Select **Sign in**. Add a [passkey](/docs/owner-login#passkey) for later sign-ins.
