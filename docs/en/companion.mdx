A **companion** is a device that connects to your SwB server. Agents can then use features on that device.

## Pair a device

Ask an agent signed in as the owner to call `companion_code`. Ask the agent to save the code in a file with permissions `0600`. These permissions give only the file owner access.

To get a code in the console, [sign in with a passkey](/docs/owner-login#passkey). Open **Settings**. In **Connections**, select **Pair a device**. If you use Cloudflare Access, use the `companion_code` tool.

Run this command on the device. Replace the example address with your SwB HTTPS address. For SwB on this device, you can use `http://127.0.0.1:8870`.

```sh
uvx swb-one companion connect https://swb.example.com --cap notify
```

Enter the pairing code at the hidden prompt. The code works once and expires after 10 minutes. The audit log records who made it.

The device saves its own key in a private file.

## Choose features

Add one `--cap` option for each feature you want to enable.

| Option | Feature |
| --- | --- |
| `--cap notify` | Shows desktop notifications on the device |
| `--cap drop` | Shares files up to 10 MiB each through the `~/SwB Drop` folder |
| `--cap mcp --mcp NAME=COMMAND` | Gives your agents access to tools on an MCP server on the device |
| `--cap herdr` | [Herdr](/docs/blocks/local-sessions#herdr) |
| `--cap codex` | [Codex app server](/docs/blocks/local-sessions#codex) |
| `--cap opencode` | [OpenCode server](/docs/blocks/local-sessions#opencode) |
| `--cap dsh` | [DeepSeek Harness](/docs/blocks/local-sessions#deepseek-harness) |
| `--cap hooks` | [Status hooks](/docs/blocks/local-sessions#status-hooks) |
| `--cap muse` | Pairs Muse over Bluetooth on a Mac or a Linux computer |

On Linux, notifications use `notify-send`. On Debian and Ubuntu, install it with the `libnotify-bin` package.

Use Python 3.13 to pair the Muse gadget. Follow the [Muse pairing guide](/docs/setup/muse). After pairing, the SwB server keeps the connection to Muse open.

```sh
uvx --python 3.13 --from 'swb-one[companion]' swb companion connect https://swb.example.com --cap muse
```

Add one `--mcp` option per MCP server. For a program, use `--mcp 'NAME=COMMAND'`. Replace `NAME` with a name for your server. Replace `COMMAND` with the program's start command. For an HTTP server on the device, use its local address, such as `--mcp notes=http://127.0.0.1:8000/mcp`.

Your agents use `companion_list` to see each paired device and its actions. They use `companion_invoke` to run an action.

Companion text results have a 1 MiB limit. Read Drop file data from `structuredContent.result.content_b64`.

## Local sessions

A **local session** is a coding agent's open conversation on the device. SwB lists its status with its `local:session:<companion>:<harness>:<session>` address.

Use the link for your coding agent in the feature table. Set up the agent before pairing. After pairing, keep the companion running. Ask an agent signed in as the owner to call `targets(block="local")`. Check that your session address appears.

SwB tries to deliver each message to the open session. It puts the message in the agent's mailbox when the sender can use that mailbox. The answer comes back in the same conversation.

Use the session address from `targets`. Find the resource for that address in `visibility_list`. Share the resource with `visibility_set`.

For commands and supported agents, see [Local sessions](/docs/blocks/local-sessions).

## Keep it running

Pairing starts the companion. Use `swb companion run` to start it again. Use `swb companion status` to see the local device ID and features.

Use `uvx swb-one` in place of `swb` to run these commands with `uvx`. For Muse, keep the package and Python options from the [Muse guide](/docs/setup/muse).

The device starts each connection to SwB.

## Disconnect

Run `swb companion disconnect` on the device to remove its key. To revoke the key in the console, open **Connections** in **Settings**. Select **Disconnect** for the device.

A running companion removes its local key when it detects the revocation. If a key remains on the device, run `swb companion disconnect` before pairing it again.
